# 第一个 90 天策略 - 从新员工到值得信赖的贡献者

您已经协商了要约，签署了合同，并清除了通知期。第一天到来了 - 突然之间，你成为了房间里知道得最少的人。每个系统都是陌生的，每个缩写词都是新的，你的 Slack 充满了你还不理解的频道。这一刻是你职业生涯中最激动人心的时刻，也是最脆弱的时刻。您在前 90 天内所做的事情决定了您是成为值得信赖的贡献者还是在六个月内原地踏步。好消息？有一个经过验证的框架。

<Callout>你的前 90 天并不是要证明你很聪明。它们是为了证明你是人们愿意合作的人，并且你可以交付。
</Callout>

## 30-60-90 天框架

30-60-90 框架将您的前三个月分为三个阶段，每个阶段都有不同的目标：

|相|时间轴 |主要目标|
| --- | --- | --- |
| **学习** |第 1-30 天 |吸收背景、建立关系、了解景观 |
| **贡献** |第 31-60 天 |提供您的第一个有意义的贡献并加深关系 |
| **拥有** |第 61-90 天 |掌控工作流、建立影响力并获取反馈 |

每个阶段都建立在前一个阶段的基础上。试图在第二周跳到“自己”是疏远新团队的最快方法。让我们分解每个阶段。

## 第 1 阶段：学习（第 1-30 天）

### 第 1-2 周：倾听、观察和联系

前两周你唯一的工作就是学习。抵制立即“增值”的冲动。相反，应关注：

**尽可能会见每个人。** 安排与每位团队成员、您的越级经理以及相邻团队的主要利益相关者进行 30 分钟的一对一交流。使用一个简单的模板：

> “嗨，[名字]，我是[你的名字] - 刚刚加入[团队名称]团队。我很想抽出 30 分钟时间来了解一下您的工作内容以及我们的团队如何互动。您通常的一周是怎样的？”

在这些对话中，询问：
- 团队目前最大的挑战是什么？
- 当你加入时，你希望有人告诉你什么？
- 我还应该和谁谈谈？

**了解代码库。**不要尝试读取每个文件。相反：
- 找到主要入口点并端到端跟踪单个请求
- 阅读 README 文件（如果存在）、架构决策记录和最近的拉取请求
- 设置开发环境并在本地运行测试套件
- 确定代码中更改最频繁的区域 - 这可能是您工作的地方

**确定快速成功。** 在您探索时，保留您注意到的小改进的运行列表 - 过时的文档、不稳定的测试、缺少错误处理、令人困惑的变量名称。这些将成为你的第一个贡献。

<ThinkAboutIt>想想你的最后一个角色。您希望在第一周就知道什么？什么样的背景可以让你避免犯第一个错误？利用这些经验来指导您在新角色中寻找什么。
</ThinkAboutIt>

### 第 3-4 周：您的第一个贡献

到第二周结束时，你应该有足够的背景来完成一项小的、定义明确的任务。理想的第一个贡献是：

- **足够小**可在 2-3 天内完成
- **足够明显**，团队注意到
- **低风险** - 如果出错，生产不会中断
- **有价值** - 它解决了一个真正的问题，而不是一个虚构的问题

好的例子：修复已积压数周的错误、改进 CI 管道步骤、向未测试的模块添加测试覆盖率或更新过时的文档。

<FunFact>微软工程生产力团队的研究发现，与等待更长时间的员工相比，在第一周内提交第一个拉取请求的新员工的保留率和晋升时间表明显更高。早期势头很重要。
</FunFact>

**如何处理你的第一个 PR：**

1. 选择一项任务并告诉您的经理：“我想承担[任务]。这个规模和优先级看起来合适吗？”
2. 在编写代码之前阅读任何现有的模式或编码标准
3. 保持 PR 较小 - 如果可能的话，不要超过 200 行
4. 写一份完整的公关描述，解释你的方法和任何权衡
5. 请求 2-3 名团队成员进行评论（这可以建立关系）

## 第 2 阶段：贡献（第 31-60 天）

### 建立更深层次的关系

到第二个月，你应该从“与每个人见面”转向建立有意义的工作关系。重点关注：

**寻找导师。** 这不必是正式的。寻找一位有耐心、慷慨且具有深厚机构知识的高级工程师。让他们与你结对执行复杂的任务。

**了解团队动态。** 每个团队都有不成文的规则 - 谁做出真正的决定，哪些会议真正重要，如何处理冲突。仔细观察并调整你的方法。

**加入跨职能工作。** 自愿参加工作组、招聘委员会或跨团队项目。这会将您的网络扩展到直接团队之外，并使其他领导者能够看到您。

### 始终如一地交付

在第二个月，你应该独立完成中等规模的任务。关键是一致性而非英雄行为：

- 每周发布 2-3 个 PR，而不是每两周发布一个大量 PR
- 当你遇到困难时尽早提出问题 - 三天内不要消失
- 开始参与代码审查（这是学习代码库和建立信任的最快方法之一）
- 积极参加冲刺仪式 - 提出澄清问题、提供估计、标记风险

<Callout>代码审查对于新员工来说是一种超能力。审查他人的代码比任何入职文档更快地教会您模式、约定和领域知识。尽早开始审阅，即使您的评论只是问题。
</Callout>

### 有目的地浏览代码库

现在，您应该对系统架构有了一个心理模型。通过以下方式加深它：

- 绘制服务、数据流和依赖关系的图表（并分享它 - 您的新观点很有价值）
- 端到端理解部署管道
- 了解待命操作手册的位置并通读它们
- 识别团队的技术债务并理解其存在的原因

## 第 3 阶段：拥有（第 61-90 天）

### 取得工作流的所有权

到第三个月，你应该准备好拥有一些有意义的东西。这可能是：

- 领导实施从设计到生产的功能
- 拥有特定服务的可靠性
- 推动技术改进（迁移、性能优化、可观察性）
- 运行峰值并向团队展示您的发现

关键词是**所有权** - 不仅仅是编写代码，而是成为团队在该领域所依赖的人。这意味着跟踪进度、沟通状态、解锁自己以及在需要时升级。

### 分享知识

第三个月你可以做的最有影响力的事情之一就是分享你学到的东西：

- **为最难弄清楚的事情编写文档** - 你是编写文档的最佳人选，因为痛苦仍然新鲜
- **进行简短的技术演讲**或闪电般地谈论您学到的东西（在团队会议上 5-10 分钟就足够了）
- **为下一个加入者更新入职文档**

### 获取结构化反馈

不要等待您的第一次正式审查。主动安排在 90 天左右与您的经理进行反馈对话：

> “我在这里已经大约三个月了，我很想得到您诚实的反馈。我哪里做得好？我应该在哪里重点改进？有什么我应该做的不同的吗？”

这可以完成三件事：显示自我意识，为您提供可行的方向，并与您的经理建立信任。

## 新员工常犯的错误

### 1. 试图太快地改变一切
你可能会发现到处都是效率低下的情况 - 而且你可能是对的。但在第一个月提出彻底的改变表明你不尊重现有决策背后的背景。 **先学习，然后提出建议。**

### 2. 卡住时变黑
新员工常常感到需要独自解决所有问题的压力。这是适得其反的。花30分钟卡住就可以了。三天被困而不寻求帮助对你的经理来说是一个危险信号。

### 3. 将所有内容与上一家公司进行比较
“在我以前的公司，我们是这样做的”是惹恼新同事的最快方式。相反，你可以问：“我很好奇这种方法背后的原因 - 你能帮我理解上下文吗？”

### 4. 忽略非技术关系
与产品经理、设计师和利益相关者建立关系与给工程师同事留下深刻印象同样重要。软件是一项团队运动。

<ThinkAboutIt>想一想有一次您看到新加入者很好地融入了团队。他们做了什么使他们有效的？相反，想想一个陷入困境的新加入者 - 你会建议他们采取什么不同的做法？
</ThinkAboutIt>

## 何时大声说话 vs 保持安静

这是新员工最难做出判断的问题之一。这是一个实用指南：

**请在以下情况下发言：**
- 您发现真正的错误或安全问题
- 您对正在讨论的问题有直接的相关经验
- 有人征求您的意见或反馈
- 正在做出的决定会影响你的工作，并且你有清晰的视角

**在以下情况下保持安静（或提出问题）：**
- 您没有足够的背景来形成有意义的意见
- 讨论的是你还不了解的历史决策
- 你想要炫耀而不是真正做出贡献
- 该话题具有政治敏感性，您还不了解动态

前 30 天的默认设置应该是**提出问题**而不是发表声明。 “你能帮我理解为什么我们选择这种方法吗？”几乎总是比“我认为我们应该采取不同的做法”更好。

## 与新经理建立信任

您与直接经理的关系是您前 90 天内最重要的关系。以下是如何构建它：

- **要可靠。** 如果你说你会做某事，那就去做吧。如果不能，请尽早沟通。
- **主动沟通。** 发送简短的每周更新（3-5 个要点），总结您所做的工作、下一步计划做什么以及任何阻碍。这可以减少经理的焦虑并使他们的工作变得更轻松。
- **明确询问他们的期望。** “对您来说，成功的第一季度是什么样的？”消除歧义。
- **对你不知道的事情诚实。** 假装自信是透明的，会削弱信任。说“我以前没有使用过 Kafka，但我将在本周学习它”可以建立信任。

<FunFact>《哈佛商业评论》的一项研究发现，新员工长期成功的最有力预测因素不是他们的技术技能，而是他们在前 90 天内与直接经理的关系质量。对这种关系的投资不是可选的 - 而是战略性的。
</FunFact>

## 要点

- **使用 30-60-90 框架** - 学习、贡献、拥有。每个阶段都有不同的目的；不要向前跳过。
- **在前两周内优先考虑关系而非代码** - 1:1 会议比现在的拉取请求更有价值。
- **尽早实现快速胜利** - 在第三周结束时做一些小、可见且有价值的事情。
- 在第一个月**自由提问**，在第二个月开始形成意见，并在第三个月做出自己的决定。
- **避免经典错误** - 不要试图改变一切，不要陷入黑暗，也不要将一切与上一份工作进行比较。
- **通过可靠性、主动沟通和诚实的自我意识与您的经理建立信任**。
- **在 90 天后请求反馈** - 不要等待正式的审核周期。

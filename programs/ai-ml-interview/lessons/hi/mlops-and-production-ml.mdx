# ⚙️ MLOps और प्रोडक्शन एमएल

एक आंकड़ा आपके इंटरव्यू की तैयारी को दिशा देना चाहिए: **87% एमएल मॉडल कभी प्रोडक्शन तक नहीं पहुंचते।** Jupyter नोटबुक और भरोसेमंद, स्केलेबल एमएल सेवा के बीच बहुत बड़ा अंतर है, और कंपनियों को ऐसे इंजीनियरों की सख्त ज़रूरत है जो यह अंतर पाट सकें। MLOps इंटरव्यू सवाल जांचते हैं कि क्या आप मॉडल को "मेरी मशीन पर चलता है" से "शनिवार सुबह 3 बजे भी लाखों उपयोगकर्ताओं के लिए भरोसेमंद चलता है" तक ले जा सकते हैं।

## 🧭 MLOps सच में क्या कवर करता है

MLOps वे प्रैक्टिस हैं जो DevOps अनुशासन को मशीन लर्निंग में लाते हैं। यह पूरे एमएल लाइफ़सायकल में फैला होता है:

```
Data → Feature Engineering → Training → Evaluation → Deployment → Monitoring → Retraining
  ↑                                                                              |
  └──────────────────────────── Feedback Loop ────────────────────────────────────┘
```

मुख्य स्तंभों में शामिल हैं:
- **एमएल के लिए CI/CD**: केवल कोड नहीं, डेटा, फ़ीचर और मॉडल की ऑटोमेटेड टेस्टिंग
- **एक्सपेरिमेंट ट्रैकिंग**: हाइपरपैरामीटर, मेट्रिक्स और आर्टिफ़ैक्ट का व्यवस्थित रिकॉर्ड
- **मॉडल वर्ज़निंग**: कौन-सा मॉडल वर्ज़न किस ट्रैफ़िक को सर्व कर रहा है, यह ट्रैक करना
- **मॉडल सर्विंग**: भविष्यवाणियों को उपयोगकर्ताओं तक भरोसेमंद और तेज़ पहुंचाना
- **मॉनिटरिंग**: प्रोडक्शन में मॉडल कब डिग्रेड होते हैं, यह पहचानना

<Callout>
MLOps और पारंपरिक DevOps में सबसे बड़ा अंतर: सॉफ़्टवेयर में कोड बदलाव चीज़ें तोड़ते हैं। एमएल में *डेटा* बदलाव चीज़ें तोड़ते हैं, अक्सर चुपचाप, बिना किसी त्रुटि लॉग के।
</Callout>

## 🚀 मॉडल सर्विंग पैटर्न

आप भविष्यवाणियां कैसे सर्व करते हैं, यह आपकी लेटेंसी आवश्यकताएं, स्केल और भविष्यवाणियां कितनी बार बदलनी चाहिए, इस पर निर्भर करता है।

### बैच इन्फ़रेंस

शेड्यूल पर भविष्यवाणियां पहले से कम्प्यूट करें (घंटेवार, दैनिक) और लुक-अप के लिए स्टोर करें।

**सबसे अच्छा किसके लिए**: ईमेल रिकमेंडेशन, दैनिक जोखिम स्कोर, साप्ताहिक रिपोर्ट

```
Schedule → Load data → Run model → Write predictions to DB → Serve from DB
```

**लाभ**: सरल इन्फ़्रास्ट्रक्चर, बड़े मॉडल इस्तेमाल हो सकते हैं, किफ़ायती
**कमी**: भविष्यवाणियां पुरानी हो सकती हैं, रीयल-टाइम संदर्भ पर प्रतिक्रिया नहीं दे सकता

### रीयल-टाइम इन्फ़रेंस (मॉडल-ऐज़-अ-सर्विस)

मॉडल API के पीछे चलता है। हर अनुरोध भविष्यवाणी ट्रिगर करता है।

**सबसे अच्छा किसके लिए**: सर्च रैंकिंग, फ़्रॉड डिटेक्शन, चैटबॉट

```
User request → API Gateway → Feature lookup → Model inference → Response
```

**लाभ**: ताज़ा भविष्यवाणियां, रीयल-टाइम संदर्भ इस्तेमाल हो सकता है
**कमी**: लेटेंसी-संवेदनशील, मॉडल आकार और सर्विंग इन्फ़्रास्ट्रक्चर ऑप्टिमाइज़ करने पड़ते हैं

### एम्बेडेड मॉडल

मॉडल सीधे एप्लिकेशन या डिवाइस में बंडल होता है।

**सबसे अच्छा किसके लिए**: मोबाइल ऐप, IoT डिवाइस, एज गणना

**लाभ**: नेटवर्क लेटेंसी नहीं, ऑफ़लाइन काम करता है
**कमी**: अपडेट करना कठिन, डिवाइस रिसोर्स से सीमित

## 📊 एक्सपेरिमेंट ट्रैकिंग

ट्रैकिंग के बिना एमएल एक्सपेरिमेंट चलाना लैब नोटबुक के बिना विज्ञान करने जैसा है। आपको रिकॉर्ड करना चाहिए:

- **हाइपरपैरामीटर**: लर्निंग दर, बैच आकार, आर्किटेक्चर चयन
- **मेट्रिक्स**: ट्रेनिंग लॉस, हर इपॉक पर वैलिडेशन मेट्रिक्स
- **आर्टिफ़ैक्ट**: मॉडल चेकपॉइंट, फ़ीचर महत्व प्लॉट, कन्फ़्यूज़न मैट्रिक्स
- **वातावरण**: लाइब्रेरी वर्ज़न, इस्तेमाल हार्डवेयर, यादृच्छिक सीड

### लोकप्रिय टूल

| टूल | खूबियां | डिप्लॉयमेंट |
|---|---|---|
| **MLflow** | ओपन-सोर्स, मॉडल रजिस्ट्री, व्यापक स्वीकार्यता | सेल्फ़-होस्टेड या मैनेज्ड |
| **Weights & Biases (W&B)** | सुंदर UI, सहयोग फ़ीचर, स्वीप | क्लाउड-होस्टेड |
| **Neptune.ai** | हल्का, टीमों के लिए अच्छा | क्लाउड-होस्टेड |
| **TensorBoard** | मुफ़्त, TensorFlow के साथ गहराई से इंटीग्रेटेड | लोकल या एम्बेडेड |

```python
import mlflow

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run():
    mlflow.log_param("learning_rate", 0.001)
    mlflow.log_param("n_estimators", 500)

    model = train_model(X_train, y_train)
    metrics = evaluate_model(model, X_test, y_test)

    mlflow.log_metric("auc_roc", metrics["auc_roc"])
    mlflow.log_metric("precision", metrics["precision"])
    mlflow.sklearn.log_model(model, "model")
```

## 🔍 प्रोडक्शन में एमएल मॉनिटरिंग

पारंपरिक सॉफ़्टवेयर मॉनिटरिंग त्रुटियां और लेटेंसी ट्रैक करती है। एमएल मॉनिटरिंग एक अहम परत जोड़ती है: **क्या मॉडल अभी भी अच्छी भविष्यवाणियां कर रहा है?**

### ड्रिफ़्ट के प्रकार

**डेटा ड्रिफ़्ट** (कोवेरिएट शिफ़्ट): इनपुट फ़ीचर का वितरण बदलता है। उदाहरण: प्री-पैंडेमिक डेटा पर ट्रेंड ई-कॉमर्स मॉडल को होम ऑफ़िस उपकरण खोजों में उछाल दिखता है।

**कॉन्सेप्ट ड्रिफ़्ट**: फ़ीचर और लक्ष्य का संबंध बदलता है। उदाहरण: मंदी के दौरान क्रेडिट स्कोरिंग मॉडल में "रोज़गार स्थिति" फ़ीचर का अर्थ बदल जाता है।

**प्रेडिक्शन ड्रिफ़्ट**: मॉडल आउटपुट का वितरण बदलता है, भले इनपुट समान दिखें।

### क्या मॉनिटर करें

| संकेत | कैसे पहचानें | कार्रवाई |
|---|---|---|
| इनपुट फ़ीचर वितरण | सांख्यिकीय टेस्ट (KS टेस्ट, PSI) | डेटा पाइपलाइन जांचें |
| प्रेडिक्शन वितरण | समय के साथ मीन, वैरिएंस, परसेंटाइल ट्रैक करें | बेसलाइन अवधि से तुलना करें |
| मॉडल प्रदर्शन (जब लेबल उपलब्ध हों) | ग्राउंड सत्य के विरुद्ध सटीकता, F1, आदि ट्रैक करें | सीमा से नीचे हो तो रीट्रेनिंग ट्रिगर करें |
| लेटेंसी | P50, P95, P99 जवाब समय | इन्फ़्रास्ट्रक्चर स्केल करें या मॉडल ऑप्टिमाइज़ करें |
| डेटा गुणवत्ता | नल दरें, स्कीमा उल्लंघन, वॉल्यूम विसंगतियां | डेटा इंजीनियरिंग टीम को अलर्ट करें |

```python
from scipy.stats import ks_2samp

# Kolmogorov-Smirnov test for distribution shift
def detect_drift(reference_data, current_data, threshold=0.05):
    statistic, p_value = ks_2samp(reference_data, current_data)
    return p_value < threshold  # True = drift detected
```

## 🔄 मशीन लर्निंग के लिए CI/CD

एमएल CI/CD कोड टेस्टिंग से आगे जाता है। आपको डेटा, फ़ीचर और मॉडल भी वैलिडेट करने होते हैं।

### एमएल Testing Pyramid

```
              ┌──────────────┐
              │  Model Tests  │  ← Does the model meet quality thresholds?
             ┌┴──────────────┴┐
             │  Feature Tests  │  ← Are features computed correctly?
            ┌┴────────────────┴┐
            │  Data Validation  │  ← Is the data schema correct? Missing values?
           ┌┴──────────────────┴┐
           │    Unit Tests       │  ← Does the code work?
           └────────────────────┘
```

**डेटा वैलिडेशन**: स्कीमा, नल दरें, मान सीमाएं, रो गिनती जांचें
**फ़ीचर टेस्ट**: वेरिफ़ाई करें कि फ़ीचर ट्रांसफ़ॉर्मेशन अपेक्षित आउटपुट देती हैं
**मॉडल टेस्ट**: डिप्लॉयमेंट से पहले सुनिश्चित करें कि ट्रेंड मॉडल न्यूनतम गुणवत्ता सीमाओं से ऊपर है

## 💰 इन्फ़्रास्ट्रक्चर विचार

प्रोडक्शन एमएल की वास्तविक लागत होती है। इंटरव्यूअर देखना चाहते हैं कि आपको लागत की समझ है:

### GPU प्रबंधन

- **ट्रेनिंग**: लागत बचत के लिए स्पॉट/प्रीएम्प्टिबल इंस्टेंस इस्तेमाल करें (चेकपॉइंटिंग के साथ!)
- **सर्विंग**: GPU आवश्यकताएं घटाने के लिए मॉडल डिस्टिलेशन या क्वांटाइज़ेशन पर विचार करें
- **ऑटोस्केलिंग**: GPU इंस्टेंस को चरम क्षमता नहीं, ट्रैफ़िक पैटर्न के आधार पर स्केल करें

### लागत ऑप्टिमाइज़ेशन रणनीतियां

- **मॉडल कंप्रेशन**: प्रूनिंग, क्वांटाइज़ेशन, ज्ञान डिस्टिलेशन
- **कैशिंग**: दोहराए इनपुट के लिए भविष्यवाणियां कैश करें
- **टियरड सर्विंग**: अधिकांश अनुरोधों के लिए सस्ता मॉडल, महंगा मॉडल केवल विश्वास कम होने पर
- **राइट-साइज़िंग**: जब फ़ाइन-ट्यून किया गया 7B मॉडल गुणवत्ता का 95% पा लेता है, तो 175B पैरामीटर मॉडल सर्व न करें

```
Cost per prediction ≈ (GPU cost per hour) / (predictions per hour)

Example:
- GPU instance: $3/hour
- Model throughput: 1,000 predictions/second
- Cost per prediction: $3 / 3,600,000 ≈ $0.0000008
```

इन सवालों पर चर्चा के लिए तैयार रहें:

1. "नया मॉडल प्रोडक्शन में कैसे डिप्लॉय करेंगे, पूरा प्रवाह बताएं"। ट्रेनिंग से कैनरी डिप्लॉयमेंट और पूर्ण रोलआउट तक पूरी पाइपलाइन बताएं
2. "प्रोडक्शन में डिग्रेड हो रहे मॉडल को कैसे संभालेंगे?" मॉनिटरिंग, रूट कारण विश्लेषण, रोलबैक, रीट्रेनिंग
3. "मॉडल रीट्रेनिंग और मॉडल अपडेटिंग में क्या अंतर है?" नए डेटा पर पूर्ण रीट्रेनिंग बनाम इन्क्रिमेंटल/ऑनलाइन लर्निंग
4. "एमएल एक्सपेरिमेंट में रीप्रोड्यूसिबिलिटी कैसे सुनिश्चित करते हैं?" कोड, डेटा और कॉन्फ़िग के लिए वर्ज़न नियंत्रण; फिक्स्ड सीड; कंटेनरीकरण
5. "अपना आदर्श एमएल प्लेटफ़ॉर्म बताएं"। फ़ीचर स्टोर, एक्सपेरिमेंट ट्रैकर, मॉडल रजिस्ट्री, सर्विंग इन्फ़्रास्ट्रक्चर, मॉनिटरिंग डैशबोर्ड

<Callout>
MLOps इंटरव्यू सवालों के जवाब में तकनीकी निर्णय को व्यवसाय असर से हमेशा जोड़ें। "हम कैनरी डिप्लॉयमेंट इसलिए इस्तेमाल करते हैं क्योंकि खराब मॉडल रोलबैक करने में गंवाए राजस्व में X लागत आती है" सिर्फ़ तकनीकी सेट-अप बताने से अधिक प्रभावी है।
</Callout>

## 🔑 मुख्य बातें

- **MLOps मॉडल डेवलपमेंट और प्रोडक्शन के बीच का अंतर पाटता है**। यह आज सबसे अधिक मांग वाला एमएल कौशल है
- **सर्विंग पैटर्न समझदारी से चुनें**: लागत के लिए बैच, ताज़गी के लिए रीयल-टाइम, एज के लिए एम्बेडेड
- **लेटेंसी से आगे मॉनिटर करें**: डेटा ड्रिफ़्ट, कॉन्सेप्ट ड्रिफ़्ट और मॉडल डिग्रेडेशन चुप घातक हैं
- **हर एक्सपेरिमेंट ट्रैक करें**: पैरामीटर, मेट्रिक्स, आर्टिफ़ैक्ट और वातावरण
- **एमएल पाइपलाइन टेस्ट करें**, सिर्फ़ कोड नहीं: डेटा वैलिडेशन, फ़ीचर टेस्ट और मॉडल गुणवत्ता गेट
- **लागत सोचें**: मॉडल कंप्रेशन, कैशिंग और टियरड सर्विंग इन्फ़्रास्ट्रक्चर बिल घटाते हैं

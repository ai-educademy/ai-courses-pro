# ⚙️ एमएलओपीएस और प्रोडक्शन एमएल

यहां एक आँकड़ा है जो यह निर्धारित करेगा कि आप साक्षात्कार के लिए कैसे तैयारी करते हैं: **87% एमएल मॉडल कभी भी उत्पादन में नहीं आते हैं।** ज्यूपिटर नोटबुक और एक विश्वसनीय, स्केलेबल एमएल सेवा के बीच का अंतर बहुत बड़ा है - और कंपनियाँ ऐसे इंजीनियरों के लिए बेताब हैं जो इसे पाट सकें। एमएलओपीएस साक्षात्कार प्रश्न परीक्षण करते हैं कि क्या आप "यह मेरी मशीन पर काम करता है" से लेकर "यह शनिवार को सुबह 3 बजे लाखों उपयोगकर्ताओं के लिए विश्वसनीय रूप से काम करता है" तक का मॉडल ले सकते हैं।

## 🧭 एमएलओपीएस वास्तव में क्या कवर करता है

एमएलओपीएस प्रथाओं का समूह है जो मशीन लर्निंग में डेवऑप्स अनुशासन लाता है। यह संपूर्ण एमएल जीवनचक्र तक फैला है:

```
Data → Feature Engineering → Training → Evaluation → Deployment → Monitoring → Retraining
  ↑                                                                              |
  └──────────────────────────── Feedback Loop ────────────────────────────────────┘
```

प्रमुख स्तंभों में शामिल हैं:
- **एमएल के लिए सीआई/सीडी**: डेटा, सुविधाओं और मॉडलों का स्वचालित परीक्षण - न कि केवल कोड
- **प्रयोग ट्रैकिंग**: हाइपरपैरामीटर, मेट्रिक्स और कलाकृतियों की व्यवस्थित रिकॉर्डिंग
- **मॉडल संस्करण**: ट्रैक करना कि कौन-सा मॉडल संस्करण कौन-सा ट्रैफ़िक परोस रहा है
- **मॉडल सेवा**: उपयोगकर्ताओं को विश्वसनीय और तेज़ी से पूर्वानुमान प्राप्त करना
- **निगरानी**: यह पता लगाना कि मॉडल का उत्पादन कब ख़राब होता है

<Callout>एमएलओपीएस और पारंपरिक डेवऑप्स के बीच सबसे बड़ा अंतर: सॉफ्टवेयर में, कोड परिवर्तन चीजों को तोड़ देता है। एमएल में, *डेटा* परिवर्तन चीजों को तोड़ देता है - अक्सर चुपचाप, बिना किसी त्रुटि लॉग के।
</Callout>

## 🚀 मॉडल सर्विंग पैटर्न

आप पूर्वानुमान कैसे प्रस्तुत करते हैं यह आपकी विलंबता आवश्यकताओं, पैमाने और पूर्वानुमानों को कितनी बार बदलने की आवश्यकता है, इस पर निर्भर करता है।

### बैच अनुमान

एक शेड्यूल (घंटेवार, रोज़) पर भविष्यवाणियों की पूर्व-गणना करें और उन्हें खोज के लिए store करें।

**इसके लिए सर्वश्रेष्ठ**: ईमेल अनुशंसाएं, दैनिक जोखिम स्कोर, साप्ताहिक रिपोर्ट

```
Schedule → Load data → Run model → Write predictions to DB → Serve from DB
```

**पेशेवर**: सरल बुनियादी ढांचा, बड़े मॉडल का उपयोग कर सकते हैं, लागत प्रभावी
**नुकसान**: भविष्यवाणियां पुरानी हो सकती हैं, वास्तविक समय के संदर्भ पर प्रतिक्रिया नहीं दे सकतीं

### वास्तविक समय अनुमान (सेवा के रूप में मॉडल)

मॉडल एक एपीआई के पीछे चलता है। प्रत्येक अनुरोध एक भविष्यवाणी को ट्रिगर करता है।

**इसके लिए सर्वश्रेष्ठ**: खोज रैंकिंग, धोखाधड़ी का पता लगाना, चैटबॉट

```
User request → API Gateway → Feature lookup → Model inference → Response
```

**पेशेवर**: ताजा भविष्यवाणियां, वास्तविक समय के संदर्भ का उपयोग कर सकते हैं
**विपक्ष**: विलंबता-संवेदनशील, मॉडल आकार और सेवा संबंधी बुनियादी ढांचे को अनुकूलित करने की आवश्यकता

### एंबेडेड मॉडल

मॉडल को सीधे एप्लिकेशन या डिवाइस में बंडल किया गया है।

**इनके लिए सर्वश्रेष्ठ**: मोबाइल ऐप्स, इओट डिवाइस, एज कंप्यूटिंग

**पेशेवर**: कोई नेटवर्क विलंबता नहीं, ऑफ़लाइन काम करता है
**नुकसान**: अपडेट करना कठिन, डिवाइस संसाधनों द्वारा सीमित

## 📊 प्रयोग ट्रैकिंग

ट्रैकिंग के बिना एमएल प्रयोग चलाना लैब नोटबुक के बिना विज्ञान करने जैसा है। आपको रिकॉर्ड करना होगा:

- **हाइपरपैरामीटर**: सीखने की दर, बैच आकार, वास्तुकला विकल्प
- **मेट्रिक्स**: प्रशिक्षण हानि, प्रत्येक युग में सत्यापन मेट्रिक्स
- **कलाकृतियाँ**: मॉडल चौकियाँ, फ़ीचर महत्व वाले प्लॉट, भ्रम मैट्रिक्स
- **पर्यावरण**: पुस्तकालय संस्करण, प्रयुक्त हार्डवेयर, यादृच्छिक बीज

### लोकप्रिय उपकरण

| उपकरण | ताकतें | परिनियोजन |
|---|---|---|
| **एमएलफ्लो** | ओपन-सोर्स, मॉडल रजिस्ट्री, व्यापक रूप से अपनाना | स्वयं-होस्टेड या प्रबंधित |
| **वजन और पूर्वाग्रह (डब्ल्यू&बी)** | सुंदर यूआई, सहयोग सुविधाएं, स्वीप | क्लाउड-होस्टेड |
| **नेपच्यून.एआई** | हल्का, टीमों के लिए अच्छा | क्लाउड-होस्टेड |
| **टेन्सरबोर्ड** | नि:शुल्क, TensorFlow के साथ मजबूती से एकीकृत | स्थानीय या एम्बेडेड |

```python
import mlflow

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run():
    mlflow.log_param("learning_rate", 0.001)
    mlflow.log_param("n_estimators", 500)

    model = train_model(X_train, y_train)
    metrics = evaluate_model(model, X_test, y_test)

    mlflow.log_metric("auc_roc", metrics["auc_roc"])
    mlflow.log_metric("precision", metrics["precision"])
    mlflow.sklearn.log_model(model, "model")
```

<ThinkAboutIt>आपकी टीम बिना किसी ट्रैकिंग सिस्टम के छह महीने से प्रयोग चला रही है। एक हितधारक पूछता है, "पिछले महीने मॉडल का प्रदर्शन क्यों गिर गया?" आप कैसे उत्तर देंगे और भविष्य में इस स्थिति को रोकने के लिए क्या उपाय करेंगे?
</ThinkAboutIt>

## 🔍 उत्पादन में एमएल की निगरानी करना

पारंपरिक सॉफ़्टवेयर मॉनिटरिंग त्रुटियों और विलंबता को ट्रैक करती है। एमएल मॉनिटरिंग एक महत्वपूर्ण परत जोड़ती है: **क्या मॉडल अभी भी अच्छी भविष्यवाणी कर रहा है?**

### बहाव के प्रकार

**डेटा ड्रिफ्ट** (कोवरिएट शिफ्ट): इनपुट सुविधाओं का वितरण बदल जाता है। उदाहरण: महामारी-पूर्व डेटा पर प्रशिक्षित एक ई-कॉमर्स मॉडल में घरेलू कार्यालय उपकरण खोजों में एस्केलेशन देखी गई है।

**अवधारणा बहाव**: सुविधाओं और लक्ष्य परिवर्तनों के बीच संबंध। उदाहरण: मंदी के दौरान क्रेडिट स्कोरिंग मॉडल की "रोज़गार स्थिति" सुविधा का मतलब कुछ अलग है।

**भविष्यवाणी बहाव**: मॉडल आउटपुट का वितरण बदलता है, भले ही इनपुट समान दिखते हों।

### क्या निगरानी रखें

| सिग्नल | कैसे पता लगाएं | कार्रवाई |
|---|---|---|
| इनपुट सुविधा वितरण | सांख्यिकीय परीक्षण (केएस परीक्षण, पीएसआई) | डेटा पाइपलाइन की जांच करें |
| भविष्यवाणी वितरण | समय के साथ माध्य, विचरण, श्टॉक को ट्रैक करें | आधारभूत अवधि से तुलना करें |
| मॉडल प्रदर्शन (जब लेबल उपलब्ध हो) | ज़मीनी सच्चाई के विरुद्ध ट्रैक सटीकता, F1, आदि | यदि सीमा से नीचे है तो पुनः प्रशिक्षण को ट्रिगर करें |
| विलंबता | P50, P95, P99 प्रतिक्रिया समय | स्केल इंफ्रास्ट्रक्चर या ऑप्टिमाइज़ मॉडल |
| डेटा गुणवत्ता | शून्य दरें, स्कीमा उल्लंघन, वॉल्यूम विसंगतियाँ | अलर्ट डेटा इंजीनियरिंग टीम |

```python
from scipy.stats import ks_2samp

# Kolmogorov-Smirnov test for distribution shift
def detect_drift(reference_data, current_data, threshold=0.05):
    statistic, p_value = ks_2samp(reference_data, current_data)
    return p_value < threshold  # True = drift detected
```

<FunFact>जब ज़िलो के "जेस्टिमेट" होम-प्राइसिंग मॉडल ने 2021 के असामान्य हाउसिंग चिह्नितेट के दौरान अवधारणा में बदलाव का अनुभव किया, तो कंपनी को अपने स्वयं के मॉडल की भविष्यवाणियों द्वारा निर्देशित घर खरीद पर $ 500 मिलियन से अधिक का नुकसान हुआ - और अंततः अपने होम-फ़्लिपिंग व्यवसाय को बंद कर दिया।
</FunFact>

## 🔄 मशीन लर्निंग के लिए सीआई/सीडी

एमएल सीआई/सीडी कोड परीक्षण से परे है। आपको डेटा, सुविधाओं और मॉडलों को भी सत्यापित करने की आवश्यकता है।

### एमएल परीक्षण पिरामिड

```
              ┌──────────────┐
              │  Model Tests  │  ← Does the model meet quality thresholds?
             ┌┴──────────────┴┐
             │  Feature Tests  │  ← Are features computed correctly?
            ┌┴────────────────┴┐
            │  Data Validation  │  ← Is the data schema correct? Missing values?
           ┌┴──────────────────┴┐
           │    Unit Tests       │  ← Does the code work?
           └────────────────────┘
```

**डेटा सत्यापन**: स्कीमा, शून्य दरें, मूल्य श्रेणियां, पंक्ति गणना जांचें
**फ़ीचर परीक्षण**: सत्यापित करें कि फ़ीचर परिवर्तन अपेक्षित आउटपुट उत्पन्न करते हैं
**मॉडल परीक्षण**: सुनिश्चित करें कि तैनाती से पहले प्रशिक्षित मॉडल कम-से-कम गुणवत्ता सीमा से अधिक हो

## 💰 बुनियादी ढांचे संबंधी विचार

उत्पादन एमएल की वास्तविक लागत होती है। साक्षात्कारकर्ता लागत जागरूकता देखना चाहते हैं:

### जीपीयू प्रबंधन

- **प्रशिक्षण**: लागत बचत के लिए स्पॉट/प्रीमेप्टेबल इंस्टेंसेस का उपयोग करें (चेकपॉइंटिंग के साथ!)
- **सर्विंग**: जीपीयू आवश्यकताओं को कम करने के लिए मॉडल आसवन या परिमाणीकरण पर विचार करें
- **ऑटोस्केलिंग**: ट्रैफ़िक पैटर्न के आधार पर GPU इंस्टेंसेस को स्केल करें, अधिकतम क्षमता के आधार पर नहीं

### लागत अनुकूलन रणनीतियाँ

- **मॉडल संपीड़न**: छंटाई, परिमाणीकरण, ज्ञान आसवन
- **कैशिंग**: बार-बार इनपुट के लिए कैश पूर्वानुमान
- **स्तरीय सेवा**: अधिकांश अनुरोधों के लिए सस्ते मॉडल का उपयोग करें, महंगे मॉडल का उपयोग केवल तब करें जब आत्मविश्वास कम हो
- **सही आकार**: जब एक परिष्कृत 7बी मॉडल 95% गुणवत्ता प्राप्त कर लेता है तो 175बी पैरामीटर मॉडल की सेवा न करें

```
Cost per prediction ≈ (GPU cost per hour) / (predictions per hour)

Example:
- GPU instance: $3/hour
- Model throughput: 1,000 predictions/second
- Cost per prediction: $3 / 3,600,000 ≈ $0.0000008
```

## 🏗️ सामान्य साक्षात्कार प्रश्न

यहां ऐसे प्रश्न हैं जिन पर आपको चर्चा के लिए तैयार रहना चाहिए:

1. "मुझे बताएं कि आप एक नए मॉडल को उत्पादन में कैसे तैनात करेंगे" - प्रशिक्षण से लेकर कैनरी तैनाती से लेकर पूर्ण रोलआउट तक की पूरी पाइपलाइन का वर्णन करें
2. "आप ऐसे मॉडल को कैसे संभालेंगे जिसका उत्पादन ख़राब हो रहा है?" - निगरानी, मूल कारण विश्लेषण, रोलबैक, पुनः प्रशिक्षण
3. "मॉडल पुनर्प्रशिक्षण और मॉडल अद्यतनीकरण के बीच क्या अंतर है?" - नए डेटा बनाम एस्केलेशनशील/ऑनलाइन शिक्षण पर पूर्ण पुनर्प्रशिक्षण
4. "आप एमएल प्रयोगों में प्रतिलिपि प्रस्तुत करने योग्यता कैसे सुनिश्चित करते हैं?" - कोड, डेटा और कॉन्फ़िगरेशन के लिए संस्करण नियंत्रण; स्थिर बीज; कंटेनरीकरण
5. "अपने आदर्श एमएल प्लेटफॉर्म का वर्णन करें" - फीचर स्टोर, प्रयोग ट्रैकर, मॉडल रजिस्ट्री, सर्विंग इंफ्रास्ट्रक्चर, मॉनिटरिंग डैशबोर्ड

<Callout>MLOps साक्षात्कार प्रश्नों का उत्तर देते समय, हमेशा तकनीकी निर्णयों को व्यावसायिक प्रभाव से जोड़ें। "हम कैनरी डिप्लॉयमेंट का उपयोग करते हैं क्योंकि खराब मॉडल को रोलबैक करने में राजस्व हानि होती है" अकेले तकनीकी व्यवस्था बताने से ज़्यादा प्रभावी है।
</Callout>

## 🔑 मुख्य बातें

- **MLOps मॉडल विकास और उत्पादन के बीच की खाई को पाटता है** - यह आज सबसे अधिक मांग वाला ML कौशल सेट है
- **सेवारत पैटर्न बुद्धिमानी से चुनें**: लागत के लिए बैच, ताजगी के लिए वास्तविक समय, किनारे के लिए एम्बेडेड
- **विलंबता से परे मॉनिटर**: डेटा बहाव, अवधारणा बहाव, और मॉडल गिरावट मूक हत्यारे हैं
- **प्रत्येक प्रयोग को ट्रैक करें**: पैरामीटर, मेट्रिक्स, कलाकृतियाँ और पर्यावरण
- **एमएल पाइपलाइन का परीक्षण करें**, न कि केवल कोड: डेटा सत्यापन, सुविधा परीक्षण और मॉडल गुणवत्ता गेट
- **लागत के बारे में सोचें**: मॉडल संपीड़न, कैशिंग और स्तरीय सेवा बुनियादी ढांचे के बिल को कम करती है

# 💬 NLP और LLM इंटरव्यू विषय

दो साल पहले NLP इंटरव्यू सवालों का मतलब था word embeddings और LSTM vanishing gradients समझाना। आज इंटरव्यूअर उतनी ही संभावना से पूछ सकता है, "आप model fine-tune कब करेंगे और RAG कब इस्तेमाल करेंगे?" NLP परिदृश्य बहुत बदल चुका है, और इंटरव्यू भी उसके साथ बदल गए हैं। यह पाठ उन fundamentals को भी कवर करता है जिन्हें इंटरव्यूअर अभी भी जांचते हैं, और LLM युग के उन विषयों को भी जो अब बातचीत पर हावी हैं।

---

## 📚 NLP fundamentals जिनकी इंटरव्यूअर अब भी अपेक्षा करते हैं

GPT के दौर में भी आपको दिखाना होगा कि आप समझते हैं ये models *क्यों* काम करते हैं, सिर्फ़ यह नहीं कि वे काम करते हैं।

### Tokenisation

Tokenisation कच्चे text को ऐसे discrete units में बदलता है जिन्हें model process कर सकता है। तरीका मायने रखता है:

- **Word-level**: सरल, लेकिन out-of-vocabulary words नहीं संभालता ("unfriendliness" → unknown)
- **Character-level**: हर word संभालता है, लेकिन sequences बहुत लंबे होते हैं
- **Subword (BPE, WordPiece, SentencePiece)**: आधुनिक standard, rare words को meaningful pieces में तोड़ता है

```
"unfriendliness" → ["un", "friend", "li", "ness"]  (BPE)
"playing"        → ["play", "##ing"]                (WordPiece)
```

<Callout>
इंटरव्यू टिप: tokenisation पूछा जाए तो बताएं कि tokenisation choices vocabulary size, sequence length और rare या misspelt words संभालने की model क्षमता को प्रभावित करती हैं। इससे दिखता है कि आप downstream implications समझते हैं, सिर्फ़ mechanics नहीं।
</Callout>

### Embeddings

Embeddings discrete tokens को dense continuous vectors में map करते हैं, जहां semantic relationships बची रहती हैं:

- **Word2Vec / GloVe**: static embeddings। हर word को context की परवाह किए बिना एक vector मिलता है ("bank" का embedding वही रहता है, चाहे अर्थ river bank हो या financial institution)
- **Contextual embeddings (BERT, GPT)**: हर token का embedding आसपास के context पर निर्भर करता है। "bank" को अलग sentences में अलग representations मिलते हैं

### Attention mechanism

Attention वह मुख्य innovation है जो transformers को काम कराता है। मूल रूप में:

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

सरल भाषा में: हर token के लिए attention सभी अन्य tokens पर weighted average निकालता है, जहां weights बताते हैं कि हर token वर्तमान token से कितना relevant है। scaling factor √d_k dot products को बहुत बड़ा होने से रोकता है।

**Self-attention** sequence में हर token को हर दूसरे token पर ध्यान देने देता है, जिससे long-range dependencies पकड़ी जाती हैं जिनसे RNNs जूझते हैं।

### Transformer architecture

Transformer में शामिल हैं:
- **Encoder**: पूरा input process करता है (समझने के लिए BERT-style models में इस्तेमाल)
- **Decoder**: output token by token generate करता है (generation के लिए GPT-style models में इस्तेमाल)
- **Encoder-Decoder**: दोनों को जोड़ता है (T5, translation के original transformer में इस्तेमाल)

| Architecture | Examples | Best For |
|---|---|---|
| Encoder-only | BERT, RoBERTa | Classification, NER, embeddings |
| Decoder-only | GPT, Llama, Mistral | Text generation, chat, reasoning |
| Encoder-Decoder | T5, BART | Translation, summarisation |

## 🤖 LLM-specific इंटरव्यू सवाल

ये वे सवाल हैं जो पिछले दो साल में आए हैं और अब लगभग हर एमएल इंटरव्यू में दिखते हैं।

### Fine-Tuning बनाम Prompting

| Approach | When to Use | Pros | Cons |
|---|---|---|---|
| **Zero/Few-shot prompting** | Quick prototyping, general tasks | No training needed, flexible | Limited control, costs per query |
| **Prompt engineering** | Moderate customisation | Fast iteration, no GPU costs | Fragile, hard to version |
| **Fine-tuning (full)** | Domain-specific tasks with labelled data | Best quality, smaller model possible | Expensive, needs data and GPU |
| **LoRA / QLoRA** | Fine-tuning with limited resources | Efficient, small adapter weights | Slightly less expressive than full fine-tuning |
| **RAG** | Knowledge-intensive, up-to-date info needed | No retraining, citable sources | Retrieval quality bottleneck |

### Retrieval-Augmented Generation (RAG)

RAG retrieval system को language model के साथ जोड़ता है:

```
User query → Embed query → Search vector DB → Retrieve top-K documents
    → Construct prompt (query + retrieved docs) → LLM generates answer
```

**मुख्य इंटरव्यू चर्चा बिंदु**:
- **Chunking strategy**: आप documents कैसे split करते हैं, इससे retrieval quality प्रभावित होती है
- **Embedding model choice**: domain-specific बनाम general embeddings
- **Reranking**: LLM को देने से पहले retrieved chunks को rerank करने के लिए cross-encoder इस्तेमाल करें
- **RAG कब fail होता है**: जब जवाब कई documents पर reasoning मांगता है, या relevant document मौजूद नहीं होता

### RLHF (Reinforcement Learning from Human Feedback)

ChatGPT की helpfulness के पीछे की तकनीक:

1. **Supervised fine-tuning**: curated prompt-response pairs पर train करें
2. **Reward model training**: humans model outputs rank करते हैं। इन preferences पर reward model train करें
3. **PPO optimisation**: reward model से reinforcement learning के जरिए LLM fine-tune करें

<FunFact>
Original InstructGPT paper ने दिखाया कि RLHF वाला 1.3B parameter model, उसके बिना 175B parameter model से humans को अधिक पसंद आया। Alignment techniques छोटे models को real-world usefulness में विशाल models से बेहतर बना सकती हैं।
</FunFact>

### Context windows और long-context challenges

- **Context window**: tokens की maximum संख्या जिसे model एक साथ process कर सकता है। Current frontier systems सैकड़ों हजारों से लगभग एक million tokens तक जाते हैं।
- **Lost in the middle**: models लंबे contexts के बीच की जानकारी पर कम ध्यान देते हैं
- **Strategies**: लंबे documents summarise करें, critical information शुरुआत या अंत में रखें, hierarchical retrieval इस्तेमाल करें

### Hallucination

Models plausible लेकिन तथ्यात्मक रूप से गलत text generate करते हैं। Mitigation strategies:
- **RAG**: responses को retrieved evidence में ground करें
- **Constrained generation**: output को known entities या structured formats तक सीमित करें
- **Self-consistency**: कई answers generate करें और agreement जांचें
- **Citation**: model से sources cite करवाएं (फिर उन्हें verify करें)

<ThinkAboutIt>
एक legal technology company ऐसा AI assistant बनाना चाहती है जो case law पर सवालों के जवाब दे। Hallucination से non-existent legal precedents cite हो सकते हैं। उपयोगी responses रखते हुए hallucination risk कम करने के लिए आप यह system कैसे architect करेंगे?
</ThinkAboutIt>

## 🎯 मॉडल चयन: कब क्या इस्तेमाल करें

यह पसंदीदा इंटरव्यू सवाल है: "इस use case के लिए आप कौन-सा model चुनेंगे?"

**Large frontier model (GPT-6 Astra, Claude Opus 5.5) तब इस्तेमाल करें जब:**
- Task general reasoning या complex instruction following मांगता हो
- आपके पास labelled training data न हो
- Prototyping speed inference cost से अधिक मायने रखती हो

**Fine-tuned smaller model (Mistral, Llama) तब इस्तेमाल करें जब:**
- आपके पास domain-specific data हो और consistent, specialised outputs चाहिए हों
- Inference cost मायने रखता हो (scale पर serving)
- Latency requirements tight हों
- Data privacy के लिए on-premises चलाना हो

**Traditional NLP model (BERT, RoBERTa) तब इस्तेमाल करें जब:**
- Task classification, NER या extraction हो (generation नहीं)
- बहुत high throughput पर fast inference चाहिए हो
- Task well-defined हो और clear labelled data मौजूद हो

## 🔬 LLM outputs का मूल्यांकन

Generative models का मूल्यांकन classifiers से कठिन है। आम तरीके:

- **Automated metrics**: BLEU, ROUGE, BERTScore (उपयोगी लेकिन अपूर्ण)
- **LLM-as-judge**: कमजोर model outputs का मूल्यांकन करने के लिए मजबूत model इस्तेमाल करें
- **Human evaluation**: gold standard, लेकिन महंगा और धीमा
- **Task-specific evaluation**: QA benchmarks पर accuracy, code execution pass rates
- **Red-teaming**: safety, bias और harmful outputs के लिए adversarial testing

```python
# BERTScore example
from bert_score import score

precision, recall, f1 = score(
    cands=["The cat sat on the mat"],
    refs=["A cat was sitting on a mat"],
    lang="en"
)
```

## ⚖️ नैतिक विचार

NLP इंटरव्यू में ethics सवाल लगातार बढ़ रहे हैं:

- **Training data में bias**: LLMs अपने training corpora से biases absorb और amplify करते हैं
- **Privacy**: models training data याद करके वापस उगल सकते हैं (PII leakage)
- **Misinformation**: generative models बड़े scale पर विश्वसनीय दिखने वाला लेकिन झूठा content बना सकते हैं
- **Environmental cost**: बड़े models train करने का carbon footprint काफी बड़ा होता है

- **Fundamentals जानें**: tokenisation, embeddings, attention और transformer architecture अनिवार्य हैं

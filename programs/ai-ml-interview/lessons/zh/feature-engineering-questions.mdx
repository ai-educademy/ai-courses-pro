# 🔧 特征工程问题

经验丰富的机器学习工程师都知道一个秘密：**你选择的模型远不如你提供的特征重要。** 具有出色特征的简单逻辑回归几乎每次都会击败具有较差特征的深度神经网络。这就是为什么面试官喜欢特征工程问题——他们测试你是否理解机器学习的“数据”方面，而不仅仅是算法。

---

## 🤔 为什么面试官关心特征工程

特征工程位于领域知识、数据直觉和工程技能的交叉点。当面试官要求你“设计拼车预计到达时间预测系统的功能”时，他们正在测试：

- 你能创造性地思考数据中存在哪些信号吗？
- 您了解原始数据如何转换为模型输入吗？
- 您能预见泄漏、稀疏性和规模等问题吗？
- 您是否考虑过生产限制（延迟、存储、新鲜度）？

<Callout>常见的面试模式：面试官描述一个业务问题并要求你集思广益。首先询问可用的数据源——这表明你考虑的是可行性，而不仅仅是理论。
</Callout>

## 📦 功能类型

### 数值特征

可以直接输入模型的原始数据 - 但通常受益于转换：

- **标准化**：以均值 0 为中心，以单位方差为尺度（对于 SVM、KNN 等基于距离的模型至关重要）
- **对数转换**：压缩右偏分布（收入、页面浏览量）
- **Binning**：将连续值转换为离散桶（age→age_group）

```python
import numpy as np
from sklearn.preprocessing import StandardScaler

# Log transform for skewed feature
df['log_income'] = np.log1p(df['income'])

# Standardisation
scaler = StandardScaler()
df[['age_scaled', 'income_scaled']] = scaler.fit_transform(df[['age', 'income']])
```

### 分类特征

非数字数据，例如国家/地区、产品类别或用户群体。编码策略很重要：

|方法|何时使用 |优点 |缺点 |
|---|---|---|---|
| One-Hot 编码 |低基数（< 20 个类别）|简单，无序数假​​设 |稀疏、高维|
|标签编码 |序数类别（低/中/高）|紧凑|意味着非序数 | 的错误排序
|目标编码|高基数（城市、邮政编码）|捕捉类别-目标关系|数据泄露风险 |
|嵌入 |非常高的基数，深度学习 |学习密集表示 |需要神经网络|

<ThinkAboutIt>您正在构建一个推荐模型，您的特征之一是 `product_id`，具有 500,000 个唯一值。 One-hot 编码将创建 500K 稀疏列。您会考虑什么编码策略？有哪些权衡？
</ThinkAboutIt>

### 时间特征

基于时间的数据富含信号——如果你正确提取它：

- **循环编码**：一天中的小时、一周中的一天（使用 sin/cos 来捕获循环性质）
- **滞后特征**：t-1、t-7、t-30 处的值（对于时间序列至关重要）
- **滚动统计**：7天移动平均线，30天滚动标准
- **自活动以来的时间**：自上次购买以来的天数，自上次登录以来的小时数

```python
# Cyclical encoding for hour of day
df['hour_sin'] = np.sin(2 * np.pi * df['hour'] / 24)
df['hour_cos'] = np.cos(2 * np.pi * df['hour'] / 24)

# Lag and rolling features
df['sales_lag_7'] = df['sales'].shift(7)
df['sales_rolling_mean_7'] = df['sales'].rolling(window=7).mean()
```

### 文本特征

当模型需要消耗文本数据时：

- **Bag of Words / TF-IDF**：简单，可解释，与传统机器学习配合良好
- **词嵌入**：Word2Vec、GloVe — 捕获语义的密集表示
- **句子嵌入**：BERT、句子-BERT — 上下文表示
- **手工制作**：字数、平均字长、情感分数、特定关键字的存在

### 互动功能

捕获模型可能无法自行学习的关系的特征组合：

- **功能交叉**：`city × device_type`（城市移动用户的行为与农村桌面用户不同）
- **比率**：`clicks / impressions` = 点击率
- **差异**：`current_price - avg_price` = 相对定价信号

## 🧹 处理缺失数据

生产中数据缺失无处不在。您的方法表明您的经验水平：

**简单策略：**
- 删除行（仅当丢失的数据很少且随机时）
- 填充平均值/中位数（数字）或众数（分类）
- 填充哨兵值（-1 或“未知”）

**更好的策略：**
- 创建一个二进制指标功能：`is_income_missing`（数据丢失的*事实*可以提供信息！）
- 使用基于模型的插补（KNN插补器、迭代插补器）
- 对于基于树的模型，许多实现本身处理缺失值

```python
# Indicator feature + median imputation
df['is_income_missing'] = df['income'].isna().astype(int)
df['income'] = df['income'].fillna(df['income'].median())
```

<FunFact>在著名的 Netflix 大奖赛中，最强大的功能之一就是“用户是否对电影进行了评分”，而不是评分本身。评分缺失的模式比评分本身更能揭示用户的偏好。
</FunFact>

## 🔍 特征选择方法

更多功能并不总是更好。特征选择可减少过度拟合、改善延迟并使模型可解释。

### 过滤方法
通过与目标的统计相关性对特征进行排序——快速但忽略特征交互：
- 相关系数（数值目标）
- 互信息（适用于任何特征类型）
- 卡方检验（分类特征）

### 包装方法
训练具有不同特征子集的模型——准确但昂贵：
- 向前选择：从空开始，一次添加一个最好的功能
- 向后消除：从所有功能开始，一次删除最不有用的一个

### 嵌入方法
特征选择内置于模型训练过程中：
- **L1 正则化**（Lasso）：将不重要的特征权重精确为零
- **基于树的重要性**：梯度提升树报告特征重要性得分

```python
from sklearn.feature_selection import SelectKBest, mutual_info_classif

# Select top 20 features by mutual information
selector = SelectKBest(mutual_info_classif, k=20)
X_selected = selector.fit_transform(X, y)
```

## 🏭 生产中的特征工程

面试级别的特征工程并不仅限于笔记本电脑。生产考虑因素包括：

### 功能商店

特征存储是用于管理、存储和服务特征的集中式系统。它解决了：
- **一致性**：训练和服务中相同的特征定义
- **可重用性**：团队共享功能而不是重新实现它们
- **新鲜度**：预定的管道使功能保持最新

热门工具：**Feast**、**Tecton**、**Hopsworks**、**AWS SageMaker Feature Store**

### 训练-服务偏差

机器学习中最危险的生产错误：训练期间与服务期间的特征计算方式不同。常见原因：
- 批量（训练）和实时（服务）的不同代码路径
- 服务路径中的过时特征值
- 环境之间的库版本不同

<Callout>当面试官询问生产中的特征工程时，请务必提及培训服务偏差。这是大多数候选人都忽视的问题，也是大多数生产机器学习系统都遇到的问题。
</Callout>

## 🔑 要点

- **特征胜过算法** - 在特征工程上投入比模型架构更多的时间
- **将编码与基数匹配**：低时使用one-hot，高时使用目标编码或嵌入
- **缺失数据是一个功能**，而不仅仅是一个问题 - 创建指标变量
- **注意泄漏** — 如果某项功能看起来好得令人难以置信，那么它很可能是真的
- **考虑生产**：特征存储、训练服务偏差和延迟限制
- **针对常见问题练习头脑风暴功能**：建议、欺诈、ETA 预测、搜索

</ThinkAboutIt>

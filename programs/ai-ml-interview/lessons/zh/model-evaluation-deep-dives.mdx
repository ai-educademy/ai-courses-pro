# 📊 模型评估深入研究

“您的模型有 95% 的准确度 - 发货！”如果这句话没有立即让您感到不舒服，那么本课程正是您所需要的。模型评估是将“训练”模型的候选人与“部署”模型的候选人区分开来的面试主题。面试官探究评估知识，因为它揭示了你是否理解模型实际上在做什么——以及它是否应该被信任。

---

## 🎯 分类指标：超越准确性

准确性——正确预测的百分比——是每个人首先学习的指标，也是最容易产生误导的指标。考虑一个数据集上的欺诈检测模型，其中只有 0.5% 的交易是欺诈的。一个对所有事情进行“非欺诈”预测的模型可实现 **99.5% 的准确率**，同时发现零欺诈。

### 精度、召回率和 F1

这三个指标构成了分类评估的支柱：

- **精度** = TP / (TP + FP) — “在我标记为阳性的所有内容中，实际有多少？”
- **回忆** = TP / (TP + FN) — “在所有实际上积极的事情中，我抓住了多少？”
- **F1 分数** = 2 × (精度 × 召回率) / (精度 + 召回率) — 调和平均值，平衡两者

```
              Predicted Positive    Predicted Negative
Actual Positive       TP                   FN
Actual Negative       FP                   TN
```

<ThinkAboutIt>您正在构建一个模型来从医学图像中检测癌症。您会针对精确率还是召回率进行优化？在各个方向上犯错会产生什么现实后果？
</ThinkAboutIt>

### 何时使用哪个

|场景|优化 |为什么 |
|---|---|---|
|垃圾邮件过滤器 |精密|向垃圾邮件发送真实的电子邮件比让一些垃圾邮件通过更糟糕 |
|癌症筛查|回忆|错过癌症病例远比虚惊一场更糟糕 |
|搜索排名|精度@K |用户只看最上面的结果 |
|欺诈检测 | F1 或自定义 |需要平衡——太多的误报阻碍了真正的客户 |

## 📈 AUC-ROC 和 AUC-PR：全貌

### ROC 曲线

接收者操作特征曲线绘制了每个分类阈值的**真阳性率**（召回​​率）与**假阳性率** (FP / (FP + TN))。该曲线下的面积 (**AUC-ROC**) 给出了与阈值无关的模型质量度量。

- **AUC = 1.0**：完美分离
- **AUC = 0.5**：随机猜测（对角线）
- **AUC < 0.5**：比随机更糟糕（你的标签可能会被翻转！）

### 精确率-召回率曲线

当类别严重不平衡时，AUC-ROC 可能会过于乐观。 **精确率-召回率曲线**绘制了精确率与召回率的关系，对于罕见事件检测提供了更多信息。

```python
from sklearn.metrics import precision_recall_curve, auc

precision, recall, thresholds = precision_recall_curve(y_true, y_scores)
pr_auc = auc(recall, precision)
```

<Callout>面试技巧：如果面试官提到数据集不平衡，请立即建议 AUC-PR 而不是 AUC-ROC。这表明您了解 ROC 曲线在不平衡环境中的局限性——许多候选人都忽略了这一区别。
</Callout>

## 📐 回归指标

并不是所有的事情都是分类的。在预测连续值时，这些指标很重要：

### 均方误差 (MSE)

$$MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2$$

对大错误进行严厉惩罚（二次惩罚）。当大错误比小错误严重得多时，这很好——例如，预测房价，如果房价下跌 10 万英镑，远比下跌 1 万英镑更糟糕。

### 平均绝对误差 (MAE)

$$MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|$$

线性处理所有错误。比 MSE 对异常值更稳健。当异常值是预期的且不应主导您的指标时使用。

### R²（决定系数）

$$R^2 = 1 - \frac{\sum(y_i - \hat{y}_i)^2}{\sum(y_i - \bar{y})^2}$$

与简单预测平均值相比，衡量模型解释的方差有多少。 R² = 1 表示完美贴合； R² = 0 意味着您的模型并不比预测平均值更好。

<FunFact>R² 实际上可以变为负值！当模型的预测比简单地预测每个输入的目标变量的平均值更糟糕时，就会发生这种情况。这是出现严重问题的迹象。
</FunFact>

## 🔄 交叉验证策略

提供单个测试集适用于大型数据集，但交叉验证可以提供更可靠的泛化性能估计。

### K 折交叉验证

将数据分成 K 个相等的折叠。在 K-1 次折叠上进行训练，在剩余的折叠上进行验证。重复K次。报告指标的平均值和标准差。

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(model, X, y, cv=5, scoring='f1')
print(f"F1: {scores.mean():.3f} ± {scores.std():.3f}")
```

### 分层 K 折

保留每个折叠中的类分布 - 对于不平衡数据集至关重要。

### 时间序列分割

对于时态数据，**永远不要**使用随机分割。使用扩展或滑动窗口交叉验证来尊重时间顺序：

```
Fold 1: Train [Jan-Mar]  → Test [Apr]
Fold 2: Train [Jan-Apr]  → Test [May]
Fold 3: Train [Jan-May]  → Test [Jun]
```

## 🌐 离线与在线评估

离线指标（根据历史数据计算）并不总是可以预测在线性能。具有更好 AUC 的模型一旦部署，实际上可能会降低用户参与度。

|方面|线下评测 |在线评估（A/B 测试）|
|---|---|---|
|速度|快速 — 根据保存的数据运行 |慢——需要真实的流量|
|成本|低|高（工程+机会成本）|
|措施|历史数据的模型质量 |实际业务影响|
|限制|不捕捉用户行为变化 |需要严格的统计 |

### ML 模型的 A/B 测试

对新模型运行 A/B 测试时：

1. **定义主要指标**（例如，每个用户的收入）和护栏指标（例如，延迟、错误率）
2. **计算统计显着性所需的样本量**
3. **正确随机** - 在用户级别而不是请求级别进行拆分
4. **运行足够长的时间** — 考虑新奇效应和每周季节性
5. **检查干扰** — 治疗组的行为是否影响对照组？

<ThinkAboutIt>您的新推荐模型显示，线下 AUC-ROC 提高了 3%，但 A/B 测试期间的点击率“下降”了 1%。什么可以解释这种差异？您会调查什么？
</ThinkAboutIt>

## ⚖️ 处理不平衡的数据集

不平衡的数据会影响训练和评估。常见策略：

**训练期间：**
- 对少数类进行过采样（SMOTE）
- 对多数类进行欠采样
- 在损失函数中使用类别权重
- 生成综合示例

**评估期间：**
- 使用精确率、召回率、F1 代替准确率
- 使用AUC-PR代替AUC-ROC
- 报告每个类别的指标
- 使用分层交叉验证

```python
from sklearn.ensemble import RandomForestClassifier

# Class weight approach — inversely proportional to class frequency
model = RandomForestClassifier(class_weight='balanced')
```

## 🔑 要点

- **永远不要仅仅依赖准确性**——尤其是在数据不平衡的情况下
- **将指标与业务目标相匹配**：当误报代价高昂时，召回对安全至关重要、精确
- 对于不平衡问题，**AUC-PR 优于 AUC-ROC** — 这是一个高信号面试技巧
- **对时态数据使用基于时间的分割** - 随机分割会导致数据泄漏
- **离线指标还不够** — 计划进行 A/B 测试以验证现实世界的影响
- **了解公式** — 面试官可能会要求您推导或解释精确度、召回率、F1、MSE 和 R²

<Callout>当面试官问“你会如何评估这个模型？”时，他们实际上是在问“你是否了解这个模型需要什么才能正确，并且你能衡量它吗？”从业务环境开始，然后选择您的指标。
</Callout>

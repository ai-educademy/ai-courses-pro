# 💬 NLP 和 LLM 面试主题

两年前，NLP 面试问题意味着解释词嵌入和 LSTM 梯度消失。今天，面试官很可能会问：“与使用 RAG 相比，你什么时候会微调模型？” NLP 的格局已经发生了巨大的变化，采访也随之发生了变化。本课程涵盖面试官仍在测试的基础知识*和*现在主导对话的法学硕士时代主题。

## 📚 NLP 基础面试官仍然期待

即使在 GPT 时代，您也需要证明您了解这些模型“为什么”有效，而不仅仅是“它们”有效。

### 代币化

标记化将原始文本转换为模型可以处理的离散单元。方法很重要：

- **单词级**：简单但无法处理词汇表之外的单词（“不友好”→未知）
- **字符级**：处理任何单词，但序列很长
- **Subword（BPE、WordPiece、SentencePiece）**：现代标准 — 将罕见单词分解为有意义的片段

```
"unfriendliness" → ["un", "friend", "li", "ness"]  (BPE)
"playing"        → ["play", "##ing"]                (WordPiece)
```

<Callout>面试提示：如果被问及标记化，请提及标记化选择会影响词汇量大小、序列长度以及模型处理罕见或拼写错误单词的能力。这表明您了解下游影响，而不仅仅是机制。
</Callout>

### 嵌入

嵌入将离散标记映射到保留语义关系的密集连续向量：

- **Word2Vec / GloVe**：静态嵌入——无论上下文如何，每个单词都会获得一个向量（“银行”无论是指河岸还是金融机构，都具有相同的嵌入）
- **上下文嵌入（BERT，GPT）**：每个标记的嵌入取决于周围的上下文 - “bank”在不同的句子中得到不同的表示

### 注意力机制

注意力是变压器发挥作用的关键创新。其核心是：

$$\text{注意力}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

用简单的英语来说：对于每个标记，注意力计算所有其他标记的加权平均值，其中权重反映每个标记与当前标记的相关程度。缩放因子 √d_k 可防止点积变得太大。

**自注意力**允许每个标记关注序列中的每个其他标记，捕获 RNN 难以解决的远程依赖关系。

### 变压器架构

变压器由以下部分组成：
- **编码器**：处理完整输入（用于 BERT 风格模型以供理解）
- **解码器**：按令牌生成输出令牌（在 GPT 样式模型中用于生成）
- **编码器-解码器**：结合两者（在T5中使用，用于翻译的原始变压器）

|建筑|示例 |最适合 |
|---|---|---|
|仅编码器 |伯特，罗伯塔 |分类、NER、嵌入 |
|仅解码器 | GPT-4，骆驼，米斯特拉尔 |文本生成、聊天、推理 |
|编码器-解码器| T5、BART |翻译、摘要 |

## 🤖 LLM 面试问题

这些是过去两年出现的问题，现在几乎出现在每次机器学习面试中。

### 微调与提示

|方法|何时使用 |优点 |缺点 |
|---|---|---|---|
| **零/几次提示** |快速原型制作，一般任务 |无需培训，灵活 |控制有限，每次查询的成本|
| **及时工程** |适度定制|快速迭代，无GPU成本|脆弱，难以版本 |
| **微调（完整）** |具有标记数据的特定领域任务 |最好的质量，更小的型号可能 |昂贵，需要数据和 GPU |
| **LoRA / QLoRA** |用有限的资源进行微调|高效、小适配器重量 |表现力比完全微调略差 |
| **抹布** |需要知识密集型的最新信息 |无需再培训，可引用来源|检索质量瓶颈|

### 检索增强生成 (RAG)

RAG 将检索系统与语言模型结合起来：

```
User query → Embed query → Search vector DB → Retrieve top-K documents
    → Construct prompt (query + retrieved docs) → LLM generates answer
```

**面试关键讨论点**：
- **分块策略**：如何拆分文档会影响检索质量
- **嵌入模型选择**：特定领域嵌入与通用嵌入
- **重新排名**：在输入 LLM 之前使用交叉编码器对检索到的块重新排名
- **当 RAG 失败时**：当答案需要跨多个文档进行推理时，或者不存在相关文档时

### RLHF（来自人类反馈的强化学习）

ChatGPT 的帮助背后的技术：

1. **监督微调**：在策划的提示响应对上进行训练
2. **奖励模型训练**：人类对模型输出进行排名；根据这些偏好训练奖励模型
3. **PPO优化**：使用奖励模型通过强化学习对LLM进行微调

<FunFact>最初的 InstructGPT 论文表明，人类更喜欢带有 RLHF 的 1.3B 参数模型，而不是没有 RLHF 的 175B 参数模型。对齐技术可以使小型模型在现实世界的实用性方面优于大型模型。
</FunFact>

### 上下文窗口和长上下文挑战

- **上下文窗口**：模型一次可以处理的最大令牌数量（例如，GPT-4 Turbo：128K，Claude：200K）
- **迷失在中间**：模型往往不太关注长上下文中间的信息
- **策略**：总结长文档，将关键信息放在开头/结尾，使用分层检索

### 幻觉

模型生成看似合理但实际上不正确的文本。缓解策略：
- **RAG**：检索到的证据中的地面反应
- **受限生成**：将输出限制为已知实体或结构化格式
- **自我一致性**：生成多个答案并检查一致性
- **引用**：要求模型引用其来源（然后验证它们）

<ThinkAboutIt>一家法律科技公司想要构建一个人工智能助手来回答有关判例法的问题。幻觉可能会导致引用不存在的法律先例。您将如何构建这个系统以最大限度地减少幻觉风险，同时保持响应有用？
</ThinkAboutIt>

## 🎯 模型选择：何时使用什么

这是一个最喜欢的面试问题：“鉴于这个用例，您会选择哪种模型？”

**在以下情况下使用大前沿模型（GPT-4，Claude）：**
- 任务需要一般推理或遵循复杂的指令
- 您没有标记的训练数据
- 原型设计速度比推理成本更重要

**在以下情况下使用经过微调的较小模型（Mistral 7B、LLaMA 3）：**
- 您拥有特定领域的数据并且需要一致的、专业的输出
- 推理成本很重要（大规模服务）
- 延迟要求严格
- 您需要在本地运行以保护数据隐私

**在以下情况下使用传统 NLP 模型（BERT、RoBERTa）：**
- 任务是分类、NER或提取（不是生成）
- 您需要以非常高的吞吐量进行快速推理
- 任务定义明确，标记数据清晰

## 🔬 评估 LLM 输出

评估生成模型比评估分类器更难。常见方法：

- **自动化指标**：BLEU、ROUGE、BERTScore（有用但不完善）
- **LLM-as-judge**：使用更强的模型来评估较弱模型的输出
- **人工评估**：黄金标准，但昂贵且缓慢
- **特定于任务的评估**：QA 基准的准确性、代码执行通过率
- **红队**：针对安全、偏见和有害输出的对抗性测试

```python
# BERTScore example
from bert_score import score

precision, recall, f1 = score(
    cands=["The cat sat on the mat"],
    refs=["A cat was sitting on a mat"],
    lang="en"
)
```

## ⚖️ 道德考虑

NLP 访谈越来越多地包含道德问题：

- **训练数据中的偏差**：法学硕士吸收并放大了训练语料库中的偏差
- **隐私**：模型可以记忆和反省训练数据（PII 泄漏）
- **错误信息**：生成模型可以大规模创建令人信服但虚假的内容
- **环境成本**：训练大型模型会产生显着的碳足迹

## 🔑 要点

- **了解你的基础知识**：标记化、嵌入、注意力和变压器架构是不可协商的
- **了解微调谱**：从零镜头提示到全面微调，以及何时每种都合适
- **RAG 是最实用的 LLM 模式** — 了解分块、检索和重新排名
- **模型选择涉及权衡**：功能 vs 成本 vs 延迟 vs 隐私
- **生成模型的评估是一个悬而未决的问题** - 了解多种方法
- **道德不是可选的**：偏见、幻觉和隐私现在是标准采访主题

<Callout>NLP 领域的发展速度令人难以置信。在面试之前，检查一下过去三个月发布了哪些模型和技术。能够讨论最近的发展（同时了解基本原理）表明您正在积极参与该领域。
</Callout>

# ⚙️ MLOps 和生产 ML

这里有一个统计数据可以帮助你准备面试：**87% 的 ML 模型从未投入生产。** Jupyter 笔记本和可靠、可扩展的 ML 服务之间的差距是巨大的 - 公司迫切需要能够弥补这一差距的工程师。 MLOps 面试问题测试您是否可以将模型从“它在我的机器上运行”转变为“它在周六凌晨 3 点可靠地为数百万用户运行”。

---

## 🧭 MLOps 实际涵盖的内容

MLOps 是将 DevOps 规则引入机器学习的一组实践。它跨越整个机器学习生命周期：

```
Data → Feature Engineering → Training → Evaluation → Deployment → Monitoring → Retraining
  ↑                                                                              |
  └──────────────────────────── Feedback Loop ────────────────────────────────────┘
```

关键支柱包括：
- **CI/CD for ML**：数据、功能和模型的自动化测试 - 不仅仅是代码
- **实验跟踪**：系统记录超参数、指标和工件
- **模型版本控制**：跟踪哪个模型版本正在服务哪个流量
- **模型服务**：可靠、快速地向用户提供预测
- **监控**：检测模型在生产中何时退化

<Callout>MLOps 与传统 DevOps 之间的最大区别：在软件中，代码更改会破坏事物。在机器学习中，*数据*更改会破坏事物——通常是悄无声息的，没有任何错误日志。
</Callout>

## 🚀 模型服务模式

您提供预测的方式取决于您的延迟要求、规模以及预测需要更改的频率。

### 批量推理

按计划（每小时、每天）预先计算预测并存储它们以供查找。

**最适合**：电子邮件建议、每日风险评分、每周报告

```
Schedule → Load data → Run model → Write predictions to DB → Serve from DB
```

**优点**：基础设施简单，可以使用大型模型，性价比高
**缺点**：预测可能过时，无法响应实时上下文

### 实时推理（模型即服务）

该模型在 API 后面运行。每个请求都会触发一个预测。

**最适合**：搜索排名、欺诈检测、聊天机器人

```
User request → API Gateway → Feature lookup → Model inference → Response
```

**优点**：新鲜的预测，可以使用实时上下文
**缺点**：延迟敏感，需要优化模型大小和服务基础设施

### 嵌入式模型

该模型直接捆绑到应用程序或设备中。

**最适合**：移动应用、物联网设备、边缘计算

**优点**：无网络延迟，离线工作
**缺点**：更新困难，受设备资源限制

## 📊 实验跟踪

在没有跟踪的情况下运行 ML 实验就像在没有实验室笔记本的情况下进行科学研究一样。您需要记录：

- **超参数**：学习率、批量大小、架构选择
- **指标**：每个时期的训练损失、验证指标
- **人工制品**：模型检查点、特征重要性图、混淆矩阵
- **环境**：库版本、使用的硬件、随机种子

### 流行工具

|工具|优势 |部署 |
|---|---|---|
| **MLflow** |开源、模型注册、广泛采用 |自托管或托管 |
| **权重和偏差 (W&B)** |靓丽UI、协作功能一扫而空|云托管|
| **Neptune.ai** |轻量级，适合团队 |云托管|
| **张量板** |免费，与 TensorFlow 紧密集成 |本地或嵌入式|

## 🔍 监控生产中的机器学习

传统的软件监控会跟踪错误和延迟。机器学习监控添加了一个关键层：**模型是否仍能做出良好的预测？**

### 漂移的类型

**数据漂移**（协变量漂移）：输入特征的分布发生变化。示例：根据大流行前数据训练的电子商务模型发现家庭办公设备搜索量激增。

**概念漂移**：特征与目标变化之间的关系。示例：信用评分模型的“就业状况”功能在经济衰退期间意味着不同的情况。

**预测漂移**：即使输入看起来相似，模型输出的分布也会发生变化。

### 监控什么

|信号|如何检测 |行动|
|---|---|---|
|输入特征分布 |统计检验（KS 检验、PSI）|调查数据管道 |
|预测分布|跟踪一段时间内的平均值、方差、百分位数 |与基准期比较|
|模型性能（当标签可用时）|与地面实况相比跟踪精度、F1 等 |如果低于阈值则触发重新训练 |
|延迟 | P50、P95、P99 响应时间 |扩展基础设施或优化模型 |
|数据质量 |空率、架构违规、数量异常 |警报数据工程团队|

```python
from scipy.stats import ks_2samp

# Kolmogorov-Smirnov test for distribution shift
def detect_drift(reference_data, current_data, threshold=0.05):
    statistic, p_value = ks_2samp(reference_data, current_data)
    return p_value < threshold  # True = drift detected
```

<FunFact>当 Zillow 的“Zestimate”房屋定价模型在 2021 年不寻常的房地产市场中经历了概念漂移时，该公司根据自己的模型预测指导的购房损失了超过 5 亿美元，并最终关闭了其房屋​​翻转业务。
</FunFact>

## 🔄 用于机器学习的 CI/CD

ML CI/CD 不仅仅限于代码测试。您还需要验证数据、特征和模型。

### 机器学习测试金字塔

```
              ┌──────────────┐
              │  Model Tests  │  ← Does the model meet quality thresholds?
             ┌┴──────────────┴┐
             │  Feature Tests  │  ← Are features computed correctly?
            ┌┴────────────────┴┐
            │  Data Validation  │  ← Is the data schema correct? Missing values?
           ┌┴──────────────────┴┐
           │    Unit Tests       │  ← Does the code work?
           └────────────────────┘
```

**数据验证**：检查架构、空值率、值范围、行数
**功能测试**：验证功能转换是否产生预期输出
**模型测试**：确保训练后的模型在部署前超过最低质量阈值

## 💰 基础设施注意事项

生产型机器学习具有实际成本。面试官希望看到成本意识：

### GPU 管理

- **培训**：使用现货/抢占式实例来节省成本（带有检查点！）
- **服务**：考虑模型蒸馏或量化以减少 GPU 需求
- **自动缩放**：根据流量模式而不是峰值容量缩放 GPU 实例

### 成本优化策略

- **模型压缩**：剪枝、量化、知识蒸馏
- **缓存**：缓存重复输入的预测
- **分层服务**：对于大多数请求使用廉价模型，仅在置信度较低时使用昂贵模型
- **正确调整**：当微调的 7B 模型达到 95% 的质量时，不提供 175B 参数模型

```
Cost per prediction ≈ (GPU cost per hour) / (predictions per hour)

Example:
- GPU instance: $3/hour
- Model throughput: 1,000 predictions/second
- Cost per prediction: $3 / 3,600,000 ≈ $0.0000008
```

## 🏗️ 常见面试问题

以下是您应该准备讨论的问题：

1.“引导我了解如何将新模型部署到生产中”——描述从训练到金丝雀部署再到全面部署的完整流程
2.“你会如何处理在生产中性能下降的模型？” — 监控、根本原因分析、回滚、再培训
3.“模型再训练和模型更新有什么区别？” — 新数据的全面再培训与增量/在线学习
4.“如何确保机器学习实验的可重复性？” — 代码、数据和配置的版本控制；固定种子；集装箱化
5.“描述您理想的机器学习平台”——特征存储、实验跟踪器、模型注册表、服务基础设施、监控仪表板

<Callout>在回答 MLOps 面试问题时，始终将技术决策与业务影响联系起来。 “我们使用金丝雀部署，因为回滚一个糟糕的模型会导致 X 倍的收入损失”比单独描述技术设置更引人注目。
</Callout>

## 🔑 要点

- **MLOps 弥合了模型开发和生产之间的差距**——这是当今最受欢迎的 ML 技能
- **明智地选择服务模式**：批量考虑成本，实时考虑新鲜度，嵌入式考虑边缘
- **超越延迟的监控**：数据漂移、概念漂移和模型退化是无声杀手
- **跟踪每个实验**：参数、指标、工件和环境
- **测试 ML 管道**，而不仅仅是代码：数据验证、功能测试和模型质量关卡
- **考虑成本**：模型压缩、缓存和分层服务可减少基础设施费用

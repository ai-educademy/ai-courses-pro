# ⚙️ MLOps మరియు ప్రొడక్షన్ ML

మీరు ఇంటర్వ్యూల కోసం ఎలా సిద్ధం అవుతారో రూపొందించే గణాంకం ఇక్కడ ఉంది: **87% ML మోడల్‌లు ఎప్పటికీ ఉత్పత్తికి రాలేవు.** జూపిటర్ నోట్‌బుక్ మరియు నమ్మదగిన, స్కేలబుల్ ML సేవ మధ్య అంతరం అపారమైనది - మరియు కంపెనీలు దీనిని తగ్గించగల ఇంజనీర్‌ల కోసం తీవ్రంగా ప్రయత్నిస్తున్నాయి. MLOps ఇంటర్వ్యూ ప్రశ్నలు మీరు "ఇది నా మెషీన్‌లో పని చేస్తుంది" నుండి "ఇది మిలియన్ల మంది వినియోగదారుల కోసం విశ్వసనీయంగా, శనివారం తెల్లవారుజామున 3 గంటలకు పని చేస్తుంది" అనే మోడల్‌ను తీసుకోవచ్చో లేదో పరీక్షిస్తుంది.

## 🧭 MLOps వాస్తవానికి కవర్ చేస్తుంది

MLOps అనేది మెషిన్ లెర్నింగ్‌కు DevOps క్రమశిక్షణను తీసుకువచ్చే అభ్యాసాల సమితి. ఇది మొత్తం ML జీవితచక్రాన్ని విస్తరించింది:

```
Data → Feature Engineering → Training → Evaluation → Deployment → Monitoring → Retraining
  ↑                                                                              |
  └──────────────────────────── Feedback Loop ────────────────────────────────────┘
```

ప్రధాన స్తంభాలు ఉన్నాయి:
- **ML కోసం CI/CD**: డేటా, ఫీచర్లు మరియు మోడల్‌ల స్వయంచాలక పరీక్ష — కేవలం కోడ్ మాత్రమే కాదు
- **ప్రయోగ ట్రాకింగ్**: హైపర్‌పారామీటర్‌లు, మెట్రిక్‌లు మరియు కళాఖండాల క్రమబద్ధమైన రికార్డింగ్
- **మోడల్ వెర్షన్**: ఏ మోడల్ వెర్షన్ ఏ ట్రాఫిక్‌ని అందజేస్తుందో ట్రాక్ చేయడం
- **మోడల్ సర్వింగ్**: వినియోగదారులకు విశ్వసనీయంగా మరియు వేగంగా అంచనాలను అందిస్తోంది
- **మానిటరింగ్**: మోడల్‌లు ఉత్పత్తిలో క్షీణించినప్పుడు గుర్తించడం

<Callout>MLOps మరియు సాంప్రదాయ DevOps మధ్య అతిపెద్ద వ్యత్యాసం: సాఫ్ట్‌వేర్‌లో, కోడ్ మార్పులు విషయాలను విచ్ఛిన్నం చేస్తాయి. MLలో, *డేటా* మార్పులు విషయాలను విచ్ఛిన్నం చేస్తాయి — తరచుగా నిశ్శబ్దంగా, ఎటువంటి లోపం లాగ్‌లు లేకుండా.
</Callout>

## 🚀 మోడల్ సర్వింగ్ ప్యాటర్న్‌లు

మీరు అంచనాలను ఎలా అందిస్తారు అనేది మీ జాప్యం అవసరాలు, స్కేల్ మరియు ఎంత తరచుగా అంచనాలు మారాలి అనే దానిపై ఆధారపడి ఉంటుంది.

### బ్యాచ్ అనుమితి

షెడ్యూల్‌లో (గంటకు, ప్రతిరోజూ) అంచనాలను ముందుగా గణించండి మరియు వాటిని వెతకడానికి నిల్వ చేయండి.

**దీనికి ఉత్తమం**: ఇమెయిల్ సిఫార్సులు, రోజువారీ ప్రమాద స్కోర్‌లు, వారపు నివేదికలు

```
Schedule → Load data → Run model → Write predictions to DB → Serve from DB
```

** ప్రోస్**: సాధారణ మౌలిక సదుపాయాలు, పెద్ద మోడళ్లను ఉపయోగించవచ్చు, ఖర్చుతో కూడుకున్నది
**కాన్స్**: అంచనాలు పాతవి కావచ్చు, నిజ-సమయ సందర్భానికి ప్రతిస్పందించలేవు

### నిజ-సమయ అనుమితి (మోడల్-యాజ్-ఎ-సర్వీస్)

మోడల్ API వెనుక నడుస్తుంది. ప్రతి అభ్యర్థన ఒక అంచనాను ప్రేరేపిస్తుంది.

**దీనికి ఉత్తమం**: శోధన ర్యాంకింగ్, మోసం గుర్తింపు, చాట్‌బాట్‌లు

```
User request → API Gateway → Feature lookup → Model inference → Response
```

**ప్రోస్**: తాజా అంచనాలు, నిజ-సమయ సందర్భాన్ని ఉపయోగించవచ్చు
**కాన్స్**: జాప్యం-సెన్సిటివ్, మోడల్ పరిమాణాన్ని ఆప్టిమైజ్ చేయడం మరియు మౌలిక సదుపాయాలను అందించడం అవసరం

### ఎంబెడెడ్ మోడల్

మోడల్ నేరుగా అప్లికేషన్ లేదా పరికరంలో బండిల్ చేయబడింది.

**దీనికి ఉత్తమమైనది**: మొబైల్ యాప్‌లు, IoT పరికరాలు, ఎడ్జ్ కంప్యూటింగ్

**ప్రోస్**: నెట్‌వర్క్ జాప్యం లేదు, ఆఫ్‌లైన్‌లో పని చేస్తుంది
** నష్టాలు**: నవీకరించడం కష్టం, పరికర వనరుల ద్వారా పరిమితం చేయబడింది

## 📊 ప్రయోగం ట్రాకింగ్

ట్రాకింగ్ లేకుండా ML ప్రయోగాలను అమలు చేయడం అనేది ల్యాబ్ నోట్‌బుక్ లేకుండా సైన్స్ చేయడం లాంటిది. మీరు రికార్డ్ చేయాలి:

- **హైపర్‌పారామీటర్లు**: లెర్నింగ్ రేట్, బ్యాచ్ పరిమాణం, ఆర్కిటెక్చర్ ఎంపికలు
- **కొలమానాలు**: శిక్షణ నష్టం, ప్రతి యుగంలో ధ్రువీకరణ కొలమానాలు
- **కళాఖండాలు**: మోడల్ చెక్‌పాయింట్‌లు, ఫీచర్ ఇంపార్టెన్స్ ప్లాట్‌లు, గందరగోళ మాత్రికలు
- ** పర్యావరణం**: లైబ్రరీ సంస్కరణలు, ఉపయోగించిన హార్డ్‌వేర్, యాదృచ్ఛిక విత్తనాలు

### జనాదరణ పొందిన సాధనాలు

| సాధనం | బలాలు | విస్తరణ |
|---|---|---|
| **MLflow** | ఓపెన్ సోర్స్, మోడల్ రిజిస్ట్రీ, విస్తృత స్వీకరణ | స్వీయ-హోస్ట్ లేదా నిర్వహించబడుతుంది |
| **బరువులు & పక్షపాతాలు (W&B)** | అందమైన UI, సహకార ఫీచర్‌లు, స్వీప్‌లు | క్లౌడ్-హోస్ట్ చేసిన |
| **Neptune.ai** | తేలికైనది, జట్లకు మంచిది | క్లౌడ్-హోస్ట్ చేసిన |
| **టెన్సర్‌బోర్డ్** | ఉచితంగా, టెన్సర్‌ఫ్లోతో పటిష్టంగా ఏకీకృతం చేయబడింది | లోకల్ లేదా ఎంబెడెడ్ |

```python
import mlflow

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run():
    mlflow.log_param("learning_rate", 0.001)
    mlflow.log_param("n_estimators", 500)

    model = train_model(X_train, y_train)
    metrics = evaluate_model(model, X_test, y_test)

    mlflow.log_metric("auc_roc", metrics["auc_roc"])
    mlflow.log_metric("precision", metrics["precision"])
    mlflow.sklearn.log_model(model, "model")
```

## 🔍 ఉత్పత్తిలో ML పర్యవేక్షణ

సాంప్రదాయ సాఫ్ట్‌వేర్ పర్యవేక్షణ లోపాలు మరియు జాప్యాన్ని ట్రాక్ చేస్తుంది. ML పర్యవేక్షణ ఒక క్లిష్టమైన పొరను జోడిస్తుంది: ** మోడల్ ఇంకా మంచి అంచనాలను ఇస్తోందా?**

### డ్రిఫ్ట్ రకాలు

**డేటా డ్రిఫ్ట్** (కోవేరియేట్ షిఫ్ట్): ఇన్‌పుట్ లక్షణాల పంపిణీ మార్పులు. ఉదాహరణ: ప్రీ-పాండమిక్ డేటాపై శిక్షణ పొందిన ఇ-కామర్స్ మోడల్ హోమ్ ఆఫీస్ పరికరాల శోధనలలో పెరుగుదలను చూస్తుంది.

**కాన్సెప్ట్ డ్రిఫ్ట్**: లక్షణాలు మరియు లక్ష్య మార్పుల మధ్య సంబంధం. ఉదాహరణ: క్రెడిట్ స్కోరింగ్ మోడల్ యొక్క "ఉపాధి స్థితి" ఫీచర్ అంటే మాంద్యం సమయంలో భిన్నమైనది.

**ప్రిడిక్షన్ డ్రిఫ్ట్**: ఇన్‌పుట్‌లు ఒకేలా కనిపించినప్పటికీ, మోడల్ అవుట్‌పుట్‌ల పంపిణీ మారుతుంది.

### ఏమి పర్యవేక్షించాలి

| సిగ్నల్ | ఎలా గుర్తించాలి | చర్య |
|---|---|---|
| ఇన్‌పుట్ ఫీచర్ పంపిణీలు | గణాంక పరీక్షలు (KS పరీక్ష, PSI) | డేటా పైప్‌లైన్‌ని పరిశోధించండి |
| అంచనా పంపిణీ | కాలక్రమేణా సగటు, వ్యత్యాసం, శాతాలను ట్రాక్ చేయండి | బేస్‌లైన్ కాలంతో పోల్చండి |
| మోడల్ పనితీరు (లేబుల్‌లు అందుబాటులో ఉన్నప్పుడు) | గ్రౌండ్ ట్రూత్‌కు వ్యతిరేకంగా ట్రాక్ ఖచ్చితత్వం, F1, మొదలైనవి | థ్రెషోల్డ్ కంటే తక్కువ ఉంటే మళ్లీ శిక్షణని ట్రిగ్గర్ చేయండి |

# Kolmogorov-Smirnov test for distribution shift
def detect_drift(reference_data, current_data, threshold=0.05):
    statistic, p_value = ks_2samp(reference_data, current_data)
    return p_value < threshold  # True = drift detected

## 🔄 మెషిన్ లెర్నింగ్ కోసం CI/CD

ML CI/CD కోడ్ టెస్టింగ్‌కు మించినది. మీరు డేటా, ఫీచర్లు మరియు మోడల్‌లను కూడా ధృవీకరించాలి.

### ML టెస్టింగ్ పిరమిడ్

```
              ┌──────────────┐
              │  Model Tests  │  ← Does the model meet quality thresholds?
             ┌┴──────────────┴┐
             │  Feature Tests  │  ← Are features computed correctly?
            ┌┴────────────────┴┐
            │  Data Validation  │  ← Is the data schema correct? Missing values?
           ┌┴──────────────────┴┐
           │    Unit Tests       │  ← Does the code work?
           └────────────────────┘
```

**డేటా ధ్రువీకరణ**: స్కీమా, శూన్య రేట్లు, విలువ పరిధులు, అడ్డు వరుసల గణనలను తనిఖీ చేయండి
**ఫీచర్ పరీక్షలు**: ఫీచర్ పరివర్తనలు ఆశించిన అవుట్‌పుట్‌లను ఉత్పత్తి చేయడాన్ని ధృవీకరించండి
**మోడల్ పరీక్షలు**: శిక్షణ పొందిన మోడల్ అమలు చేయడానికి ముందు కనీస నాణ్యత పరిమితులను మించిందని నిర్ధారించుకోండి

## 💰 మౌలిక సదుపాయాల పరిగణనలు

ఉత్పత్తి ML నిజమైన ఖర్చులను కలిగి ఉంది. ఇంటర్వ్యూ చేసేవారు ఖర్చుపై అవగాహన కలిగి ఉండాలన్నారు.

### GPU నిర్వహణ

- **శిక్షణ**: ఖర్చు ఆదా కోసం స్పాట్/ప్రీమ్ప్టిబుల్ ఇన్‌స్టాన్స్‌లను ఉపయోగించండి (చెక్‌పాయింటింగ్‌తో!)
- **అందించడం**: GPU అవసరాలను తగ్గించడానికి మోడల్ స్వేదనం లేదా పరిమాణాన్ని పరిగణించండి
- **ఆటోస్కేలింగ్**: ట్రాఫిక్ ప్యాటర్న్‌ల ఆధారంగా స్కేల్ GPU ఉదంతాలు, గరిష్ట సామర్థ్యం కాదు

### ఖర్చు ఆప్టిమైజేషన్ వ్యూహాలు

- **మోడల్ కంప్రెషన్**: కత్తిరింపు, పరిమాణీకరణ, జ్ఞాన స్వేదనం
- **కాషింగ్**: పునరావృత ఇన్‌పుట్‌ల కోసం కాష్ అంచనాలు
- **టైర్డ్ సర్వింగ్**: చాలా అభ్యర్థనల కోసం చౌకైన మోడల్‌ను ఉపయోగించండి, విశ్వాసం తక్కువగా ఉన్నప్పుడు మాత్రమే ఖరీదైన మోడల్‌ను ఉపయోగించండి
- **రైట్-సైజింగ్**: ఫైన్-ట్యూన్ చేయబడిన 7B మోడల్ నాణ్యతలో 95% సాధించినప్పుడు 175B పారామీటర్ మోడల్‌ను అందించవద్దు

```
Cost per prediction ≈ (GPU cost per hour) / (predictions per hour)

Example:
- GPU instance: $3/hour
- Model throughput: 1,000 predictions/second
- Cost per prediction: $3 / 3,600,000 ≈ $0.0000008
```

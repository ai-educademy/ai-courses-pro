# 🔧 Questions d'ingénierie des fonctionnalités

Voici un secret que connaissent les ingénieurs ML chevronnés : **le modèle que vous choisissez compte bien moins que les fonctionnalités que vous lui alimentez.** Une simple régression logistique avec des fonctionnalités brillantes battra presque à chaque fois un réseau neuronal profond avec des fonctionnalités médiocres. C'est pourquoi les enquêteurs adorent les questions d'ingénierie des fonctionnalités : ils testent si vous comprenez le côté *données* de l'apprentissage automatique, et pas seulement les algorithmes.

---

## 🤔 Pourquoi les enquêteurs se soucient de l'ingénierie des fonctionnalités

L'ingénierie des fonctionnalités se situe à l'intersection de la connaissance du domaine, de l'intuition des données et des compétences en ingénierie. Lorsqu'un intervieweur vous demande de « concevoir des fonctionnalités pour un système de prédiction de l'heure d'arrivée prévue pour le covoiturage », il teste :

- Pouvez-vous réfléchir de manière créative aux signaux qui existent dans les données ?
- Comprenez-vous comment les données brutes se transforment en entrées de modèle ?
- Pouvez-vous anticiper des problèmes tels que les fuites, la rareté et l'échelle ?
- Pensez-vous aux contraintes de production (latence, stockage, fraîcheur) ?

<Callout>Un modèle d'entretien courant : l'intervieweur décrit un problème commercial et vous demande de réfléchir aux fonctionnalités. Commencez par poser des questions sur les sources de données disponibles : cela montre que vous réfléchissez à la faisabilité, et pas seulement à la théorie.
</Callout>

## 📦 Types de fonctionnalités

### Caractéristiques numériques

Des chiffres bruts qui peuvent être introduits directement dans les modèles, mais qui bénéficient souvent d'une transformation :

- **Standardisation** : centre à moyenne 0, échelle à variance unitaire (essentiel pour les modèles basés sur la distance comme SVM, KNN)
- **Transformation du journal** : compressez les distributions asymétriques à droite (revenus, pages vues)
- **Binning** : convertissez les valeurs continues en compartiments discrets (age → age_group)

```python
import numpy as np
from sklearn.preprocessing import StandardScaler

# Log transform for skewed feature
df['log_income'] = np.log1p(df['income'])

# Standardisation
scaler = StandardScaler()
df[['age_scaled', 'income_scaled']] = scaler.fit_transform(df[['age', 'income']])
```

### Caractéristiques catégorielles

Données non numériques telles que le pays, la catégorie de produit ou le segment d'utilisateurs. La stratégie d’encodage est importante :

| Méthode | Quand utiliser | Avantages | Inconvénients |
|---|---|---|---|
| Encodage à chaud | Faible cardinalité (< 20 catégories) | Simple, sans hypothèse ordinale | clairsemé et de grande dimension |
| Encodage des étiquettes | Catégories ordinales (faible/moyen/élevé) | Compacte | Implique un faux ordre pour les |
| Encodage cible | Cardinalité élevée (ville, code postal) | Capture la relation catégorie-cible | Risque de fuite de données |
| Intégrations | Très haute cardinalité, deep learning | Apprend les représentations denses | Nécessite un réseau neuronal |

</ThinkAboutIt>

### Caractéristiques temporelles

Les données temporelles sont riches en signaux — si vous les extrayez correctement :

- **Encodage cyclique** : heure de la journée, jour de la semaine (utilisez sin/cos pour capturer la nature cyclique)
- **Caractéristiques de décalage** : valeur à t-1, t-7, t-30 (critique pour les séries temporelles)
- **Statistiques glissantes** : moyenne mobile sur 7 jours, moyenne mobile sur 30 jours
- **Durée depuis l'événement** : jours depuis le dernier achat, heures depuis la dernière connexion

```python
# Cyclical encoding for hour of day
df['hour_sin'] = np.sin(2 * np.pi * df['hour'] / 24)
df['hour_cos'] = np.cos(2 * np.pi * df['hour'] / 24)

# Lag and rolling features
df['sales_lag_7'] = df['sales'].shift(7)
df['sales_rolling_mean_7'] = df['sales'].rolling(window=7).mean()
```

### Fonctionnalités de texte

Lorsque les modèles doivent consommer des données textuelles :

- **Bag of Words / TF-IDF** : simple, interprétable, fonctionne bien avec le ML traditionnel
- **Incorporations de mots** : Word2Vec, GloVe — représentations denses capturant la signification sémantique
- **Incorporations de phrases** : BERT, Sentence-BERT — représentations contextuelles
- **Fabriqué à la main** : nombre de mots, longueur moyenne des mots, score de sentiment, présence de mots-clés spécifiques

### Fonctionnalités d'interaction

Combinaisons de fonctionnalités qui capturent les relations que le modèle pourrait ne pas apprendre seul :

- **Fonctionnalités croisées** : `city × device_type` (les utilisateurs mobiles urbains se comportent différemment des utilisateurs ruraux d'ordinateurs de bureau)
- **Ratios** : `clicks / impressions` = taux de clics
- **Différences** : `current_price - avg_price` = signal de tarification relatif

## 🧹 Gestion des données manquantes

Les données manquantes sont omniprésentes en production. Votre approche signale votre niveau d’expérience :

**Stratégies simples :**
- Supprimer des lignes (uniquement si les données manquantes sont rares et aléatoires)
- Remplir avec moyenne/médiane (numérique) ou mode (catégorique)
- Remplir avec une valeur sentinelle (-1 ou "INCONNU")

**Meilleures stratégies :**
- Créez une fonctionnalité d'indicateur binaire : `is_income_missing` (le *fait* que des données manquent peut être informatif !)
- Utiliser l'imputation basée sur un modèle (imputateur KNN, imputeur itératif)
- Pour les modèles arborescents, de nombreuses implémentations gèrent nativement les valeurs manquantes

```python
# Indicator feature + median imputation
df['is_income_missing'] = df['income'].isna().astype(int)
df['income'] = df['income'].fillna(df['income'].median())
```

<FunFact>Dans le célèbre concours Netflix Prize, l'une des fonctionnalités les plus puissantes était simplement « si un utilisateur avait noté un film * – et non la note elle-même. La tendance des notes manquantes révèle mieux les préférences des utilisateurs que les notes elles-mêmes.

## 🔍 Méthodes de sélection des fonctionnalités

Plus de fonctionnalités n’est pas toujours mieux. La sélection des fonctionnalités réduit le surapprentissage, améliore la latence et rend les modèles interprétables.

### Méthodes de filtrage
Classez les fonctionnalités par corrélation statistique avec la cible - rapide mais ignore les interactions entre les fonctionnalités :
- Coefficient de corrélation (cibles numériques)
- Informations mutuelles (fonctionne pour tout type de fonctionnalité)
- Test du chi carré (caractéristiques catégorielles)

### Méthodes d'emballage
Former des modèles avec différents sous-ensembles de fonctionnalités – précis mais coûteux :
- Sélection directe : démarrez vide, ajoutez la meilleure fonctionnalité une à la fois
- Élimination en amont : commencez par toutes les fonctionnalités, supprimez la moins utile à la fois

### Méthodes intégrées
La sélection des fonctionnalités est intégrée au processus de formation du modèle :
- **Régularisation L1** (Lasso) : ramène les poids des caractéristiques sans importance à exactement zéro
- **Importance basée sur les arbres** : les arbres améliorés par le gradient rapportent les scores d'importance des fonctionnalités

```python
from sklearn.feature_selection import SelectKBest, mutual_info_classif

# Select top 20 features by mutual information
selector = SelectKBest(mutual_info_classif, k=20)
X_selected = selector.fit_transform(X, y)
```

## 🏭 Ingénierie des fonctionnalités en production

L’ingénierie des fonctionnalités au niveau des entretiens ne s’arrête pas aux ordinateurs portables. Les considérations de production comprennent :

### Magasins de fonctionnalités

Un magasin de fonctionnalités est un système centralisé permettant de gérer, de stocker et de servir des fonctionnalités. Il résout :
- **Cohérence** : même définition des fonctionnalités en formation et en service
- **Réutilisabilité** : les équipes partagent des fonctionnalités au lieu de les réimplémenter
- **Fraîcheur** : les pipelines planifiés maintiennent les fonctionnalités à jour

Outils populaires : **Feast**, **Tecton**, **Hopsworks**, **AWS SageMaker Feature Store**

### Désalignement entre la formation et le service

Le bug de production le plus dangereux en ML : les fonctionnalités sont calculées différemment lors de l'entraînement et du service. Causes courantes :
- Différents chemins de code pour le batch (formation) et le temps réel (serving)
- Valeurs de fonctionnalités obsolètes dans le chemin de diffusion
- Différentes versions de bibliothèque entre les environnements

<Callout>Lorsqu'un intervieweur pose des questions sur l'ingénierie des fonctionnalités en production, mentionnez toujours le biais de formation et de diffusion. C'est le problème que la plupart des candidats négligent et dont souffrent la plupart des systèmes de production ML.
</Callout>

## 🔑 Points clés à retenir

- **Les fonctionnalités l'emportent sur les algorithmes** : investissez plus de temps dans l'ingénierie des fonctionnalités que dans l'architecture des modèles
- **Faire correspondre l'encodage à la cardinalité** : one-hot pour faible, encodage cible ou intégrations pour élevé
- **Les données manquantes sont une fonctionnalité**, pas seulement un problème — créez des variables indicatrices
- **Surveillez les fuites** : si une fonctionnalité semble trop belle pour être vraie, c'est probablement le cas.
- **Pensez à la production** : magasins de fonctionnalités, décalage entre la formation et la diffusion et contraintes de latence
- **Pratiquez les fonctionnalités de brainstorming** pour les problèmes courants : recommandations, fraude, prédiction d'ETA, recherche

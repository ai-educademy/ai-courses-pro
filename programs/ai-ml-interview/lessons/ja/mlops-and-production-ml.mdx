# ⚙️ MLOps と本番環境 ML

面接の準備方法を形作る統計は次のとおりです。**87% の ML モデルが本番環境に導入されることはありません。** Jupyter ノートブックと信頼性が高くスケーラブルな ML サービスとの間にあるギャップは非常に大きく、企業はそれを埋めることができるエンジニアを切望しています。 MLOps の面接の質問では、モデルを「私のマシンで動作する」から「土曜日の午前 3 時に何百万ものユーザーに対して確実に動作する」にできるかどうかをテストします。

---

## 🧭 MLOps が実際にカバーする内容

MLOps は、DevOps の規律を機械学習にもたらす一連のプラクティスです。これは ML ライフサイクル全体に及びます。

```
Data → Feature Engineering → Training → Evaluation → Deployment → Monitoring → Retraining
  ↑                                                                              |
  └──────────────────────────── Feedback Loop ────────────────────────────────────┘
```

重要な柱は次のとおりです。
- **CI/CD for ML**: コードだけでなく、データ、機能、モデルの自動テスト
- **実験追跡**: ハイパーパラメータ、メトリクス、アーティファクトの体系的な記録
- **モデルのバージョン管理**: どのモデル バージョンがどのトラフィックを処理しているかを追跡します
- **モデル提供**: ユーザーに予測を確実かつ迅速に提供します
- **モニタリング**: 本番環境でのモデルの劣化を検出します

<Callout>MLOps と従来の DevOps の最大の違いは、ソフトウェアではコードの変更によって問題が発生することです。 ML では、*データ* の変更により、多くの場合、エラー ログなしで、静かに問題が発生します。
</Callout>

## 🚀 モデル提供パターン

予測を提供する方法は、レイテンシー要件、規模、予測を変更する必要がある頻度によって異なります。

### バッチ推論

スケジュール (時間ごと、毎日) に基づいて予測を事前に計算し、検索用に保存します。

**最適な用途**: 電子メールによる推奨事項、日次リスクスコア、週次レポート

```
Schedule → Load data → Run model → Write predictions to DB → Serve from DB
```

**長所**: シンプルなインフラストラクチャ、大規模なモデルを使用可能、コスト効率が高い
**短所**: 予測が古くなる可能性があり、リアルタイムのコンテキストに応答できない

### リアルタイム推論 (Model-as-a-Service)

モデルは API の背後で実行されます。各リクエストは予測をトリガーします。

**最適な用途**: 検索ランキング、不正検出、チャットボット

```
User request → API Gateway → Feature lookup → Model inference → Response
```

**長所**: 新鮮な予測、リアルタイムのコンテキストを使用できる
**短所**: 遅延の影響を受けやすいため、モデルのサイズとサービス提供インフラストラクチャを最適化する必要がある

### 組み込みモデル

モデルはアプリケーションまたはデバイスに直接バンドルされます。

**最適な用途**: モバイル アプリ、IoT デバイス、エッジ コンピューティング

**長所**: ネットワーク遅延がなく、オフラインで動作します
**短所**: 更新が難しく、デバイスのリソースによって制限される

## 📊 実験の追跡

追跡せずに ML 実験を実行することは、実験ノートなしで科学を行うようなものです。以下を記録する必要があります。

- **ハイパーパラメータ**: 学習率、バッチサイズ、アーキテクチャの選択
- **メトリクス**: トレーニング損失、各エポックでの検証メトリクス
- **アーティファクト**: モデルのチェックポイント、特徴量の重要度プロット、混同行列
- **環境**: ライブラリのバージョン、使用されるハードウェア、ランダム シード

### 人気のツール

|ツール |強み |導入 |
|---|---|---|
| **MLflow** |オープンソース、モデル レジストリ、幅広い採用 |自己ホスト型または管理型 |
| **重みとバイアス (W&B)** |美しい UI、コラボレーション機能、スイープ |クラウドホスト |
| **Neptune.ai** |軽量でチームに最適 |クラウドホスト |
| **テンソルボード** |無料、TensorFlow と緊密に統合 |ローカルまたは組み込み |

```python
import mlflow

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run():
    mlflow.log_param("learning_rate", 0.001)
    mlflow.log_param("n_estimators", 500)

    model = train_model(X_train, y_train)
    metrics = evaluate_model(model, X_test, y_test)

    mlflow.log_metric("auc_roc", metrics["auc_roc"])

```

## 🔍 本番環境での ML のモニタリング

従来のソフトウェア監視では、エラーと遅延を追跡します。 ML モニタリングにより、**モデルはまだ適切な予測を行っていますか?** という重要なレイヤーが追加されます。

### ドリフトの種類

**データ ドリフト** (共変量シフト): 入力特徴の分布が変化します。例: パンデミック前のデータに基づいてトレーニングされた e コマース モデルでは、ホーム オフィス機器の検索が急増しています。

**コンセプト ドリフト**: 機能とターゲット変更の間の関係。例: 信用スコアリング モデルの「雇用状況」機能は、不況時には意味が異なります。

**予測ドリフト**: 入力が類似しているように見えても、モデル出力の分布は変化します。

### 監視対象

|信号 |検出方法 |アクション |
|---|---|---|
|入力特徴分布 |統計検定（KS検定、PSI） |データ パイプラインを調査する |
|予測分布 |平均、分散、パーセンタイルを経時的に追跡 |ベースライン期間との比較 |
|モデルのパフォーマンス (ラベルが利用可能な場合) |グラウンド トゥルースに対して精度、F1 などを追跡 |しきい値を下回った場合に再トレーニングをトリガーする |
|レイテンシ | P50、P95、P99 の応答時間 |インフラストラクチャの拡張またはモデルの最適化 |
|データ品質 | Null 率、スキーマ違反、ボリューム異常 |アラート データ エンジニアリング チーム |

```python
from scipy.stats import ks_2samp

# Kolmogorov-Smirnov test for distribution shift
def detect_drift(reference_data, current_data, threshold=0.05):
    statistic, p_value = ks_2samp(reference_data, current_data)
    return p_value < threshold  # True = drift detected
```

<FunFact>Zillowの「Zestimate」住宅価格モデルが2021年の異例の住宅市場でコンセプトのずれを経験したとき、同社は独自のモデルの予測に基づいた住宅購入で5億ドル以上の損失を出し、最終的には住宅反転事業を停止した。
</FunFact>

## 🔄 機械学習用の CI/CD

ML CI/CD はコードのテストを超えています。データ、機能、モデルも検証する必要があります。

### ML テスト ピラミッド

```
              ┌──────────────┐
              │  Model Tests  │  ← Does the model meet quality thresholds?
             ┌┴──────────────┴┐
             │  Feature Tests  │  ← Are features computed correctly?
            ┌┴────────────────┴┐
            │  Data Validation  │  ← Is the data schema correct? Missing values?
           ┌┴──────────────────┴┐
           │    Unit Tests       │  ← Does the code work?
           └────────────────────┘
```

**データ検証**: スキーマ、NULL 率、値の範囲、行数をチェックします。
**機能テスト**: 機能変換が期待される出力を生成することを検証します。
**モデル テスト**: トレーニングされたモデルが展開前に最低品質しきい値を超えていることを確認します。

## 💰 インフラストラクチャに関する考慮事項

本番環境の ML には実際のコストがかかります。面接官はコスト意識を知りたいと考えています。

### GPU管理

- **トレーニング**: スポット/プリエンプティブル インスタンスを使用してコストを削減します (チェックポイント機能付き!)
- **サービス**: GPU 要件を軽減するために、モデルの蒸留または量子化を検討します。
- **自動スケーリング**: ピーク容量ではなく、トラフィック パターンに基づいて GPU インスタンスをスケーリングします。

### コスト最適化戦略

- **モデル圧縮**: 枝刈り、量子化、知識の蒸留
- **キャッシュ**: 繰り返される入力に対する予測をキャッシュします。
- **段階的サービス**: ほとんどのリクエストには安価なモデルを使用し、信頼性が低い場合にのみ高価なモデルを使用します。
- **適切なサイジング**: 微調整された 7B モデルが品質の 95% を達成している場合は、175B パラメータ モデルを提供しないでください。

```
Cost per prediction ≈ (GPU cost per hour) / (predictions per hour)

Example:
- GPU instance: $3/hour
- Model throughput: 1,000 predictions/second
- Cost per prediction: $3 / 3,600,000 ≈ $0.0000008
```

## 🏗️ 面接でよくある質問

話し合う準備が必要な質問は次のとおりです。

1. 「新しいモデルを運用環境にデプロイする方法を説明してください」 - トレーニングからカナリア デプロイ、完全なロールアウトまでの完全なパイプラインについて説明します。
2. 「本番環境で機能が低下したモデルにどのように対処しますか?」 — モニタリング、根本原因分析、ロールバック、再トレーニング
3. 「モデルの再トレーニングとモデルの更新の違いは何ですか?」 — 新しいデータでの完全な再トレーニングと増分/オンライン学習の比較
4. 「ML 実験の再現性をどのように確保しますか?」 — コード、データ、構成のバージョン管理。固定種子。コンテナ化
5. 「理想的な ML プラットフォームについて説明する」 — フィーチャー ストア、実験トラッカー、モデル レジストリ、サービス インフラストラクチャ、モニタリング ダッシュボード

<Callout>MLOps の面接の質問に答えるときは、常に技術的な決定をビジネスへの影響と結び付けてください。 「不良モデルをロールバックすると収益損失 X が発生するため、カナリア デプロイメントを使用しています」は、技術的な設定だけを説明するよりも説得力があります。
</Callout>

## 🔑 重要なポイント

- **MLOps はモデル開発と運用の間のギャップを埋める** - これは現在最も需要の高い ML スキルセットです
- **提供パターンを賢く選択**: コストを重視してバッチ、鮮度を重視してリアルタイム、エッジを重視して埋め込み
- **遅延を超えた監視**: データ ドリフト、コンセプト ドリフト、モデルの劣化はサイレント キラーです。
- **すべての実験を追跡**: パラメーター、メトリクス、アーティファクト、環境
- **コードだけでなく ML パイプラインをテスト**: データ検証、機能テスト、モデル品質ゲート
- **コストについて考える**: モデルの圧縮、キャッシュ、階層化されたサービスにより、インフラストラクチャの料金が削減されます

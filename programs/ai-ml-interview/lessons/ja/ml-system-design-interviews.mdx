# 🏗️ ML システム設計インタビュー

コーディングラウンドを完了しました。次に、面接官はテーブル上でホワイトボード マーカーをスライドさせ、「5,000 万人のユーザー向けのレコメンデーション システムを設計してください」と言います。手のひらが湿ってしまうのは、ML を知らないからではなく、システム全体について *声に出して考える* 練習をしたことがないからです。このレッスンでは、自由回答型の質問を構造化された会話に変える、繰り返し可能なフレームワークを提供します。

---

## 🗺️ ML システム設計が異なる理由

従来のソフトウェア システム設計は、データ フロー、ストレージ、およびスケーラビリティに重点を置いています。 ML システム設計は、さらなる次元を追加します。**モデルは生きたコンポーネント**であり、時間の経過とともに劣化し、データの品質に依存し、継続的な評価が必要になります。

面接官は完璧なアーキテクチャ図を求めているわけではありません。彼らは、次のことができることを知りたいと考えています。

- 漠然としたビジネス上の問題を、広範囲にわたる ML タスクに変換します。
- データ要件と潜在的な落とし穴を早期に特定する
- 教科書の答えを暗唱するのではなく、トレードオフについて説明する
- モデルがデプロイされた*後* 何が起こるかを考える

<Callout>候補者が犯す最大の間違いは、モデルの選択に直行することです。面接官は一貫して、問題の枠組みとデータに関するディスカッションが候補者を差別化する場所であると報告しています。
</Callout>

## 🧩 8 ステップの ML システム設計フレームワーク

このフレームワークを、あらゆる設計上の質問に対する骨格として使用してください。すべてのステップに同じ時間を費やす必要はありません（質問に基づいて調整します）が、それぞれのステップに触れることは成熟の合図です。

### 1. 問題定義とビジネス指標

まずは目標を明確にすることから始めましょう。質問してください: *ビジネスにとって成功とはどのようなものですか?*

- **検索ランキング**: クリックスルー率を最大化しますか?結果が出るまでの時間は？
- **不正検出**: 誤検出 (正当なユーザーのブロック) を制御しながら、誤検出 (不正の見逃し) を最小限に抑えますか?
- **コンテンツの管理**: 正確さよりも再現 (有害なものをすべてキャッチ) を優先しますか?

ビジネス指標を ML に適した目標に早期にマッピングします。たとえば、「ユーザー エンゲージメントを向上させる」は、「各アイテムのクリック確率を予測し、スコアでランク付けする」と言い換えることができます。

### 2. データパイプラインと収集

データの出所、収集方法、予想される問題について話し合います。

- **データ ソース**: ユーザー行動ログ、トランザクション記録、サードパーティ API
- **ラベル付け戦略**: 明示的なラベル (ユーザー評価)、暗黙的なシグナル (クリック数、滞留時間)、または人間による注釈
- **データの鮮度**: データはどのくらいの頻度で変更されますか?また、古いとパフォーマンスに悪影響を及ぼしますか?

### 3. 特徴量エンジニアリング

抽出する特徴について説明します。それらを論理的にグループ化します。

|機能グループ |例 |
|---|---|
|ユーザー機能 |年齢バケット、在職期間、過去のクリック率 |
|アイテムの特徴 |カテゴリ、価格帯、人気スコア |
|コンテキスト機能 |時刻、デバイスの種類、場所 |
|インタラクション機能 |ユーザー×アイテムの共起、セッション深度 |

### 4. モデルの選択

今、そして今だけですが、モデルについて議論します。自分の選択を正当化します:

- **ベースライン**: ロジスティック回帰または勾配ブースト ツリー (トレーニングが速く、解釈可能)
- **上級**: 深層学習 (検索用の 2 タワー モデル、トランスフォーマー ベースのランカー)
- **アンサンブル**: 高速検索モデルと、低速だがより正確な再ランカーを組み合わせます。

### 5. トレーニング戦略

トレーニングと検証の方法について説明します。

- トレーニング/検証/テストの分割 (時系列データの時間ベースの分割)
- クラスの不均衡の処理 (オーバーサンプリング、損失重み付け)
- ハイパーパラメータ調整アプローチ

### 6. オフライン評価

ビジネス目標に合致する指標を選択してください。ランキングには Precision@K、バイナリ分類には AUC-ROC、順序付きリストには NDCG。

### 7. 導入とサービス提供

モデルがユーザーにどのように届くかについて話し合います。

- **バッチ推論**: 毎晩予測を事前計算します (電子メールによる推奨に適しています)
- **リアルタイム推論**: すべてのリクエストのスコア (検索ランキングに必要)
- **ハイブリッド**: 候補セットを事前計算し、リアルタイムで再ランク付けします

### 8. モニタリングと反復

データのドリフト、予測分布の変化、A/B テストによるオンライン指標など、リリース後に注目する内容について説明します。

<ThinkAboutIt>不正行為検出システムを設計していると想像してください。この企業は「すべての詐欺を捕まえる」と言っています。 100% の再現率が危険な目標であるのはなぜですか? 許容可能なトレードオフについてどのように会話を組み立てますか?
</ThinkAboutIt>

## 🎯 ML 設計に関するよくある質問とその対処方法

### レコメンドシステム

- **フレーミング**: P(ユーザーがアイテムをクリックする)を予測 → アイテムをスコアでランク付け
- **重要な課題**: 新規ユーザー/アイテムのコールドスタートの問題
- **アーキテクチャ**: 候補生成 (高速、近似) → ランキング (正確、低速) → 再ランキング (ビジネス ルール、多様性)

### 検索ランキング

- **フレーミング**: クエリが与えられた場合、関連性によってドキュメントをランク付けします。
- **主な課題**: 関連性、新鮮さ、パーソナライゼーションのバランスを取る
- **アーキテクチャ**: 転置インデックスの取得 → ランク付け学習モデル → ビジネス ルールとの融合

### 不正行為の検出

- **フレーミング**: 二項分類 — この取引は不正ですか?
- **主要な課題**: 極端な階級不均衡 (不正行為は取引の 0.1% 未満)
- **アーキテクチャ**: ルールベースのフィルター → ML モデル → 不確実なケースに対する人によるレビューキュー

## ⚖️ 上級エンジニアのようにトレードオフについて議論する

面接官は、経験の深さを明らかにするため、トレードオフの議論を好みます。 Here are the trade-offs that come up most:

|トレードオフ |左を好む場合 |適切な場合 |
|---|---|---|
|レイテンシと精度 | Real-time user-facing (search) | Batch offline (email recs) |
|単純なモデルと複雑なモデル | Small data, need interpretability | Large data, accuracy is critical |
| Batch vs Real-time serving |予測はすぐには変わりません。予測は最新のコンテキストを反映する必要があります。
|構築 vs 購入 | Core differentiator for the business |コモディティ機能 (OCR など) |



> 「[利点] が得られる **オプション A** を選択することもできますが、欠点は [コスト] です。あるいは、**オプション B** [利点] を選択することもできますが、[コスト] が発生します。[問題による特定の制約] を考慮すると、**オプション A** に傾くでしょう。なぜなら...」

<FunFact>Netflix は、そのレコメンデーション システムにより、解約率が減少し、年間 10 億ドル以上を節約できると見積もっています。その 1 つの ML システムの価値は、一部の小国の GDP を超えます。
</FunFact>

## 🛠️ すべてをまとめる: ミニウォークスルー

**プロンプト**: 「ソーシャル メディア プラットフォーム用のコンテンツ モデレーション システムを設計します。」

1. **問題**: ユーザーが作成したコンテンツ (テキスト + 画像) を安全、境界線、または有害に分類する
2. **データ**: 人間のレビュー担当者によるラベル付きモデレーション決定、ユーザーレポート
3. **機能**: テキストの埋め込み、画像の機能 (ヌードスコア、暴力指標)、ユーザー履歴 (以前の違反)
4. **モデル**: マルチモーダル分類器 (テキスト ブランチ + 画像ブランチ → 融合層 → 分類ヘッド)
5. **トレーニング**: クラスの不均衡に対処するための層別サンプリング。新しい有害なパターンが出現した場合の定期的な再トレーニング
6. **評価**: 有害なコンテンツの再現率が高い。ボーダーラインでは精度が重要（過剰な検閲を避ける）
7. **サービス**: アップロード時のリアルタイム推論。 queue borderline cases for human review
8. **モニタリング**: ユーザーの申し立てを通じて誤検知率を追跡します。 monitor for new abuse patterns

## 🔑 重要なポイント

- **フレームワークを使用する**: 問題 → データ → 機能 → モデル → トレーニング → 評価 → 導入 → モニタリング
- **モデルではなく、ビジネス上の問題から始めます** - これをスキップすると面接官は気づきます
- **トレードオフについて明確に話し合う** — これが中堅候補者と上級候補者の間の最大の差別化要因です
- **精度を超えて考える** — 実稼働環境では、遅延、コスト、公平性、保守性がすべて重要です
- **大声で練習する** — ML システムの設計は、技術的なものであると同時にコミュニケーションの練習でもあります

<Callout>最適な ML システム設計の答えは、講義ではなく会話のように感じられます。面接官に確認するために一時停止し、明確な質問をし、面接官が別の方向に誘導した場合には、進んで方向転換するようにしてください。
</Callout>

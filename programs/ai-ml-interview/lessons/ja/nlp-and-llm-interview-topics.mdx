# 💬 NLP および LLM インタビューのトピック

2 年前、NLP の面接の質問は、単語の埋め込みと LSTM の消失勾配について説明することを意味していました。今日、インタビュアーは、「RAG を使用するのではなく、いつモデルを微調整しますか?」と尋ねる可能性が高くなります。 NLP の状況は劇的に変化し、インタビューもそれに伴って変化しました。このレッスンでは、面接官が現在もテストしている基礎的な事項と、現在会話の中心となっている LLM 時代のトピックの両方を取り上げます。

## 📚 NLP の基礎について面接官はまだ期待している

GPT の時代であっても、これらのモデルが単に「機能する」だけでなく、「なぜ」機能するかを理解していることを証明する必要があります。

### トークン化

トークン化は、生のテキストをモデルが処理できる個別の単位に変換します。アプローチは重要です:

- **単語レベル**: 単純だが語彙外の単語を処理できない (「不親切」→不明)
- **文字レベル**: 任意の単語を処理しますが、シーケンスは非常に長いです
- **サブワード (BPE、WordPiece、SentencePiece)**: 現代の標準 - 珍しい単語を意味のある部分に分割します

```
"unfriendliness" → ["un", "friend", "li", "ness"]  (BPE)
"playing"        → ["play", "##ing"]                (WordPiece)
```

<Callout>インタビューのヒント: トークン化について質問された場合は、トークン化の選択が語彙サイズ、シーケンスの長さ、まれな単語やスペルミスのある単語を処理するモデルの能力に影響することを述べてください。これは、メカニズムだけでなく、下流への影響を理解していることを示しています。
</Callout>

### 埋め込み

埋め込みは、意味論的な関係が保持される密な連続ベクトルに離散トークンをマップします。

- **Word2Vec / GloVe**: 静的埋め込み - 各単語はコンテキストに関係なく 1 つのベクトルを取得します (「銀行」は川岸を意味する場合でも金融機関を意味する場合でも同じ埋め込みを持ちます)
- **コンテキスト埋め込み (BERT、GPT)**: 各トークンの埋め込みは周囲のコンテキストに依存します - 「銀行」は異なる文で異なる表現を取得します

### アテンションのメカニズム

注意こそが変圧器を機能させるための重要な革新です。その核心は次のとおりです。

$$\text{注意}(Q, K, V) = \text{ソフトマックス}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

簡単に言うと、各トークンに対して、attention は他のすべてのトークンに対する加重平均を計算します。この重みは、各トークンが現在のトークンとどの程度関連しているかを反映します。スケーリング係数 √d_k は、ドット積が大きくなりすぎるのを防ぎます。

**セルフアテンション** により、すべてのトークンがシーケンス内の他のすべてのトークンに注意を向けることができ、RNN が苦労する長距離の依存関係をキャプチャできます。

### 変圧器のアーキテクチャ

変圧器は次のもので構成されます。
- **エンコーダー**: 完全な入力を処理します (理解のために BERT スタイルのモデルで使用されます)
- **デコーダー**: 出力トークンをトークンごとに生成します (GPT スタイルのモデルで生成に使用されます)
- **エンコーダー-デコーダー**: 両方を組み合わせます (T5 で使用され、変換用のオリジナルのトランスフォーマー)

|建築 |例 |最適な用途 |
|---|---|---|
|エンコーダのみ |ロベルタ・バート |分類、NER、埋め込み |
|デコーダのみ | GPT、Llama、ミストラル |テキスト生成、チャット、推論 |
|エンコーダ-デコーダ | T5、バート |翻訳、要約 |

## 🤖 LLM 固有の面接の質問

これらは過去 2 年間に浮上した質問であり、現在ではほぼすべての ML インタビューで聞かれます。

### 微調整とプロンプト

|アプローチ |いつ使用するか |長所 |短所 |
|---|---|---|---|
| **ゼロ/少数ショットのプロンプト** |クイック プロトタイピング、一般的なタスク |トレーニングは不要、柔軟 |制限された制御、クエリごとのコスト |
| **迅速なエンジニアリング** |適度なカスタマイズ |高速な反復、GPU コストなし |壊れやすい、バージョン管理が難しい |
| **微調整 (フル)** |ラベル付きデータを使用したドメイン固有のタスク |最高の品質、可能な限り小型のモデル |高価で、データと GPU が必要 |
| **LoRA / QLoRA** |限られたリソースでの微調整 |効率的で小型のアダプター重量 |完全な微調整よりも表現力がわずかに劣ります |
| **ラグ** |知識集約型の最新情報が必要 |再トレーニングなし、引用可能な出典 |取得品質のボトルネック |

### 検索拡張生成 (RAG)

RAG は、検索システムと言語モデルを組み合わせます。

```
User query → Embed query → Search vector DB → Retrieve top-K documents
    → Construct prompt (query + retrieved docs) → LLM generates answer
```

**面接での重要な議論のポイント**:
- **チャンク戦略**: ドキュメントをどのように分割するかが検索品質に影響します
- **埋め込みモデルの選択**: ドメイン固有の埋め込みと一般的な埋め込み
- **再ランキング**: LLM に供給する前に、クロスエンコーダーを使用して、取得したチャンクを再ランク付けします。
- **RAG が失敗した場合**: 答えを得るために多くの文書にわたる推論が必要な場合、または関連する文書が存在しない場合

### RLHF (ヒューマンフィードバックからの強化学習)

ChatGPT の有用性の背後にあるテクニック:

1. **監視付き微調整**: 厳選されたプロンプト応答ペアでトレーニングします
2. **報酬モデルのトレーニング**: 人間がモデルの出力をランク付けします。これらの好みに基づいて報酬モデルをトレーニングする
3. **PPO 最適化**: 報酬モデルを使用して、強化学習を通じて LLM を微調整します

<FunFact>InstructGPT の元の論文では、RLHF を使用した 1.3B パラメータ モデルが、RLHF を使用しない 175B パラメータ モデルよりも人間に好まれることが示されています。位置合わせ技術を使用すると、現実世界での有用性に関して、小さなモデルが巨大なモデルよりも優れたパフォーマンスを発揮できるようになります。
</FunFact>

### コンテキストウィンドウとロングコンテキストの課題

- **コンテキスト ウィンドウ**: モデルが一度に処理できるトークンの最大数。現在の 最先端システム は、数十万から約 100 万 トークン まで幅があります。
- **途中で失われる**: モデルは、長いコンテキストの途中にある情報にあまり注意を払わない傾向があります。
- **戦略**: 長い文書を要約し、重要な情報を先頭/末尾に配置し、階層検索を使用します。

### 幻覚

モデルは、もっともらしいが事実としては不正確なテキストを生成します。緩和戦略:
- **RAG**: 回収された証拠における地上応答
- **制約された生成**: 出力を既知のエンティティまたは構造化フォーマットに制限します
- **自己一貫性**: 複数の回答を生成し、一致を確認します。
- **引用**: モデルにソースを引用するよう要求します (その後、ソースを検証します)。

<ThinkAboutIt>リーガル テクノロジー企業は、判例法に関する質問に答える AI アシスタントを構築したいと考えています。幻覚により、存在しない判例を引用することになる可能性があります。応答を有効に保ちながら幻覚のリスクを最小限に抑えるには、このシステムをどのように設計しますか?
</ThinkAboutIt>

## 🎯 モデルの選択: いつ何を使用するか

これはインタビューでよくある質問です。「この使用例を考慮すると、どのモデルを選択しますか?」

**次の場合には大規模 最先端モデル (GPT-6 Astra、Claude Opus 5.5) を使用します。**
- タスクには一般的な推論または以下の複雑な指示が必要です
- ラベル付きトレーニング データがない
- 推論コストよりもプロトタイピングの速度が重要

**次の場合には、微調整された小型モデル (Mistral、Llama) を使用してください。**
- ドメイン固有のデータがあり、一貫した特殊な出力が必要です
- 推論コストが重要 (大規模なサービス)
- 遅延要件が厳しい
- データプライバシーのためにオンプレミスで実行する必要がある

**次の場合には従来の NLP モデル (BERT、RoBERTa) を使用します。**
- タスクは分類、NER、または抽出です (生成ではありません)
- 非常に高いスループットでの高速推論が必要です
- タスクは明確にラベル付けされたデータで明確に定義されています

## 🔬 LLM 出力の評価

生成モデルの評価は、分類器の評価よりも困難です。一般的なアプローチ:

- **自動メトリクス**: BLEU、ROUGE、BERTScore (便利ですが不完全)
- **LLM-as-judge**: より強力なモデルを使用して、より弱いモデルの出力を評価します
- **人間による評価**: ゴールドスタンダードだが高価で時間がかかる
- **タスク固有の評価**: QA ベンチマークの精度、コード実行の合格率
- **レッドチーム**: 安全性、偏見、有害な出力に対する敵対的テスト

```python
# BERTScore example
from bert_score import score

precision, recall, f1 = score(
    cands=["The cat sat on the mat"],
    refs=["A cat was sitting on a mat"],
    lang="en"
)
```

## ⚖️ 倫理的配慮

NLP の面接には、倫理に関する質問が含まれることが増えています。

- **トレーニング データのバイアス**: LLM はトレーニング コーパスからバイアスを吸収および増幅します。
- **プライバシー**: モデルはトレーニング データを記憶および逆流する可能性があります (PII 漏洩)
- **誤った情報**: 生成モデルは、説得力があるが誤ったコンテンツを大規模に作成する可能性があります
- **環境コスト**: 大規模モデルのトレーニングには多大な二酸化炭素排出量が発生します

## 🔑 重要なポイント

- **基礎を理解してください**: トークン化、埋め込み、アテンション、トランスフォーマー アーキテクチャは交渉の余地がありません
- **微調整スペクトルを理解する**: ゼロショット プロンプトから完全な微調整まで、およびそれぞれがいつ適切であるか
- **RAG は最も実用的な LLM パターン** - チャンキング、取得、および再ランキングを理解する
- **モデルの選択はトレードオフに関するものです**: 機能、コスト、遅延、プライバシー
- **生成モデルの評価は未解決の問題です** - 複数のアプローチを知っておく
- **倫理は任意ではありません**: 偏見、幻覚、プライバシーは現在、面接の標準的なトピックになっています

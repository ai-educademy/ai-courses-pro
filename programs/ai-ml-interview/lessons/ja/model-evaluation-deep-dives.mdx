# 📊 モデル評価の詳細

「あなたのモデルの精度は 95% です。出荷してください。」この文を読んですぐに不快に思わない場合は、このレッスンがまさにあなたに必要なものです。モデルの評価は、モデルを *トレーニング*した候補者とモデルを *デプロイ*した候補者を分ける面接のトピックです。面接官は、モデルが実際に何を行っているかを理解しているかどうか、そしてそれを信頼すべきかどうかを明らかにするため、評価に関する知識を精査します。

---

## 🎯 分類メトリクス: 精度を超えて

精度 (正しい予測の割合) は、誰もが最初に学ぶ指標であり、誤解を招くことが最も多い指標です。トランザクションの 0.5% のみが不正であるデータセットの不正検出モデルを考えてみましょう。すべてについて「不正ではない」と予測するモデルは、不正を検出せずに **99.5% の精度** を達成します。

### 精度、再現率、および F1

これら 3 つの指標は、分類評価のバックボーンを形成します。

- **精度** = TP / (TP + FP) - 「陽性とフラグを立てたすべてのうち、実際の陽性率はどれくらいですか?」
- **思い出してください** = TP / (TP + FN) - 「実際にポジティブだったすべてのことのうち、どれだけ理解できましたか?」
- **F1 スコア** = 2 × (精度 × 再現率) / (精度 + 再現率) - 両方のバランスをとる調和平均

```
              Predicted Positive    Predicted Negative
Actual Positive       TP                   FN
Actual Negative       FP                   TN
```

<ThinkAboutIt>あなたは医療画像からがんを検出するモデルを構築しています。精度または再現率を最適化しますか?これをそれぞれの方向で間違えると、実際にはどのような結果が生じるのでしょうか?
</ThinkAboutIt>

### いつどれを使用するか

|シナリオ |最適化 |なぜ |
|---|---|---|
|スパムフィルター |精度 |本物の電子メールをスパムに送信することは、スパムを通過させることよりも悪いです。
|がん検診 |思い出す |ガンの症例を見逃すことは、誤報よりもはるかに悪いことです。
|検索ランキング |プレシジョン@K |ユーザーは上位の結果のみを参照します。
|不正行為の検出 | F1 またはカスタム |バランスが必要 - 誤検知が多すぎると実際の顧客がブロックされる |

## 📈 AUC-ROC と AUC-PR: 全体像

### ROC 曲線

受信者動作特性曲線は、すべての分類しきい値で **真陽性率** (リコール) と **偽陽性率** (FP / (FP + TN)) をプロットします。この曲線の下の面積 (**AUC-ROC**) は、しきい値に依存しないモデルの品質の尺度を示します。

- **AUC = 1.0**: 完全な分離
- **AUC = 0.5**: ランダムな推測 (対角線)
- **AUC < 0.5**: ランダムよりも悪い (ラベルが反転する可能性があります!)

### 適合率-再現率曲線

クラスの不均衡が著しく大きい場合、AUC-ROC は誤解を招くほど楽観的になる可能性があります。 **適合率-再現率曲線**は適合率と再現率をプロットしており、レアイベントの検出により多くの情報を提供します。

```python
from sklearn.metrics import precision_recall_curve, auc

precision, recall, thresholds = precision_recall_curve(y_true, y_scores)
pr_auc = auc(recall, precision)
```

<Callout>面接のヒント: 面接官が不均衡なデータセットについて言及した場合は、すぐに AUC-ROC ではなく AUC-PR を提案します。これは、アンバランスな設定における ROC 曲線の限界を理解していることを示しています。多くの受験者がこの区別を見逃しています。
</Callout>

## 📐 回帰メトリクス

すべてが分類されるわけではありません。連続値を予測する場合、次の指標が重要になります。

### 平均二乗誤差 (MSE)

$$MSE = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2$$

大きなエラーに重くペナルティを課します (二次ペナルティ)。大きな間違いが小さな間違いよりもはるかに悪い場合に適しています。たとえば、住宅価格を予測する場合、10 万ポンドの誤差は 1 万ポンドの誤差よりもはるかに悪いです。

### 平均絶対誤差 (MAE)

$$MAE = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|$$

すべてのエラーを線形に処理します。 MSE よりも外れ値に対して堅牢です。外れ値が予想され、メトリクスを支配すべきではない場合に使用します。

### R² (決定係数)

$$R^2 = 1 - \frac{\sum(y_i - \hat{y}_i)^2}{\sum(y_i - \bar{y})^2}$$

単純に平均を予測する場合と比較して、モデルがどの程度の分散を説明するかを測定します。 R² = 1 は完全に適合することを意味します。 R² = 0 は、モデルが平均を予測する以上のものではないことを意味します。

<FunFact>R² は実際にはマイナスになる可能性があります。これは、モデルの予測がすべての入力のターゲット変数の平均を単純に予測するよりも悪い場合に発生します。それは何かが非常に間違っていることを示す兆候です。
</FunFact>

## 🔄 相互検証戦略

単一のテスト セットを保持することは大規模なデータセットに対して機能しますが、相互検証により汎化パフォーマンスのより信頼性の高い推定値が得られます。

### K フォールド相互検証

データを K 個の等しい折り畳みに分割します。 K-1 フォールドでトレーニングし、残りのフォールドで検証します。 K回繰り返します。メトリクスの平均と標準偏差を報告します。

```python
from sklearn.model_selection import cross_val_score

scores = cross_val_score(model, X, y, cv=5, scoring='f1')
print(f"F1: {scores.mean():.3f} ± {scores.std():.3f}")
```

### 層別 K フォールド

各フォールド内のクラス分布を維持します。これは、不均衡なデータセットに不可欠です。

### 時系列分割

時間データの場合は、ランダム分割を**決して**使用しないでください。時間順序を尊重するには、拡張ウィンドウまたはスライディング ウィンドウの相互検証を使用します。

```
Fold 1: Train [Jan-Mar]  → Test [Apr]
Fold 2: Train [Jan-Apr]  → Test [May]
Fold 3: Train [Jan-May]  → Test [Jun]
```

## 🌐 オフラインとオンラインの評価

オフラインの指標 (履歴データに基づいて計算) は、常にオンラインのパフォーマンスを予測するとは限りません。 AUC が優れたモデルは、導入後のユーザー エンゲージメントを実際に低下させる可能性があります。

|側面 |オフライン評価 |オンライン評価（A/Bテスト） |
|---|---|---|
|スピード |高速 - 保存されたデータで実行 |遅い - 実際のトラフィックが必要 |
|コスト |低い |高 (エンジニアリング + 機会費用) |
|対策 |履歴データに基づくモデルの品質 |実際のビジネスへの影響 |
|制限 |ユーザーの行動の変化を捕捉しない |統計的な厳密性が必要 |

### ML モデルの A/B テスト

新しいモデルの A/B テストを実行する場合:

1. **主要指標を定義** (例: ユーザーあたりの収益) およびガードレール指標 (例: 遅延、エラー率)
2. **統計的有意性を得るために必要なサンプル サイズを計算**
3. **正しくランダム化** - リクエスト レベルではなくユーザー レベルで分割します
4. **十分な期間実行** - 新規性の効果と毎週の季節性を考慮する
5. **干渉をチェックする** - 治療グループの行動は対照グループに影響を与えますか?

<ThinkAboutIt>新しいレコメンデーション モデルでは、オフラインでは AUC-ROC が 3% 向上しましたが、A/B テスト中のクリックスルー率は 1% *減少*しました。この矛盾は何を説明できますか?何を調査しますか?
</ThinkAboutIt>

## ⚖️ 不均衡なデータセットの処理

不均衡なデータはトレーニングと評価の両方に影響を与えます。一般的な戦略:

**トレーニング中:**
- 少数派クラスのオーバーサンプリング (SMOTE)
- 過半数クラスをアンダーサンプリングする
- 損失関数でクラスの重みを使用する
- 合成例の生成

**評価中:**
- 精度の代わりに精度、再現率、F1 を使用します
- AUC-ROC の代わりに AUC-PR を使用する
- クラスごとのレポート指標
- 階層化された相互検証を使用する

```python
from sklearn.ensemble import RandomForestClassifier

# Class weight approach — inversely proportional to class frequency
model = RandomForestClassifier(class_weight='balanced')
```

## 🔑 重要なポイント

- **精度だけに依存しないでください** - 特に不均衡なデータの場合
- **メトリクスをビジネス目標に一致させる**: 安全性が重要であり、誤検知によりコストがかかる場合の精度についてはリコールします。
- 不均衡な問題には **AUC-ROC よりも AUC-PR** - これは高信号の面接のヒントです
- **時系列データには時間ベースの分割を使用します** - ランダムな分割はデータ漏洩の原因となります
- **オフラインの指標だけでは十分ではありません** - 現実世界への影響を検証するために A/B テストを計画します
- **公式を知っておく** - 面接官は、適合率、再現率、F1、MSE、および R² を導出または説明するよう求める場合があります。

# ⚙️ MLOps und Produktions-ML

Hier ist eine Statistik, die beeinflussen sollte, wie Sie sich auf Vorstellungsgespräche vorbereiten: **87 % der ML-Modelle schaffen es nie in die Produktion.** Die Lücke zwischen einem Jupyter-Notebook und einem zuverlässigen, skalierbaren ML-Dienst ist enorm – und Unternehmen suchen verzweifelt nach Ingenieuren, die diese Lücke schließen können. MLOps-Interviewfragen testen, ob Sie ein Modell von „Es funktioniert auf meinem Computer“ zu „Es funktioniert für Millionen von Benutzern zuverlässig, um 3 Uhr morgens an einem Samstag“ umwandeln können.

---

## 🧭 Was MLOps tatsächlich abdeckt

MLOps ist eine Reihe von Praktiken, die DevOps-Disziplin in das maschinelle Lernen bringen. Es umfasst den gesamten ML-Lebenszyklus:

```
Data → Feature Engineering → Training → Evaluation → Deployment → Monitoring → Retraining
  ↑                                                                              |
  └──────────────────────────── Feedback Loop ────────────────────────────────────┘
```

Zu den wichtigsten Säulen gehören:
- **CI/CD für ML**: automatisiertes Testen von Daten, Funktionen und Modellen – nicht nur von Code
- **Experimentverfolgung**: systematische Aufzeichnung von Hyperparametern, Metriken und Artefakten
- **Modellversionierung**: Verfolgen, welche Modellversion welchen Datenverkehr bedient
- **Modellbereitstellung**: Vorhersagen zuverlässig und schnell an Benutzer weiterleiten
- **Überwachung**: Erkennen, wenn Modelle in der Produktion schlechter werden

<Callout>Der größte Unterschied zwischen MLOps und traditionellem DevOps: Bei Software machen Codeänderungen Dinge kaputt. In ML führen *Daten*-Änderungen zu Problemen – oft stillschweigend und ohne Fehlerprotokolle.
</Callout>

## 🚀 Modellieren Sie Serviermuster

Wie Sie Vorhersagen bereitstellen, hängt von Ihren Latenzanforderungen, Ihrem Umfang und der Häufigkeit, mit der sich Vorhersagen ändern müssen, ab.

### Batch-Inferenz

Berechnen Sie Vorhersagen nach einem Zeitplan (stündlich, täglich) vor und speichern Sie sie zum Nachschlagen.

**Am besten für**: E-Mail-Empfehlungen, tägliche Risikobewertungen, wöchentliche Berichte

```
Schedule → Load data → Run model → Write predictions to DB → Serve from DB
```

**Vorteile**: einfache Infrastruktur, große Modelle einsetzbar, kostengünstig
**Nachteile**: Vorhersagen können veraltet sein und nicht auf den Echtzeitkontext reagieren

### Echtzeit-Inferenz (Model-as-a-Service)

Das Modell läuft hinter einer API. Jede Anfrage löst eine Vorhersage aus.

**Am besten geeignet**: Suchranking, Betrugserkennung, Chatbots

```
User request → API Gateway → Feature lookup → Model inference → Response
```

**Vorteile**: neue Vorhersagen, kann Echtzeitkontext nutzen
**Nachteile**: latenzempfindlich, Modellgröße und Bereitstellungsinfrastruktur müssen optimiert werden

### Eingebettetes Modell

Das Modell wird direkt in die Anwendung oder das Gerät gebündelt.

**Am besten geeignet für**: mobile Apps, IoT-Geräte, Edge Computing

**Vorteile**: Keine Netzwerklatenz, funktioniert offline
**Nachteile**: schwieriger zu aktualisieren, begrenzt durch Geräteressourcen

## 📊 Experimentverfolgung

Die Durchführung von ML-Experimenten ohne Nachverfolgung ist wie Wissenschaft ohne Labornotizbuch. Sie müssen Folgendes aufzeichnen:

- **Hyperparameter**: Lernrate, Stapelgröße, Architekturauswahl
- **Metriken**: Trainingsverlust, Validierungsmetriken in jeder Epoche
- **Artefakte**: Modellkontrollpunkte, Merkmalswichtigkeitsdiagramme, Verwirrungsmatrizen
- **Umgebung**: Bibliotheksversionen, verwendete Hardware, zufällige Seeds

### Beliebte Tools

| Werkzeug | Stärken | Bereitstellung |
|---|---|---|
| **MLflow** | Open-Source, Modellregister, breite Akzeptanz | Selbstgehostet oder verwaltet |
| **Gewichte und Verzerrungen (W&B)** | Schöne Benutzeroberfläche, Funktionen für die Zusammenarbeit, Sweeps | Cloud-gehostet |
| **Neptune.ai** | Leicht, gut für Teams | Cloud-gehostet |
| **TensorBoard** | Kostenlos, eng integriert mit TensorFlow | Lokal oder eingebettet |

```python
import mlflow

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run():
    mlflow.log_param("learning_rate", 0.001)
    mlflow.log_param("n_estimators", 500)

    model = train_model(X_train, y_train)
    metrics = evaluate_model(model, X_test, y_test)

    mlflow.log_metric("auc_roc", metrics["auc_roc"])
    mlflow.log_metric("precision", metrics["precision"])
    mlflow.sklearn.log_model(model, "model")
```

## 🔍Überwachung von ML in der Produktion

Herkömmliche Softwareüberwachung verfolgt Fehler und Latenz. Die ML-Überwachung fügt eine kritische Ebene hinzu: **Macht das Modell immer noch gute Vorhersagen?**

### Arten von Drift

**Datendrift** (Kovariatenverschiebung): Die Verteilung der Eingabemerkmale ändert sich. Beispiel: Ein E-Commerce-Modell, das auf Daten aus der Zeit vor der Pandemie trainiert wurde, verzeichnet einen Anstieg der Suchanfragen nach Home-Office-Geräten.

**Konzeptdrift**: die Beziehung zwischen Funktionen und Zieländerungen. Beispiel: Die Funktion „Beschäftigungsstatus“ eines Kreditbewertungsmodells bedeutet während einer Rezession etwas anderes.

**Vorhersagedrift**: Die Verteilung der Modellausgaben ändert sich, auch wenn die Eingaben ähnlich aussehen.

### Was zu überwachen ist

| Signal | So erkennen Sie | Aktion |
|---|---|---|
| Eingabe-Feature-Verteilungen | Statistische Tests (KS-Test, PSI) | Datenpipeline untersuchen |
| Vorhersageverteilung | Verfolgen Sie Mittelwert, Varianz und Perzentile im Zeitverlauf | Vergleich mit Basiszeitraum |
| Modellleistung (sofern Labels verfügbar) | Streckengenauigkeit, F1 usw. im Vergleich zur Grundwahrheit | Neuschulung auslösen, wenn unter dem Schwellenwert |
| Latenz | P50, P95, P99 Reaktionszeiten | Infrastruktur skalieren oder Modell optimieren |
| Datenqualität | Nullraten, Schemaverletzungen, Volumenanomalien | Alert-Data-Engineering-Team |

```python
from scipy.stats import ks_2samp

# Kolmogorov-Smirnov test for distribution shift
def detect_drift(reference_data, current_data, threshold=0.05):
    statistic, p_value = ks_2samp(reference_data, current_data)
    return p_value < threshold  # True = drift detected
```

<FunFact>Als das Hauspreismodell „Zestimate“ von Zillow während des ungewöhnlichen Immobilienmarktes 2021 eine Konzeptverschiebung erlebte, verlor das Unternehmen über 500 Millionen US-Dollar durch Hauskäufe, die sich an den Prognosen seines eigenen Modells orientierten – und stellte schließlich sein Home-Flipping-Geschäft ein.
</FunFact>

## 🔄 CI/CD für maschinelles Lernen

ML CI/CD geht über das Testen von Code hinaus. Sie müssen auch Daten, Funktionen und Modelle validieren.

### Die ML-Testpyramide

```
              ┌──────────────┐
              │  Model Tests  │  ← Does the model meet quality thresholds?
             ┌┴──────────────┴┐
             │  Feature Tests  │  ← Are features computed correctly?
            ┌┴────────────────┴┐
            │  Data Validation  │  ← Is the data schema correct? Missing values?
           ┌┴──────────────────┴┐
           │    Unit Tests       │  ← Does the code work?
           └────────────────────┘
```

**Datenvalidierung**: Schema, Nullraten, Wertebereiche, Zeilenanzahl prüfen
**Feature-Tests**: Überprüfen Sie, ob Feature-Transformationen erwartete Ergebnisse liefern
**Modelltests**: Stellen Sie vor der Bereitstellung sicher, dass das trainierte Modell die Mindestqualitätsschwellenwerte überschreitet

## 💰 Überlegungen zur Infrastruktur

Produktions-ML verursacht echte Kosten. Interviewer wollen Kostenbewusstsein sehen:

### GPU-Verwaltung

- **Training**: Nutzen Sie Spot-/Preemptible-Instanzen für Kosteneinsparungen (mit Checkpointing!)
- **Bereitstellung**: Erwägen Sie die Modelldestillation oder -quantisierung, um die GPU-Anforderungen zu reduzieren
- **Autoscaling**: Skalieren Sie GPU-Instanzen basierend auf Verkehrsmustern, nicht auf Spitzenkapazität

### Strategien zur Kostenoptimierung

- **Modellkomprimierung**: Bereinigung, Quantisierung, Wissensdestillation
- **Caching**: Cache-Vorhersagen für wiederholte Eingaben
- **Abgestufte Bereitstellung**: Verwenden Sie für die meisten Anfragen ein günstiges Modell, ein teures Modell nur, wenn das Vertrauen gering ist
- **Richtige Dimensionierung**: Stellen Sie kein 175B-Parametermodell bereit, wenn ein fein abgestimmtes 7B-Modell 95 % der Qualität erreicht

```
Cost per prediction ≈ (GPU cost per hour) / (predictions per hour)

Example:
- GPU instance: $3/hour
- Model throughput: 1,000 predictions/second
- Cost per prediction: $3 / 3,600,000 ≈ $0.0000008
```

## 🏗️ Häufige Fragen im Vorstellungsgespräch

Hier sind die Fragen, auf deren Diskussion Sie vorbereitet sein sollten:

1. „Erläutern Sie mir, wie Sie ein neues Modell in der Produktion bereitstellen würden“ – beschreiben Sie die gesamte Pipeline von der Schulung über die Canary-Bereitstellung bis hin zur vollständigen Einführung
2. „Wie würden Sie mit einem Modell umgehen, dessen Qualität in der Produktion nachlässt?“ — Überwachung, Ursachenanalyse, Rollback, Umschulung
3. „Was ist der Unterschied zwischen Modellumschulung und Modellaktualisierung?“ — vollständige Umschulung auf neue Daten im Vergleich zu inkrementellem/Online-Lernen
4. „Wie stellen Sie die Reproduzierbarkeit in ML-Experimenten sicher?“ – Versionskontrolle für Code, Daten und Konfiguration; feste Samen; Containerisierung
5. „Beschreiben Sie Ihre ideale ML-Plattform“ – Feature Store, Experiment-Tracker, Modellregistrierung, Bereitstellungsinfrastruktur, Überwachungs-Dashboard

<Callout>Berücksichtigen Sie bei der Beantwortung von MLOps-Interviewfragen immer technische Entscheidungen mit geschäftlichen Auswirkungen. „Wir verwenden Canary-Bereitstellungen, weil das Zurücksetzen eines fehlerhaften Modells X an Umsatzeinbußen kostet“ ist überzeugender, als nur den technischen Aufbau zu beschreiben.

## 🔑 Wichtige Erkenntnisse

- **MLOps schließt die Lücke** zwischen Modellentwicklung und Produktion – dies ist heute die gefragteste ML-Fähigkeit
- **Wählen Sie die Serviermuster mit Bedacht aus**: Charge nach Kosten, Echtzeit nach Frische, eingebettet nach Rand
- **Überwachung über die Latenz hinaus**: Datendrift, Konzeptdrift und Modellverschlechterung sind die stillen Killer
- **Verfolgen Sie jedes Experiment**: Parameter, Metriken, Artefakte und Umgebung
- **Testen Sie die ML-Pipeline**, nicht nur den Code: Datenvalidierung, Funktionstests und Modellqualitäts-Gates
- **Denken Sie an die Kosten**: Modellkomprimierung, Caching und mehrstufige Bereitstellung reduzieren die Infrastrukturkosten

# ⚙️ MLOps وML الإنتاج

فيما يلي إحصائية من شأنها أن تحدد كيفية الاستعداد للمقابلات: **87% من نماذج تعلم الآلة لا تصل إلى مرحلة الإنتاج أبدًا.** الفجوة بين دفتر Jupyter وخدمة تعلم الآلة الموثوقة والقابلة للتطوير هائلة - والشركات في حاجة ماسة للمهندسين الذين يمكنهم سد هذه الفجوة. تختبر أسئلة مقابلة MLOps ما إذا كان بإمكانك أخذ نموذج من "إنه يعمل على جهازي" إلى "إنه يعمل لملايين المستخدمين، بشكل موثوق، في الساعة 3 صباحًا يوم السبت".

---

## 🧭 ما يغطيه MLOps فعليًا

MLOps هي مجموعة من الممارسات التي تجلب انضباط DevOps إلى التعلم الآلي. يمتد دورة حياة ML بأكملها:

```
Data → Feature Engineering → Training → Evaluation → Deployment → Monitoring → Retraining
  ↑                                                                              |
  └──────────────────────────── Feedback Loop ────────────────────────────────────┘
```

تشمل الركائز الأساسية ما يلي:
- **CI/CD for ML**: اختبار آلي للبيانات والميزات والنماذج — وليس فقط التعليمات البرمجية
- **تتبع التجربة**: تسجيل منهجي للمعلمات الفائقة والمقاييس والمصنوعات اليدوية
- **إصدار النموذج**: تتبع إصدار النموذج الذي يخدم أي حركة مرور
- **عرض النماذج**: الحصول على تنبؤات للمستخدمين بشكل موثوق وسريع
- **المراقبة**: اكتشاف متى تتدهور النماذج في الإنتاج

<Callout>الفرق الأكبر بين MLOps وDevOps التقليدية: في البرامج، تؤدي تغييرات التعليمات البرمجية إلى كسر الأشياء. في تعلم الآلة، تؤدي تغييرات *البيانات* إلى كسر الأشياء - غالبًا بصمت، دون أي سجلات أخطاء.
</Callout>

## 🚀أنماط التقديم النموذجية

تعتمد كيفية تقديم التنبؤات على متطلبات زمن الاستجابة وحجمه وعدد المرات التي تحتاج فيها التنبؤات إلى التغيير.

### استنتاج الدفعة

قم بحساب التوقعات مسبقًا وفقًا لجدول زمني (كل ساعة، يوميًا) وقم بتخزينها للبحث عنها.

**الأفضل لـ**: توصيات البريد الإلكتروني، ونتائج المخاطر اليومية، والتقارير الأسبوعية

```
Schedule → Load data → Run model → Write predictions to DB → Serve from DB
```

**الإيجابيات**: بنية أساسية بسيطة، ويمكن استخدام نماذج كبيرة، وفعالة من حيث التكلفة
**السلبيات**: يمكن أن تكون التوقعات قديمة، ولا يمكنها الاستجابة لسياق الوقت الفعلي

### الاستدلال في الوقت الفعلي (النموذج كخدمة)

يعمل النموذج خلف واجهة برمجة التطبيقات (API). كل طلب يؤدي إلى التنبؤ.

**الأفضل لـ**: ترتيب البحث، واكتشاف الاحتيال، وروبوتات الدردشة

```
User request → API Gateway → Feature lookup → Model inference → Response
```

**الإيجابيات**: تنبؤات جديدة، ويمكن استخدام السياق في الوقت الفعلي
**السلبيات**: حساسة لزمن الاستجابة، وتحتاج إلى تحسين حجم النموذج والبنية التحتية للخدمة

### النموذج المضمن

يتم تجميع النموذج مباشرة في التطبيق أو الجهاز.

**الأفضل لـ**: تطبيقات الأجهزة المحمولة، وأجهزة إنترنت الأشياء، والحوسبة المتطورة

**الإيجابيات**: لا يوجد زمن استجابة للشبكة، ويعمل دون اتصال بالإنترنت
**السلبيات**: صعوبة التحديث ومحدودية موارد الجهاز

## 📊 تتبع التجارب

إن إجراء تجارب تعلم الآلة بدون تتبع يشبه إجراء العلوم بدون دفتر ملاحظات معملي. تحتاج إلى تسجيل:

- **المعلمات الفائقة**: معدل التعلم، وحجم الدفعة، وخيارات البنية
- **المقاييس**: فقدان التدريب، ومقاييس التحقق من الصحة في كل فترة
- **المصنوعات اليدوية**: نقاط التفتيش النموذجية، ومؤامرات الأهمية، ومصفوفات الارتباك
- **البيئة**: إصدارات المكتبة، الأجهزة المستخدمة، البذور العشوائية

### الأدوات الشعبية

| أداة | نقاط القوة | النشر |
|---|---|---|
| **MLflow** | مفتوح المصدر، نموذج التسجيل، اعتماد واسع النطاق | مستضافة ذاتيًا أو مُدارة |
| **الأوزان والتحيزات (W&B)** | واجهة مستخدم جميلة، ميزات التعاون، عمليات المسح | مستضافة على السحابة |
| **Neptune.ai** | خفيف الوزن، جيد للفرق | مستضافة على السحابة |
| ** TensorBoard ** | مجاني، ومتكامل بإحكام مع TensorFlow | محلي أو مضمن |

import mlflow

mlflow.set_experiment("fraud-detection-v2")

## 🔍 مراقبة التعلم الآلي في الإنتاج

تعمل مراقبة البرامج التقليدية على تتبع الأخطاء وزمن الوصول. تضيف مراقبة التعلم الآلي طبقة مهمة: **هل لا يزال النموذج يقدم تنبؤات جيدة؟**

### أنواع الانجراف

**انجراف البيانات** (التحول المتغير): يتغير توزيع ميزات الإدخال. مثال: نموذج التجارة الإلكترونية الذي تم تدريبه على بيانات ما قبل الوباء يشهد زيادة كبيرة في عمليات البحث عن معدات المكاتب المنزلية.

**انحراف المفهوم**: العلاقة بين الميزات وتغييرات الهدف. مثال: ميزة "حالة التوظيف" في نموذج تسجيل الائتمان تعني شيئًا مختلفًا أثناء فترة الركود.

**انحراف التنبؤ**: يتغير توزيع مخرجات النموذج، حتى لو كانت المدخلات متشابهة.

### ما يجب مراقبته

| إشارة | كيفية الكشف | العمل |
|---|---|---|
| توزيعات ميزة الإدخال | الاختبارات الإحصائية (اختبار KS، PSI) | التحقيق في خط أنابيب البيانات |
| توزيع التنبؤ | تتبع المتوسط ​​والتباين والنسب المئوية مع مرور الوقت | قارن بفترة خط الأساس |
| أداء النموذج (عند توفر التسميات) | دقة المسار، F1، وما إلى ذلك مقابل الحقيقة الأرضية | إعادة التدريب على الزناد إذا كان أقل من العتبة |
| الكمون | أوقات الاستجابة P50، P95، P99 | توسيع نطاق البنية التحتية أو تحسين النموذج |
| جودة البيانات | معدلات فارغة، انتهاكات المخطط، الشذوذ في الحجم | تنبيه فريق هندسة البيانات |

```python
from scipy.stats import ks_2samp

# Kolmogorov-Smirnov test for distribution shift
def detect_drift(reference_data, current_data, threshold=0.05):
    statistic, p_value = ks_2samp(reference_data, current_data)
    return p_value < threshold  # True = drift detected
```

<FunFact>عندما شهد نموذج Zillow لتسعير المنازل "Zestimate" انحرافًا في المفهوم خلال سوق الإسكان غير المعتاد لعام 2021، خسرت الشركة أكثر من 500 مليون دولار في مشتريات المنازل مسترشدة بتنبؤات نموذجها الخاص - وأغلقت في النهاية أعمالها المتعلقة بتقليب المنازل.
</FunFact>

## 🔄 CI/CD للتعلم الآلي

يتجاوز ML CI/CD اختبار التعليمات البرمجية. تحتاج إلى التحقق من صحة البيانات والميزات والنماذج أيضًا.

### هرم اختبار تعلم الآلة

```
              ┌──────────────┐
              │  Model Tests  │  ← Does the model meet quality thresholds?
             ┌┴──────────────┴┐
             │  Feature Tests  │  ← Are features computed correctly?
            ┌┴────────────────┴┐
            │  Data Validation  │  ← Is the data schema correct? Missing values?
           ┌┴──────────────────┴┐
           │    Unit Tests       │  ← Does the code work?
           └────────────────────┘
```

**التحقق من صحة البيانات**: تحقق من المخطط، والمعدلات الخالية، ونطاقات القيمة، وعدد الصفوف
**اختبارات الميزات**: التحقق من أن تحويلات الميزات تنتج المخرجات المتوقعة
**اختبارات النماذج**: تأكد من أن النموذج المُدرب يتجاوز الحد الأدنى للجودة قبل النشر

## 💰اعتبارات البنية التحتية

إنتاج ML له تكاليف حقيقية. يرغب القائمون على إجراء المقابلات في رؤية الوعي بالتكلفة:

### إدارة GPU

- **التدريب**: استخدم المثيلات الفورية/الاستباقية لتوفير التكاليف (مع نقاط التفتيش!)
- **العرض**: فكر في تقطير النموذج أو تكميمه لتقليل متطلبات وحدة معالجة الرسومات
- **القياس التلقائي**: يتم قياس مثيلات وحدة معالجة الرسومات بناءً على أنماط حركة المرور، وليس السعة القصوى

### استراتيجيات تحسين التكلفة

- **ضغط النموذج**: التقليم، والتكميم، وتقطير المعرفة
- **التخزين المؤقت**: تنبؤات ذاكرة التخزين المؤقت للمدخلات المتكررة
- **الخدمة المتدرجة**: استخدم نموذجًا رخيصًا لمعظم الطلبات، ونموذجًا باهظ الثمن فقط عندما تكون الثقة منخفضة
- **التحجيم الصحيح**: لا يتم عرض نموذج معلمة 175B عندما يحقق نموذج 7B المضبوط بدقة 95% من الجودة

```
Cost per prediction ≈ (GPU cost per hour) / (predictions per hour)

Example:
- GPU instance: $3/hour
- Model throughput: 1,000 predictions/second
- Cost per prediction: $3 / 3,600,000 ≈ $0.0000008
```

## 🏗️ أسئلة المقابلة الشائعة

فيما يلي بعض الأسئلة التي يجب أن تكون مستعدًا لمناقشتها:

1. "أطلعني على كيفية نشر نموذج جديد للإنتاج" - قم بوصف المسار الكامل بدءًا من التدريب وحتى نشر Canary وحتى الطرح الكامل
2. "كيف يمكنك التعامل مع نموذج مهين في الإنتاج؟" — المراقبة، وتحليل السبب الجذري، والتراجع، وإعادة التدريب
3. "ما الفرق بين إعادة تدريب النموذج وتحديث النموذج؟" - إعادة التدريب الكامل على البيانات الجديدة مقابل التعلم المتزايد/عبر الإنترنت
4. "كيف يمكنك التأكد من إمكانية تكرار نتائج تجارب تعلم الآلة؟" - التحكم في إصدار التعليمات البرمجية والبيانات والتكوين؛ بذور ثابتة النقل بالحاويات
5. "وصف النظام الأساسي المثالي لتعلم الآلة" - متجر الميزات، ومتتبع التجارب، وسجل النماذج، والبنية التحتية للخدمة، ولوحة التحكم

<Callout>عند الإجابة على أسئلة مقابلة MLOps، قم دائمًا بربط القرارات الفنية بتأثير الأعمال. "نحن نستخدم عمليات نشر Canary لأن التراجع عن النموذج السيئ يكلف X من الإيرادات المفقودة" يعد أكثر إلحاحًا من وصف الإعداد الفني وحده.
</Callout>

## 🔑 الوجبات السريعة الرئيسية

- **عمليات MLOs تعمل على سد الفجوة** بين تطوير النماذج والإنتاج — وهي مجموعة مهارات تعلم الآلة الأكثر طلبًا اليوم
- **اختر أنماط التقديم بحكمة**: دفعة مقابل التكلفة، وفي الوقت الفعلي للنضارة، ومضمنة للحافة
- **مراقبة ما بعد زمن الاستجابة**: انجراف البيانات، وانجراف المفاهيم، وتدهور النماذج هي العوامل القاتلة الصامتة
- **تتبع كل تجربة**: المعلمات والمقاييس والعناصر والبيئة
- **اختبر مسار التعلم الآلي**، وليس فقط الكود: التحقق من صحة البيانات، واختبارات الميزات، وبوابات جودة النموذج
- **فكر في التكلفة**: يؤدي ضغط النماذج والتخزين المؤقت والعرض المتدرج إلى تقليل فواتير البنية التحتية

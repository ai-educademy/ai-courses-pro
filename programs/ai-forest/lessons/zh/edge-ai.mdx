# 边缘人工智能

并非每个预测都应该传输到云端并返回。 边缘 AI 直接在设备（您的手机、浏览器、相机、汽车）上运行模型。其优势非常引人注目：零网络延迟、完全隐私（数据永远不会离开设备）、离线功能以及大幅降低服务成本。

挑战？您需要一个适合兆字节的模型，在有限的硬件上运行，并且仍然提供有用的准确性。

## 为什么选择边缘而非云？

边缘和云之间的决定不是二元的 - 大多数生产系统都使用混合方法。但了解权衡至关重要：

|因素|云推理 |边缘推理 |
|--------------------|----------------|----------------|
| **延迟** | 100-500ms（网络往返）| 5-50 毫秒（设备上）|
| **隐私** |数据发送到服务器 |数据保留在设备上 |
| **成本** |每个请求的 GPU 成本 |零边际成本|
| **离线** |需要连接 |随时随地工作 |
| **可扩展性** |服务器瓶颈 |随设备扩展 |
| **型号尺寸** |无限 |受设备内存限制 |

对于实时翻​​译、键盘预测、面部解锁或健康监控等应用，边缘不仅更可取，而且是唯一可行的选择。

## 模型压缩技术

生产模型对于边缘设备来说太大。 FP32 精度的 GPT 级模型将消耗千兆字节的内存。压缩技术使部署变得可行。

### 量化

量化将模型权重的数值精度从 32 位浮点 (FP32) 降低到更小的表示形式：

- **FP16** - 半精度。内存减少 2 倍，精度损失最小。 GPU 推理标准。
- **INT8** - 内存减少 4 倍。大多数边缘部署的最佳选择。
- **INT4** - 内存减少 8 倍。激进，但对于经过仔细校准的大型语言模型来说是可行的。

训练后量化 (PTQ) 转换已训练的模型。量化感知训练 (QAT) 在训练过程中模拟低精度，以更好地保持精度。

<FunFact>iPhone 15 Pro 上的 Apple 神经引擎以 35 TOPS（每秒万亿次运算）的速度处理 INT8 运算 - 大致相当于五年前的中档数据中心 GPU。</FunFact>

### 修剪

修剪会删除对模型输出影响最小的权重（或整个神经元）。非结构化剪枝将个体权重归零；结构化修剪会删除整个通道或注意力头，以实现硬件上的实际加速。

一个经过良好剪枝的模型可以删除 50-90% 的参数，而准确率下降不到 1%，但剪枝后的模型必须在事后进行微调才能恢复性能。

### 知识蒸馏

训练小型“学生”模型来模仿大型“教师”模型的输出。学生不仅学到了正确的标签，还学到了老师的完整概率分布 - 包括哪些错误答案“几乎是正确的”。这种软信息的传输效果出奇的好。

例如，DistilBERT 在 60% 的大小和 2 倍的速度下保留了 BERT 97% 的准确率。

## ONNX：通用格式

**开放神经网络交换 (ONNX)** 是一种与框架无关的模型格式。在 PyTorch 中训练，导出到 ONNX，在任何地方部署 - TensorFlow Lite、Core ML、ONNX 运行时或浏览器。

ONNX 运行时通过单个 API 提供跨 CPU、GPU 和 NPU 的优化推理。它自动处理算子融合、内存规划和特定于硬件的加速。

## 特定于平台的运行时

### TensorFlow Lite（移动/物联网）

适用于 Android、iOS 和微控制器的 Google 运行时。 TFLite 模型是平面缓冲区 - 小、加载速度快、无动态内存分配。解释器小于 1 MB。委托 API 将计算负载卸载到 GPU、DSP 或 NPU 硬件。

### Core ML（Apple 生态系统）

Apple 的框架自动在 CPU、GPU 和专用神经引擎之间路由计算。如果您发布具有 ML 功能的 iOS 应用程序，Core ML 是阻力最小的路径。支持模型加密，实现IP保护。

### WebAssembly + ONNX 运行时 Web

在浏览器中以接近本机的性能运行 ML 模型。 ONNX Runtime Web 将模型编译为 WebAssembly，并使用 WebGL 或 WebGPU 进行 GPU 加速。没有服务器，没有安装，没有数据离开浏览器。

使用案例：视频通话中的实时背景去除、页面内容审核以及基于浏览器的文档 OCR。

## 设备上的大型语言模型

两年前，在消费类硬件上运行法学硕士似乎是不可能的。如今，40 亿参数以下的量化模型可以在旗舰手机上轻松运行：

- **Gemma 2B/7B** (Google) - 通过 TFLite 和 MediaPipe 针对移动设备进行了优化
- **Phi-3 Mini** (Microsoft) - 3.8B 参数，对其大小有强有力的推理
- **小型 Llama-family 模型** (Meta) - 专为设备端部署而构建
- **Gemini Nano** (Google) - 通过 AICore 集成到 Android 14+

这些模型无需任何网络调用即可处理摘要、翻译、智能回复和代码完成。

## 边缘硬件加速器

现代设备包括用于神经网络推理的专用芯片：

- **Apple 神经引擎** - M 系列和 A 系列芯片中的 16 核 NPU。紧密的核心 ML 集成。
- **Qualcomm Hexagon NPU** - 为 Snapdragon 芯片上的 Android AI 提供支持。原生支持 INT4。
- **Google Tensor TPU** - Pixel 手机中的定制芯片，用于设备上的语音、翻译和照片。
- **英特尔 Movidius** - 适用于物联网相机和无人机的低功耗 VPU。

趋势很明显：现在每个主要芯片制造商都将人工智能加速视为一流的功能，而不是事后的想法。

## 现实世界的边缘人工智能应用

- **键盘预测**（GBoard、SwiftKey） - 使用个性化模型完全在设备上运行下一个单词预测
- **实时翻译**（谷歌离线翻译） - 无需连接的完整神经机器翻译
- **人脸识别** (Face ID) - Apple 的 TrueDepth 系统在神经引擎上处理 3D 人脸图
- **智能摄像头** - 零售分析、野生动物监测和边缘交通管理
- **助听器** - 设备上的噪声消除和语音增强，具有亚毫秒级延迟

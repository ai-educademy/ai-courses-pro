# ఓపెన్ సోర్స్కు సహకరించడం

ఓపెన్ సోర్స్ సహకారాలు నేర్చుకోవడానికి, విశ్వసనీయత పెంచుకోవడానికి మరియు AI సమాజంతో అనుసంధానం కావడానికి అత్యంత వేగవంతమైన మార్గం. ఈ పాఠంలో మీరు ఎలా ప్రారంభించాలో మరియు నిజంగా ప్రభావం చూపే సహకారాలు ఎలా చేయాలో తెలుసుకుంటారు.

## ఎందుకు సహకరించాలి?

Open సోర్స్కు సహకరించడం దాతృత్వం కాదు - ఇది ఒక వ్యూహాత్మక కెరీర్ నిర్ణయం.

**నేర్చుకోవడం** - ప్రొడక్షన్-క్వాలిటీ కోడ్‌ను చదవడం మరియు మార్చడం వల్ల ట్యుటోరియల్స్‌లో ఎప్పటికీ కనిపించని నమూనాలు నేర్చుకుంటారు. నిజమైన సిస్టమ్‌లు ముందంజ సందర్భాలు, పరీక్షలు మరియు స్కేల్ ను ఎలా హ్యాండిల్ చేస్తాయో తెలుస్తుంది.

**నెట్‌వర్కింగ్** - మీ PR reviewers మరియు co-సహకారులు తరచుగా collaborators, referees లేదా co-founders అవుతారు. AI ఓపెన్ సోర్స్ సమాజం చాలా సన్నిహితంగా ఉంటుంది.

**కెరీర్ ప్రభావం** - టాప్ AI కంపెనీల నియామకం మేనేజర్లు GitHub ప్రొఫైల్‌లను చురుకుగా చూస్తారు. గౌరవప్రదమైన ప్రాజెక్ట్‌లో మర్జ్ అయిన PR ఏ certification కంటే ఎక్కువ సామర్థ్యాన్ని చూపిస్తుంది.

**తిరిగి ఇవ్వడం** - మీరు దాదాపు ఖచ్చితంగా ఓపెన్ సోర్స్ టూల్స్ నుండి ప్రయోజనం పొందారు. సహకరించడం ద్వారానే ఈ ఎకోసిస్టమ్ నిలబడుతుంది.

<FunFact>
2024 GitHub సర్వే ప్రకారం, 87% AI/ML నియామకం మేనేజర్లు అభ్యర్థులను అంచనా వేసేటప్పుడు ఓపెన్ సోర్స్ సహకారాలను పరిగణనలోకి తీసుకుంటారు - ఇది సంబంధిత పని అనుభవం తర్వాత రెండవ అత్యంత విలువైన సంకేతం.
</FunFact>

## సరైన ప్రాజెక్ట్ కనుగొనడం

PyTorch లేదా TensorFlowకు సహకరించడంతో మొదలుపెట్టకండి. మీ సహకారం గుర్తించబడే మరియు విలువైనదిగా భావించబడే చోట ప్రారంభించండి.

**ఎక్కడ చూడాలి:**
- **GitHub విషయాలు** - `good-first-issue` + `machine-learning` లేదా `artificial-intelligence` బ్రౌజ్ చేయండి
- **Hugging Face** - వారి `transformers`, `datasets` మరియు `diffusers` లైబ్రరీలు సహకారులు ను చురుకుగా స్వాగతిస్తాయి
- **LangChain / LlamaIndex** - వేగంగా మారుతున్న ప్రాజెక్ట్‌లు, చాలా open ఇష్యూలు ఉంటాయి
- **చిన్న టూల్స్** - 500–5,000 స్టార్లు ఉన్న లైబ్రరీల maintainers తరచుగా responsive గా ఉంటారు మరియు సహాయాన్ని అభినందిస్తారు

**ప్రాజెక్ట్‌ను ఎలా అంచనా వేయాలి:**
1. చివరి కమిట్ తేదీ చూడండి - ఇది చురుకుగా నిర్వహించండి అవుతోందా?
2. CONTRIBUTING.md చదవండి - ఉందా?
3. Open PRలు చూడండి - వాటిని సమీక్ష చేస్తున్నారా, లేదా ignore చేస్తున్నారా?
4. ఇష్యూ రెస్పాన్స్ సార్లు చెక్ చేయండి - maintainers చురుకుగా పాల్గొనండి అవుతున్నారా?

## సహకార వర్క్‌ఫ్లో

ప్రతి సహకారం ఒకే నమూనా ను అనుసరిస్తుంది. దీన్ని ఒకసారి నేర్చుకోండి, ఎక్కడైనా సహకరించడం చేయగలరు.

### స్టెప్ 1: Fork మరియు Clone

```bash
gh repo fork owner/project --clone
cd project
git remote add upstream https://github.com/owner/project.git
```

### స్టెప్ 2: Branch సృష్టించండి

```bash
git checkout -b fix/improve-tokeniser-docs
```

వివరణాత్మక branch పేర్లు ఉపయోగించండి. `fix/`, `feat/`, లేదా `docs/` వంటి prefixes maintainersకు ఒక చూపులో ఉద్దేశ్యం అర్థం చేసుకోవడంలో సహాయపడతాయి.

### స్టెప్ 3: మీ మార్పులు చేయండి

- ప్రాజెక్ట్ యొక్క కోడింగ్ style ను ఖచ్చితంగా అనుసరించండి
- మీ మార్పులకు ముందు మరియు తర్వాత ఇప్పటికే ఉన్న పరీక్షలు రన్ చేయండి
- కొత్త functionality కోసం పరీక్షలు జోడించండి
- మార్పులు కేంద్రీకృత గా ఉంచండి - ఒక PR కి ఒక concern మాత్రమే

### స్టెప్ 4: కమిట్ మరియు పుష్

```bash
git add .
git commit -m "docs: clarify tokeniser padding ప్రవర్తన for batch inputs"
git push origin fix/improve-tokeniser-docs
```

### స్టెప్ 5: పుల్ రిక్వెస్ట్ తెరవండి

మీరు **ఏమి** మార్చారో, **ఎందుకు** మార్చారో, మరియు దాన్ని **ఎలా** పరీక్ష చేయాలో వివరించే స్పష్టమైన PR వివరణ రాయండి. ఇష్యూ నంబర్ ఉంటే దాన్ని reference చేయండి.

<ThinkAboutIt>
ఒక ఓపెన్ సోర్స్ AI టూల్ లో మీరు ఎదుర్కొన్న bug గురించి ఆలోచించండి. మీరే దాన్ని fix చేసి PR submit చేయగలిగేవారా? తరచుగా సమాధానం అవును - మరియు ఆ మొదటి సహకారం అధిగమించడానికి అత్యంత కష్టమైన మానసిక అడ్డంకి.
</ThinkAboutIt>

## గొప్ప PRలు మరియు కమిట్‌లు రాయడం

మీ PR మీ ప్రొఫెషనల్ విజిటింగ్ కార్డ్. దాన్ని అద్భుతంగా తయారు చేయండి.

**Commit సందేశాలు** - Conventional కమిట్‌లు ఉపయోగించండి: `feat:`, `fix:`, `docs:`, `test:`, `refactor:`. Subject ను 72 అక్షరాలు లోపు ఉంచండి. సంక్లిష్ట మార్పులకు body జోడించండి.

**PR వివరణలో ఇవి ఉండాలి:**
- మార్పు యొక్క ఒక-లైన్ సారాంశం
- సందర్భం: ఇది ఏ సమస్యను పరిష్కరిస్తుంది?
- మార్పును ఎలా పరీక్ష చేయాలి
- సంబంధితమైతే స్క్రీన్‌షాట్‌లు లేదా అవుట్‌పుట్ samples
- మీరు తీసుకున్న ట్రేడ్‌ఆఫ్‌లు లేదా నిర్ణయాలు

**తప్పనిసరిగా నివారించాల్సిన సాధారణ తప్పులు:**
- ఒక PR లో సంబంధం లేని మార్పులు కలపడం
- ప్రాజెక్ట్ యొక్క linting మరియు formatting నియమాలను పట్టించుకోకపోవడం
- సమీక్ష ఫీడ్‌బ్యాక్ కు త్వరగా స్పందించకపోవడం
- సమీక్ష సమయంలో హెచ్చరిక లేకుండా force-పుష్ చేయడం

## కోడ్ కంటే మించి

అత్యంత విలువైన సహకారాలలో కొన్నింటిలో ఒక్క లైన్ కోడ్ కూడా ఉండదు.

**డాక్యుమెంటేషన్** - Typos సరిచేయండి, ఉదాహరణలు మెరుగుపరచండి, docs అనువదించండి. చాలా ప్రాజెక్ట్‌లకు డాక్యుమెంటేషన్ సహాయం చాలా అవసరం మరియు ఇది ఒక అద్భుతమైన ప్రవేశ మార్గం.

**Issue triage** - Bugs reproduce చేయండి, సందర్భం జోడించండి, ఇష్యూలు లేబుల్ చేయండి. ప్రాసెస్ చేయని ఇష్యూలు లో మునిగిపోతున్న maintainers కు ఇది చాలా విలువైనది.

**Translations** - AI టూల్స్ ను ప్రపంచవ్యాప్తంగా అందుబాటులోకి తీసుకురావడంలో సహాయపడండి. Hugging Face వంటి ప్రాజెక్ట్‌లు translators కోసం చురుకుగా వెతుకుతాయి.

**సమూహం మద్దతు** - Discord, Stack Overflow, లేదా GitHub చర్చలు లో ప్రశ్నలకు సమాధానాలు ఇవ్వండి. ఇతరులకు సహాయం చేయడం కూడా ఒక సహకారమే.

<Callout>
**ప్రో టిప్:** డాక్యుమెంటేషన్ PRలకు అన్ని సహకార రకాలలో అత్యధిక acceptance రేట్ ఉంటుంది. Codebase నేర్చుకోవడానికి, maintainers విశ్వాసం సంపాదించడానికి, మరియు తర్వాత పెద్ద కోడ్ సహకారాలు కు బాట వేసుకోవడానికి ఇవి అత్యుత్తమ మార్గం.

## ముఖ్య అంశాలు

- ఓపెన్ సోర్స్ సహకారాలు నేర్చుకోవడం, నెట్‌వర్కింగ్ మరియు కెరీర్ వృద్ధిని వేగవంతం చేస్తాయి
- చిన్న, చురుకుగా maintained ప్రాజెక్ట్‌లతో ప్రారంభించండి - mega-repos తో కాదు
- Fork → branch → PR వర్క్‌ఫ్లో లో నైపుణ్యం సాధించి ప్రతిచోటా ఉపయోగించండి
- వివరణాత్మక కమిట్ సందేశాలు తో స్పష్టమైన, కేంద్రీకృత PRలు రాయండి
- డాక్యుమెంటేషన్ మరియు ఇష్యూ triage కోడ్ అవసరం లేని విలువైన సహకారాలు
- పరిమాణం కంటే స్థిరత్వం ముఖ్యం - క్రమం తప్పకుండా చేసే చిన్న సహకారాలు compound అవుతాయి

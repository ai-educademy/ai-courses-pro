# AI インフラストラクチャ

AI のあらゆる進歩の背後には、巨大なインフラストラクチャのストーリーがあります。最先端モデル のトレーニングは、計算、データ、エネルギー、エンジニアリングを含めると数億ドルかかることがあります。最新の AI を強化するハードウェア、クラウド プラットフォーム、最適化手法を理解することは、大規模な構築を行う人にとって不可欠です。

## AI において GPU が CPU に勝る理由

CPU はシーケンシャル タスク用に最適化されており、いくつかの強力なコアが複雑なロジックを処理します。 GPU は並列処理、つまり数千のシンプルなコアが異なるデータに対して同じ操作を同時に実行できるように最適化されています。

ニューラル ネットワークのトレーニングは、基本的には大規模な行列の乗算です。大規模なモデルの 1 つのトレーニング ステップには、数十億の要素を含む行列の乗算が含まれます。 CPUはこれらを順番に処理します。 GPU は数千の要素を並行して処理します。

NVIDIA H100 GPU は、約 **4,000 TFLOPS** の FP8 コンピューティングを実現します。ハイエンド サーバーの CPU は、おそらく 2 TFLOPS を管理します。深層学習の恥ずかしいほどの並列ワークロードでは、GPU が 3 桁も優れています。

## NVIDIA の優位性

NVIDIA は AI アクセラレータ市場の約 80 ～ 90% を支配しています。彼らの堀は単なるハードウェアではなく、**CUDA エコシステム**です。ほぼすべての ML フレームワーク (PyTorch、TensorFlow、JAX) は CUDA 上に構築されています。競合他社に切り替えるということは、低レベルのカーネルを書き直し、潜在的な非互換性を受け入れることを意味します。

### GPU ラインナップ

| GPU |メモリ | FP8 パフォーマンス |使用例 |
|-----|----------|------|----------|
| **A100** | 80 GB HBM2e | 624 TFLOPS |現在のデータセンターの主力 |
| **H100** | 80 GB HBM3 | 3,958 TFLOPS |フロンティアモデルトレーニング |
| **H200** | 141 GB HBM3e | 3,958 TFLOPS |メモリバウンド LLM 推論 |
| **B200** | 192 GB HBM3e | 9,000 TFLOPS |次世代のトレーニングと推論 |

H100 から B200 へのジャンプは 2.3 倍のパフォーマンスの向上を表します。しかし、本当のボトルネックは多くの場合、生のコンピューティングではなく **メモリ帯域幅**です。 H200 の 141 GB の HBM3e メモリは、KV キャッシュがメモリ使用量の大半を占める LLM 推論を特にターゲットにしています。

<FunFact>1 つの NVIDIA B200 GPU の価格は約 30,000 ドルから 40,000 ドルです。これらの GPU を 8 基搭載した DGX B200 サーバーの価格は 30 万ドルを超えます。伝えられるところによると、Meta はラマのトレーニング用に 350,000 個の H100 GPU を注文しました。これは 100 億ドルを超えるハードウェア投資です。</FunFact>

## Google TPU

Google の Tensor Processing Unit は、行列演算専用に設計されたカスタム ASIC です。グラフィックスと計算を処理する GPU とは異なり、TPU はニューラル ネットワーク専用に構築されています。

- **TPU v5p** - Google の最新トレーニング チップ。高速インターコネクト経由で接続された最大 8,960 チップのポッドで利用可能
- **TPU v5e** - 推論ワークロード向けにコストが最適化されています
- 主な利点: JAX および XLA コンパイラーとの緊密な統合
- キーの制限: Google Cloud 経由でのみ利用可能 - オンプレミスのオプションなし

Google はすべての基礎モデル (Gemini、PaLM) を TPU 上でトレーニングし、最前線で NVIDIA と競争できることを証明しています。

## AMD と競合他社

AMD の **MI300X** は、最も信頼できる NVIDIA の代替品です。
- 192 GB HBM3 メモリ (H100 以上)
- 強力な ROCm ソフトウェア スタック (改善はされていますが、CUDA にはまだ及ばない)
- 大幅な価格上の利点 - 同等の NVIDIA よりも約 30 ～ 40% 安い
- ネイティブ ROCm サポート (PyTorch、JAX) を備えた ML フレームワークのエコシステムの成長

Microsoft、Meta、Oracle はすべて、推論ワークロードに MI300X を採用しています。メモリの利点は、KV キャッシュが主なボトルネックとなっている大規模な言語モデルにとって特に魅力的です。

Intel の **Gaudi 3** アクセラレータも加わり、企業の価格対パフォーマンス比を重視した競争力のあるトレーニング パフォーマンスを提供します。 AI アクセラレータ市場は、ついにマルチベンダーのエコシステムになりつつあります。

## クラウドプロバイダーの比較

ハイパースケーラー以外の企業には、フロンティア AI 用に独自の GPU クラスターを構築する余裕はありません。クラウドの戦いは熾烈を極めます。

|プラットフォーム |主要な製品 |強さ |
|----------|---------------|----------|
| **AWS SageMaker** |エンドツーエンドの ML プラットフォーム |最も幅広い GPU セレクション、Inferentia カスタム チップ |
| **GCP Vertex AI** | TPU アクセスを使用したマネージド ML | TPU の可用性、BigQuery の緊密な統合 |
| **Azure ML** |エンタープライズ ML プラットフォーム | OpenAI パートナーシップ、エンタープライズ コンプライアンス |
| **ラムダ研究所** | AI 用 GPU クラウド |シンプル、競争力のある H100 価格設定 |
| **コアウィーブ** | GPUネイティブクラウド | AI 専用、NVIDIA パートナーシップ |

**スポット インスタンス** により、トレーニング コストを 60 ～ 90% 削減できます。トレードオフ: トレーニング作業はいつでも中断される可能性があります。 **PyTorch Lightning** や **DeepSpeed** などのフレームワークは、プリエンプション後にトレーニングをシームレスに再開するためのチェックポイント設定をサポートしています。

## GPU 不足と地政学

AI インフラストラクチャは現在、地政学的な問題となっています。

- **TSMC** (台湾) は、NVIDIA、AMD、Apple、Google 向けのほぼすべての高度な AI チップを製造しています。 TSMCへの混乱は世界全体でAIの進歩を止めることになるだろう。
- **米国の輸出規制**により、中国による先進チップへのアクセスが制限されています（A100、H100は禁止）。中国は国内の代替品（Huawei Ascend、Biren）に多額の投資を行っています。
- **NVIDIA の中国固有チップ** (H20) は、市場へのアクセスを維持しながら輸出規則に準拠するためにパフォーマンスが低下しています。
- **CHIPS 法** (米国) および EU および日本の同様のプログラムは、半導体製造の多様化を目的としています。

<ThinkAboutIt>先進的な AI チップはほぼ独占的に台湾で製造されています。地政学的な緊張によってこのサプライチェーンが混乱した場合、世界中の AI 開発にどのような影響が及ぶでしょうか?どの国や企業が最も脆弱ですか?</ThinkAboutIt>

## カスタム シリコン スタートアップ

いくつかのスタートアップが GPU パラダイムに完全に挑戦しています。

- **Groq** - LPU (言語処理ユニット) アーキテクチャは、決定論的で超低遅延の推論を実現します。バッチ処理は必要ありません。
- **Cerebras** - ウェーハスケールのチップ (ディナープレートのサイズ) により、トレーニング時のメモリ帯域幅のボトルネックが解消されます。
- **SambaNova** - エンタープライズ AI 向けに最適化された再構成可能なデータフロー アーキテクチャ。
- **Graphcore** (SoftBank が買収) - グラフ構造のワークロード向けの大規模なオンチップ SRAM を備えた IPU アーキテクチャ。

これらは現在の NVIDIA の代替品ではありません。しかし、これらは、AI ワークロードがトランスフォーマーを超えて多様化するにつれて、市場を再形成する可能性がある真のアーキテクチャ革新を表しています。

## 推論の最適化

トレーニングは見出しで取り上げられますが、お金がかかるのは推論です。推論コストを削減する手法:

- **動的バッチ処理** - 受信リクエストをグループ化して GPU 使用率を最大化します。
- **KV キャッシュ管理** - vLLM の PagedAttendance はメモリの断片化を回避します
- **投機的デコード** - 小規模モデルを使用してトークンをドラフトし、大規模モデルで並行して検証します (2 ～ 3 倍の高速化)
- **連続バッチ処理** - 現在のすべてのリクエストが完了するのを待たずに、新しいリクエストを処理します。
- **モデルの並列処理** - レイテンシーに敏感なサービスを提供するために、大規模なモデルを複数の GPU に分割します

## AI インフラストラクチャの総コスト

インフラストラクチャのコストは GPU のレンタルをはるかに超えています。全体像には次のものが含まれます。

- **コンピューティング** - トレーニングと推論のための GPU 時間 (通常、総コストの 60 ～ 70%)
- **ストレージ** - トレーニング データ、チェックポイント、モデル アーティファクト、およびログ
- **ネットワーク** - GPU、リージョン間、およびエンドユーザー間のデータ転送
- **エンジニアリング** - スタックを操作する ML エンジニア、プラットフォーム エンジニア、DevOps スタッフ
- **電力** - 1 台の H100 サーバーは 10 kW 以上を消費します。データセンターの電力に対する制約が増大

Meta のような企業は、AI インフラストラクチャに年間 100 億ドル以上を費やしています。スタートアップの場合、フロンティア モデルのトレーニングを 1 回実行するためのクラウド コストは 100 万ドルを超える場合があります。このコストスタックを理解し、最適化することがコアコンピテンシーです。

<ThinkAboutIt>あなたの会社は、70B パラメータ モデルを 10,000 人の同時ユーザーに 1 秒未満の遅延で提供する必要があります。インフラストラクチャの計画を立てます: GPU の数、どのフレームワークを提供するか、どのような最適化手法を使用するか、月々のクラウド料金はいくらになるでしょうか?</ThinkAboutIt>

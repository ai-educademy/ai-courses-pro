# エッジAI

すべての予測がクラウドに送られて戻ってくる必要はありません。 Edge AI は、携帯電話、ブラウザ、カメラ、車などのデバイス上でモデルを直接実行します。ネットワーク遅延ゼロ、完全なプライバシー (データがデバイスから流出することはありません)、オフライン機能、およびサービス コストの大幅な削減など、魅力的なメリットがあります。

挑戦は？メガバイト単位に収まり、限られたハードウェアで実行され、有用な精度を提供できるモデルが必要です。

## クラウド上でエッジを使用する理由

エッジとクラウドのどちらを選択するかは二者択一ではありません。ほとんどの実稼働システムはハイブリッド アプローチを使用しています。ただし、トレードオフを理解することが重要です。

|係数 |クラウド推論 |エッジ推論 |
|------|----------------|----------------|
| **レイテンシ** | 100 ～ 500 ミリ秒 (ネットワーク往復) | 5 ～ 50 ミリ秒 (デバイス上) |
| **プライバシー** |サーバーに送信されるデータ |データはデバイス上に残ります |
| **コスト** |リクエストごとの GPU コスト |限界費用ゼロ |
| **オフライン** |接続が必要です |どこでも使える |
| **スケーラビリティ** |サーバーのボトルネック |デバイス付きスケール |
| **モデルサイズ** |無制限 |デバイスのメモリによる制約 |

リアルタイム翻訳、キーボード予測、顔認証ロック解除、ヘルスモニタリングなどのアプリケーションでは、エッジが望ましいだけでなく、唯一の実行可能なオプションです。

## モデル圧縮手法

実稼働モデルはエッジ デバイスには大きすぎます。 FP32 精度の GPT クラスのモデルは、ギガバイトのメモリを消費します。圧縮技術により展開が可能になります。

### 量子化

量子化により、モデルの重みの数値精度が 32 ビット浮動小数点 (FP32) からより小さな表現に低下します。

- **FP16** - 半精度。メモリを 2 倍に削減し、精度の低下を最小限に抑えます。 GPU 推論の標準。
- **INT8** - メモリを 4 倍削減します。ほとんどのエッジ展開のスイート スポット。
- **INT4** - メモリを 8 倍削減します。積極的ですが、慎重に調整すれば大規模な言語モデルでも実行可能です。

トレーニング後の量子化 (PTQ) は、トレーニング済みのモデルを変換します。量子化対応トレーニング (QAT) は、トレーニング中に低精度をシミュレートし、精度の保持を向上します。

<FunFact>iPhone 15 Pro の Apple のニューラル エンジンは、INT8 演算を 35 TOPS (1 秒あたり 1 兆回の演算) で処理します。これは、わずか 5 年前のミッドレンジ データセンター GPU とほぼ同等です。</FunFact>

### 剪定

枝刈りでは、モデルの出力に最も寄与しない重み (またはニューロン全体) が削除されます。非構造化枝刈りにより、個々の重みがゼロになります。構造化されたプルーニングにより、チャネル全体またはアテンションヘッドが削除され、ハードウェアの実際の速度が向上します。

適切に枝刈りされたモデルでは、精度の低下が 1% 未満でパラメータの 50 ～ 90% を削除できますが、パフォーマンスを回復するには、枝刈りされたモデルを後で微調整する必要があります。

### 知識の蒸留

小規模の「生徒」モデルをトレーニングして、大規模な「教師」モデルの出力を模倣します。生徒は正しいラベルだけでなく、どの間違った答えが「ほぼ正しい」のかを含む、教師の完全な確率分布を学習します。このソフトな情報は驚くほどうまく伝達されます。

たとえば、DistilBERT は、60% のサイズと 2 倍の速度で BERT の 97% の精度を維持します。

## ONNX: ユニバーサルフォーマット

**Open Neural Network Exchange (ONNX)** は、フレームワークに依存しないモデル形式です。 PyTorch でトレーニングし、ONNX にエクスポートし、TensorFlow Lite、Core ML、ONNX ランタイム、ブラウザなどのどこにでもデプロイします。

ONNX ランタイムは、単一の API を使用して、CPU、GPU、NPU 全体で最適化された推論を提供します。オペレータ フュージョン、メモリ プランニング、ハードウェア固有のアクセラレーションを自動的に処理します。

## プラットフォーム固有のランタイム

### TensorFlow Lite (モバイル / IoT)

Android、iOS、マイクロコントローラー用の Google ランタイム。 TFLite モデルはフラット バッファーであり、小さく、読み込みが速く、動的メモリ割り当てはありません。インタプリタは 1 MB 未満です。デリゲート API は、計算を GPU、DSP、または NPU ハードウェアにオフロードします。

### Core ML (Apple エコシステム)

Apple のフレームワークは、CPU、GPU、専用のニューラル エンジンにわたって計算を自動的にルーティングします。 ML 機能を備えた iOS アプリを出荷する場合、Core ML は最も抵抗の少ない方法です。 IP 保護のためのモデル暗号化をサポートします。

### WebAssembly + ONNX ランタイム Web

ネイティブに近いパフォーマンスでブラウザーで ML モデルを実行します。 ONNX ランタイム Web はモデルを WebAssembly にコンパイルし、GPU アクセラレーションに WebGL または WebGPU を使用します。サーバーもインストールも、ブラウザからデータが送信されることもありません。

使用例: ビデオ通話でのリアルタイムの背景除去、ページ上のコンテンツのモデレーション、ブラウザベースのドキュメント OCR。

## オンデバイスの大規模言語モデル

2 年前には、消費者向けハードウェアで LLM を実行することは不可能だと思われていました。現在、40 億パラメータの下で量子化されたモデルは、主力携帯電話で快適に動作します。

- **Gemma 2B/7B** (Google) - TFLite および MediaPipe 経由でモバイル用に最適化
- **Phi-3 Mini** (Microsoft) - 38 億のパラメータ、そのサイズの強力な理由
- **小型 Llama-family models** (Meta) - オンデバイス展開向けに設計
- **Gemini Nano** (Google) - AICore 経由で Android 14 以降に統合

これらのモデルは、ネットワーク呼び出しを行わずに要約、翻訳、スマート リプライ、コード補完を処理します。

<ThinkAboutIt>オンデバイス LLM により、プライベート メッセージ、健康データ、閲覧履歴が携帯電話から離れることがなくなります。しかし、それは安全監視の可視性が低下することも意味します。デバイスメーカーはプライバシーとコンテンツの安全性のバランスをどのようにとるべきですか?</ThinkAboutIt>

## エッジのハードウェア アクセラレータ

最新のデバイスには、ニューラル ネットワーク推論用の専用シリコンが含まれています。

- **Apple Neural Engine** - M シリーズおよび A シリーズ チップの 16 コア NPU。 Core ML の緊密な統合。
- **Qualcomm Hexagon NPU** - Snapdragon チップ上の Android AI を強化します。 INT4をネイティブにサポートします。
- **Google Tensor TPU** - デバイス上での音声、翻訳、写真用の Pixel スマートフォンのカスタム チップ。
- **Intel Movidius** - IoT カメラおよびドローン用の低電力 VPU。

傾向は明らかです。現在、どの大手チップメーカーも AI アクセラレーションを後付けの機能ではなく、第一級の機能として扱っています。

## 現実世界のエッジ AI アプリケーション

- **キーボード予測** (GBoard、SwiftKey) - 次の単語予測は、パーソナライズされたモデルを使用して完全にデバイス上で実行されます
- **リアルタイム翻訳** (Google 翻訳オフライン) - 接続なしの完全なニューラル機械翻訳
- **顔認識** (Face ID) - Apple の TrueDepth システムは、ニューラル エンジンで 3D 顔マップを処理します。
- **スマート カメラ** - 小売分析、野生生物の監視、エッジでの交通管理
- **補聴器** - オンデバイスのノイズ キャンセルとミリ秒未満の遅延による音声強調

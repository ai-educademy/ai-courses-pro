# ओपन-सोर्स में योगदान

ओपन-सोर्स में योगदान सीखने, विश्वसनीयता बनाने और AI समुदाय से जुड़ने का सबसे तेज़ तरीका है। इस लेसन में हम आपको बताएंगे कि शुरुआत कैसे करें और ऐसे योगदान कैसे दें जो वाकई मायने रखते हैं।

## योगदान क्यों करें?

ओपेन स्रोत में योगदान कोई दान नहीं है - यह एक स्मार्ट करियर मूव है।

**सीखना** - प्रोडक्शन-क्वालिटी कोड पढ़ना और उसमें बदलाव करना आपको ऐसे पैटर्न सिखाता है जो ट्यूटोरियल में कभी नहीं मिलते। आप सीखते हैं कि असली सिस्टम एज मामले, परीक्षण और स्केल को कैसे हैंडल करते हैं।

**नेटवर्किंग** - आपके PR समीक्षक और co-योगदानकर्ता अक्सर सहयोगी, रेफ़रर, या यहाँ तक कि co-संस्थापक बन जाते हैं। AI ओपन-सोर्स समुदाय बेहद करीबी है।

**करियर पर असर** - टॉप AI कंपनियों के भर्ती मैनेजर GitHub प्रोफ़ाइल को सक्रिय रूप से देखते हैं। किसी अच्छे प्रोजेक्ट में मेरगेद PR किसी केरटिफ़िकशन से कहीं ज़्यादा योग्यता दर्शाता है।

**वापस देना** - आपने लगभग निश्चित रूप से ओपन-सोर्स टूल्स का फ़ायदा उठाया है। योगदान ही इस इकोसिस्टम को टिकाए रखता है।

<FunFact>
2024 की एक GitHub सर्वे में पाया गया कि 87% AI/ML भर्ती मैनेजर उम्मीदवारों का मूल्यांकन करते समय ओपन-सोर्स योगदान को ध्यान में रखते हैं - यह प्रासंगिक काम अनुभव के बाद दूसरा सबसे महत्वपूर्ण सिग्नल है।
</FunFact>

## सही प्रोजेक्ट कैसे खोजें

PyTorch या TensorFlow में योगदान से शुरुआत न करें। वहाँ से शुरू करें जहाँ आपका योगदान दिखेगा और सराहा जाएगा।

**कहाँ देखें:**
- **GitHub विषय** - `good-first-issue` + `machine-learning` या `artificial-intelligence` ब्राउज़ करें
- **Hugging Face** - उनकी `transformers`, `datasets`, और `diffusers` लाइब्रेरीज़ योगदानकर्ता का स्वागत करती हैं
- **LangChain / LlamaIndex** - तेज़ी से एजे प्रोजेक्ट जिnameं कई ओपेन मुद्दे हैं
- **छोटे टूल्स** - 500-5,000 स्टार वाली लाइब्रेरीज़ के मेंटेनर अक्सर उत्तरदायी होते हैं और मदद की कद्र करते हैं

**प्रोजेक्ट का मूल्यांकन कैसे करें:**
1. आखिरी कमिट की तारीख़ देखें - क्या यह सक्रिय रूप से बनाएेद है?
2. CONTRIBUTING.md पढ़ें - क्या यह मौजूद है?
3. खुले PR देखें - क्या उनकी समीक्षा हो रही है या उन्हें अनदेखा किया जा रहा है?
4. इसुए प्रतिक्रिया समय चेक करें - क्या मेंटेनर जुड़ें करते हैं?

## योगदान का वर्k़्लो

हर योगदान एक ही पैटर्न फ़ॉलो करता है। इसे एक बार सीख लो, फिर कहीं भी योगदान कर सकते हो।

### स्टेप 1: फ़ोर्क और कलोने करें

```bash
gh repo fork owner/project --clone
cd project
git remote add upstream https://github.com/owner/project.git
```

### स्टेप 2: ब्रांच बनाएँ

```bash
git checkout -b fix/improve-tokeniser-docs
```

वर्णनात्मक ब्रांच नाम इस्तेमाल करें। `fix/`, `feat/`, या `docs/` जैसे प्रीफ़िक्स मेंटेनर को एक नज़र में इरादा समझने में मदद करते हैं।

### स्टेप 3: अपने बदलाव करें

- प्रोजेक्ट की Coding शैली को बिल्कुल फ़ॉलो करें
- अपने बदलावों से पहले और बाद में मौजूदा टेस्ट रन करें
- नई कार्यक्षमता के लिए टेस्ट जोड़ें
- बदलाव केंद्रित रखें - एक PR में एक ही कोनकेरन

### स्टेप 4: कमिट और पुश करें

```bash
git add .
git commit -m "docs: clarify tokeniser padding behaviour for batch inputs"
git push origin fix/improve-tokeniser-docs
```

### स्टेप 5: पुलल रिक्वेस्ट खोलें

एक स्पष्ट PR description लिखें जो बताए कि आपने **क्या** बदला, **क्यों** बदला, और इसे **कैसे** टेस्ट करें। अगर कोई इसुए नंबर है तो उसका रेफ़ेरेनके दें।

<ThinkAboutIt>
किसी ओपन-सोर्स AI टूल में आपने जो बुग देखा है, उसके बारे में सोचें। क्या आप उसे ख़ुद फ़िक्स करके PR सबमिट कर सकते थे? अक्सर जवाब हाँ होता है - और वह पहला योगदान सबसे बड़ी मानसिक बाधा होती है।
</ThinkAboutIt>

## बेहतरीन PRs और कमिटस कैसे लिखें

आपका PR आपका प्रोफ़ेशनल विज़िटिंग कार्ड है। इसे बेहतरीन बनाएँ।

**कमिट संदेश** - कन्वेंशनल कमिट इस्तेमाल करें: `feat:`, `fix:`, `docs:`, `test:`, `refactor:`। विषय 72 अक्षर से कम रखें। जटिल बदलावों के लिए मुख्य भाग जोड़ें।

**PR description में शामिल करें:**
- बदलाव का एक-लाइन सारांश
- संदर्भ: यह कौन सी समस्या हल करता है?
- बदलाव को कैसे टेस्ट करें
- अगर प्रासंगिक हो तो सकरीनशोटस या आउटपुट सैंपलस
- आपने जो भी टरदे-ओफ़फ़स या फ़ैसले लिए

**आम गलतियों से बचें:**
- एक PR में असंबंधित बदलाव मिलाना
- प्रोजेक्ट के लिंटिंग और फ़ॉर्मैटिंग नियमों को अनदेखा करना
- समीक्षा फ़ीडबैक का जवाब देने में देरी करना
- समीक्षा के दौरान बिना चेतावनी फ़ोर्के-पुश करना

## कोड से परे

कुछ सबसे मूल्यवान योगदानों में एक भी लाइन कोड नहीं होती।

**दस्तावेज़ीकरण** - टयपोस OK करें, उदाहरण बेहतर बनाएँ, दस्तावेज़ का अनुवाद करें। कई प्रोजेक्ट को दस्तावेज़ीकरण मदद की सख़्त ज़रूरत है और यह शुरुआत का बेहतरीन ज़रिया है।

**इसुए टरिअगे** - बुगस रेबनाने करें, संदर्भ जोड़ें, मुद्दे को लबेल करें। यह उनपरोकेसेद मुद्दे में डूबे मेंटेनर के लिए बेहद क़ीमती है।

**अनुवाद** - AI टूल्स को वैश्विक स्तर पर सुलभ बनाने में मदद करें। Hugging Face जैसे प्रोजेक्ट अनुवादकों की तलाश में रहते हैं।

**समुदाय सपोर्ट** - Discord, Stack Overflow, या GitHub discussionस पर सवालों के जवाब दें। दूसरों की मदद करना भी एक योगदान है।

<Callout>
**प्रो टिप:** दस्तावेज़ीकरण PRs की स्वीकृति दर सभी योगदान प्रकारों में सबसे ज़्यादा होती है। ये कोदेबसे सीखने, मेंटेनर का विश्वास जीतने, और बाद में बड़े कोड योगदान की नींव रखने का सबसे बढ़िया तरीका है।
</Callout>

## पब्लिक प्रोफ़ाइल बनाना

लगातार योगदान एक शक्तिशाली प्रोफ़ेशनल एसेट में बदल जाता है।

**व्यावहारिक कदम:**
1. अपने बेहतरीन योगदानों को GitHub प्रोफ़ाइल पर पिन करें
2. हर योगदान से सीखी गई बातों पर छोटे ब्लॉग पोसटस लिखें
3. प्रोजेक्ट चर्चाओं में हिस्सा लें - सोच-समझकर की गई टिप्पणियाँ ध्यान खींचती हैं
4. अपने प्रोजेक्ट से जुड़ी वर्चुअल बैठकों या सम्मेलनों में भाग लें
5. ओपन-सोर्स काम को अपने CV में मेरगेद PRs के लिंक के साथ जोड़ें

## मुख्य बातें

- ओपन-सोर्स योगदान सीखने, नेटवर्किंग और करियर ग्रोथ को तेज़ करता है
- छोटे, सक्रिय रूप से बनाएेद प्रोजेक्ट से शुरू करें - मेग-रेपोस से नहीं
- फ़ोर्क → ब्रांच → PR वर्कफ़्लो में महारत हासिल करें और इसे हर जगह इस्तेमाल करें
- स्पष्ट, केंद्रित PRs लिखें जिnameं देसकरिपटिवे कमिट संदेश हों
- दस्तावेज़ीकरण और इसुए टरिअगे मूल्यवान योगदान हैं जिnameं कोड की ज़रूरत नहीं
- सकले से ज़्यादा संगति मायने रखती है - नियमित छोटे योगदान कोमपोउनद होते हैं

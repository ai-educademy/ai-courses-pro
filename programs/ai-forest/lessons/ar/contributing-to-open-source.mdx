# المساهمة في المصدر المفتوح

تعد المساهمات مفتوحة المصدر أسرع طريقة للتعلم وبناء المصداقية والتواصل مع مجتمع الذكاء الاصطناعي. يوضح لك هذا الدرس بالضبط كيفية البدء وتقديم المساهمات المهمة.

## لماذا تساهم؟

المساهمة في المصادر المفتوحة ليست عملاً خيريًا، بل هي خطوة مهنية استراتيجية.

**التعلم** - تعلمك قراءة كود جودة الإنتاج وتعديله أنماطًا لا تغطيها البرامج التعليمية أبدًا. ستتعرف على كيفية تعامل الأنظمة الحقيقية مع حالات الحافة والاختبار والقياس.

**الشبكات** - غالبًا ما يصبح مراجعو العلاقات العامة والمساهمون المشاركون متعاونين أو حكامًا أو حتى مؤسسين مشاركين. مجتمع الذكاء الاصطناعي مفتوح المصدر متماسك بشكل ملحوظ.

**التأثير الوظيفي** - يطلع مديرو التوظيف في أفضل شركات الذكاء الاصطناعي بشكل نشط على الملفات الشخصية على GitHub. إن العلاقات العامة المدمجة لمشروع محترم تشير إلى الكفاءة أكثر بكثير من مجرد شهادة.

**رد الجميل** - من المؤكد أنك استفدت من الأدوات مفتوحة المصدر. المساهمة هي الطريقة التي يحافظ بها النظام البيئي على نفسه.

<FunFact>وجد استطلاع GitHub لعام 2024 أن 87% من مديري التوظيف في الذكاء الاصطناعي/التعلم الآلي يأخذون في الاعتبار المساهمات مفتوحة المصدر عند تقييم المرشحين، مما يجعلها الإشارة الثانية الأكثر قيمة بعد خبرة العمل ذات الصلة.
</FunFact>

## العثور على المشروع المناسب

لا تبدأ بالمساهمة في PyTorch أو TensorFlow. ابدأ حيث سيتم ملاحظة مساهمتك وتقديرها.

**أين تبحث:**
- **موضوعات GitHub** - تصفح `good-first-issue` + `machine-learning` أو `artificial-intelligence`
- **معانقة الوجه** - ترحب مكتباتهم `transformers` و`datasets` و`diffusers` بالمساهمين بشكل نشط
- **LangChain / LlamaIndex** - مشاريع سريعة الحركة مع العديد من المشكلات المفتوحة
- **أدوات أصغر** - المكتبات التي تضم ما بين 500 إلى 5000 نجم غالبًا ما يكون بها مشرفون مستجيبون وممتنون للمساعدة

**كيفية تقييم المشروع:**
1. تحقق من تاريخ الالتزام الأخير - هل تم الاحتفاظ به بشكل نشط؟
2. اقرأ CONTRIBUTING.md - هل يوجد واحد؟
3. انظر إلى العلاقات العامة المفتوحة - هل تتم مراجعتها أم يتم تجاهلها؟
4. تحقق من أوقات الاستجابة للمشكلة - هل يشارك المشرفون؟

## سير عمل المساهمة

كل مساهمة تتبع نفس النمط. أتقن هذا مرة واحدة ويمكنك المساهمة في أي مكان.

### الخطوة 1: الشوكة والاستنساخ

```bash
gh repo fork owner/project --clone
cd project
git remote add upstream https://github.com/owner/project.git
```

### الخطوة الثانية: إنشاء فرع

```bash
git checkout -b fix/improve-tokeniser-docs
```

استخدم أسماء الفروع الوصفية. البادئات مثل `fix/` أو `feat/` أو `docs/` تساعد المشرفين على فهم النية في لمحة.

### الخطوة 3: قم بإجراء التغييرات

- اتبع أسلوب ترميز المشروع تمامًا
- تشغيل الاختبارات الموجودة قبل وبعد التغييرات
- إضافة اختبارات للوظائف الجديدة
- حافظ على تركيز التغييرات - اهتمام واحد لكل علاقات عامة

### الخطوة 4: الالتزام والدفع

```bash
git add .
git commit -m "docs: clarify tokeniser padding behaviour for batch inputs"
git push origin fix/improve-tokeniser-docs
```

### الخطوة 5: افتح طلب السحب

اكتب وصفًا واضحًا للعلاقات العامة يشرح **ما** قمت بتغييره، و**لماذا** قمت بتغييره، و**كيف**** لاختباره. مع الإشارة إلى رقم الإصدار إن وجد.

<ThinkAboutIt>فكر في الخطأ الذي واجهته في أداة الذكاء الاصطناعي مفتوحة المصدر. هل كان بإمكانك إصلاح الأمر بنفسك وتقديم العلاقات العامة؟ غالبًا ما تكون الإجابة بنعم - وهذه المساهمة الأولى هي أصعب حاجز عقلي يجب التغلب عليه.
</ThinkAboutIt>

## كتابة رسائل عامة والتزامات رائعة

العلاقات العامة الخاصة بك هي بطاقة الاتصال المهنية الخاصة بك. اجعلها تحسب.

**رسائل الالتزام** - استخدم الالتزامات التقليدية: `feat:`، `fix:`، `docs:`، `test:`، `refactor:`. اجعل الموضوع أقل من 72 حرفًا. أضف نصًا للتغييرات المعقدة.

**يجب أن تتضمن أوصاف العلاقات العامة ما يلي:**
- ملخص من سطر واحد للتغيير
- السياق: ما هي المشكلة التي يحلها هذا؟
- كيفية اختبار التغيير
- لقطات الشاشة أو عينات الإخراج إذا كانت ذات صلة
- أي مقايضات أو قرارات قمت بها

**أخطاء شائعة يجب تجنبها:**
- خلط التغييرات غير المرتبطة في علاقات عامة واحدة
- تجاهل قواعد الفحص والتنسيق الخاصة بالمشروع
- عدم الاستجابة لملاحظات المراجعة على الفور
- الدفع بالقوة دون سابق إنذار أثناء المراجعة

## ما وراء الكود

تتضمن بعض المساهمات الأكثر قيمة رمزًا صفريًا.

**الوثائق** - إصلاح الأخطاء المطبعية، وتحسين الأمثلة، وترجمة المستندات. العديد من المشاريع بحاجة ماسة إلى المساعدة في التوثيق وهي نقطة دخول ممتازة.

**فرز المشكلات** - إعادة إنتاج الأخطاء، وإضافة السياق، وتصنيف المشكلات. يعد هذا أمرًا ذا قيمة لا تصدق للمشرفين الغارقين في المشكلات غير المعالجة.

**الترجمات** - ساعد في إتاحة الوصول إلى أدوات الذكاء الاصطناعي عالميًا. تبحث مشاريع مثل Hugging Face بنشاط عن مترجمين.

**دعم المجتمع** - أجب عن الأسئلة المتعلقة بمناقشات Discord أو Stack Overflow أو GitHub. مساعدة الآخرين هي مساهمة أيضًا.

<Callout>**نصيحة احترافية:** يتمتع ممثلو العلاقات العامة بالوثائق بأعلى معدل قبول من أي نوع مساهمة. إنها الطريقة المثالية لتعلم قاعدة التعليمات البرمجية، وبناء الثقة مع المشرفين، وإعداد نفسك لمساهمات أكبر في التعليمات البرمجية لاحقًا.
</Callout>

## بناء ملف شخصي عام

تتراكم المساهمات المتسقة في أصول مهنية قوية.

**خطوات عملية:**
1. قم بتثبيت أفضل مساهماتك في ملفك الشخصي على GitHub
2. اكتب منشورات مدونة قصيرة حول ما تعلمته من كل مساهمة
3. شارك في مناقشات المشروع - سيتم ملاحظة التعليقات المدروسة
4. احضر اللقاءات أو المؤتمرات الافتراضية المتعلقة بمشاريعك
5. أضف عملاً مفتوح المصدر إلى سيرتك الذاتية مع روابط إلى العلاقات العامة المدمجة

<FunFact>ساعدت مساهمات أندريه كارباثي المبكرة مفتوحة المصدر في مكتبات الشبكات العصبية في ترسيخ سمعته قبل وقت طويل من انضمامه إلى Tesla أو OpenAI. ملفك الشخصي على GitHub عبارة عن محفظة حية.
</FunFact>

## الوجبات السريعة الرئيسية

- تعمل المساهمات مفتوحة المصدر على تسريع التعلم والتواصل والنمو الوظيفي
- ابدأ بمشاريع أصغر يتم صيانتها بشكل نشط - وليس اتفاقيات إعادة الشراء الضخمة
- أتقن الشوكة ← الفرع ← سير عمل العلاقات العامة واستخدمها في كل مكان
- اكتب علاقات عامة واضحة ومركزة مع رسائل التزام وصفية
- يعد التوثيق وفرز المشكلات من المساهمات القيمة التي لا تحتاج إلى تعليمات برمجية
- الاتساق مهم أكثر من الحجم - المساهمات الصغيرة المنتظمة مركبة

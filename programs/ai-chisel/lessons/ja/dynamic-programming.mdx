## ビッグアイデア

一部の問題は、**小さな繰り返しのサブ問題**で構成されていることに気づくまで、信じられないほど複雑に見えます。ダイナミック プログラミング (DP) は、各部分問題を **1 回**解決し、その結果を保存して再利用します。これにより、少量のメモリと引き換えに劇的な速度向上が実現します。

2 つの条件が DP の機会を示します。

1. **重複する部分問題** - 同じ計算が何度も繰り返されます。
2. **最適な下部構造** - 問題全体に対する最適なソリューションは、その部分に対する最適なソリューションから構築できます。

## フィボナッチ: 古典的な例

### 単純再帰 - O(2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)` を呼び出すと **15** 関数呼び出しがトリガーされ、多くは冗長です。 `fib(40)`では数秒かかります。 `fib(100)`では、それは宇宙よりも長く続くでしょう。

### メモ化 (トップダウン) - O(n)

結果をキャッシュに保存します。サブ問題をすでに解決している場合は、キャッシュされた回答を返します。

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### 集計 (ボトムアップ) - O(n)

基本ケースから上に向かって繰り返し答えを構築します。

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## 古典的な DP の問題

### 階段を登る

一度に 1 つまたは 2 つのステップを実行できます。ステップ _n_ に到達するための個別の方法は何通りありますか?

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

これはフィボナッチの変装です。ステップ _n_ の答えは、ステップ _n−1_ と _n−2_ に到達する方法の合計です。

### コインチェンジ

コインの額面を指定して、目標金額を達成するための**最小のコイン**を見つけます。

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### 最長共通部分列 (LCS)

2 つの文字列 (必ずしも連続しているとは限りません) に共通する最長の文字シーケンスを見つけます。

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

## トップダウンとボトムアップ

|側面 |トップダウン (メモ化) |ボトムアップ（集計） |
|----------|----------------------|-----------|
|スタイル |再帰的 + キャッシュ |反復 + テーブル |
|サブ問題が解決されました |必要なものだけ | _n_ | までのすべてのサブ問題
|スタック オーバーフローのリスク |はい、深い再帰の場合 |いいえ |
|最適化の容易さ |スペースを減らすのが難しい |より簡単 (多くの場合、最後の行を保持するだけです) |

**経験則:** 繰り返しを理解するためにメモ化から始めて、スペースを最適化する必要がある場合やスタック制限を回避する必要がある場合は表形式に変換します。

<ThinkAboutIt>硬貨釣銭台のサイズはO(金額)です。 LCS テーブルのサイズは O(m × n) です。一度に 2 行だけを保持することで、LCS スペースを O(min(m, n)) に減らすことはできますか?どのような情報を失うことになりますか?</ThinkAboutIt>

## 重要なポイント

1. DP は、**繰り返し行われた作業をキャッシュ**することで、指数関数的な総当たり処理を多項式時間に変換します。
2. DP に到達する前に、重複する部分問題と最適な部分構造を特定します。
3. メモ化は直感的です。集計は効率的です - 両方を学びましょう。
4. 編集距離、ビタビ、シーケンス アライメントは、現代の AI の中心となる DP を示します。

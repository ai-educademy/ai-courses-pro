## AI では木がどこにでも存在します

スパム フィルターが電子メールを分類したり、データベースがミリ秒単位で注文を取得したりするたびに、ツリー データ構造が重労働を行っています。ツリー モデル **階層的な決定** - 各ノードは、答えに到達するまで検索空間を狭めます。

## 二分探索木 (BST)

BST は、どのノードでも、**左** サブツリー内のすべての値が小さくなり、**右** サブツリー内のすべての値が大きくなるように要素を格納します。

＃＃＃ 検索

```
function search(node, target):
    if node is null: return null
    if target == node.value: return node
    if target < node.value: return search(node.left, target)
    return search(node.right, target)
```

各比較では、バランスのとれたツリー上の残りのノードのおよそ半分、つまり O(log n) が削除されます。

### 挿入

```
function insert(node, value):
    if node is null: return new Node(value)
    if value < node.value:
        node.left = insert(node.left, value)
    else:
        node.right = insert(node.right, value)
    return node
```

＃＃＃ 削除

削除は最も難しい操作です。次の 3 つのケースが発生します。

1. **リーフ ノード** - 単純に削除します。
2. **1 つの子** - ノードをその子に置き換えます。
3. **2 つの子** - ノードの値をその順序の後続者 (右のサブツリーの最小値) と交換し、その後続者を削除します。

## バランス型とアンバランス型

ソートされたデータをプレーンな BST に挿入すると、操作ごとに O(n) のリンク リストに縮退します。 **自己バランス** ツリーはこれを修正します。

|木 |バランスルール |一般的な使用法 |
|------|---------------|---------------|
| AVL |サブツリー間の高さの差 ≤ 1 |インメモリルックアップ |
|赤黒 |色ベースの回転ルール |言語標準ライブラリ (例: Java TreeMap) |
| Bツリー |ノードごとに複数のキー、すべてのリーフが同じ深さ |データベースとファイル システム |

<FunFact>PostgreSQL と MySQL はどちらも、デフォルトのインデックス構造として B ツリー バリアントを使用します。分岐係数 100 の B ツリーは、わずか 5 レベルで 10 億行のインデックスを作成できます。</FunFact>

## ツリートラバーサル

トラバーサルはすべてのノードを 1 回だけ訪問します。 3 つの古典的な順序は、子に対して現在のノードを処理する**場合** のみが異なります。

|トラバーサル |注文 |使用例 |
|----------|----------|----------|
| **注文中** |左→ノード→右 | BST | からソートされた出力を生成します。
| **予約注文** |ノード → 左 → 右 |ツリーのシリアル化/クローン作成 |
| **注文後** |左→右→ノード |ツリーを安全に削除します。式ツリーを評価する |

```
function inOrder(node):
    if node is null: return
    inOrder(node.left)
    process(node)
    inOrder(node.right)
```

<ThinkAboutIt>コンパイラはコードを解析して抽象構文ツリー (AST) にします。ツリーとして保存されている式 `(3 + 5) * 2` を評価するには、どの走査順序を使用しますか?なぜ?</ThinkAboutIt>

## ヒープと優先キュー

**ヒープ** は完全なバイナリ ツリーであり、すべての親がその子よりも大きい (最大ヒープ) か、小さい (最小ヒープ) になります。以下をサポートします。

- **挿入** - 最後に追加し、泡立てます。 O(log n)。
- **最小値/最大値を抽出** - ルートを削除し、最後の要素をルートに移動し、下に移動します。 O(log n)。

ヒープパワーに基づいて構築された優先キュー:
- **ダイクストラのアルゴリズム** (次のレッスン!) - 常に最も近い未訪問のノードを展開します。
- **タスク スケジューリング** - OS スケジューラは、最も優先度の高いプロセスを選択します。
- **NLP でのビーム検索** - 最も有望な文の補完の上位から k 個を保持します。

```
function siftUp(heap, index):
    while index > 0:
        parent = (index - 1) / 2
        if heap[index] < heap[parent]:
            swap(heap, index, parent)
            index = parent
        else: break
```

## 実際の AI アプリケーション

- 機械学習の **デシジョン ツリー** は、クラスを最もよく分離する機能 (ツリー構造の直接適用) を使用して、各ノードでデータを分割します。
- NLP の **構文ツリー** は文法構造を表し、感情分析や機械翻訳などのタスクを可能にします。
- **モンテカルロ ツリー検索 (MCTS)** は、AlphaGo などのゲームプレイ AI を強化し、ゲーム状態のツリーとして可能な手を探索します。
- **ハフマン ツリー** は、頻繁に使用されるシンボルに短いコードを割り当てることでデータを圧縮します。これはモデルの重み圧縮に使用されます。

<FunFact>scikit-learn デシジョン ツリー分類子は、各内部ノードが特徴のしきい値をテストするツリーを構築します。深さ 20 のトレーニング済みモデルは、100 万を超える異なる意思決定パスを表現できます。</FunFact>

<ThinkAboutIt>オートコンプリート システムを構築する場合、BST、ヒープ、または別のツリー構造 (トライなど) を使用しますか?高速化するにはどのような操作が必要かを検討してください。</ThinkAboutIt>

## 重要なポイント

1. BST は、O(log n) 検索、挿入、削除を提供しますが、バランスが取れている場合に限ります。
2. 走査順序によって、ツリーからどのような情報を抽出するかが決まります。
3. ヒープにより、極値への O(1) アクセスと O(log n) の挿入が可能になり、優先順位ベースの AI アルゴリズムに最適です。
4. ツリーは、ML、データベース、コンパイラー、ゲーム AI にわたる意思決定を支えます。

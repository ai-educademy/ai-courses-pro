## O que é uma tentativa?

Um **trie** (pronuncia-se "try") é uma estrutura semelhante a uma árvore onde cada nó representa um único caractere. Caminhos da raiz até os nós marcados indicam as palavras armazenadas. Ao contrário dos mapas hash, as tentativas permitem consultar *todas as palavras que compartilham um prefixo* sem verificar todas as chaves.

```
        root
       / | \
      a   b   c
     /     \
    p       a
   / \       \
  p   e      t
  |
  l
  e
```

Cada caminho codifica uma palavra: **apple**, **ape**, **bat**, **cat**.

## A classe TrieNode

Cada nó contém um mapa de filhos e uma bandeira indicando a conclusão da palavra.

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False
```

Um Trie completo envolve isso com operações de inserção, pesquisa e prefixo.

## Operações principais

### Inserir - O(m) onde m = comprimento da palavra

Caminhe caractere por caractere, criando nós conforme necessário e marque o último nó.

```python
def insert(self, word):
    node = self.root
    for ch in word:
        if ch not in node.children:
            node.children[ch] = TrieNode()
        node = node.children[ch]
    node.is_end = True
```

### Pesquise e comeceCom

**Pesquisar** segue o caminho e verifica `is_end`. **startsWith** apenas verifica se o caminho existe - não requer `is_end = True`.

## Preenchimento automático com DFS

Para sugerir conclusões para um prefixo, navegue até o nó do prefixo e execute o DFS coletando todas as palavras abaixo dele.

```python
def autocomplete(self, prefix):
    node = self._find(prefix)
    if not node:
        return []
    results = []
    self._dfs(node, prefix, results)
    return results
```

O auxiliar `_dfs` recorre através dos filhos, anexando aos resultados sempre que `is_end` for `True`.

## Pesquisa curinga - Dicionário de palavras

**Estrutura de dados de adição e pesquisa de palavras do LeetCode** solicita que você trate `.` como um curinga que corresponde a qualquer caractere único.

Durante a pesquisa, quando você atingir `.`, ramifique em *todos* filhos e continue recursivamente. Isso transforma um simples percurso em uma busca de retrocesso limitada.

```python
def search_wild(self, node, word, i):
    if i == len(word):
        return node.is_end
    if word[i] == '.':
        return any(
            self.search_wild(c, word, i + 1)
            for c in node.children.values()
        )
    if word[i] not in node.children:
        return False
    return self.search_wild(
        node.children[word[i]], word, i + 1
    )
```

## Prefixo comum mais longo

Faça a tentativa desde a raiz. O prefixo comum mais longo termina no primeiro nó com mais de um filho ou um sinalizador `is_end`.

## Roteamento IP com tentativas

Os roteadores armazenam prefixos IP em um **trie binário** - cada bit (0 ou 1) forma uma ramificação. A correspondência de prefixo mais longa encontra a rota mais específica. É assim que seus pacotes passam pela Internet.

<FunFact>Os roteadores de backbone da Internet realizam bilhões de pesquisas de correspondência de prefixo mais longas por segundo, usando tentativas otimizadas por hardware incorporadas em chips especializados chamados TCAMs.</FunFact>

## Tentativas compactadas (Árvores Radix)

O padrão tenta desperdiçar espaço em cadeias de filhos únicos. Uma **árvore radix** mescla essas cadeias em arestas únicas que armazenam rótulos de vários caracteres.

```
Standard:  r → u → n → n → i → n → g
Radix:     r → "unning"
```

Isso reduz drasticamente a contagem de nós e é usado pelas tabelas de roteamento do kernel Linux e roteadores HTTP como o `httprouter` do Go.

## Complexidade de Tempo e Espaço

| Operação | Experimente | Mapa de hash |
|------------|--------|----------|
| Inserir | O(m) | O(m) |
| Pesquisar | O(m) | O(m) |
| Consulta de prefixo | O(m+k) | O(n·m) |

Aqui *m* é o comprimento da palavra, *k* é a contagem de resultados e *n* é o total de chaves. As tentativas dominam cargas de trabalho com muitos prefixos.

## Quando tentar

- Consultas baseadas em prefixo (preenchimento automático, digitação antecipada)
- Correspondência curinga ou semelhante a regex em strings
- Prefixo comum mais longo em um conjunto
- Roteamento IP/correspondência de prefixo mais longo
- Verificação ortográfica com variações de distância de edição

## Por que o hash é importante

Quando um mecanismo de recomendação precisa verificar se você já assistiu a um filme – entre milhões em seu catálogo – ele não pode se dar ao luxo de escanear uma lista. Uma **tabela hash** responde a essa pergunta em tempo médio O(1).

As tabelas hash são a estrutura de dados mais usada em software de produção, e os sistemas de IA dependem fortemente delas para pesquisas de recursos, armazenamento em cache e desduplicação.

## Como funciona o hash

Uma **função hash** recebe uma entrada (uma string, número ou objeto) e retorna um número inteiro - o **código hash**. Esse código é mapeado para um **índice de bucket** via módulo:

```
index = hashFunction(key) % numberOfBuckets
```

Uma boa função hash é:
- **Determinístico** - a mesma entrada sempre produz a mesma saída.
- **Uniform** – distribui chaves uniformemente entre buckets.
- **Rápido** - computável em O(1) relativo ao tamanho da chave.

### Exemplo

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

Isso é deliberadamente ingênuo - funções hash de produção como MurmurHash3 ou xxHash usam mistura de bits para obter uma distribuição muito melhor.

## Tratamento de Colisões

As colisões são inevitáveis ​​(princípio do pombo). Duas estratégias principais:

### Encadeamento

Cada balde contém uma lista vinculada (ou pequena matriz) de entradas. As chaves de colisão são anexadas à lista.

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**Prós:** Simples, funciona bem com carga moderada.
**Contras:** Cache hostil devido à perseguição de ponteiro.

### Endereçamento Aberto

Todas as entradas residem diretamente na matriz. Em caso de colisão, **sonde** o próximo slot livre.

- **Teste linear:** Verifique índice+1, índice+2,…
- **Teste quadrático:** Verifique índice+1², índice+2²,…
- **Hashing duplo:** Use uma segunda função hash para determinar o tamanho do passo.

**Prós:** Melhor desempenho de cache, sem dicas extras.
**Contras:** O clustering pode degradar o desempenho; a exclusão é complicada (requer lápides).

<FunFact>Os dicionários Python usam endereçamento aberto com uma sequência de investigação personalizada. A implementação do dict do CPython é tão otimizada que processa mais de 50 milhões de pesquisas por segundo em hardware moderno.</FunFact>

## Fator de carga e rehashing

O **fator de carga** α = número de entradas/número de buckets. À medida que α cresce, as colisões aumentam e o desempenho diminui.

| Fator de carga | Pesquisas esperadas (encadeamento) |
|------------|----------------------------|
| 0,5 | ~1,25 |
| 0,75 | ~1.375 |
| 1,0 | ~1,5 |
| 2.0 | ~2,0 |

A maioria das implementações **refaz** quando α excede um limite (geralmente 0,75): aloque uma matriz maior, recalcule o índice de cada chave e reinsira.

O rehashing é O(n), mas raramente acontece, então o custo **amortizado** de inserção permanece O(1).

<ThinkAboutIt>O rehashing dobra o tamanho da tabela e reinsere todos os elementos. Se o seu sistema de IA estiver lidando com um fluxo de solicitação ao vivo, essa pausa poderá causar um pico de latência. Como você pode distribuir o custo de rehashing por múltiplas inserções em vez de fazer tudo de uma vez?</ThinkAboutIt>

## Aplicativos reais de IA

| Caso de uso | Como as tabelas hash ajudam |
|----------|----------|
| **Incorporando tabelas** | Mapear IDs de token para representações vetoriais densas em O(1) |
| **Hashing de recurso** | Hash de recursos categóricos de alta cardinalidade em um vetor de tamanho fixo (o "truque de hash") |
| **Desduplicação** | Detecte documentos ou imagens duplicados fazendo hash de suas impressões digitais de conteúdo |
| **Camadas de cache** | Armazenar previsões de modelos pré-computados codificadas por hash de entrada |
| **Esboço de contagem mínima** | Contagens de frequência aproximadas em streaming de dados usando múltiplas funções hash |

## Filtros Bloom: Associação Probabilística

Um **filtro Bloom** responde "Este elemento está no conjunto?" com:
- **Definitivamente não** - o elemento certamente está ausente.
- **Provável sim** - o elemento provavelmente está presente (pequena taxa de falsos positivos).

Ele usa funções hash _k_ e uma matriz de bits. Conjuntos de inserção _k_ bits; lookup verifica se todos os _k_ bits estão definidos.

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**Usos de IA:** verificar se um URL já foi rastreado, filtrar spam e evitar consultas redundantes ao banco de dados em camadas de cache.

<FunFact>O Google Chrome usa um filtro Bloom contendo milhões de URLs maliciosos conhecidos. Antes de carregar qualquer página, seu navegador verifica o filtro - se disser "provavelmente sim", o Chrome busca a lista completa para confirmar.</FunFact>

## Conjuntos vs mapas: quando usar quais

| Estrutura | Lojas | Usar quando |
|-----------|--------|----------|
| **Definir** | Somente chaves | Você precisa de verificações de adesão - "já vi isso antes?" |
| **Mapa** | Pares chave-valor | Você precisa associar dados a cada chave - "qual é o valor desta chave?" |

Ambos são apoiados por tabelas hash e oferecem operações médias O(1). Escolha um **conjunto** para desduplicação, rastreamento de visitas e restrições de exclusividade. Escolha um **mapa** para pesquisas, caches e armazenamentos de configuração.

## Principais conclusões

1. As tabelas hash fornecem pesquisas de caso médio O(1) - a espinha dorsal do cache, da indexação e da engenharia de recursos.
2. As colisões são gerenciadas por meio de encadeamento ou endereçamento aberto; o fator de carga controla quando refazer.
3. Os filtros Bloom trocam uma pequena taxa de falsos positivos por enormes economias de memória em consultas de associação.
4. Compreender os aspectos internos do hash ajuda você a escolher a ferramenta certa – conjunto, mapa ou filtro probabilístico – para cada carga de trabalho de IA.

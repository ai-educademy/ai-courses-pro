## A grande ideia

Alguns problemas parecem incrivelmente complexos até você perceber que são feitos de **subproblemas menores e repetidos**. A programação dinâmica (DP) resolve cada subproblema **uma vez**, armazena o resultado e o reutiliza – trocando um pouco de memória por uma aceleração drástica.

Duas condições sinalizam uma oportunidade de DP:

1. **Subproblemas sobrepostos** - os mesmos cálculos se repetem muitas vezes.
2. **Subestrutura ideal** - a melhor solução para todo o problema pode ser construída a partir das melhores soluções para suas partes.

## Fibonacci: o exemplo clássico

### Recursão ingênua - O (2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

Chamar `fib(5)` aciona **15** chamadas de função, muitas delas redundantes. Em `fib(40)` leva segundos; em `fib(100)`, sobreviveria ao universo.

### Memoização (de cima para baixo) - O(n)

Armazene os resultados em um cache. Se você já resolveu um subproblema, retorne a resposta em cache.

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### Tabulação (de baixo para cima) - O(n)

Construa a resposta iterativamente a partir dos casos base para cima.

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## Problemas clássicos de DP

### Subindo escadas

Você pode dar 1 ou 2 passos de cada vez. Quantas maneiras distintas de alcançar a etapa _n_?

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

Este é Fibonacci disfarçado - a resposta para o passo _n_ é a soma das maneiras de alcançar os passos _n−1_ e _n−2_.

### Mudança de moeda

Dadas as denominações das moedas, encontre o **menor número de moedas** para atingir o valor desejado.

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### Maior Subsequência Comum (LCS)

Encontre a sequência mais longa de caracteres comuns a duas strings (não necessariamente contíguas).

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

## Aplicativos reais de IA

| Problema | Domínio de IA | Técnica DP |
|--------|-----------|-------------|
| **Editar distância** (Levenshtein) | Corretores ortográficos, pesquisa difusa | Tabela 2D comparando caracteres |
| **Algoritmo de Viterbi** | Reconhecimento de fala, marcação de PDV | Melhor caminho através de um modelo oculto de Markov |
| **Alinhamento de sequência** | Bioinformática (correspondência de DNA) | Variante do LCS com penalidades de gap |
| **Decodificação CTC** | Escrita à mão/fala para texto | Mesclando caracteres repetidos de maneira otimizada |
| **Remoção de pesquisa de feixe** | Tradução automática | Mantendo as principais traduções parciais |

## De cima para baixo versus de baixo para cima

| Aspecto | De cima para baixo (memorização) | De baixo para cima (Tabulação) |
|--------|----------------------|----------------------|
| Estilo | Recursivo + cache | Iterativo + tabela |
| Subproblemas resolvidos | Somente aqueles necessários | Todos os subproblemas até _n_ |
| Risco de estouro de pilha | Sim, para recursão profunda | Não |
| Facilidade de otimização | Mais difícil de reduzir espaço | Mais fácil (muitas vezes apenas mantém a última linha) |

**Regra prática:** comece com a memorização para entender a recorrência e, em seguida, converta para tabulação se precisar otimizar o espaço ou evitar limites de pilha.

<ThinkAboutIt>A tabela de troca de moedas tem tamanho O(quantidade). A tabela LCS tem tamanho O(m × n). Você poderia reduzir o espaço LCS para O(min(m, n)) mantendo apenas duas linhas por vez? Que informações você perderia?</ThinkAboutIt>

## Principais conclusões

1. DP transforma força bruta exponencial em tempo polinomial **armazenando em cache o trabalho repetido**.
2. Identifique subproblemas sobrepostos e subestrutura ideal antes de chegar ao DP.
3. A memorização é intuitiva; a tabulação é eficiente - aprenda ambos.
4. Editar distância, Viterbi e alinhamento de sequência mostram DP no centro da IA ​​moderna.

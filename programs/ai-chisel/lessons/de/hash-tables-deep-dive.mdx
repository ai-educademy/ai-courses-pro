## Warum Hashing wichtig ist

Wenn eine Empfehlungsmaschine überprüfen muss, ob Sie einen Film aus Millionen in ihrem Katalog bereits gesehen haben, kann sie es sich nicht leisten, eine Liste zu scannen. Eine **Hash-Tabelle** beantwortet diese Frage in der durchschnittlichen Zeit von O(1).

Hash-Tabellen sind die am häufigsten verwendete Datenstruktur in Produktionssoftware, und KI-Systeme stützen sich bei der Funktionssuche, dem Caching und der Deduplizierung stark auf sie.

## So funktioniert Hashing

Eine **Hash-Funktion** nimmt eine Eingabe (eine Zeichenfolge, eine Zahl oder ein Objekt) entgegen und gibt eine Ganzzahl zurück – den **Hash-Code**. Dieser Code wird über Modulo einem **Bucket-Index** zugeordnet:

```
index = hashFunction(key) % numberOfBuckets
```

Eine gute Hash-Funktion ist:
- **Deterministisch** – die gleiche Eingabe erzeugt immer die gleiche Ausgabe.
- **Uniform** – verteilt die Schlüssel gleichmäßig auf die Buckets.
- **Schnell** – berechenbar in O(1) relativ zur Schlüsselgröße.

### Beispiel

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

Das ist bewusst naiv – Produktions-Hash-Funktionen wie MurmurHash3 oder xxHash nutzen Bit-Mixing, um eine viel bessere Verteilung zu erreichen.

## Kollisionsbehandlung

Kollisionen sind vorprogrammiert (Schubladenprinzip). Zwei Hauptstrategien:

### Verkettung

Jeder Bucket enthält eine verknüpfte Liste (oder ein kleines Array) von Einträgen. Kollidierende Schlüssel werden an die Liste angehängt.

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**Vorteile:** Einfach, funktioniert gut bei mäßiger Last.
**Nachteile:** Cache-unfreundlich aufgrund der Zeigerverfolgung.

### Öffnen Sie die Adressierung

Alle Einträge leben direkt im Array. Bei einer Kollision **suchen** Sie nach dem nächsten freien Slot.

- **Lineare Abtastung:** Index+1, Index+2, … prüfen
- **Quadratische Abtastung:** Index+1², Index+2², … prüfen
- **Doppeltes Hashing:** Verwenden Sie eine zweite Hash-Funktion, um die Schrittgröße zu bestimmen.

**Vorteile:** Bessere Cache-Leistung, keine zusätzlichen Zeiger.
**Nachteile:** Clustering kann die Leistung beeinträchtigen; Das Löschen ist umständlich (erfordert Tombstones).

<FunFact>Python-Wörterbücher verwenden offene Adressierung mit einer benutzerdefinierten Prüfsequenz. Die dict-Implementierung von CPython ist so stark optimiert, dass sie auf moderner Hardware über 50 Millionen Suchvorgänge pro Sekunde verarbeitet.</FunFact>

## Ladefaktor und Aufwärmen

Der **Lastfaktor** α = Anzahl der Einträge / Anzahl der Buckets. Mit zunehmendem α nehmen die Kollisionen zu und die Leistung nimmt ab.

| Lastfaktor | Erwartete Suchvorgänge (Verkettung) |
|------------|-------------|
| 0,5 | ~1,25 |
| 0,75 | ~1,375 |
| 1,0 | ~1,5 |
| 2,0 | ~2,0 |

Die meisten Implementierungen führen einen **Rehash** durch, wenn α einen Schwellenwert überschreitet (üblicherweise 0,75): Weisen Sie ein größeres Array zu, berechnen Sie den Index jedes Schlüssels neu und fügen Sie ihn erneut ein.

Das erneute Aufwärmen ist O(n), kommt aber selten vor, sodass die **amortisierten** Kosten der Einfügung O(1) bleiben.

<ThinkAboutIt>Durch das erneute Aufbereiten wird die Tabellengröße verdoppelt und jedes Element erneut eingefügt. Wenn Ihr KI-System einen Live-Anfragestream verarbeitet, kann diese Pause zu einem Latenzanstieg führen. Wie können Sie die Kosten für die erneute Aufbereitung auf mehrere Einfügungen verteilen, anstatt alles auf einmal durchzuführen?</ThinkAboutIt>

## Bloom-Filter: Probabilistische Mitgliedschaft

Ein **Bloom-Filter** antwortet: „Ist dieses Element in der Menge?“ mit:
- **Definitiv nein** – das Element fehlt definitiv.
- **Wahrscheinlich ja** – das Element ist wahrscheinlich vorhanden (geringe Falsch-Positiv-Rate).

Es verwendet _k_ Hash-Funktionen und ein Bit-Array. Einfügung setzt _k_ Bits; Lookup prüft, ob alle _k_ Bits gesetzt sind.

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**KI verwendet Folgendes:** Überprüfen, ob eine URL bereits gecrawlt wurde, Filtern von Spam und Vermeiden redundanter Datenbankabfragen in Caching-Ebenen.

<FunFact>Google Chrome verwendet einen Bloom-Filter, der Millionen bekannter schädlicher URLs enthält. Bevor Sie eine Seite laden, überprüft Ihr Browser den Filter. Wenn er „wahrscheinlich ja“ sagt, ruft Chrome zur Bestätigung die vollständige Liste ab.</FunFact>

## Sets vs. Karten: Wann welche verwendet werden sollten

| Struktur | Geschäfte | Verwenden Sie Wann |
|-----------|--------|----------|
| **Set** | Nur Schlüssel | Sie benötigen Mitgliedsschecks – „Habe ich das schon einmal gesehen?“ |
| **Karte** | Schlüssel-Wert-Paare | Sie müssen jedem Schlüssel Daten zuordnen: „Was ist der Wert für diesen Schlüssel?“ |

Beide basieren auf Hash-Tabellen und bieten O(1)-Durchschnittsoperationen. Wählen Sie einen **Satz** für Deduplizierung, Besuchsverfolgung und Eindeutigkeitseinschränkungen. Wählen Sie eine **Karte** für Suchvorgänge, Caches und Konfigurationsspeicher.

<ThinkAboutIt>Ein KI-Content-Moderationssystem muss eingehende Nachrichten anhand einer Sperrliste mit 10 Millionen verbotenen Phrasen prüfen. Würden Sie ein Hash-Set, einen Bloom-Filter oder beides verwenden? Welche Kompromisse gibt es in Bezug auf Speicher, Geschwindigkeit und Genauigkeit?</ThinkAboutIt>

## Wichtige Erkenntnisse

1. Hash-Tabellen liefern O(1)-Durchschnittsfall-Suchen – das Rückgrat von Caching, Indizierung und Feature-Engineering.
2. Kollisionen werden durch Verkettung oder offene Adressierung verwaltet; Der Lastfaktor steuert, wann erneut aufgewärmt werden soll.
3. Bloom-Filter tauschen eine geringe Falsch-Positiv-Rate gegen massive Speichereinsparungen bei Mitgliedschaftsabfragen ein.
4. Das Verständnis der Hashing-Interna hilft Ihnen bei der Auswahl des richtigen Tools – Set, Karte oder probabilistischer Filter – für jede KI-Arbeitslast.

##الفكرة الكبيرة

تبدو بعض المشكلات معقدة بشكل مستحيل حتى تلاحظ أنها مكونة من **مشكلات فرعية أصغر حجمًا ومتكررة**. تحل البرمجة الديناميكية (DP) كل مشكلة فرعية **مرة واحدة**، وتخزن النتيجة، وتعيد استخدامها - مع استبدال القليل من الذاكرة بتسريع كبير.

هناك شرطان يشيران إلى فرصة DP:

1. **المسائل الفرعية المتداخلة** - تتكرر نفس الحسابات عدة مرات.
2. **البنية الأساسية المثالية** - يمكن بناء الحل الأفضل للمشكلة بأكملها من أفضل الحلول لأجزائها.

## فيبوناتشي: المثال الكلاسيكي

### العودية الساذجة - O(2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

يؤدي استدعاء `fib(5)` إلى تشغيل **15** استدعاءات الوظائف، والعديد منها زائدة عن الحاجة. عند `fib(40)` يستغرق الأمر ثوانٍ؛ عند `fib(100)` سوف يدوم أطول من الكون.

### التذكير (من أعلى إلى أسفل) - O(n)

تخزين النتائج في ذاكرة التخزين المؤقت. إذا كنت قد قمت بالفعل بحل مشكلة فرعية، قم بإرجاع الإجابة المخزنة مؤقتًا.

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### الجدولة (من الأسفل إلى الأعلى) - O(n)

قم ببناء الإجابة بشكل متكرر من الحالات الأساسية إلى أعلى.

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## مشاكل DP الكلاسيكية

### صعود السلالم

يمكنك اتخاذ خطوة أو خطوتين في المرة الواحدة. كم عدد الطرق المميزة للوصول إلى الخطوة _n_؟

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

هذا هو فيبوناتشي المقنع - إجابة الخطوة _n_ هي مجموع الطرق للوصول إلى الخطوتين _n−1_ و _n−2_.

### تغيير العملة

بالنظر إلى فئات العملات، ابحث عن **أقل عدد من العملات** للحصول على المبلغ المستهدف.

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### أطول لاحقة مشتركة (LCS)

ابحث عن أطول تسلسل من الأحرف المشتركة بين سلسلتين (ليس بالضرورة متجاورتين).

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

<FunFact>يتم تشغيل الأداة `diff` التي تعرض التغييرات بين إصدارات الملفات بواسطة LCS. يستخدم Git متغيرًا منه في كل مرة تقوم فيها بتشغيل `git diff`.</FunFact>

<ThinkAboutIt>يتطلب تغيير العملة الحد الأدنى لعدد العملات المعدنية. ماذا لو أردت حساب العدد الإجمالي للطرق المختلفة لتكوين المبلغ؟ كيف ستتغير علاقة التكرار؟</ThinkAboutIt>

## تطبيقات الذكاء الاصطناعي الحقيقية

| مشكلة | مجال الذكاء الاصطناعي | تقنية DP |
|---------|----------|-------------|
| **تعديل المسافة** (ليفنشتاين) | المدقق الإملائي، بحث غامض | جدول ثنائي الأبعاد لمقارنة الشخصيات |
| **خوارزمية فيتربي** | التعرف على الكلام، ووضع علامات على نقاط البيع | أفضل مسار من خلال نموذج ماركوف المخفي |
| **محاذاة التسلسل** | المعلوماتية الحيوية (مطابقة الحمض النووي) | البديل من LCS مع عقوبات الفجوة |
| **فك تشفير CTC** | الكتابة اليدوية / تحويل الكلام إلى نص | دمج الحروف المتكررة بالشكل الأمثل |
| **تقليم بحث الشعاع** | الترجمة الآلية | حفظ الترجمات الجزئية top-k |

## من أعلى إلى أسفل مقابل من أسفل إلى أعلى

| الجانب | من أعلى إلى أسفل (التذكار) | من أسفل إلى أعلى (التبويب) |
|--------|----------------------|---------------------|
| النمط | العودية + ذاكرة التخزين المؤقت | تكراري + جدول |
| مسائل فرعية تم حلها | فقط تلك اللازمة | جميع المسائل الفرعية حتى _n_ |
| خطر تجاوز سعة المكدس | نعم، للتكرار العميق | لا |
| سهولة التحسين | أصعب لتقليل المساحة | أسهل (غالبًا ما يحتفظ بالصف الأخير فقط) |

**القاعدة الأساسية:** ابدأ بالحفظ لفهم التكرار، ثم قم بالتحويل إلى الجدولة إذا كنت بحاجة إلى تحسين المساحة أو تجنب حدود المكدس.

<ThinkAboutIt>جدول تغيير العملة له حجم O (المبلغ). جدول LCS له حجم O(m×n). هل يمكنك تقليل مساحة LCS إلى O(min(m, n)) عن طريق الاحتفاظ بصفين فقط في المرة الواحدة؟ ما هي المعلومات التي ستفقدها؟</ThinkAboutIt>

## الوجبات السريعة الرئيسية

1. يقوم DP بتحويل القوة الغاشمة الأسية إلى وقت متعدد الحدود عن طريق **التخزين المؤقت للعمل المتكرر**.
2. تحديد المشاكل الفرعية المتداخلة والبنية التحتية المثالية قبل الوصول إلى DP.
3. الحفظ أمر بديهي. الجدولة تتسم بالكفاءة - تعلم كليهما.
4. تظهر محاذاة المسافة وViterbi وتسلسل DP في قلب الذكاء الاصطناعي الحديث.

## لماذا تعتبر التجزئة مهمة؟

عندما يحتاج محرك التوصيات إلى التحقق مما إذا كنت قد شاهدت فيلمًا بالفعل - من بين ملايين الأفلام الموجودة في كتالوجه - فلا يمكنه تحمل تكاليف مسح القائمة. يجيب **جدول التجزئة** على هذا السؤال في متوسط ​​الوقت O(1).

تعد جداول التجزئة هي بنية البيانات الأكثر استخدامًا في برامج الإنتاج، وتعتمد أنظمة الذكاء الاصطناعي عليها بشكل كبير في عمليات البحث عن الميزات والتخزين المؤقت وإلغاء البيانات المكررة.

## كيف يعمل التجزئة

تأخذ **دالة التجزئة** مدخلاً (سلسلة أو رقمًا أو كائنًا) وترجع عددًا صحيحًا - **رمز التجزئة**. يتم تعيين هذا الرمز إلى **فهرس المجموعة** عبر modulo:

```
index = hashFunction(key) % numberOfBuckets
```

وظيفة التجزئة الجيدة هي:
- **حتمية** - نفس المدخلات تنتج دائمًا نفس المخرجات.
- **الزي الرسمي** - يوزع المفاتيح بالتساوي عبر المجموعات.
- **سريع** - قابل للحساب في O(1) بالنسبة لحجم المفتاح.

### مثال

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

يعد هذا أمرًا ساذجًا عن عمد - حيث تستخدم وظائف تجزئة الإنتاج مثل MurmurHash3 أو xxHash خلط البتات لتحقيق توزيع أفضل بكثير.

## التعامل مع الاصطدام

الاصطدامات لا مفر منها (مبدأ الحمامة). استراتيجيتين رئيسيتين:

### تسلسل

تحتوي كل مجموعة على قائمة مرتبطة (أو مجموعة صغيرة) من الإدخالات. يتم إلحاق مفاتيح التصادم بالقائمة.

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**الإيجابيات:** بسيط، ويعمل بشكل جيد عند التحميل المعتدل.
**السلبيات:** ذاكرة التخزين المؤقت غير مناسبة بسبب مطاردة المؤشر.

### فتح العنونة

جميع الإدخالات تعيش مباشرة في المصفوفة. عند الاصطدام، **استكشف** المكان المجاني التالي.

- **الفحص الخطي:** تحقق من الفهرس+1، الفهرس+2،...
- **سبر التربيعية:** تحقق من الفهرس+1²، الفهرس+2²،...
- **التجزئة المزدوجة:** استخدم دالة التجزئة الثانية لتحديد حجم الخطوة.

**الإيجابيات:** أداء أفضل لذاكرة التخزين المؤقت، ولا توجد مؤشرات إضافية.
**السلبيات:** قد يؤدي التجميع إلى انخفاض الأداء؛ الحذف أمر تافه (يتطلب شواهد القبور).

<FunFact>تستخدم قواميس بايثون العنونة المفتوحة مع تسلسل فحص مخصص. تم تحسين تطبيق CPython للإملاء بشكل كبير لدرجة أنه يعالج أكثر من 50 مليون عملية بحث في الثانية على الأجهزة الحديثة.</FunFact>

## عامل التحميل وإعادة الصياغة

**عامل الحمولة** α = عدد الإدخالات / عدد الجرافات. مع نمو α، تزداد التصادمات ويتدهور الأداء.

| عامل التحميل | عمليات البحث المتوقعة (التسلسل) |
|------------|--------------------------|
| 0.5 | ~1.25 |
| 0.75 | ~1.375 |
| 1.0 | ~1.5 |
| 2.0 | ~2.0 |

معظم التطبيقات **تعيد الصياغة** عندما يتجاوز α العتبة (عادةً 0.75): تخصيص مصفوفة أكبر، وإعادة حساب فهرس كل مفتاح، وإعادة إدراجه.

إعادة الصياغة هي O(n) ولكنها تحدث بشكل غير متكرر، لذا تظل تكلفة الإدراج **المطفأة** O(1).

<ThinkAboutIt>تؤدي إعادة صياغة إلى مضاعفة حجم الجدول وإعادة إدراج كل عنصر. إذا كان نظام الذكاء الاصطناعي الخاص بك يتعامل مع بث مباشر للطلب، فقد يتسبب هذا الإيقاف المؤقت في زيادة وقت الاستجابة. كيف يمكنك توزيع تكلفة إعادة الصياغة على عمليات إدخال متعددة بدلاً من القيام بذلك مرة واحدة؟ </ThinkAboutIt>

## تطبيقات الذكاء الاصطناعي الحقيقية

| حالة الاستخدام | كيف تساعد جداول التجزئة |
|----------|---------------------|
| **تضمين الجداول** | قم بتعيين معرفات الرموز المميزة لتمثيلات المتجهات الكثيفة في O(1) |
| **تجزئة الميزة** | قم بتجزئة الميزات الفئوية ذات الأهمية العالية إلى متجه ذي حجم ثابت ("خدعة التجزئة") |
| **إلغاء البيانات المكررة** | اكتشف المستندات أو الصور المكررة عن طريق تجزئة بصمات محتوياتها |
| **طبقات التخزين المؤقت** | قم بتخزين تنبؤات النماذج المحسوبة مسبقًا بواسطة تجزئة الإدخال |
| ** رسم العد دقيقة ** | أعداد التكرار التقريبية في تدفق البيانات باستخدام وظائف التجزئة المتعددة |

## مرشحات بلوم: العضوية الاحتمالية

يجيب **مرشح Bloom** على السؤال "هل هذا العنصر موجود في المجموعة؟" مع:
- **لا قطعا** - العنصر غائب بالتأكيد.
- **نعم محتمل** - من المحتمل أن يكون العنصر موجودًا (معدل إيجابي كاذب صغير).

ويستخدم وظائف التجزئة _k_ ومجموعة بت. مجموعات الإدراج _k_ بت؛ يتحقق البحث من تعيين جميع البتات _k_.

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**استخدامات الذكاء الاصطناعي:** التحقق مما إذا كان عنوان URL قد تم الزحف إليه بالفعل، وتصفية البريد العشوائي، وتجنب استعلامات قاعدة البيانات المتكررة في طبقات التخزين المؤقت.

<FunFact>يستخدم Google Chrome مرشح Bloom الذي يحتوي على الملايين من عناوين URL الضارة المعروفة. قبل تحميل أي صفحة، يتحقق متصفحك من الفلتر - إذا كانت الإجابة "ربما نعم"، فسيجلب Chrome القائمة الكاملة للتأكيد.</FunFact>

## المجموعات مقابل الخرائط: متى يتم استخدام أي منها؟

| الهيكل | متاجر | استخدم متى |
|-----------|-------|----------|
| **مجموعة** | مفاتيح فقط | أنت بحاجة إلى فحوصات العضوية - "هل رأيت هذا من قبل؟" |
| **الخريطة** | أزواج المفتاح والقيمة | تحتاج إلى ربط البيانات بكل مفتاح - "ما قيمة هذا المفتاح؟" |

كلاهما مدعوم بجداول التجزئة ويقدمان عمليات متوسطة O(1). اختر **مجموعة** لإلغاء البيانات المكررة وتتبع الزيارات وقيود التفرد. اختر **خريطة** لعمليات البحث وذاكرة التخزين المؤقت ومخازن التكوين.

<ThinkAboutIt>يحتاج نظام الإشراف على محتوى الذكاء الاصطناعي إلى التحقق من الرسائل الواردة ومقارنتها بقائمة حظر تضم 10 ملايين عبارة محظورة. هل ستستخدم مجموعة التجزئة أم مرشح بلوم أم كليهما؟ ما هي المفاضلات في الذاكرة والسرعة والدقة؟ </ThinkAboutIt>

## الوجبات السريعة الرئيسية

1. توفر جداول التجزئة عمليات بحث ذات حالة متوسطة لـ O(1) - وهي العمود الفقري للتخزين المؤقت والفهرسة وهندسة الميزات.
2. تتم إدارة التصادمات عبر التسلسل أو العنونة المفتوحة؛ يتحكم عامل التحميل في وقت إعادة الصياغة.
3. تتاجر مرشحات Bloom بمعدل إيجابي كاذب صغير لتحقيق توفير هائل في الذاكرة في استعلامات العضوية.
4. يساعدك فهم عناصر التجزئة الداخلية على اختيار الأداة المناسبة - المجموعة أو الخريطة أو المرشح الاحتمالي - لكل عبء عمل للذكاء الاصطناعي.

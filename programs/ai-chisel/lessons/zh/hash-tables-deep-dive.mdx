## 为什么哈希很重要

当推荐引擎需要检查您是否已经观看过目录中的数百万部电影时，它无法扫描列表。 **哈希表**可以在平均 O(1) 时间内回答该问题。

哈希表是生产软件中最常用的数据结构，人工智能系统在功能查找、缓存和重复数据删除方面严重依赖它们。

## 哈希如何工作

**哈希函数**接受输入（字符串、数字或对象）并返回一个整数 - **哈希码**。该代码通过模数映射到 **存储桶索引**：

```
index = hashFunction(key) % numberOfBuckets
```

一个好的哈希函数是：
- **确定性** - 相同的输入总是产生相同的输出。
- **统一** - 在存储桶之间均匀分配密钥。
- **快速** - 相对于密钥大小，可在 O(1) 内计算。

＃＃＃ 例子

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

这是故意天真的 - 像 MurmurHash3 或 xxHash 这样的生产哈希函数使用位混合来实现更好的分布。

## 碰撞处理

碰撞是不可避免的（鸽巢原理）。两个主要策略：

### 链接

每个桶都保存一个条目的链表（或小数组）。冲突的键将附加到列表中。

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**优点：**简单，在中等负载下工作良好。
**缺点：** 由于指针追逐，缓存不友好。

### 开放寻址

所有条目都直接存在于数组中。发生冲突时，**探测**下一个空闲槽。

- **线性探测：** 检查索引+1、索引+2、...
- **二次探测：** 检查索引+1²、索引+2²、...
- **双重哈希：** 使用第二个哈希函数来确定步长。

**优点：**更好的缓存性能，没有额外的指针。
**缺点：** 集群会降低性能；删除很繁琐（需要墓碑）。

<FunFact>Python 字典使用带有自定义探测序列的开放寻址。 CPython 的 dict 实现经过高度优化，在现代硬件上每秒可处理超过 5000 万次查找。</FunFact>

## 负载因子和重新哈希

**负载因子** α = 条目数 / 桶数。随着 α 的增大，冲突会增加，性能会下降。

|负载系数|预期查找（链接）|
|------------------------|----------------------------------------|
| 0.5 | 0.5 〜1.25 |
| 0.75 | 0.75 〜1.375 |
| 1.0 | 〜1.5 |
| 2.0 | 〜2.0 |

当 α 超过阈值（通常为 0.75）时，大多数实现 **重新散列**：分配更大的数组，重新计算每个键的索引，然后重新插入。

重新散列的时间复杂度为 O(n)，但很少发生，因此插入的**摊销**成本仍为 O(1)。

<ThinkAboutIt>重新散列会使表大小加倍并重新插入每个元素。如果您的 AI 系统正在处理实时请求流，则此暂停可能会导致延迟峰值。如何将重新散列成本分摊到多次插入而不是一次完成所有操作？</ThinkAboutIt>

## 布隆过滤器：概率成员资格

**布隆过滤器**回答“这个元素在集合中吗？”与：
- **绝对不** - 该元素肯定不存在。
- **可能是** - 该元素可能存在（假阳性率小）。

它使用 _k_ 个哈希函数和一个位数组。插入集_k_位；查找检查是否设置了所有 _k_ 位。

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**AI用途：** 检查URL是否已被爬取，过滤垃圾邮件，并避免缓存层中多余的数据库查询。

<FunFact>Google Chrome 使用包含数百万个已知恶意 URL 的 Bloom 过滤器。在加载任何页面之前，您的浏览器会检查过滤器 - 如果显示“可能是”，Chrome 会获取完整列表进行确认。</FunFact>

## 集合与地图：何时使用哪个

|结构|商店 |使用时间 |
|------------|--------|----------|
| **设置** |仅钥匙 |你需要会员资格检查——“我以前见过这个吗？” |
| **地图** |键值对 |您需要将数据与每个键相关联 - “这个键的值是多少？” |

两者都由哈希表支持并提供 O(1) 平均运算。选择一个用于重复数据删除、访问跟踪和唯一性约束的**集**。选择用于查找、缓存和配置存储的**映射**。

<ThinkAboutIt>人工智能内容审核系统需要根据 1000 万个禁止短语的黑名单检查传入消息。您会使用哈希集、布隆过滤器还是两者都使用？内存、速度和准确性之间的权衡是什么？</ThinkAboutIt>

## 要点

1. 哈希表提供 O(1) 平均情况查找 - 缓存、索引和特征工程的支柱。
2. 通过链接或开放寻址来管理冲突；负载因子控制何时重新散列。
3. 布隆过滤器以微小的误报率换取成员资格查询中的大量内存节省。
4. 了解哈希内部原理有助于您为每个 AI 工作负载选择正确的工具 - 集、映射或概率过滤器。

## Por qué es importante el hash

Cuando un motor de recomendación necesita comprobar si ya has visto una película (entre millones en su catálogo) no puede permitirse el lujo de escanear una lista. Una **tabla hash** responde a esa pregunta en un tiempo promedio de O(1).

Las tablas hash son la estructura de datos más utilizada en el software de producción, y los sistemas de inteligencia artificial se basan en gran medida en ellas para la búsqueda de funciones, el almacenamiento en caché y la deduplicación.

## Cómo funciona el hash

Una **función hash** toma una entrada (una cadena, número u objeto) y devuelve un número entero: el **código hash**. Ese código se asigna a un **índice de depósito** mediante el módulo:

```
index = hashFunction(key) % numberOfBuckets
```

Una buena función hash es:
- **Determinista**: la misma entrada siempre produce la misma salida.
- **Uniforme**: distribuye las claves de manera uniforme entre los depósitos.
- **Rápido**: computable en O(1) en relación con el tamaño de la clave.

### Ejemplo

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

Esto es deliberadamente ingenuo: las funciones hash de producción como MurmurHash3 o xxHash utilizan la mezcla de bits para lograr una distribución mucho mejor.

## Manejo de colisiones

Las colisiones son inevitables (principio de encasillamiento). Dos estrategias principales:

### Encadenamiento

Cada depósito contiene una lista vinculada (o una pequeña matriz) de entradas. Las claves en colisión se agregan a la lista.

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**Pros:** Simple, funciona bien con carga moderada.
**Contras:** No compatible con la caché debido a la persecución del puntero.

### Direccionamiento abierto

Todas las entradas viven directamente en la matriz. En caso de colisión, **sonda** para encontrar el siguiente espacio libre.

- **Sonda lineal:** Comprobar índice+1, índice+2,…
- **Sondeo cuadrático:** Comprobar índice+1², índice+2²,…
- **Doble hash:** Utilice una segunda función hash para determinar el tamaño del paso.

**Ventajas:** Mejor rendimiento de la caché, sin sugerencias adicionales.
**Contras:** La agrupación en clústeres puede degradar el rendimiento; la eliminación es complicada (requiere lápidas).

<FunFact>Los diccionarios de Python utilizan direccionamiento abierto con una secuencia de sondeo personalizada. La implementación dict de CPython está tan optimizada que procesa más de 50 millones de búsquedas por segundo en hardware moderno.</FunFact>

## Factor de carga y repetición

El **factor de carga** α = número de entradas / número de depósitos. A medida que α crece, las colisiones aumentan y el rendimiento se degrada.

| Factor de carga | Búsquedas esperadas (encadenamiento) |
|------------|----------------------|
| 0,5 | ~1,25 |
| 0,75 | ~1,375 |
| 1.0 | ~1,5 |
| 2.0 | ~2.0 |

La mayoría de las implementaciones **repiten** cuando α excede un umbral (comúnmente 0,75): asigna una matriz más grande, vuelve a calcular el índice de cada clave y vuelve a insertarla.

El refrito es O(n) pero ocurre con poca frecuencia, por lo que el costo **amortizado** de inserción sigue siendo O(1).

<ThinkAboutIt>El refrito duplica el tamaño de la tabla y vuelve a insertar cada elemento. Si su sistema de inteligencia artificial está manejando una transmisión de solicitudes en vivo, esta pausa podría provocar un aumento de latencia. ¿Cómo podría distribuir el costo del refrito entre múltiples inserciones en lugar de hacerlo todo a la vez?</ThinkAboutIt>

## Aplicaciones reales de IA

| Caso de uso | Cómo ayudan las tablas hash |
|----------|---------------------|
| **Mesas de incrustar** | Asigne ID de token a representaciones vectoriales densas en O(1) |
| **Hashing de funciones** | Hash de características categóricas de alta cardinalidad en un vector de tamaño fijo (el "truco de hash") |
| **Deduplicación** | Detectar documentos o imágenes duplicados mediante el hash de las huellas digitales de su contenido |
| **Capas de almacenamiento en caché** | Almacenar predicciones de modelos precalculadas codificadas por hash de entrada |
| **Boceto de conteo mínimo** | Recuentos de frecuencia aproximados en la transmisión de datos utilizando múltiples funciones hash |

## Filtros Bloom: membresía probabilística

Un **filtro Bloom** responde "¿Este elemento está en el conjunto?" con:
- **No rotundo** - el elemento ciertamente está ausente.
- **Probablemente sí**: es probable que el elemento esté presente (pequeña tasa de falsos positivos).

Utiliza funciones hash _k_ y una matriz de bits. La inserción establece _k_ bits; La búsqueda comprueba si todos los _k_ bits están configurados.

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**Usos de la IA:** Comprobar si una URL ya se ha rastreado, filtrar el spam y evitar consultas redundantes a la base de datos en las capas de almacenamiento en caché.

<FunFact>Google Chrome utiliza un filtro Bloom que contiene millones de URL maliciosas conocidas. Antes de cargar cualquier página, su navegador verifica el filtro; si dice "probablemente sí", Chrome busca la lista completa para confirmar.</FunFact>

## Conjuntos versus mapas: cuándo usar cuáles

| Estructura | Tiendas | Usar cuando |
|-----------|--------|----------|
| **Establecer** | Sólo llaves | Necesita controles de membresía: "¿He visto esto antes?" |
| **Mapa** | Pares clave-valor | Debe asociar datos con cada clave: "¿cuál es el valor de esta clave?" |

Ambos están respaldados por tablas hash y ofrecen operaciones promedio O(1). Elija un **conjunto** para la deduplicación, el seguimiento de visitas y las restricciones de unicidad. Elija un **mapa** para búsquedas, cachés y almacenes de configuración.

<ThinkAboutIt>Un sistema de moderación de contenido de IA necesita comparar los mensajes entrantes con una lista de bloqueo de 10 millones de frases prohibidas. ¿Usarías un conjunto de hash, un filtro Bloom o ambos? ¿Cuáles son las ventajas y desventajas de la memoria, la velocidad y la precisión?</ThinkAboutIt>

## Conclusiones clave

1. Las tablas hash ofrecen búsquedas de casos promedio O(1): la columna vertebral del almacenamiento en caché, la indexación y la ingeniería de funciones.
2. Las colisiones se gestionan mediante encadenamiento o direccionamiento abierto; El factor de carga controla cuándo repetir.
3. Los filtros Bloom intercambian una pequeña tasa de falsos positivos por un enorme ahorro de memoria en las consultas de membresía.
4. Comprender los aspectos internos del hash le ayuda a elegir la herramienta adecuada (conjunto, mapa o filtro probabilístico) para cada carga de trabajo de IA.

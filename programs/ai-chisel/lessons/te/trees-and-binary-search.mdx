## AIలో వృక్షాలు ప్రతిచోటా ఉన్నాయి

*Spam* ఫిల్టర్ ఒక ఇమెయిల్ ను క్ల్అస్స్ిఫ్య్ చేసినప్పుడు లేదా డేటాబేస్ మిల్లీసెకన్లలో మీ క్రమం తీసుకురండి చేసినప్పుడు, వెనుక ఒక వృక్షం డేటా నిర్మాణం పని చేస్తుంటుంది. వృక్షాలు **హ్ిర్ార్చ్ిక్ల్ నిర్ణయాలు** ను మోడల్ చేస్తాయి - ప్రతి నోడ్ సెర్చ్ స్థలం ను తగ్గిస్తుంది, మీరు సమాధానం కు చేరుకునే వరకు.

## బైనరీ సెర్చ్ వృక్షాలు (*BSTs*)

*BST* ఎలిమెంట్‌లు ను ఇలా నిల్వ చేస్తుంది - ఏ నోడ్ కైనా, దాని **మిగిలిన** స్ుబ్ట్ర్ీ లోని అన్ని విలువలు చిన్నవిగా మరియు **సరైన** స్ుబ్ట్ర్ీ లోని అన్ని విలువలు పెద్దవిగా ఉంటాయి.

### సెర్చ్

```
function search(node, target):
    if node is null: return null
    if target == node.value: return node
    if target < node.value: return search(node.left, target)
    return search(node.right, target)
```

ప్రతి పోలిక మిగిలిన నోడ్‌లు లో సగాన్ని తొలగించండి చేస్తుంది - బ్ల్అన్క్ెడ్ వృక్షం పై O(లాగ్ n).

### *Insertion*

```
function insert(node, value):
    if node is null: return new Node(value)
    if value < node.value:
        node.left = insert(node.left, value)
    else:
        node.right = insert(node.right, value)
    return node
```

### తొలగింపు

తొలగింపు అత్యంత కష్టమైన ఆపరేషన్. మూడు సందర్భాలు ఉంటాయి:

1. **Leaf నోడ్** - దాన్ని తీసేయండి.
2. **ఒక చ్ిల్డ్** - నోడ్ ను దాని చ్ిల్డ్ తో మార్చండి చేయండి.
3. **రెండు చ్ిల్డ్ర్ెన్** - నోడ్ విలువ ను దాని లో-క్రమం స్ుక్క్ెస్స్ర్ (సరైన స్ుబ్ట్ర్ీ లో అత్యంత చిన్న విలువ) తో స్వ్అప్ చేసి, ఆ స్ుక్క్ెస్స్ర్ ను తొలగించండి చేయండి.

## *Balanced* వర్సెస్ *Unbalanced*

క్రమబద్ధమైన డేటా ను ప్ల్ైన్ *BST* లో చేర్చండి చేస్తే, అది ల్ిన్క్ెడ్ జాబితా గా మారిపోతుంది - ప్రతి ఆపరేషన్ O(n). **Self-balancing** వృక్షాలు దీన్ని ఫ్ిక్స్ చేస్తాయి:

| వృక్షం | బ్యాలెన్స్ నియమం | సాధారణ వాడుక |
|------|-------------|--------------|
| *AVL* | *Subtrees* మధ్య హ్ెిగ్హ్ట్ డ్ిఫ్ఫ్ర్ెన్క్ె ≤ 1 | లో-మెమరీ లుక్‌అప్‌లు |
| *Red-Black* | *Colour-*ఆధారిత ర్ోట్అషన్ నియమాలు | భాష ప్రామాణిక ల్ిబ్ర్ార్ిెస్ (ఉదా. *Java* *TreeMap*) |
| B-వృక్షం | ప్రతి నోడ్ లో అనేక కీలు, అన్ని ల్అవ్ెస్ ఒకే లోతు లో | డేటాబేస్‌లు మరియు ఫైల్ సిస్టమ్‌లు |

<FunFact>*PostgreSQL* మరియు *MySQL* రెండూ B-వృక్షం వ్ార్ిఅన్ట్స్ ను డిఫాల్ట్ ఇండెక్స్ నిర్మాణం గా వాడతాయి. *Branching* గుణకం 100 ఉన్న B-వృక్షం కేవలం ఐదు స్థాయులు లో ఒక బిలియన్ వరుసలు ను ఇండెక్స్ చేయగలదు.</FunFact>

## వృక్షం ట్రావర్సల్స్

ట్రావర్సల్స్ ప్రతి నోడ్ ను సరిగ్గా ఒకసారి సందర్శన చేస్తాయి. మూడు సాంప్రదాయ ఆర్డర్లు లో తేడా ఏమిటంటే ప్రస్తుత నోడ్ ను దాని చ్ిల్డ్ర్ెన్ కంటే **ఎప్పుడు** ప్రక్రియ చేస్తారు అనేది మాత్రమే.

| ట్రావర్సల్ | క్రమం | వాడుక |
|-----------|-------|-------|
| **In-క్రమం** | మిగిలిన → నోడ్ → సరైన | *BST* నుండి క్రమబద్ధమైన అవుట్‌పుట్ ఇస్తుంది |
| **Pre-క్రమం** | నోడ్ → మిగిలిన → సరైన | వృక్షం ను స్ర్ిల్ైజ్ / క్లోన్ చేయడం |
| **పోస్ట్-క్రమం** | మిగిలిన → సరైన → నోడ్ | వృక్షం ను స్అఫ్ెల్య్ తొలగించండి చేయడం; ెక్స్ప్ర్ెస్షన్ వృక్షాలు మూల్యాంకనం చేయండి చేయడం |

```
function inOrder(node):
    if node is null: return
    inOrder(node.left)
    process(node)
    inOrder(node.right)
```

<ThinkAboutIt>*Compiler* మీ కోడ్ ను *Abstract* *Syntax* వృక్షం (*AST*) గా పార్స్ చేయండి చేస్తుంది. `(3 + 5) * 2` ెక్స్ప్ర్ెస్షన్ ను వృక్షం గా నిల్వ చేసి మూల్యాంకనం చేయండి చేయడానికి ఏ ట్రావర్సల్ క్రమం వాడతారు? ఎందుకు?</ThinkAboutIt>

## హీప్‌లు మరియు ప్రాధాన్యం క్యూలు

**Heap** అనేది ఒక పూర్తి చేయండి ద్విమీయ వృక్షం, దీనిలో ప్రతి ప్ార్ెన్ట్ దాని చ్ిల్డ్ర్ెన్ కంటే పెద్దది (మ్అక్స్-హీప్) లేదా చిన్నది (నిమి-హీప్). ఇది మద్దతు చేస్తుంది:

- **చేర్చండి** - చివర జోడించు చేసి, బ్ుబ్బ్ల్ up చేయండి. O(లాగ్ n).
- **తీయండి నిమి/మ్అక్స్** - రూట్ తీసేసి, చివరి ఎలిమెంట్ ను రూట్ కు మారడం చేసి, స్ిఫ్ట్ కిందికి చేయండి. O(లాగ్ n).

హీప్‌లు పై నిర్మించిన ప్రాధాన్యం క్యూలు వీటిని శక్తి చేస్తాయి:
- **Dijkstra's అల్గారిథమ్** (తదుపరి పాఠం!) - ఎల్లప్పుడూ న్ీర్ెస్ట్ సందర్శించని నోడ్ ను ెక్స్ప్అన్డ్ చేయండి.
- **పని స్చ్ెడ్ుల్ింగ్** - OS స్చ్ెడ్ుల్ర్స్ హ్ిగ్హ్ెస్ట్-ప్రాధాన్యం ప్రక్రియ ను ప్ిక్ చేస్తాయి.
- **Beam సెర్చ్ in NLP** - ముఖ్యమైన-k అత్యంత ప్ర్ోమ్ిస్ింగ్ స్ెన్ట్ెన్క్ె క్ోమ్ప్ల్షన్స్ ను ఉంచండి.

```
function siftUp(heap, index):
    while index > 0:
        parent = (index - 1) / 2
        if heap[index] < heap[parent]:
            swap(heap, index, parent)
            index = parent
        else: break
```

## నిజమైన AI అప్లికేషన్‌లు

- **నిర్ణయం వృక్షాలు** మెషిన్ లెర్నింగ్ లో ప్రతి నోడ్ వద్ద క్ల్అస్స్ెస్ ను బాగా వేరు చేసే ఫీచర్ ద్వారా డేటా ను విభజించండి చేస్తాయి - వృక్షం నిర్మాణం యొక్క ప్రత్యక్ష అప్లికేషన్.
- **Syntax వృక్షాలు** *NLP* లో గ్ర్అమ్మ్అట్ిక్ల్ నిర్మాణం ను ప్రతినిధ్యం చేస్తుంది చేస్తాయి, స్ెన్ట్ిమెంట్ విశ్లేషణ మరియు యంత్రం ట్ర్అన్స్ల్అషన్ వంటి పనులు ను సాధ్యం చేయండి చేస్తాయి.
- **Monte Carlo వృక్షం సెర్చ్ (MCTS)** *AlphaGo* వంటి గ్అమ్ె-ప్ల్ేింగ్ AI ను శక్తి చేస్తుంది, సాధ్యమైన మ్ోవ్ెస్ ను గ్అమ్ె స్థితులు వృక్షం గా అన్వేషించండి చేస్తుంది.
- **Huffman వృక్షాలు** తరచుగా స్య్మ్బ్ోల్స్ కు చిన్నది కోడ్‌లు కేటాయించండి చేసి డేటా క్ోమ్ప్ర్ెస్స్ చేస్తాయి - మోడల్ బరువు కంప్రెషన్ లో వాడతారు.

<FunFact>స్క్ిక్ిట్-నేర్చుకోవడం నిర్ణయం వృక్షం వర్గీకరణ మోడల్ ఒక వృక్షం నిర్మిస్తుంది, దీనిలో ప్రతి అంతర్గత నోడ్ ఒక ఫీచర్ పరిమితి పరీక్ష చేస్తుంది. లోతు 20 ఉన్న శిక్షణ పొందిన మోడల్ పది లక్షలకు పైగా డ్ిస్ట్ిన్క్ట్ నిర్ణయం మార్గాలు ప్రతినిధ్యం చేస్తుంది చేయగలదు.</FunFact>

<ThinkAboutIt>మీరు ఆటోకంప్లీట్ సిస్టమ్ నిర్మిస్తుంటే, *BST*, హీప్, లేదా వేరే వృక్షం నిర్మాణం (ట్రై వంటిది) - ఏది వాడతారు? ఏ ఆపరేషన్లు వేగంగా ఉండాలో ఆలోచించండి.</ThinkAboutIt>

## ముఖ్యమైన విషయాలు

1. *BSTs* O(లాగ్ n) సెర్చ్, చేర్చండి, మరియు తొలగించండి అందిస్తాయి - కానీ బ్ల్అన్క్ెడ్ అయినప్పుడు మాత్రమే.
2. ట్రావర్సల్ క్రమం వృక్షం నుండి ఏ సమాచారం తీయండి చేస్తారో నిర్ణయిస్తుంది.

## హ్యాషింగ్ ఎందుకు ముఖ్యం

ఒక సిఫార్సు ఇంజిన్ మీరు ఇప్పటికే ఒక సినిమా చూశారో లేదో తనిఖీ చేయాలనుకుంటే - తన కేటలాగ్ లో లక్షల సినిమాల్లో - అది ఒక జాబితా ను స్కాన్ చేయడం భరించలేడు. ఒక **హ్యాష్ పట్టిక** ఆ ప్రశ్నకు O(1) సగటు సమయంలో సమాధానం ఇస్తుంది.

హ్యాష్ tables ప్రొడక్షన్ సాఫ్ట్‌వేర్ లో అత్యధికంగా ఉపయోగించే డేటా నిర్మాణం, మరియు AI సిస్టమ్‌లు ఫీచర్ లుక్‌అప్‌లు, క్యాషింగ్ మరియు డీడూప్లికేషన్ కోసం వీటిపై ఎక్కువగా ఆధారపడతాయి.

## హ్యాషింగ్ ఎలా పని చేస్తుంది

ఒక **హ్యాష్ ఫంక్షన్** ఒక ఇన్‌పుట్ (స్ట్రింగ్, సంఖ్య లేదా ఆబ్జెక్ట్) తీసుకుని ఒక పూర్ణసంఖ్య రిటర్న్ చేస్తుంది - అదే **హ్యాష్ కోడ్**. ఆ కోడ్ ను మాడ్యులో ద్వారా **బకెట్ ఇండెక్స్** కు మ్యాప్ చేస్తారు:

```
index = hashFunction(key) % numberOfBuckets
```

మంచి హ్యాష్ ఫంక్షన్ యొక్క లక్షణాలు:
- **Deterministic** - ఒకే ఇన్‌పుట్ ఎల్లప్పుడూ ఒకే అవుట్‌పుట్ ఇస్తుంది.
- **సమానంగా పంపిణీ చేయేది** - కీలను బకెట్ల అంతటా సమానంగా విస్తరిస్తుంది.
- **వేగంగా** - కీ పరిమాణం కి అనుగుణంగా O(1) లో కంప్యూట్ అవుతుంది.

### ఉదాహరణ

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

ఇది ఉద్దేశపూర్వకంగా సరళంగా ఉంచబడింది - ప్రొడక్షన్ హ్యాష్ ఫంక్షన్‌లు అయిన MurmurHash3 లేదా xxHash మెరుగైన వితరణ కోసం బిట్-కలయిక ఉపయోగిస్తాయి.

## ఢీకొను నిర్వహణ

ఢీకొన్లు తప్పనిసరి (పిజన్‌హోల్ సూత్రం). రెండు ప్రధాన వ్యూహాలు:

### Chaining

ప్రతి బకెట్ లో ఒక లింక్డ్ జాబితా (లేదా చిన్న అరే) ఉంటుంది. ఢీకొనే కీలను జాబితా కు చేర్చుతారు.

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**ప్రయోజనాలు:** సరళం, మోస్తరు లోడ్ లో బాగా పని చేస్తుంది.
**అప్రయోజనాలు:** పాయింటర్ వెంటాడటం వల్ల క్యాష్-unfriendly.

### ఓపెన్ అడ్రెసింగ్

అన్ని ఎంట్రీలు నేరుగా అరే లోనే ఉంటాయి. ఢీకొను అయినప్పుడు, తదుపరి ఖాళీ స్లాట్ ను **ప్రోబ్** చేస్తారు.

- **Linear ప్రోబింగ్:** ఇండెక్స్+1, ఇండెక్స్+2, … తనిఖీ చేయండి.
- **Quadratic ప్రోబింగ్:** ఇండెక్స్+1², ఇండెక్స్+2², … తనిఖీ చేయండి.
- **Double హ్యాషింగ్:** దశ పరిమాణం నిర్ణయించడానికి రెండవ హ్యాష్ ఫంక్షన్ ఉపయోగించండి.

**ప్రయోజనాలు:** మెరుగైన క్యాష్ పనితీరు, అదనపు పాయింటర్లు లేవు.
**అప్రయోజనాలు:** గుంపులుగా చేరడం పనితీరు ను దెబ్బతీయవచ్చు; తొలగింపు కష్టం (టూంబ్‌స్టోన్‌లు అవసరం).

<FunFact>Python నిఘంటువులు కస్టమ్ ప్రోబింగ్ వరుస తో ఓపెన్ అడ్రెసింగ్ ఉపయోగిస్తాయి. CPython యొక్క dict అమలు చాలా మెరుగుపరచబడింది - ఆధునిక హార్డ్‌వేర్ పై సెకనుకు 5 కోట్ల కంటే ఎక్కువ లుక్‌అప్‌లు ప్రాసెస్ చేస్తుంది.</FunFact>

## లోడ్ Factor మరియు మళ్లీ హ్యాష్ చేయడం

**లోడ్ గుణకం** α = ఎంట్రీలు సంఖ్య / బకెట్లు సంఖ్య. α పెరిగేకొద్దీ, ఢీకొన్లు పెరుగుతాయి మరియు పనితీరు తగ్గుతుంది.

| లోడ్ Factor | అంచనా లుక్‌అప్‌లు (గొలుసుదారి) |
|------------|--------------------------|
| 0.5 | ~1.25 |
| 0.75 | ~1.375 |
| 1.0 | ~1.5 |
| 2.0 | ~2.0 |

చాలా అమలు రూపాలు α ఒక పరిమితి (సాధారణంగా 0.75) దాటినప్పుడు **మళ్లీ హ్యాష్** చేస్తాయి: పెద్ద అరే కేటాయించి, ప్రతి కీ యొక్క ఇండెక్స్ తిరిగి కంప్యూట్ చేసి, మళ్లీ చొప్పిస్తాయి.

మళ్లీ హ్యాష్ చేయడం O(n) అయినా అరుదుగా జరుగుతుంది, కాబట్టి చొప్పింపు యొక్క **అమోర్టైజ్డ్** ఖర్చు O(1) గానే ఉంటుంది.

<ThinkAboutIt>మళ్లీ హ్యాష్ చేయడం పట్టిక పరిమాణం ను రెట్టు చేసి ప్రతి ఎలిమెంట్ ను తిరిగి చేర్చుతుంది. మీ AI సిస్టమ్ ప్రత్యక్ష రిక్వెస్ట్ ప్రవాహం ను నిర్వహిస్తుంటే, ఈ విరామం లేటెన్సీ ఎగసిపాటు కు కారణమవుతుంది. మళ్లీ హ్యాష్ చేయడం ఖర్చు ను ఒకేసారి చేయకుండా అనేక చొప్పింపులు లో ఎలా విభజించవచ్చు?</ThinkAboutIt>

## బ్లూమ్ ఫిల్టర్లు: సంభావ్యత ఆధారిత సభ్యత్వం

ఒక **Bloom ఫిల్టర్** "ఈ ఎలిమెంట్ సెట్ లో ఉందా?" అనే ప్రశ్నకు సమాధానం ఇస్తుంది:
- **ఖచ్చితంగా లేదు** - ఎలిమెంట్ తప్పకుండా లేదు.
- **బహుశా ఉంది** - ఎలిమెంట్ ఉండే అవకాశం ఉంది (తక్కువ తప్పుడు-positive రేట్).

ఇది _k_ హ్యాష్ ఫంక్షన్‌లు మరియు ఒక బిట్ అరే ఉపయోగిస్తుంది. చేర్చేటప్పుడు _k_ బిట్‌లు సెట్ అవుతాయి; శోధనలో అన్ని _k_ బిట్‌లు సెట్ అయ్యాయో తనిఖీ చేస్తారు.

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**AIలో ఉపయోగాలు:** ఒక URL ఇప్పటికే క్రాల్ అయిందో తనిఖీ చేయడం, spam ఫిల్టరింగ్ మరియు క్యాషింగ్ పొరలు లో అనవసరమైనవి డేటాబేస్ క్వెరీలు ను నివారించడం.

<FunFact>Google Chrome లక్షల తెలిసిన హానికరమైన URLలు ఉన్న బ్లూమ్ ఫిల్టర్ ఉపయోగిస్తుంది. ఏదైనా పేజీ లోడ్ చేయడానికి ముందు, మీ బ్రౌజర్ ఫిల్టర్ ను తనిఖీ చేస్తుంది - అది "బహుశా ఉంది" అంటే, Chrome నిర్ధారించడానికి పూర్తి జాబితా ను తీసుకొస్తుంది.</FunFact>

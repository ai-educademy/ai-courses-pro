## హ్యాషింగ్ ఎందుకు ముఖ్యం

ఒక సిఫార్సు ఇంజిన్ మీరు ఇప్పటికే ఒక సినిమా చూశారో లేదో తనిఖీ చేయాలనుకుంటే - తన catalogue లో లక్షల సినిమాల్లో - అది ఒక జాబితా ను scan చేయడం afford చేయలేదు. ఒక **హ్యాష్ పట్టిక** ఆ ప్రశ్నకు O(1) సగటు సమయంలో సమాధానం ఇస్తుంది.

హ్యాష్ tables ప్రొడక్షన్ సాఫ్ట్‌వేర్ లో అత్యధికంగా ఉపయోగించే డేటా నిర్మాణం, మరియు AI సిస్టమ్‌లు ఫీచర్ లుక్‌అప్‌లు, క్యాషింగ్ మరియు డీడూప్లికేషన్ కోసం వీటిపై ఎక్కువగా ఆధారపడతాయి.

## హ్యాషింగ్ ఎలా పని చేస్తుంది

ఒక **హ్యాష్ ఫంక్షన్** ఒక ఇన్‌పుట్ (string, సంఖ్య లేదా object) తీసుకుని ఒక integer రిటర్న్ చేస్తుంది - అదే **హ్యాష్ కోడ్**. ఆ కోడ్ ను modulo ద్వారా **బకెట్ ఇండెక్స్** కు మ్యాప్ చేస్తారు:

```
index = hashFunction(key) % numberOfBuckets
```

మంచి హ్యాష్ ఫంక్షన్ యొక్క లక్షణాలు:
- **Deterministic** - ఒకే ఇన్‌పుట్ ఎల్లప్పుడూ ఒకే అవుట్‌పుట్ ఇస్తుంది.
- **Uniform** - కీలు ను buckets అంతటా సమానంగా విస్తరించండి చేస్తుంది.
- **వేగంగా** - కీ పరిమాణం కి అనుగుణంగా O(1) లో కంప్యూట్ అవుతుంది.

### ఉదాహరణ

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

ఇది ఉద్దేశపూర్వకంగా సరళంగా ఉంచబడింది - ప్రొడక్షన్ హ్యాష్ ఫంక్షన్‌లు అయిన MurmurHash3 లేదా xxHash మెరుగైన వితరణ కోసం బిట్-mixing ఉపయోగిస్తాయి.

## Collision నిర్వహణ

Collisions తప్పనిసరి (pigeonhole principle). రెండు ప్రధాన వ్యూహాలు:

### Chaining

ప్రతి బకెట్ లో ఒక linked జాబితా (లేదా చిన్న అరే) ఉంటుంది. Collide అయ్యే కీలు ను జాబితా కు append చేస్తారు.

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**ప్రయోజనాలు:** సరళం, మోస్తరు లోడ్ లో బాగా పని చేస్తుంది.
**అప్రయోజనాలు:** పాయింటర్ chasing వల్ల క్యాష్-unfriendly.

### Open Addressing

అన్ని entries నేరుగా అరే లోనే ఉంటాయి. Collision అయినప్పుడు, తదుపరి ఖాళీ slot ను **probe** చేస్తారు.

- **Linear probing:** ఇండెక్స్+1, ఇండెక్స్+2, … తనిఖీ చేయండి.
- **Quadratic probing:** ఇండెక్స్+1², ఇండెక్స్+2², … తనిఖీ చేయండి.
- **Double హ్యాషింగ్:** దశ పరిమాణం నిర్ణయించడానికి రెండవ హ్యాష్ ఫంక్షన్ ఉపయోగించండి.

**ప్రయోజనాలు:** మెరుగైన క్యాష్ పనితీరు, అదనపు పాయింటర్లు లేవు.
**అప్రయోజనాలు:** Clustering పనితీరు ను దెబ్బతీయవచ్చు; deletion కష్టం (tombstones అవసరం).

<FunFact>Python dictionaries కస్టమ్ probing sequence తో open addressing ఉపయోగిస్తాయి. CPython యొక్క dict implementation చాలా optimize చేయబడి ఉంది - ఆధునిక hardware పై సెకనుకు 5 కోట్ల కంటే ఎక్కువ లుక్‌అప్‌లు ప్రక్రియ చేస్తుంది.</FunFact>

## లోడ్ Factor మరియు Rehashing

**లోడ్ factor** α = entries సంఖ్య / buckets సంఖ్య. α పెరిగేకొద్దీ, collisions పెరుగుతాయి మరియు పనితీరు తగ్గుతుంది.

| లోడ్ Factor | అంచనా లుక్‌అప్‌లు (chaining) |
|------------|--------------------------|
| 0.5 | ~1.25 |
| 0.75 | ~1.375 |
| 1.0 | ~1.5 |
| 2.0 | ~2.0 |

చాలా implementations α ఒక threshold (సాధారణంగా 0.75) దాటినప్పుడు **rehash** చేస్తాయి: పెద్ద అరే allocate చేసి, ప్రతి కీ యొక్క ఇండెక్స్ తిరిగి కంప్యూట్ చేసి, reinsert చేస్తాయి.

Rehashing O(n) అయినా అరుదుగా జరుగుతుంది, కాబట్టి insertion యొక్క **amortised** ఖర్చు O(1) గానే ఉంటుంది.

<ThinkAboutIt>Rehashing పట్టిక పరిమాణం ను double చేసి ప్రతి ఎలిమెంట్ ను తిరిగి చేర్చండి చేస్తుంది. మీ AI సిస్టమ్ ప్రత్యక్ష రిక్వెస్ట్ stream ను నిర్వహించు చేస్తుంటే, ఈ pause లేటెన్సీ spike కు కారణమవుతుంది. Rehashing ఖర్చు ను ఒకేసారి చేయకుండా అనేక insertions లో ఎలా విభజించవచ్చు?</ThinkAboutIt>

|----------|------------------------------|
| **Embedding tables** | టోకెన్ IDs ను O(1) లో dense వెక్టర్ representations కు మ్యాప్ చేయడం |

| **క్యాషింగ్ పొరలు** | ఇన్‌పుట్ హ్యాష్ ద్వారా keyed precomputed మోడల్ అంచనాలు ను నిల్వ చేయడం |
| **లెక్క-నిమి sketch** | అనేక హ్యాష్ ఫంక్షన్‌లు ఉపయోగించి స్ట్రీమింగ్ డేటా లో approximate frequency counts |

## బ్లూమ్ ఫిల్టర్లు: సంభావ్యత ఆధారిత సభ్యత్వం

ఒక **Bloom ఫిల్టర్** "ఈ ఎలిమెంట్ సెట్ లో ఉందా?" అనే ప్రశ్నకు సమాధానం ఇస్తుంది:
- **ఖచ్చితంగా లేదు** - ఎలిమెంట్ తప్పకుండా లేదు.
- **బహుశా ఉంది** - ఎలిమెంట్ ఉండే అవకాశం ఉంది (తక్కువ తప్పుడు-positive రేట్).

ఇది _k_ హ్యాష్ ఫంక్షన్‌లు మరియు ఒక బిట్ అరే ఉపయోగిస్తుంది. చేర్చండి చేసేటప్పుడు _k_ బిట్‌లు సెట్ అవుతాయి; lookup లో అన్ని _k_ బిట్‌లు సెట్ అయ్యాయో తనిఖీ చేస్తారు.

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**AIలో ఉపయోగాలు:** ఒక URL ఇప్పటికే క్రాల్ అయిందో తనిఖీ చేయడం, spam ఫిల్టరింగ్ మరియు క్యాషింగ్ పొరలు లో redundant డేటాబేస్ క్వెరీలు ను నివారించడం.

<FunFact>Google Chrome లక్షల తెలిసిన హానికరమైన URLs ఉన్న బ్లూమ్ ఫిల్టర్ ఉపయోగిస్తుంది. ఏదైనా పేజీ లోడ్ చేయడానికి ముందు, మీ బ్రౌజర్ ఫిల్టర్ ను తనిఖీ చేస్తుంది - అది "బహుశా ఉంది" అంటే, Chrome నిర్ధారించడానికి పూర్తి జాబితా ను fetch చేస్తుంది.</FunFact>

## సెట్లు వర్సెస్ మ్యాప్‌లు: ఏది ఎప్పుడు ఉపయోగించాలి

| నిర్మాణం | ఏమి నిల్వ చేస్తుంది | ఎప్పుడు ఉపయోగించాలి |
|-----------|---------------------|----------------------|
| **సెట్** | కీలు మాత్రమే | సభ్యత్వం తనిఖీలు కావాలి - "ఇది నేను ఇంతకు ముందు చూశానా?" |
| **మ్యాప్** | కీ–విలువ pairs | ప్రతి కీ తో డేటా associate చేయాలి - "ఈ కీ యొక్క విలువ ఏమిటి?" |

రెండూ హ్యాష్ tables పై ఆధారపడి ఉంటాయి మరియు సగటున O(1) ఆపరేషన్లు అందిస్తాయి. డీడూప్లికేషన్, visited ట్రాకింగ్ మరియు uniqueness constraints కోసం **సెట్** ఎంచుకోండి. లుక్‌అప్‌లు, caches మరియు configuration నిల్వలు కోసం **మ్యాప్** ఎంచుకోండి.

<ThinkAboutIt>ఒక AI కంటెంట్ మోడరేషన్ సిస్టమ్ incoming సందేశాలు ను 1 కోటి banned phrases blocklist తో తనిఖీ చేయాలి. మీరు హ్యాష్ సెట్, బ్లూమ్ ఫిల్టర్ లేదా రెండూ ఉపయోగిస్తారా? మెమరీ, వేగం మరియు ఖచ్చితత్వం లో ట్రేడ్‌ఆఫ్‌లు ఏమిటి?</ThinkAboutIt>

## ముఖ్యమైన అంశాలు

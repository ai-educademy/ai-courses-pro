## హ్యాషింగ్ ఎందుకు ముఖ్యం

ఒక సిఫార్సు ఇంజిన్ మీరు ఇప్పటికే ఒక సినిమా చూశారో లేదో తనిఖీ చేయాలనుకుంటే - తన క్అట్ల్ోగ్ుె లో లక్షల సినిమాల్లో - అది ఒక జాబితా ను స్కాన్ చేయండి చేయడం అఫ్ఫ్ర్డ్ చేయలేదు. ఒక **హ్యాష్ పట్టిక** ఆ ప్రశ్నకు O(1) సగటు సమయంలో సమాధానం ఇస్తుంది.

హ్యాష్ పట్టికలు ప్రొడక్షన్ సాఫ్ట్‌వేర్ లో అత్యధికంగా ఉపయోగించే డేటా నిర్మాణం, మరియు AI సిస్టమ్‌లు ఫీచర్ లుక్‌అప్‌లు, క్యాషింగ్ మరియు డీడూప్లికేషన్ కోసం వీటిపై ఎక్కువగా ఆధారపడతాయి.

## హ్యాషింగ్ ఎలా పని చేస్తుంది

ఒక **హ్యాష్ ఫంక్షన్** ఒక ఇన్‌పుట్ (స్ట్ర్ింగ్, సంఖ్య లేదా ోబ్జ్ెక్ట్) తీసుకుని ఒక ిన్ట్ెగ్ర్ రిటర్న్ చేస్తుంది - అదే **హ్యాష్ కోడ్**. ఆ కోడ్ ను మ్ోడ్ుల్ో ద్వారా **బకెట్ ఇండెక్స్** కు మ్యాప్ చేస్తారు:

```
index = hashFunction(key) % numberOfBuckets
```

మంచి హ్యాష్ ఫంక్షన్ యొక్క లక్షణాలు:
- **Deterministic** - ఒకే ఇన్‌పుట్ ఎల్లప్పుడూ ఒకే అవుట్‌పుట్ ఇస్తుంది.
- **Uniform** - కీలు ను బ్ుక్ెట్స్ అంతటా సమానంగా విస్తరించండి చేస్తుంది.
- **వేగంగా** - కీ పరిమాణం కి అనుగుణంగా O(1) లో కంప్యూట్ అవుతుంది.

### ఉదాహరణ

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

ఇది ఉద్దేశపూర్వకంగా సరళంగా ఉంచబడింది - ప్రొడక్షన్ హ్యాష్ ఫంక్షన్‌లు అయిన *MurmurHash*3 లేదా క్స్క్స్హ్అష్ మెరుగైన వితరణ కోసం బిట్-మ్ిక్స్ింగ్ ఉపయోగిస్తాయి.

## ఢీకొనడం నిర్వహణ

ఢీకొనడాలు తప్పనిసరి (ప్ిగ్ెోన్హ్ోల్ ప్ర్ిన్క్ిప్ల్). రెండు ప్రధాన వ్యూహాలు:

### చైనింగ్

ప్రతి బకెట్ లో ఒక ల్ిన్క్ెడ్ జాబితా (లేదా చిన్న అరే) ఉంటుంది. *Collide* అయ్యే కీలు ను జాబితా కు అప్ప్ెన్డ్ చేస్తారు.

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**ప్రయోజనాలు:** సరళం, మోస్తరు లోడ్ లో బాగా పని చేస్తుంది.
**అప్రయోజనాలు:** పాయింటర్ చ్అస్ింగ్ వల్ల క్యాష్-ున్ఫ్ర్ిెన్డ్ల్య్.

### తెరిచి ఉన్న *Addressing*

అన్ని ఎంట్రీలు నేరుగా అరే లోనే ఉంటాయి. ఢీకొనడం అయినప్పుడు, తదుపరి ఖాళీ స్ల్ోట్ ను **ప్ర్ోబ్ె** చేస్తారు.

- **రేఖీయ ప్రోబింగ్:** ఇండెక్స్+1, ఇండెక్స్+2, … తనిఖీ చేయండి.
- **Quadratic ప్రోబింగ్:** ఇండెక్స్+1², ఇండెక్స్+2², … తనిఖీ చేయండి.
- **రెట్టి హ్యాషింగ్:** దశ పరిమాణం నిర్ణయించడానికి రెండవ హ్యాష్ ఫంక్షన్ ఉపయోగించండి.

**ప్రయోజనాలు:** మెరుగైన క్యాష్ పనితీరు, అదనపు పాయింటర్లు లేవు.
**అప్రయోజనాలు:** *Clustering* పనితీరు ను దెబ్బతీయవచ్చు; డ్ెల్షన్ కష్టం (ట్ోమ్బ్స్ట్ోన్ెస్ అవసరం).

<FunFact>*Python* డ్ిక్షన్ార్ిెస్ కస్టమ్ ప్రోబింగ్ క్రమం తో తెరిచి ఉన్న అడ్డ్ర్ెస్స్ింగ్ ఉపయోగిస్తాయి. *CPython* యొక్క డ్ిక్ట్ అమలు చాలా మెరుగుపరచండి చేయబడి ఉంది - ఆధునిక హార్డ్‌వేర్ పై సెకనుకు 5 కోట్ల కంటే ఎక్కువ లుక్‌అప్‌లు ప్రక్రియ చేస్తుంది.</FunFact>

## లోడ్ గుణకం మరియు *Rehashing*

**లోడ్ గుణకం** α = ఎంట్రీలు సంఖ్య / బ్ుక్ెట్స్ సంఖ్య. α పెరిగేకొద్దీ, ఢీకొనడాలు పెరుగుతాయి మరియు పనితీరు తగ్గుతుంది.

| లోడ్ గుణకం | అంచనా లుక్‌అప్‌లు (చైనింగ్) |
|------------|--------------------------|
| 0.5 | ~1.25 |
| 0.75 | ~1.375 |
| 1.0 | ~1.5 |
| 2.0 | ~2.0 |

చాలా ిమ్ప్ల్మెంట్అషన్స్ α ఒక పరిమితి (సాధారణంగా 0.75) దాటినప్పుడు **ర్ెహ్అష్** చేస్తాయి: పెద్ద అరే ల్ల్ోక్అట్ె చేసి, ప్రతి కీ యొక్క ఇండెక్స్ తిరిగి కంప్యూట్ చేసి, ర్ెిన్స్ర్ట్ చేస్తాయి.

*Rehashing* O(n) అయినా అరుదుగా జరుగుతుంది, కాబట్టి ిన్స్ర్షన్ యొక్క **అమార్టైజ్డ్** ఖర్చు O(1) గానే ఉంటుంది.

<ThinkAboutIt>*Rehashing* పట్టిక పరిమాణం ను రెట్టి చేసి ప్రతి ఎలిమెంట్ ను తిరిగి చేర్చండి చేస్తుంది. మీ AI సిస్టమ్ ప్రత్యక్ష రిక్వెస్ట్ స్ట్రీమ్ ను నిర్వహించు చేస్తుంటే, ఈ విరామం లేటెన్సీ ఒక్కసారిగా పెరుగుదల కు కారణమవుతుంది. *Rehashing* ఖర్చు ను ఒకేసారి చేయకుండా అనేక చేర్పులు లో ఎలా విభజించవచ్చు?</ThinkAboutIt>

## బ్లూమ్ ఫిల్టర్లు: సంభావ్యత ఆధారిత సభ్యత్వం

ఒక **Bloom ఫిల్టర్** "ఈ ఎలిమెంట్ సెట్ లో ఉందా?" అనే ప్రశ్నకు సమాధానం ఇస్తుంది:
- **ఖచ్చితంగా లేదు** - ఎలిమెంట్ తప్పకుండా లేదు.
- **బహుశా ఉంది** - ఎలిమెంట్ ఉండే అవకాశం ఉంది (తక్కువ తప్పుడు-ప్ోస్ిట్ివ్ రేట్).

ఇది _k_ హ్యాష్ ఫంక్షన్‌లు మరియు ఒక బిట్ అరే ఉపయోగిస్తుంది. చేర్చండి చేసేటప్పుడు _k_ బిట్‌లు సెట్ అవుతాయి; లుక్‌అప్ లో అన్ని _k_ బిట్‌లు సెట్ అయ్యాయో తనిఖీ చేస్తారు.

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

## అనుసంధానం సమస్య

మీ దగ్గర నోడ్‌లు ఉన్న నెట్‌వర్క్ ఉందనుకోండి. మీకు రెండు రకాల ప్రశ్నలు వస్తూ ఉంటాయి: *నోడ్ A ను నోడ్ B తో కలపండి* మరియు *A, B కలిసివున్నాయా ఉన్నాయా?* ప్రతి ప్రశ్న కి BFS/DFS చేస్తే మొత్తం గ్రాఫ్ సంచరించాల్సి వస్తుంది. లక్షల చర్యలు ఉన్నప్పుడు ఇది చాలా నెమ్మదిగా ఉంటుంది.

**Union-Find** ఈ రెండు ప్రశ్నలు కు దాదాపు స్థిర సమయం లో సమాధానం ఇస్తుంది.

## సరళ విధానం - క్విక్ ఫైండ్

ప్రతి నోడ్ కి ఒక భాగం ID నిల్వ చేయండి. అనుసంధానం తనిఖీ చేయడానికి IDలను O(1)లో పోల్చండి. కానీ రెండు భాగాలు మర్జ్ చేయడానికి ఒక గుంపు లోని ప్రతి సభ్యుడిని నవీకరించాలి - ప్రతి యూనియన్ కి O(n).

```
IDs:  [0, 0, 0, 3, 3]
       └─group 0─┘ └group 3┘
union(0, 3) → update all 3s to 0 → O(n)
```

మనకు ఏదైనా మెరుగైనది కావాలి.

## Union-Find డేటా నిర్మాణం

ప్రతి నోడ్ ఒక **తల్లి నోడ్** వైపు స్థానం చేస్తుంది. ప్రతి వృక్షం యొక్క రూట్ ఆ భాగం యొక్క representative. రెండు నోడ్‌లు ఒకే రూట్ పంచుకుంటే మాత్రమే అవి కలిసిన.

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
```

## ఫైండ్‌తో మార్గం కుదింపు

లోతైన వృక్షం లో తల్లి నోడ్ పాయింటర్లను అనుసరించడం నెమ్మది గా ఉంటుంది. **మార్గం కుదింపు** వృక్షం ని సమతలంగా చేస్తుంది - ప్రతి సందర్శించిన నోడ్ ని నేరుగా రూట్ కి స్థానం చేయిస్తుంది.

```python
def find(self, x):
    if self.parent[x] != x:
        self.parent[x] = self.find(self.parent[x])
    return self.parent[x]
```

నోడ్ 4 ని find చేయడానికి ముందు మరియు తర్వాత:

```
Before:  0←1←2←3←4     After:  0←1
                                0←2
                                0←3
                                0←4
```

## Union ద్వారా ర్యాంక్

ఎల్లప్పుడూ చిన్న వృక్షం ని పెద్ద వృక్షం కింద జత చేయండి. ఇది వృక్షం ఎత్తు ని లాగారిథ్మిక్ గా ఉంచుతుంది మరియు క్షీణించిన గొలుసులు ఏర్పడకుండా చేస్తుంది.

```python
def union(self, x, y):
    rx, ry = self.find(x), self.find(y)
    if rx == ry:
        return False
    if self.rank[rx] < self.rank[ry]:
        rx, ry = ry, rx
    self.parent[ry] = rx
    if self.rank[rx] == self.rank[ry]:
        self.rank[rx] += 1
    return True
```

## క్రుస్కల్ MST అల్గారిథమ్

Union-Find **క్రుస్కల్ అల్గారిథమ్** ని శక్తి చేస్తుంది - కనిష్ఠ స్పానింగ్ వృక్షాలు కోసం:

1. అన్ని ఎడ్జ్‌లను బరువు ప్రకారం క్రమబద్ధీకరించండి
2. ప్రతి ముందంజ (u, v) కి, `find(u) ≠ find(v)` అయితే, దాన్ని జోడించి `union(u, v)` చేయండి
3. n − 1 ఎడ్జ్‌లు వచ్చినప్పుడు ఆపండి

Union-Find చక్రాలను నిరోధిస్తుంది - ముందంజ చివరలు ఇప్పటికే ఒకే రూట్ పంచుకుంటే ఎడ్జ్ తిరస్కరించబడుతుంది. మొత్తం సమయం: **O(E లాగ్ E)** - క్రమబద్ధీకరణ ఆధిపత్యం చూపుతుంది.

<ThinkAboutIt>క్రుస్కల్ అల్గారిథమ్ చక్రాలు గుర్తించడానికి Union-Find వాడుతుంది. DFS తో చక్రం ఎలా గుర్తిస్తారు, మరియు ఇక్కడ Union-Find ఎందుకు మరింత సహజం?</ThinkAboutIt>

## సాంప్రదాయ సమస్యలు

### సంఖ్య of కలిసిన భాగాలు

Union-Find ని n నోడ్‌లు తో ప్రారంభించండి. ప్రతి ముందంజ ని `union` తో ప్రాసెస్ చేయండి. చివరలో వేర్వేరు రూట్లను లెక్కించండి.

### ఖాతాలు మర్జ్ (LeetCode 721)

ప్రతి ఖాతా లో ఇమెయిళ్లు ఉంటాయి. రెండు ఖాతాలు ఒక ఇమెయిల్ పంచుకుంటే, అవి ఒకే వ్యక్తికి చెందినవి. పంచుకున్న ఇమెయిళ్లు ఆధారంగా ఖాతాలను యూనియన్ చేసి, గుంపు మరియు క్రమబద్ధీకరించండి.

### Redundant కనెక్షన్ (LeetCode 684)

ఒక వృక్షం ఇవ్వబడింది దానిలో ఒక extra ముందంజ ఉంది - అనవసరమైనవి ముందంజ కనుగొనండి. ఎడ్జ్‌లను క్రమం లో ప్రాసెస్ చేయండి - `union` మొదటిసారి `False` రిటర్న్ చేసే ముందంజ (ఇప్పటికే కలిసిన) అదే సమాధానం.

<FunFact>Union-Find రెండు మెరుగుదలలు తో O(α(n)) లో నడుస్తుందని రుజువు ని Tarjan 1975 లో ప్రచురించారు - ఇది కంప్యూటర్ సైన్స్ లో అత్యంత అందమైన అమోర్టైజ్డ్ విశ్లేషణలు లో ఒకటిగా పరిగణించబడుతుంది.</FunFact>

## Union-Find వర్సెస్ BFS/DFS - ఎప్పుడు ఏది ఎంచుకోవాలి

| సన్నివేశం | ఉత్తమ ఎంపిక |
|----------|-------------|
| మళ్ళీ మళ్ళీ అనుసంధానం క్వెరీలు | Union-Find |
| ఒకే సంచారం / చిన్నదైన మార్గం | BFS/DFS |
| దశలవారీ ముందంజ చేర్పులు | Union-Find |
| ముందంజ తొలగింపులు (డైనమిక్ గ్రాఫ్) | BFS/DFS (లేదా ఆఫ్‌లైన్ UF) |
| క్రుస్కల్ MST | Union-Find |
| టోపాలజికల్ క్రమబద్ధీకరణ / దిశా ఉన్న గ్రాఫ్ లో చక్రం | DFS |

ఎడ్జ్‌లను *దశలవారీగా* ప్రాసెస్ చేస్తూ వేగంగా అనుసంధానం తనిఖీలు కావాలంటే Union-Find బాగా పని చేస్తుంది. ఒకే సారి సంచరించాల్సి వస్తే లేదా మార్గ సమాచారం కావాలంటే BFS/DFS వాడండి.

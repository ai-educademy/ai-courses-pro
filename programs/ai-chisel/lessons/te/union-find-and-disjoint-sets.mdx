## Connectivity సమస్య

మీ దగ్గర nodes ఉన్న నెట్‌వర్క్ ఉందనుకోండి. మీకు రెండు రకాల queries వస్తూ ఉంటాయి: *node A ను node B తో connect చేయండి* మరియు *A, B connected గా ఉన్నాయా?* ప్రతి query కి BFS/DFS చేస్తే మొత్తం graph traverse చేయాల్సి వస్తుంది. లక్షల operations ఉన్నప్పుడు ఇది చాలా నెమ్మదిగా ఉంటుంది.

**Union-Find** ఈ రెండు queries కు దాదాపు constant time లో సమాధానం ఇస్తుంది.

## Naive విధానం - Quick Find

ప్రతి నోడ్ కి ఒక భాగం ID నిల్వ చేయండి. Connectivity తనిఖీ చేయడానికి IDs ని O(1) లో పోల్చండి చేయండి. కానీ రెండు భాగాలు మర్జ్ చేయడానికి ఒక గుంపు లోని ప్రతి member ని నవీకరించు చేయాలి - ప్రతి union కి O(n).

```
IDs:  [0, 0, 0, 3, 3]
       └─group 0─┘ └group 3┘
union(0, 3) → update all 3s to 0 → O(n)
```

మనకు ఏదైనా మెరుగైనది కావాలి.

## Union-Find డేటా నిర్మాణం

ప్రతి నోడ్ ఒక **parent** వైపు స్థానం చేస్తుంది. ప్రతి వృక్షం యొక్క రూట్ ఆ భాగం యొక్క representative. రెండు నోడ్‌లు ఒకే రూట్ పంచుకోండి చేస్తే మాత్రమే అవి కలిసిన.

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
```

## Find తో మార్గం Compression

లోతైన వృక్షం లో parent పాయింటర్లు అనుసరించండి చేయడం నెమ్మది గా ఉంటుంది. **మార్గం compression** వృక్షం ని flat చేస్తుంది - ప్రతి visited నోడ్ ని directly రూట్ కి స్థానం చేయిస్తుంది.

```python
def find(self, x):
    if self.parent[x] != x:
        self.parent[x] = self.find(self.parent[x])
    return self.parent[x]
```

నోడ్ 4 ని find చేయడానికి ముందు మరియు తర్వాత:

```
Before:  0←1←2←3←4     After:  0←1
                                0←2
                                0←3
                                0←4
```

## Union ద్వారా ర్యాంక్

ఎల్లప్పుడూ చిన్న వృక్షం ని పెద్ద వృక్షం కింద attach చేయండి. ఇది వృక్షం height ని logarithmic గా ఉంచుతుంది మరియు degenerate chains ఏర్పడకుండా చేస్తుంది.

```python
def union(self, x, y):
    rx, ry = self.find(x), self.find(y)
    if rx == ry:
        return False
    if self.rank[rx] < self.rank[ry]:
        rx, ry = ry, rx
    self.parent[ry] = rx
    if self.rank[rx] == self.rank[ry]:
        self.rank[rx] += 1
    return True
```

## Kruskal's MST అల్గారిథమ్

Union-Find **Kruskal's అల్గారిథమ్** ని శక్తి చేస్తుంది - కనిష్ఠ Spanning వృక్షాలు కోసం:

1. అన్ని ఎడ్జ్‌లు ని బరువు ప్రకారం క్రమబద్ధీకరించండి చేయండి
2. ప్రతి ముందంజ (u, v) కి, `find(u) ≠ find(v)` అయితే, దాన్ని జోడించు చేసి `union(u, v)` చేయండి
3. n − 1 ఎడ్జ్‌లు వచ్చినప్పుడు ఆపండి

Union-Find cycles ని నిరోధించండి చేస్తుంది - endpoints ఇప్పటికే ఒకే రూట్ పంచుకోండి చేస్తుంటే ముందంజ తిరస్కరించండి అవుతుంది. మొత్తం సమయం: **O(E లాగ్ E)** - sorting dominate చేస్తుంది.

<ThinkAboutIt>Kruskal's అల్గారిథమ్ cycles గుర్తించండి చేయడానికి Union-Find వాడండి చేస్తుంది. DFS తో చక్రం ఎలా గుర్తించండి చేస్తారు, మరియు ఇక్కడ Union-Find ఎందుకు మరింత natural?</ThinkAboutIt>

## సాంప్రదాయ సమస్యలు

### సంఖ్య of కలిసిన భాగాలు

Union-Find ని n నోడ్‌లు తో initialise చేయండి. ప్రతి ముందంజ ని `union` తో ప్రక్రియ చేయండి. చివరలో distinct roots లెక్క చేయండి.

### ఖాతాలు మర్జ్ (LeetCode 721)

ప్రతి account లో emails ఉంటాయి. రెండు ఖాతాలు ఒక ఇమెయిల్ పంచుకోండి చేస్తే, అవి ఒకే వ్యక్తికి చెందినవి. పంచుకున్న emails ఆధారంగా ఖాతాలు ని union చేసి, గుంపు మరియు క్రమబద్ధీకరించండి చేయండి.

### Redundant కనెక్షన్ (LeetCode 684)

ఒక వృక్షం ఇవ్వబడింది దానిలో ఒక extra ముందంజ ఉంది - redundant ముందంజ కనుగొనండి. ఎడ్జ్‌లు ని క్రమం లో ప్రక్రియ చేయండి - `union` మొదటిసారి `False` రిటర్న్ చేసే ముందంజ (ఇప్పటికే కలిసిన) అదే సమాధానం.

<FunFact>Union-Find రెండు optimisations తో O(α(n)) లో నడపండి అవుతుందని proof ని Tarjan 1975 లో ప్రచురించండి చేశారు - ఇది కంప్యూటర్ సైన్స్ లో అత్యంత elegant amortised analyses లో ఒకటిగా పరిగణించబడుతుంది.</FunFact>

## Union-Find వర్సెస్ BFS/DFS - ఎప్పుడు ఏది ఎంచుకోవాలి

| సన్నివేశం | ఉత్తమ ఎంపిక |
|----------|-------------|
| మళ్ళీ మళ్ళీ connectivity క్వెరీలు | Union-Find |
| ఒకే traversal / చిన్నదైన మార్గం | BFS/DFS |
| Incremental ముందంజ additions | Union-Find |
| ముందంజ removals (dynamic గ్రాఫ్) | BFS/DFS (లేదా offline UF) |
| Kruskal's MST | Union-Find |
| Topological క్రమబద్ధీకరించండి / directed గ్రాఫ్ లో చక్రం | DFS |

ఎడ్జ్‌లు ని *incrementally* ప్రక్రియ చేస్తూ వేగంగా connectivity తనిఖీలు కావాలంటే Union-Find బాగా పని చేస్తుంది. ఒకే సారి traverse చేయాల్సి వస్తే లేదా మార్గం సమాచారం కావాలంటే BFS/DFS వాడండి.

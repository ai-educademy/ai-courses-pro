## పెద్ద ఆలోచన

కొన్ని సమస్యలు చూడటానికి చాలా క్లిష్టమైన గా కనిపిస్తాయి, కానీ జాగ్రత్తగా చూస్తే అవి **చిన్న, పునరావృతమయ్యే ఉప-సమస్యలు** తో తయారయ్యాయని తెలుస్తుంది. Dynamic ప్రోగ్రామింగ్ (DP) ప్రతి ఉప-సమస్య ను **ఒక్కసారి** మాత్రమే పరిష్కరించండి చేసి, ఫలితం ను నిల్వ చేసి, దాన్ని reuse చేస్తుంది - కొంచెం మెమరీ ఖర్చు చేసి గొప్ప వేగం-up సాధిస్తుంది.

రెండు conditions DP అవకాశాన్ని సూచిస్తాయి:

1. **Overlapping sub-సమస్యలు** - అదే calculations చాలాసార్లు పునరావృతమవుతాయి.
2. **Optimal substructure** - మొత్తం సమస్య యొక్క ఉత్తమ పరిష్కారం దాని భాగాల ఉత్తమ పరిష్కారాలు నుండి నిర్మించవచ్చు.

## Fibonacci: అత్యంత సాంప్రదాయ ఉదాహరణ

### Naïve Recursion - O(2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)` కాల్ చేస్తే **15** ఫంక్షన్ కాల్‌లు జరుగుతాయి, వాటిలో చాలా redundant. `fib(40)` కి సెకన్లు పడుతుంది; `fib(100)` కి అయితే universe కంటే ఎక్కువ సమయం పడుతుంది.

### Memoisation (ముఖ్యమైన-Down) - O(n)

ఫలితాలు ను ఒక క్యాష్ లో నిల్వ చేయండి. ఒక ఉప-సమస్య ఇప్పటికే పరిష్కరించండి అయి ఉంటే, cached సమాధానం తిరిగి ఇవ్వండి.

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### Tabulation (Bottom-Up) - O(n)

బేస్ సందర్భాలు నుండి iteratively సమాధానం నిర్మించండి.

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## సాంప్రదాయ DP సమస్యలు

### మెట్లు ఎక్కడం

మీరు ఒకేసారి 1 లేదా 2 మెట్లు ఎక్కవచ్చు. దశ _n_ కి చేరుకోవడానికి ఎన్ని విభిన్న మార్గాలు ఉన్నాయి?

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

ఇది మారువేషంలో Fibonacci - దశ _n_ కి సమాధానం, దశ _n−1_ మరియు _n−2_ కి చేరుకునే మార్గాల మొత్తం.

### Coin Change

ఇచ్చిన coin denominations తో లక్ష్య amount చేయడానికి **అత్యల్ప coins** కనుగొనండి.

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### Longest సాధారణ Subsequence (LCS)

రెండు strings లో సాధారణ అక్షరాలు యొక్క పొడవైన sequence కనుగొనండి (తప్పనిసరిగా contiguous కానవసరం లేదు).

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

<FunFact>ఫైల్ వెర్షన్‌లు మధ్య మార్పులు చూపించే `diff` టూల్ LCS పై ఆధారపడింది. మీరు `git diff` నడపండి చేసినప్పుడల్లా Git దాని variant ని వాడుతుంది.</FunFact>

<ThinkAboutIt>Coin change కనిష్ఠ coins సంఖ్య అడుగుతుంది. Amount చేయడానికి మొత్తం విభిన్న మార్గాల సంఖ్య లెక్కించాలంటే? Recurrence relation ఎలా మారుతుంది?</ThinkAboutIt>

## AIలో నిజమైన అనువర్తనాలు

| సమస్య | AI డొమైన్ | DP Technique |
|---------|-----------|-------------|
| **Edit distance** (Levenshtein) | Spell checkers, fuzzy సెర్చ్ | అక్షరాలు పోల్చే 2D పట్టిక |
| **Viterbi అల్గారిథమ్** | Speech recognition, POS tagging | Hidden Markov మోడల్ లో ఉత్తమ మార్గం |
| **Sequence సమలేఖనం** | Bioinformatics (DNA matching) | అంతరం penalties తో LCS variant |
| **CTC decoding** | Handwriting / speech-కు-టెక్స్ట్ | Repeated అక్షరాలు ను optimally మర్జ్ చేయడం |
| **Beam సెర్చ్ pruning** | Machine translation | ముఖ్యమైన-k పాక్షిక translations ఉంచడం |

## ముఖ్యమైన-Down వర్సెస్ Bottom-Up

| అంశం | ముఖ్యమైన-Down (Memoisation) | Bottom-Up (Tabulation) |
|------|----------------------|----------------------|
| Style | Recursive + క్యాష్ | Iterative + పట్టిక |
| పరిష్కరించండి అయిన ఉప-సమస్యలు | అవసరమైనవి మాత్రమే | _n_ వరకు అన్ని ఉప-సమస్యలు |
| స్టాక్ overflow రిస్క్ | అవును, లోతైన recursion లో | కాదు |
| ఆప్టిమైజేషన్ సౌలభ్యం | స్థలం తగ్గించడం కష్టం | సులభం (తరచుగా last వరుస మాత్రమే ఉంచితే చాలు) |

**సాధారణ నియమం:** ముందు memoisation తో recurrence అర్థం చేసుకోండి, తర్వాత స్థలం optimise చేయడానికి లేదా స్టాక్ పరిమితులు నివారించడానికి tabulation కి మార్చండి చేయండి.

<ThinkAboutIt>Coin change పట్టిక పరిమాణం O(amount). LCS పట్టిక పరిమాణం O(m × n). ఒకేసారి రెండు వరుసలు మాత్రమే ఉంచి LCS స్థలం ను O(నిమి(m, n)) కి తగ్గించగలరా? ఏ సమాచారం కోల్పోతారు?</ThinkAboutIt>

## ముఖ్యమైన అంశాలు

1. DP exponential brute-force ను polynomial సమయం గా మారుస్తుంది **repeated పని ను క్యాష్ చేయడం** ద్వారా.
2. DP వాడే ముందు overlapping ఉప-సమస్యలు మరియు అనుకూలమైన substructure గుర్తించండి.
3. Memoisation intuitive; tabulation efficient - రెండూ నేర్చుకోండి.
4. Edit distance, Viterbi మరియు sequence సమలేఖనం ఆధునిక AI హృదయంలో DP ని చూపిస్తాయి.

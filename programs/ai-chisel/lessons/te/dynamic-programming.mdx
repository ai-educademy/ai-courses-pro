## పెద్ద ఆలోచన

కొన్ని సమస్యలు చూడటానికి చాలా క్లిష్టంగా కనిపిస్తాయి, కానీ జాగ్రత్తగా చూస్తే అవి **చిన్న, పునరావృతమయ్యే ఉప-సమస్యలు** తో తయారయ్యాయని తెలుస్తుంది. డైనమిక్ ప్రోగ్రామింగ్ (DP) ప్రతి ఉప-సమస్య ను **ఒక్కసారి** మాత్రమే పరిష్కరించి, ఫలితం ను నిల్వ చేసి, దాన్ని తిరిగి వాడుతుంది - కొంచెం మెమరీ ఖర్చు చేసి గొప్ప వేగ పెరుగుదల సాధిస్తుంది.

రెండు పరిస్థితులు DP అవకాశాన్ని సూచిస్తాయి:

1. **Overlapping sub-సమస్యలు** - అదే calculations చాలాసార్లు పునరావృతమవుతాయి.
2. **Optimal ఉపనిర్మాణం** - మొత్తం సమస్య యొక్క ఉత్తమ పరిష్కారం దాని భాగాల ఉత్తమ పరిష్కారాలు నుండి నిర్మించవచ్చు.

## Fibonacci: అత్యంత సాంప్రదాయ ఉదాహరణ

### Naïve Recursion - O(2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)` కాల్ చేస్తే **15** ఫంక్షన్ కాల్‌లు జరుగుతాయి, వాటిలో చాలా అనవసరమైనవి. `fib(40)` కి సెకన్లు పడుతుంది; `fib(100)` కి అయితే విశ్వం కంటే ఎక్కువ సమయం పడుతుంది.

### మెమోయిజేషన్ (పై నుంచి కిందికి) - O(n)

ఫలితాలను ఒక క్యాష్ లో నిల్వ చేయండి. ఒక ఉప-సమస్య ఇప్పటికే పరిష్కారమై ఉంటే, క్యాష్ చేసిన సమాధానం తిరిగి ఇవ్వండి.

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### పట్టికీకరణ (కింద నుంచి పైకి) - O(n)

బేస్ సందర్భాలు నుండి పునరావృతంగా సమాధానం నిర్మించండి.

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## సాంప్రదాయ DP సమస్యలు

### మెట్లు ఎక్కడం

మీరు ఒకేసారి 1 లేదా 2 మెట్లు ఎక్కవచ్చు. దశ _n_ కి చేరుకోవడానికి ఎన్ని విభిన్న మార్గాలు ఉన్నాయి?

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

ఇది మారువేషంలో Fibonacci - దశ _n_ కి సమాధానం, దశ _n−1_ మరియు _n−2_ కి చేరుకునే మార్గాల మొత్తం.

### నాణెం మార్పు

ఇచ్చిన నాణేల విలువలు తో లక్ష్య మొత్తం చేయడానికి **అత్యల్ప నాణేలు** కనుగొనండి.

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### పొడవైన సాధారణ ఉపవరుస (LCS)

రెండు స్ట్రింగ్‌లు లో సాధారణ అక్షరాలు యొక్క పొడవైన వరుస కనుగొనండి (తప్పనిసరిగా వరుసగా కానవసరం లేదు).

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

<FunFact>ఫైల్ వెర్షన్‌లు మధ్య మార్పులు చూపించే `diff` టూల్ LCS పై ఆధారపడింది. మీరు `git diff` నడిపినప్పుడల్లా Git దాని రకం ని వాడుతుంది.</FunFact>

<ThinkAboutIt>నాణెం మార్పు కనిష్ఠ నాణేలు సంఖ్య అడుగుతుంది. మొత్తం చేయడానికి మొత్తం విభిన్న మార్గాల సంఖ్య లెక్కించాలంటే? పునరావృత సంబంధం ఎలా మారుతుంది?</ThinkAboutIt>

## AIలో నిజమైన అనువర్తనాలు

| సమస్య | AI డొమైన్ | DP Technique |
|---------|-----------|-------------|
| **ఎడిట్ దూరం** (Levenshtein) | అక్షరక్రమ తనిఖీలు, అస్పష్ట శోధన | అక్షరాలు పోల్చే 2D పట్టిక |
| **Viterbi అల్గారిథమ్** | మాట గుర్తింపు, POS ట్యాగింగ్ | హిడెన్ మార్కోవ్ మోడల్ లో ఉత్తమ మార్గం |
| **Sequence సమలేఖనం** | జీవసమాచార శాస్త్రం (DNA సరిపోలిక) | అంతరం జరిమానాలు తో LCS రకం |
| **CTC decoding** | చేతిరాత / మాట నుంచి పాఠ్యం | పునరావృత అక్షరాలను ఉత్తమంగా మర్జ్ చేయడం |
| **Beam సెర్చ్ pruning** | యంత్ర అనువాదం | ముఖ్యమైన k పాక్షిక అనువాదాలు ఉంచడం |

## పై నుంచి కిందికి వర్సెస్ కింద నుంచి పైకి

| అంశం | పై నుంచి కిందికి (మెమోయిజేషన్) | కింద నుంచి పైకి (పట్టికీకరణ) |
|------|----------------------|----------------------|
| శైలి | రికర్సివ్ + క్యాష్ | పునరావృత + పట్టిక |
| పరిష్కారమైన ఉప-సమస్యలు | అవసరమైనవి మాత్రమే | _n_ వరకు అన్ని ఉప-సమస్యలు |
| స్టాక్ ఓవర్‌ఫ్లో రిస్క్ | అవును, లోతైన రికర్షన్ లో | కాదు |
| ఆప్టిమైజేషన్ సౌలభ్యం | స్థలం తగ్గించడం కష్టం | సులభం (తరచుగా చివరి వరుస మాత్రమే ఉంచితే చాలు) |

**సాధారణ నియమం:** ముందు మెమోయిజేషన్ తో పునరావృత సంబంధం అర్థం చేసుకోండి, తర్వాత స్థలం మెరుగుపరచడానికి లేదా స్టాక్ పరిమితులు నివారించడానికి పట్టికీకరణ కి మార్చండి.

<ThinkAboutIt>నాణెం మార్పు పట్టిక పరిమాణం O(మొత్తం). LCS పట్టిక పరిమాణం O(m × n). ఒకేసారి రెండు వరుసలు మాత్రమే ఉంచి LCS స్థలం ను O(నిమి(m, n)) కి తగ్గించగలరా? ఏ సమాచారం కోల్పోతారు?</ThinkAboutIt>

## ముఖ్యమైన అంశాలు

1. DP ఘాతాంక బ్రూట్ ఫోర్స్ ను బహుపద సమయం గా మారుస్తుంది **పునరావృత పని ను క్యాష్ చేయడం** ద్వారా.
2. DP వాడే ముందు మిళితమయ్యే ఉప-సమస్యలు మరియు అనుకూలమైన ఉపనిర్మాణం గుర్తించండి.
3. మెమోయిజేషన్ సహజంగా అర్థమయ్యేది; పట్టికీకరణ సమర్థవంతమైనది - రెండూ నేర్చుకోండి.
4. ఎడిట్ దూరం, Viterbi మరియు వరుస సమలేఖనం ఆధునిక AI హృదయంలో DP ని చూపిస్తాయి.

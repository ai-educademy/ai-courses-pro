## AI में ट्री हर जगह हैं

जब भी कोई स्पैम फ़िल्टर किसी ईमेल को वर्गीकृत करता है या कोई डेटाबेस मिलीसेकंड में आपका ऑर्डर लाता करता है, तो पीछे एक ट्री डेटा संरचना काम कर रही होती है। ट्री **पदानुक्रमित फ़ैसले** को मॉडल करते हैं - हर नोड सर्च स्पेस को छोटा करता है जब तक आप उत्तर तक नहीं पहुँच जाते।

## Binary search trees (BSTs)

BST एलिमेंट को इस तरह स्टोर करता है कि किसी भी नोड के लिए, उसके **लेफ़ट** सुबटरी की सभी वलुएस छोटी होती हैं और **अधिकार** सुबटरी की सभी वलुएस बड़ी होती हैं।

### सर्च

```
function search(node, target):
    if node is null: return null
    if target == node.value: return node
    if target < node.value: return search(node.left, target)
    return search(node.right, target)
```

हर कोमपरिसोन लगभग आधे बचे हुए नोड को एलिमिनटे कर देता है - संतुलित ट्री पर O(लॉग n)।

### इनसेरशन

```
function insert(node, value):
    if node is null: return new Node(value)
    if value < node.value:
        node.left = insert(node.left, value)
    else:
        node.right = insert(node.right, value)
    return node
```

### देलेशन

देलेशन सबसे पेचीदा ऑपरेशन है। तीन मामले बनते हैं:

1. **लेअफ़ नोड** - बस हटा दो।
2. **एक चिलद** - नोड को उसके चिलद से रेपलके कर दो।
3. **दो चिलदरेन** - नोड की मूल्य को उसके इन-ओरदेर सफलताोर (अधिकार सुबटरी की सबसे छोटी मूल्य) से सवप करो, फिर उस सफलताोर को डिलीट करो।

## Balanced vs unbalanced

अगर आप सॉर्टेड डेटा को एक पलैन BST में इन्सर्ट करो, तो वो एक लिंक्ड लिस्ट बन जाता है - हर ऑपरेशन O(n)। **सेलफ़-बलनकिङ** ट्री इसे फ़िक्स करते हैं:

| टरी | बलनके रुले | टयचुनताल उपयोग |
|------|-------------|-------------|
| AVL | सुबट्री के बीच ऊँचाई दिफ़फ़ेरेनके ≤ 1 | इन-मेमोरय लूकुपस |
| Red-Black | colour-based rotation rules | भाषा की standard libraries (जैसे Java TreeMap) |
| ब-टरी | हर नोड में कई की, सभी लेअवेस एक ही गहराई पर | डेटाबेस और फ़ाइल सिस्टम |

<FunFact>PostgreSQL और MySQL दोनों अपनी default index structure के लिए B-tree variants इस्तेमाल करते हैं। branching factor 100 वाला B-tree सिर्फ़ पाँच levels में एक अरब rows index कर सकता है।</FunFact>

## टरी टरवेरसेल्स

टरवेरसेल्स हर नोड को ठीक एक बार विसिट करते हैं। तीन क्लासिक ऑर्डर में फ़र्क सिर्फ इतना है कि वर्तमान नोड को उसके चिलदरेन के रेलटिवे **कब** प्रोसेस किया जाता है।

| ट्रैवर्सल | ओरदेर | उपयोग कसे |
|-----------|-------|----------|
| **इन-ओरदेर** | लेफ़ट → Node → अधिकार | BST से सॉर्टेड आउटपुट निकालना |
| **परे-ओरदेर** | Node → लेफ़ट → अधिकार | टरी को सेरिअलिसे / क्लोन करना |
| **पोसट-ओरदेर** | लेफ़ट → अधिकार → Node | टरी को सफ़ेलय डिलीट करना; एक्सप्रेशन ट्री मूल्यांकन करना |

```
function inOrder(node):
    if node is null: return
    inOrder(node.left)
    process(node)
    inOrder(node.right)
```

<ThinkAboutIt>एक कंपाइलर आपके कोड को अमूर्त सिंटैक्स ट्री (AST) में PRsे करता है। एक्सप्रेशन `(3 + 5) * 2` को ट्री में स्टोर करने पर मूल्यांकन करने के लिए कौन सा ट्रैवर्सल ऑर्डर उपयोग करोगे? क्यों?</ThinkAboutIt>

## हेअपस और परिओरिटय क्यूस

**हेअप** एक पूरा बाइनरी ट्री है जहाँ हर परेनट अपने चिलदरेन से बड़ा (मक्स-हेअप) या छोटा (मिन-हेअप) होता है। यह सपोर्ट करता है:

- **इनसेरट** - एनद में जोड़ें करो, बुबबले up करो। O(लॉग n)।
- **Extract min/max** - root हटाओ, last element को root पर लाओ, sift down करो। O(log n)।

परिओरिटय क्यू जो हेअपस पर बनी हैं, ये चीज़ें पोवेर करती हैं:
- **Dijkstra's algorithm** (अगला पाठ!) - हमेशा nearest unvisited node को expand करो।
- **काम सचेदुलिङ** - OS सचेदुलेरस उच्चेसट-परिओरिटय प्रोसेस को चुनता करते हैं।
- **बेअम सर्च in NLP** - टोप-क सबसे परोमिसिङ सेनटेनके कोमपलेशनस रखो।

```
function siftUp(heap, index):
    while index > 0:
        parent = (index - 1) / 2
        if heap[index] < heap[parent]:
            swap(heap, index, parent)
            index = parent
        else: break
```

## वास्तविक AI ऐप्लिकेशन

- **देकिसिओन ट्री** मशीन लर्निंग में हर नोड पर डेटा को उस फ़ीचर से सपलिट करते हैं जो कलसेस को सबसे अच्छे से सेपरटे करता है - ट्री संरचना का दिरेकट अपपलिकशन।
- **Syntax trees** NLP में grammatical structure दर्शाते हैं, जिससे sentiment analysis और machine translation जैसे tasks सम्भव होते हैं।
- **मोनटे करलो टरी सर्च (MCTS)** अलफगो जैसी गमे-पलयिङ AI को पोवेर करता है, पोसिबले मोवेस को गमे सटटेस के ट्री के रूप में एक्सप्लोर करता है।
- **Huffman trees** frequent symbols को shorter codes assign करके data compress करते हैं - model weight compression में इस्तेमाल होते हैं।

<FunFact>scikit-learn निर्णय ट्री कलसिफ़िएर एक ऐसा ट्री बनाता है जहाँ हर इनटेरनल नोड एक फ़ीचर थरेशोलद टेस्ट करता है। देपथ 20 वाला टरैनेद मॉडल दस लाख से ज़्यादा दिसटिनकट निर्णय रास्ते रेपरेसेनट कर सकता है।</FunFact>

<ThinkAboutIt>अगर आप एक औटोकोमपलेटे सिस्टम बना रहे हो, तो BST, हीप, या कोई और ट्री संरचना (जैसे ट्राइ) - कौन सा उपयोग करोगे? सोचो कि कौन से ऑपरेशन तेज़ होने चाहिए।</ThinkAboutIt>

## मुख्य बातें

1. BSTs O(log n) search, insert, और delete देते हैं - लेकिन तभी जब balanced हों।
2. ट्रैवर्सल ऑर्डर तय करता है कि ट्री से कौन सी जानकारी निकलेगी।
3. हेअपस एक्सटरेमे मूल्य तक O(1) एक्सेस और O(लॉग n) इन्सर्शन देते हैं - परिओरिटय-बसेद AI एल्गोरिदमस के लिए विचारल।
4. ट्री ML, डेटाबेस, कंपाइलरस, और गमे AI में देकिसिओन-मकिङ की नींव हैं।

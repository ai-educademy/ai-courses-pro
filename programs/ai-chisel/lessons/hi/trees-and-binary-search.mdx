## AI में ट्री हर जगह हैं

जब भी कोई स्पैम फ़िल्टर किसी ईमेल को वर्गीकृत करता है या कोई डेटाबेस मिलीसेकंड में आपका ऑर्डर लाता करता है, तो पीछे एक ट्री डेटा संरचना काम कर रही होती है। ट्री **पदानुक्रमित फ़ैसले** को मॉडल करते हैं - हर नोड सर्च स्पेस को छोटा करता है जब तक आप उत्तर तक नहीं पहुँच जाते।

## बाइनरी सर्च ट्री (BSTs)

BST एलिमेंट को इस तरह स्टोर करता है कि किसी भी नोड के लिए, उसके **बाएँ** सुबटरी की सभी वलुएस छोटी होती हैं और **दाएँ** सुबटरी की सभी वलुएस बड़ी होती हैं।

### सर्च

```
function search(node, target):
    if node is null: return null
    if target == node.value: return node
    if target < node.value: return search(node.left, target)
    return search(node.right, target)
```

हर कोमपरिसोन लगभग आधे बचे हुए नोड को एलिमिनटे कर देता है - संतुलित ट्री पर O(लॉग n)।

### टर्म

```
function insert(node, value):
    if node is null: return new Node(value)
    if value < node.value:
        node.left = insert(node.left, value)
    else:
        node.right = insert(node.right, value)
    return node
```

### डिलीशन

डिलीशन सबसे पेचीदा ऑपरेशन है। तीन मामले बनते हैं:

1. **लेअफ़ नोड** - बस हटा दो।
2. **एक चिलद** - नोड को उसके चिलद से रेपलके कर दो।
3. **दो बच्चे** - नोड के मान को उसके इनऑर्डर सक्सेसर (दाएँ सबट्री के सबसे छोटे मान) से स्वैप करें, फिर उस सक्सेसर को डिलीट करें।

## संतुलित बनाम असंतुलित

अगर आप सॉर्टेड डेटा को एक टर्म BST में इन्सर्ट करें, तो वो एक लिंक्ड लिस्ट बन जाता है - हर ऑपरेशन O(n)। **टर्म-balancing** ट्री इसे ठीक करते हैं:

| टरी | टर्म रुले | टयचुनताल उपयोग |
|------|-------------|-------------|
| AVL | सुबट्री के बीच ऊँचाई दिफ़फ़ेरेनके ≤ 1 | इन-memory खोज |
| Red-Black | रंग-आधारित रोटेशन नियम | भाषा की मानक लाइब्रेरी (जैसे Java TreeMap) |
| ब-टरी | हर नोड में कई की, सभी leaveस एक ही गहराई पर | डेटाबेस और फ़ाइल सिस्टम |

<FunFact>PostgreSQL और MySQL दोनों अपनी डिफ़ॉल्ट इंडेक्स संरचना के लिए B-tree वैरिएंट इस्तेमाल करते हैं। ब्रांचिंग फ़ैक्टर 100 वाला B-tree सिर्फ़ पाँच स्तरों में एक अरब पंक्तियों को इंडेक्स कर सकता है।</FunFact>

## टरी टरवेरसेल्स

टरवेरसेल्स हर नोड को ठीक एक बार विज़िट करते हैं। तीन क्लासिक ऑर्डर में फ़र्क सिर्फ इतना है कि वर्तमान नोड को उसके बच्चे के रेलटिवे **कब** प्रोसेस किया जाता है।

| ट्रैवर्सल | ओरदेर | उपयोग मामला |
|-----------|-------|----------|
| **इन-ओरदेर** | बाएँ → टर्म → दाएँ | BST से सॉर्टेड आउटपुट निकालना |
| **परे-ओरदेर** | टर्म → बाएँ → दाएँ | टरी को सेरिअलिसे / क्लोन करना |
| **पोसट-ओरदेर** | बाएँ → दाएँ → टर्म | टरी को सफ़ेलय डिलीट करना; एक्सप्रेशन ट्री मूल्यांकन करना |

```
function inOrder(node):
    if node is null: return
    inOrder(node.left)
    process(node)
    inOrder(node.right)
```

<ThinkAboutIt>एक कंपाइलर आपके कोड को अमूर्त सिंटैक्स ट्री (AST) में टर्म करता है। एक्सप्रेशन `(3 + 5) * 2` को ट्री में स्टोर करने पर मूल्यांकन करने के लिए कौन सा ट्रैवर्सल ऑर्डर उपयोग करेंगे? क्यों?</ThinkAboutIt>

## हीप और प्राथमिकता क्यू

**हीप** एक पूरा बाइनरी ट्री है जहाँ हर पैरेंट अपने बच्चे से बड़ा (max-हीप) या छोटा (मिन-हीप) होता है। यह सपोर्ट करता है:

- **इन्सर्ट** - एनद में जोड़ें करें, बुबबले up करें। O(लॉग n)।
- **टर्म min/max** - रूट हटाएँ, आखिरी एलिमेंट को रूट पर लाएँ, नीचे सरकाएँ। O(log n)।

हीप पर बनी प्राथमिकता क्यू ये चीज़ें सक्षम करती हैं:
- **टर्म का एल्गोरिदम** (अगला पाठ!) - हमेशा सबसे नज़दीकी अनदेखे नोड को फैलाएँ।
- **काम टर्म** - OS टर्म टर्म-priority प्रोसेस को चुनते हैं।
- **बेअम सर्च in NLP** - टोप-क सबसे परोमिसिंग सेनटेनके टर्म रखो।

```
function siftUp(heap, index):
    while index > 0:
        parent = (index - 1) / 2
        if heap[index] < heap[parent]:
            swap(heap, index, parent)
            index = parent
        else: break
```

## वास्तविक AI ऐप्लिकेशन

- **देकिसिओन ट्री** मशीन लर्निंग में हर नोड पर डेटा को उस फ़ीचर से सपलिट करते हैं जो कलसेस को सबसे अच्छे से सेपरटे करता है - ट्री संरचना का दिरेकट ऐप्लिकेशन।
- **टर्म ट्री** NLP में व्याकरणिक संरचना दर्शाते हैं, जिससे भावना विश्लेषण और मशीन अनुवाद जैसे कार्य सम्भव होते हैं।
- **मोनटे करलो टरी सर्च (MCTS)** अलफगो जैसी गमे-पलयिङ AI को पावर करता है, पोसिबले मूव को गमे स्टेट के ट्री के रूप में एक्सप्लोर करता है।
- **टर्म ट्री** बार-बार आने वाले चिह्न को छोटे कोड सौंपकर डेटा टर्म करते हैं - मॉडल वज़न कम्प्रेशन में इस्तेमाल होते हैं।

<FunFact>टर्म-learn निर्णय ट्री कलसिफ़िएर एक ऐसा ट्री बनाता है जहाँ हर टर्म नोड एक फ़ीचर थरेशोलद टेस्ट करता है। देपथ 20 वाला टरैनेद मॉडल दस लाख से ज़्यादा अलग निर्णय रास्ते दर्शाते कर सकता है।</FunFact>

<ThinkAboutIt>अगर आप एक औटोकोमपलेटे सिस्टम बना रहे हो, तो BST, हीप, या कोई और ट्री संरचना (जैसे ट्राइ) - कौन सा उपयोग करेंगे? सोचें कि कौन से ऑपरेशन तेज़ होने चाहिए।</ThinkAboutIt>

## मुख्य बातें

1. BSTs O(log n) सर्च, इन्सर्ट, और डिलीट देते हैं - लेकिन तभी जब संतुलित हों।
2. ट्रैवर्सल ऑर्डर तय करता है कि ट्री से कौन सी जानकारी निकलेगी।
3. हीप टर्म मान तक O(1) एक्सेस और O(log n) इन्सर्शन देते हैं - प्राथमिकता-based AI एल्गोरिदम के लिए उपयुक्त।
4. ट्री ML, डेटाबेस, कंपाइलरस, और गमे AI में देकिसिओन-मकिङ की नींव हैं।

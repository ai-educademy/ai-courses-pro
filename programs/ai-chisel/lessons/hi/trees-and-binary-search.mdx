## AI में ट्री हर जगह हैं

जब भी कोई स्पैम फ़िल्टर ईमेल को वर्गीकृत करता है या डेटाबेस आपका ऑर्डर मिलीसेकंड में खोजता है, कोई ट्री डेटा संरचना भारी काम कर रही होती है। ट्री **पदानुक्रमित निर्णयों** को मॉडल करते हैं। हर नोड खोज क्षेत्र को छोटा करता है, जब तक आप उत्तर तक नहीं पहुँच जाते।

## बाइनरी सर्च ट्री (BST)

BST एलिमेंट को इस तरह रखता है कि किसी भी नोड के लिए उसके **बाएँ** उप-ट्री के सभी मान छोटे और **दाएँ** उप-ट्री के सभी मान बड़े हों।

### खोज

```
function search(node, target):
    if node is null: return null
    if target == node.value: return node
    if target < node.value: return search(node.left, target)
    return search(node.right, target)
```

हर तुलना बचे हुए नोड का लगभग आधा हिस्सा हटा देती है। संतुलित ट्री पर यह O(log n) है।

### सम्मिलन

```
function insert(node, value):
    if node is null: return new Node(value)
    if value < node.value:
        node.left = insert(node.left, value)
    else:
        node.right = insert(node.right, value)
    return node
```

### हटाना

हटाना सबसे पेचीदा ऑपरेशन है। तीन मामले आते हैं:

1. **पत्ती नोड** - उसे बस हटा दें।
2. **एक बच्चा** - नोड को उसके बच्चे से बदल दें।
3. **दो बच्चे** - नोड का मान उसके इन-ऑर्डर सक्सेसर (दाएँ उप-ट्री का सबसे छोटा मान) से बदलें, फिर उस सक्सेसर को हटा दें।

## संतुलित बनाम असंतुलित

अगर आप साधारण BST में क्रमबद्ध डेटा डालते हैं, तो वह लिंक्ड लिस्ट जैसा बन जाता है। तब हर ऑपरेशन O(n) हो जाता है। **स्वयं-संतुलित** ट्री इसे ठीक करते हैं:

| ट्री | संतुलन नियम | सामान्य उपयोग |
|------|-------------|-------------|
| AVL | उप-ट्री के बीच ऊँचाई का अंतर ≤ 1 | इन-मेमोरी लुकअप |
| Red-Black | रंग-आधारित रोटेशन नियम | भाषा की मानक लाइब्रेरी, जैसे Java TreeMap |
| B-Tree | हर नोड में कई कुंजियाँ, सभी पत्तियाँ समान गहराई पर | डेटाबेस और फ़ाइल सिस्टम |

<FunFact>PostgreSQL और MySQL दोनों अपनी डिफ़ॉल्ट इंडेक्स संरचना के रूप में B-tree वैरिएंट इस्तेमाल करते हैं। 100 ब्रांचिंग फ़ैक्टर वाला B-tree सिर्फ़ पाँच स्तरों में एक अरब पंक्तियाँ इंडेक्स कर सकता है।</FunFact>

## ट्री ट्रैवर्सल

ट्रैवर्सल हर नोड को ठीक एक बार देखते हैं। तीन क्लासिक क्रमों में फ़र्क सिर्फ़ इस बात का है कि बच्चों की तुलना में वर्तमान नोड को **कब** प्रोसेस किया जाता है।

| ट्रैवर्सल | क्रम | उपयोग |
|-----------|-------|----------|
| **इन-ऑर्डर** | बायाँ → नोड → दायाँ | BST से क्रमबद्ध आउटपुट देता है |
| **प्री-ऑर्डर** | नोड → बायाँ → दायाँ | ट्री को सीरियलाइज़ / क्लोन करना |
| **पोस्ट-ऑर्डर** | बायाँ → दायाँ → नोड | ट्री को सुरक्षित हटाना, एक्सप्रेशन ट्री का मूल्यांकन |

```
function inOrder(node):
    if node is null: return
    inOrder(node.left)
    process(node)
    inOrder(node.right)
```

<ThinkAboutIt>कंपाइलर आपके कोड को Abstract Syntax Tree (AST) में पार्स करता है। ट्री में रखे `(3 + 5) * 2` एक्सप्रेशन का मूल्यांकन करने के लिए आप कौन सा ट्रैवर्सल क्रम इस्तेमाल करेंगे? क्यों?</ThinkAboutIt>

## हीप और प्रायोरिटी क्यू

**हीप** एक पूर्ण बाइनरी ट्री है जहाँ हर पैरेंट अपने बच्चों से बड़ा (max-heap) या छोटा (min-heap) होता है। यह इन्हें समर्थन देता है:

- **Insert** - अंत में जोड़ें, ऊपर उठाएँ। O(log n)।
- **Extract min/max** - जड़ हटाएँ, अंतिम एलिमेंट को जड़ पर लाएँ, नीचे खिसकाएँ। O(log n)।

हीप पर बने प्रायोरिटी क्यू इनमें काम आते हैं:
- **Dijkstra's algorithm** (अगला पाठ!) - हमेशा सबसे नज़दीकी अनदेखे नोड को फैलाएँ।
- **कार्य निर्धारण** - OS शेड्यूलर सबसे अधिक प्राथमिकता वाली प्रक्रिया चुनते हैं।
- **NLP में बीम सर्च** - सबसे आशाजनक top-k वाक्य पूर्णताएँ रखें।

```
function siftUp(heap, index):
    while index > 0:
        parent = (index - 1) / 2
        if heap[index] < heap[parent]:
            swap(heap, index, parent)
            index = parent
        else: break
```

## AI में वास्तविक उपयोग

- मशीन लर्निंग में **डिसीजन ट्री** हर नोड पर उस फ़ीचर से डेटा बाँटते हैं जो वर्गों को सबसे अच्छी तरह अलग करता है। यह ट्री संरचना का सीधा उपयोग है।
- NLP में **सिंटैक्स ट्री** व्याकरणिक संरचना दिखाते हैं, जिससे भाव विश्लेषण और मशीन अनुवाद जैसे काम सम्भव होते हैं।
- **Monte Carlo Tree Search (MCTS)** AlphaGo जैसे गेम खेलने वाले AI को शक्ति देता है, जहाँ सम्भावित चालों को गेम अवस्थाओं के ट्री के रूप में खोजा जाता है।
- **Huffman trees** बार-बार आने वाले प्रतीकों को छोटे कोड देकर डेटा संपीड़ित करते हैं। यह मॉडल वेट संपीड़न में इस्तेमाल होता है।

<FunFact>scikit-learn डिसीजन ट्री क्लासिफ़ायर ऐसा ट्री बनाता है जहाँ हर आंतरिक नोड किसी फ़ीचर थ्रेशहोल्ड को जाँचता है। गहराई 20 वाला प्रशिक्षित मॉडल दस लाख से अधिक अलग निर्णय पथ दिखा सकता है।</FunFact>

<ThinkAboutIt>अगर आप ऑटोकम्प्लीट सिस्टम बना रहे हों, तो क्या आप BST, हीप, या कोई अलग ट्री संरचना जैसे ट्राई इस्तेमाल करेंगे? सोचें कि किन ऑपरेशन का तेज़ होना ज़रूरी है।</ThinkAboutIt>

2. ट्रैवर्सल क्रम तय करता है कि आप ट्री से कौन सी जानकारी निकालते हैं।

4. ML, डेटाबेस, कंपाइलर और गेम AI में निर्णय लेने की बुनियाद ट्री हैं।

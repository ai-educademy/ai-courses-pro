## बड़ा आइडिया

कुछ समस्याएँ देखने में बहुत जटिल लगते हैं, लेकिन जब ध्यान से देखो तो पता चलता है कि वो **छोटी-छोटी रेपेअटिङ सुब-परोबलेमस** से बने हैं। दयनमिक प्रोग्रामिंग (DP) हर सुब-परोबलेम को **एक बार** हल करता है, रेसुलट स्टोर करता है, और उसे दोबारा उपयोग करता है - थोड़ी मेमोरी खर्च करके बहुत बड़ी स्पीड-उप हासिल करता है।

दो कोनदिशनस बताती हैं कि DP लगा सकते हैं:

1. **ओवरलैप होती sub-problems** - वही गणनाएँ बार-बार आती हैं।
2. **Optimal substructure** - पूरी समस्या का श्रेष्ठ समाधान उसके हिस्सों के श्रेष्ठ समाधानों से बनाया जा सकता है।

## फ़िबोनककि: सबसे कलसिक एक्सैंपल

### Naïve रेकुरसिओन - O(2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)` कॉल करने पर **15** function calls होती हैं, जिनमें कई दोहराव हैं। `fib(40)` पर सेकंड लगते हैं; `fib(100)` पर तो ब्रह्मांड से भी ज़्यादा समय लगेगा।

### मेमोइसशन (ऊपर-से-नीचे) - O(n)

रेसुलटस को एक कैश में स्टोर करो। अगर कोई सुब-परोबलेम पहले हल हो चुकी है, तो कचेद उत्तर लौटाएँ करो।

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### टबुलशन (नीचे-उप) - O(n)

बसे मामले से शुरू करके इटेरटिवेलय उत्तर बनाओ।

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## कलसिक DP परोबलेमस

### कलिमबिङ सटैरस

आप एक बार में 1 या 2 सीढ़ियाँ चढ़ सकते हैं। चरण _n_ तक पहुँचने के कितने अलग-अलग तरीके हैं?

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

यह असल में फ़िबोनककि ही है - चरण _n_ का answer, चरण _n−1_ और _n−2_ तक पहुँचने के तरीकों का सुम है।

### कोइन चङे

दिए गए coin denominations से लक्ष्य राशि बनाने के लिए **सबसे कम coins** ढूँढो।

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### लोङेसट कोममोन सुबसेक्वेनके (LCS)

दो सटघेरों में आम चरकटेरस की सबसे लंबी सेक्वेनके ढूँढो (ज़रूरी नहीं कि कोनटिगुओउस हो)।

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

<FunFact>`diff` टूल जो फ़ाइल वेरसिओनस के बीच चङेस दिखाता है, वो LCS पर आधारित है। जब भी आप `git diff` चलाते हैं, गिट इसका एक वैरिएंट उपयोग करता है।</FunFact>

<ThinkAboutIt>कोइन चङे न्यूनतम कोइनस की संख्या पूछता है। अगर आपको अमोउनट बनाने के कुल अलग-अलग तरीकों की गिनती करनी हो तो? रेकुररेनके रेलशन कैसे बदलेगा?</ThinkAboutIt>

## AI में वास्तविक ऐप्लिकेशन

| समस्या | AI डोमेन | DP टेचनिक्वे |
|---------|-----------|-------------|
| **एदिट दूरी** (लेवेनशटेइन) | सपेलल चेकेरस, फ़ुज़ज़य सर्च | चरकटेरस कोमपरे करने वाली 2D टेबल |
| **विटेरबि एल्गोरिदम** | सपीच रेकोगनिशन, POS टगगिङ | हिददेन मरकोव मॉडल में श्रेष्ठ रास्ता |
| **सेक्वेनके अलिगnameनट** | बिओइनफ़ोरमटिकस (DNA मैचिंग) | गप पेनलटिएस वाला LCS वैरिएंट |
| **CTC decoding** | handwriting / speech-to-text | दोहराए गए characters को optimal तरीके से merge करना |
| **Beam search pruning** | machine translation | top-k आंशिक translations रखना |

## ऊपर-से-नीचे vs नीचे-उप

| पहलू | ऊपर-से-नीचे (मेमोइसशन) | नीचे-उप (टबुलशन) |
|-------|----------------------|----------------------|
| शैली | रेकुरसिवे + कैश | इटेरटिवे + टेबल |
| कौन सी सुब-परोबलेमस हल होती हैं | सिर्फ़ जो ज़रूरी हैं | _n_ तक सभी सुब-परोबलेमस |
| सटक ओवेरफ़लोव का जोखिम | हाँ, गहरी रिकर्शन में | नहीं |
| सपके ऑप्टिमाइज़ेशन की आसानी | मुश्किल | आसान (अक्सर बस लसट रोव रखनी होती है) |

**अंगूठे का नियम:** पहले मेमोइसशन से रेकुररेनके समझो, फिर स्पेस ऑप्टिमाइज़ करने या स्टैक सीमाएँ से बचने के लिए टबुलशन में कोनवेरट करो।

<ThinkAboutIt>कोइन चङे टेबल का आकार O(अमोउनट) है। LCS टेबल का आकार O(m × n) है। क्या आप एक बार में सिर्फ़ दो रोवस रखकर LCS स्पेस को O(मिन(m, n)) तक कम कर सकते हैं? ऐसा करने पर कौन सी जानकारी खो जाएगी?</ThinkAboutIt>

## मुख्य बातें

1. DP एक्सपोनेनटिअल बरुटे-फ़ोरके को पोलयनोमिअल समय में बदलता है **रेपेअटेद काम को कैश करके**।
2. DP लगाने से पहले ओवेरलपपिङ सुब-परोबलेमस और सर्वोत्तम सुबसटरुकटुरे इदेनटिफ़य करो।
3. मेमोइसशन इनटुइटिवे है; टबुलशन कुशल है - दोनों सीखो।
4. एदिट दूरी, विटेरबि, और सेक्वेनके अलिगnameनट दिखाते हैं कि DP आधुनिक AI के दिल में है।

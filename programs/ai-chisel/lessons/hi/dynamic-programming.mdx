## बड़ा आइडिया

कुछ समस्याएँ देखने में बहुत जटिल लगते हैं, लेकिन जब ध्यान से देखें तो पता चलता है कि वो **छोटी-छोटी दोहराई जाने वाली उप-समस्याएँ** से बने हैं। डायनेमिक प्रोग्रामिंग (DP) हर सुब-परोबलेम को **एक बार** हल करता है, नतीजा स्टोर करता है, और उसे दोबारा इस्तेमाल करता है - थोड़ी मेमोरी खर्च करके बहुत बड़ी तेज़ी हासिल करता है।

दो शर्तें बताती हैं कि DP लगा सकते हैं:

1. **ओवरलैप होती उप-समस्याएँ** - वही गणनाएँ बार-बार आती हैं।
2. **सर्वोत्तम उप-संरचना** - पूरी समस्या का श्रेष्ठ समाधान उसके हिस्सों के श्रेष्ठ समाधानों से बनाया जा सकता है।

## Fibonacci: सबसे क्लासिक उदाहरण

### Naïve रिकर्शन - O(2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)` कॉल करने पर **15** फ़ंक्शन कॉल होती हैं, जिनमें कई दोहराव हैं। `fib(40)` पर सेकंड लगते हैं; `fib(100)` पर तो ब्रह्मांड से भी ज़्यादा समय लगेगा।

### मेमोइज़ेशन (टॉप-down) - O(n)

नतीजास को एक कैश में स्टोर करें। अगर कोई सुब-परोबलेम पहले हल हो चुकी है, तो कैश्ड उत्तर लौटाएँ।

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### टैबुलेशन (बॉटम-up) - O(n)

बेस केस से शुरू करके दोहराकर उत्तर बनाएँ।

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## क्लासिक DP समस्याएँ

### सीढ़ियाँ चढ़ना

आप एक बार में 1 या 2 सीढ़ियाँ चढ़ सकते हैं। चरण _n_ तक पहुँचने के कितने अलग-अलग तरीके हैं?

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

यह असल में Fibonacci ही है - चरण _n_ का उत्तर, चरण _n−1_ और _n−2_ तक पहुँचने के तरीकों का टर्म है।

### सिक्का बदलाव

दिए गए सिक्कों के मूल्यवर्ग से लक्ष्य राशि बनाने के लिए **सबसे कम सिक्के** ढूँढें।

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### लोङेसट कोममोन सुबैक्रम (LCS)

दो स्ट्रिंग में आम अक्षर की सबसे लंबी क्रम ढूँढें (ज़रूरी नहीं कि लगातार हो)।

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

<FunFact>`diff` टूल जो फ़ाइल टर्म के बीच टर्म दिखाता है, वो LCS पर आधारित है। जब भी आप `git diff` चलाते हैं, गिट इसका एक वैरिएंट इस्तेमाल करता है।</FunFact>

<ThinkAboutIt>सिक्का बदलाव न्यूनतम सिक्के की संख्या पूछता है। अगर आपको राशि बनाने के कुल अलग-अलग तरीकों की गिनती करनी हो तो? टर्म टर्म कैसे बदलेगा?</ThinkAboutIt>

## टॉप-down vs बॉटम-up

| पहलू | टॉप-down (मेमोइज़ेशन) | बॉटम-up (टैबुलेशन) |
|-------|----------------------|----------------------|
| शैली | रेकुरसिवे + कैश | इटेरटिवे + टेबल |
| कौन सी उप-समस्याएँ हल होती हैं | सिर्फ़ जो ज़रूरी हैं | _n_ तक सभी उप-समस्याएँ |
| स्टैक ओवरफ़्लो का जोखिम | हाँ, गहरी रिकर्शन में | नहीं |
| स्पेस ऑप्टिमाइज़ेशन की आसानी | मुश्किल | आसान (अक्सर बस आखिरी row रखनी होती है) |

**अंगूठे का नियम:** पहले मेमोइज़ेशन से रेकुररेनके समझें, फिर स्पेस ऑप्टिमाइज़ करने या स्टैक सीमाएँ से बचने के लिए टैबुलेशन में बदलें।

<ThinkAboutIt>सिक्का बदलाव टेबल का आकार O(राशि) है। LCS टेबल का आकार O(m × n) है। क्या आप एक बार में सिर्फ़ दो टर्म रखकर LCS स्पेस को O(मिन(m, n)) तक कम कर सकते हैं? ऐसा करने पर कौन सी जानकारी खो जाएगी?</ThinkAboutIt>

## मुख्य बातें

1. DP एक्सपोनेनटिअल ब्रूट-force को टर्म समय में बदलता है **रेपेअटेद काम को कैश करके**।
2. DP लगाने से पहले ओवरलैप होती उप-समस्याएँ और सर्वोत्तम उप-संरचना पहचानें।
3. मेमोइज़ेशन टर्म है; टैबुलेशन कुशल है - दोनों सीखें।
4. एडिट दूरी, विटेरबि, और क्रम अलिगnameनट दिखाते हैं कि DP आधुनिक AI के दिल में है।

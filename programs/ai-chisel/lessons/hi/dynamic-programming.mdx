## बड़ा विचार

कुछ समस्याएँ असम्भव रूप से जटिल लगती हैं, जब तक आप यह नहीं देखते कि वे **छोटी, दोहराती उप-समस्याओं** से बनी हैं। डायनेमिक प्रोग्रामिंग (DP) हर उप-समस्या को **एक बार** हल करती है, परिणाम सहेजती है और उसे फिर इस्तेमाल करती है। थोड़ी मेमोरी देकर बहुत बड़ा गति लाभ मिलता है।

दो शर्तें DP के अवसर का संकेत देती हैं:

1. **ओवरलैप होती उप-समस्याएँ** - वही गणनाएँ कई बार लौटती हैं।
2. **इष्टतम उप-संरचना** - पूरी समस्या का श्रेष्ठ समाधान उसके हिस्सों के श्रेष्ठ समाधानों से बनाया जा सकता है।

## Fibonacci: क्लासिक उदाहरण

### सरल रिकर्शन - O(2ⁿ)

```
function fib(n):
    if n <= 1: return n
    return fib(n - 1) + fib(n - 2)
```

`fib(5)` कॉल करने पर **15** फ़ंक्शन कॉल होते हैं, जिनमें कई अनावश्यक हैं। `fib(40)` में सेकंड लगते हैं। `fib(100)` में ब्रह्मांड से भी ज़्यादा समय लग जाएगा।

### मेमोइज़ेशन (टॉप-डाउन) - O(n)

परिणाम कैश में रखें। अगर कोई उप-समस्या पहले ही हल हो चुकी है, तो कैश किया हुआ उत्तर लौटाएँ।

```
memo = {}
function fib(n):
    if n in memo: return memo[n]
    if n <= 1: return n
    memo[n] = fib(n - 1) + fib(n - 2)
    return memo[n]
```

### टैबुलेशन (बॉटम-अप) - O(n)

बेस केस से शुरू करके उत्तर को क्रमिक रूप से ऊपर की ओर बनाएँ।

```
function fib(n):
    table = [0, 1]
    for i in 2..n:
        table[i] = table[i - 1] + table[i - 2]
    return table[n]
```

## क्लासिक DP समस्याएँ

### सीढ़ियाँ चढ़ना

आप एक बार में 1 या 2 सीढ़ियाँ चढ़ सकते हैं। सीढ़ी _n_ तक पहुँचने के कितने अलग-अलग तरीके हैं?

```
function climbStairs(n):
    if n <= 2: return n
    a = 1, b = 2
    for i in 3..n:
        a, b = b, a + b
    return b
```

यह छिपा हुआ Fibonacci है। सीढ़ी _n_ का उत्तर, सीढ़ी _n−1_ और _n−2_ तक पहुँचने के तरीकों का योग है।

### Coin Change

दिए गए सिक्कों के मूल्यवर्ग से लक्ष्य राशि बनाने के लिए **सबसे कम सिक्के** ढूँढें।

```
function coinChange(coins, amount):
    dp = array of size (amount + 1), filled with INF
    dp[0] = 0
    for i in 1..amount:
        for coin in coins:
            if coin <= i:
                dp[i] = min(dp[i], dp[i - coin] + 1)
    return dp[amount] if dp[amount] != INF else -1
```

### Longest Common Subsequence (LCS)

दो स्ट्रिंग में साझा अक्षरों का सबसे लंबा क्रम खोजें। अक्षरों का लगातार होना ज़रूरी नहीं।

```
function lcs(s1, s2):
    m = s1.length, n = s2.length
    dp = 2D array of size (m+1) x (n+1), filled with 0
    for i in 1..m:
        for j in 1..n:
            if s1[i-1] == s2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])
    return dp[m][n]
```

<FunFact>फ़ाइल वर्ज़न के बीच बदलाव दिखाने वाला `diff` टूल LCS से शक्ति पाता है। हर बार जब आप `git diff` चलाते हैं, Git इसका एक वैरिएंट इस्तेमाल करता है।</FunFact>

<ThinkAboutIt>Coin Change सिक्कों की न्यूनतम संख्या पूछता है। अगर आपको राशि बनाने के कुल अलग-अलग तरीकों की गिनती करनी हो तो? पुनरावृत्ति संबंध कैसे बदलेगा?</ThinkAboutIt>

## AI में वास्तविक उपयोग

| समस्या | AI क्षेत्र | DP तकनीक |
|---------|-----------|-------------|
| **एडिट डिस्टेंस** (Levenshtein) | स्पेल चेकर, फ़ज़ी सर्च | अक्षरों की तुलना करने वाली 2D टेबल |
| **Viterbi एल्गोरिदम** | स्पीच रिकग्निशन, POS टैगिंग | हिडन Markov मॉडल में श्रेष्ठ पथ |
| **सीक्वेंस अलाइनमेंट** | बायोइन्फ़ॉर्मेटिक्स (DNA मिलान) | गैप पेनल्टी वाला LCS वैरिएंट |
| **CTC डिकोडिंग** | हस्तलेखन / स्पीच-to-text | दोहराए अक्षरों को इष्टतम रूप से मिलाना |
| **Beam सर्च छँटाई** | मशीन अनुवाद | top-k आंशिक अनुवाद रखना |

## टॉप-डाउन बनाम बॉटम-अप

| पहलू | टॉप-डाउन (मेमोइज़ेशन) | बॉटम-अप (टैबुलेशन) |
|--------|----------------------|----------------------|
| शैली | रिकर्सिव + कैश | इटरेटिव + टेबल |
| हल होने वाली उप-समस्याएँ | सिर्फ़ ज़रूरी उप-समस्याएँ | _n_ तक की सभी उप-समस्याएँ |
| स्टैक ओवरफ़्लो जोखिम | हाँ, गहरी रिकर्शन में | नहीं |
| ऑप्टिमाइज़ेशन की आसानी | स्पेस घटाना कठिन | आसान, अक्सर बस अंतिम पंक्ति रखनी होती है |

**व्यावहारिक नियम:** पुनरावृत्ति संबंध समझने के लिए मेमोइज़ेशन से शुरू करें। फिर अगर स्पेस ऑप्टिमाइज़ करना हो या स्टैक सीमा से बचना हो, तो टैबुलेशन में बदलें।

<ThinkAboutIt>Coin Change टेबल का आकार O(राशि) है। LCS टेबल का आकार O(m × n) है। क्या आप एक बार में सिर्फ़ दो पंक्तियाँ रखकर LCS स्पेस को O(min(m, n)) तक घटा सकते हैं? कौन सी जानकारी खो जाएगी?</ThinkAboutIt>

## मुख्य बातें

1. DP दोहराए काम को **कैश** करके घातीय बलपूर्वक समाधान को बहुपद समय में बदलता है।
2. DP इस्तेमाल करने से पहले ओवरलैप होती उप-समस्याएँ और इष्टतम उप-संरचना पहचानें।
3. मेमोइज़ेशन सहज है। टैबुलेशन कुशल है। दोनों सीखें।
4. एडिट डिस्टेंस, Viterbi और सीक्वेंस अलाइनमेंट दिखाते हैं कि आधुनिक AI के केंद्र में DP है।

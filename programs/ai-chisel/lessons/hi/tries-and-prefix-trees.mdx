## ट्राई क्या है?

**ट्राई** ("try" की तरह उच्चारित) ट्री जैसी संरचना है जिसमें हर नोड एक अक्षर को दर्शाता है। जड़ से चिह्नित नोड तक जाने वाले पथ सहेजे गए शब्द बनाते हैं। हैश मैप के विपरीत, ट्राई आपको हर कुंजी स्कैन किए बिना *एक ही प्रीफ़िक्स साझा करने वाले सभी शब्द* खोजने देता है।

```
        root
       / | \
      a   b   c
     /     \
    p       a
   / \       \
  p   e      t
  |
  l
  e
```

हर पथ एक शब्द एन्कोड करता है: **apple**, **ape**, **bat**, **cat**।

## TrieNode क्लास

हर नोड बच्चों का मैप और शब्द पूरा होने का संकेत देने वाला फ़्लैग रखता है।

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False
```

पूरा Trie इसके ऊपर insert, search और prefix ऑपरेशन जोड़ता है।

## मुख्य ऑपरेशन

### Insert - O(m), जहाँ m = शब्द की लंबाई

अक्षर दर अक्षर चलें, ज़रूरत पड़ने पर नोड बनाएँ, फिर अंतिम नोड को चिह्नित करें।

```python
def insert(self, word):
    node = self.root
    for ch in word:
        if ch not in node.children:
            node.children[ch] = TrieNode()
        node = node.children[ch]
    node.is_end = True
```

### Search और startsWith

**Search** पथ का अनुसरण करता है और `is_end` जाँचता है। **startsWith** सिर्फ़ यह जाँचता है कि पथ मौजूद है या नहीं। उसे `is_end = True` की ज़रूरत नहीं।

## DFS से ऑटोकम्प्लीट

किसी प्रीफ़िक्स के लिए सुझाव देने हेतु पहले प्रीफ़िक्स नोड तक जाएँ, फिर उसके नीचे सभी शब्द इकट्ठे करने के लिए DFS चलाएँ।

```python
def autocomplete(self, prefix):
    node = self._find(prefix)
    if not node:
        return []
    results = []
    self._dfs(node, prefix, results)
    return results
```

`_dfs` सहायक बच्चों में रिकर्स करता है और जब भी `is_end` `True` हो, परिणामों में जोड़ता है।

<ThinkAboutIt>ऑटोकम्प्लीट को top-k सबसे अधिक उपयोग होने वाले सुझावों तक कैसे सीमित करेंगे? हर नोड को कौन सा अतिरिक्त डेटा रखना होगा?</ThinkAboutIt>

## वाइल्डकार्ड सर्च - Word Dictionary

LeetCode की **Design Add and Search Words Data Structure** समस्या आपसे `.` को वाइल्डकार्ड की तरह संभालने को कहती है, जो किसी भी एक अक्षर से मेल खाता है।

सर्च के दौरान जब `.` मिले, तो *हर* बच्चे में शाखा बनाएँ और रिकर्सिव रूप से आगे बढ़ें। इससे सरल ट्रैवर्सल सीमित बैकट्रैकिंग सर्च में बदल जाता है।

```python
def search_wild(self, node, word, i):
    if i == len(word):
        return node.is_end
    if word[i] == '.':
        return any(
            self.search_wild(c, word, i + 1)
            for c in node.children.values()
        )
    if word[i] not in node.children:
        return False
    return self.search_wild(
        node.children[word[i]], word, i + 1
    )
```

## Longest Common Prefix

जड़ से ट्राई पर चलें। सबसे लंबा साझा प्रीफ़िक्स उस पहले नोड पर समाप्त होता है जिसके एक से अधिक बच्चे हों या जहाँ `is_end` फ़्लैग हो।

## ट्राई से IP रूटिंग

राउटर IP प्रीफ़िक्स को **बाइनरी ट्राई** में रखते हैं। हर बिट (0 या 1) एक शाखा बनाता है। Longest prefix match सबसे विशिष्ट रूट खोजता है। इसी से आपके पैकेट इंटरनेट पर अपना रास्ता पाते हैं।

<FunFact>Internet backbone routers विशेष TCAM नामक चिप में बने हार्डवेयर-ऑप्टिमाइज़्ड ट्राई इस्तेमाल करके प्रति सेकंड अरबों longest-prefix-match लुकअप करते हैं।</FunFact>

## संपीड़ित ट्राई (Radix Trees)

मानक ट्राई एक-बच्चे वाली चेन में स्पेस बरबाद करते हैं। **radix tree** ऐसी चेन को एक एज में मिलाता है, जो कई अक्षरों वाला लेबल रखती है।

```
Standard:  r → u → n → n → i → n → g
Radix:     r → "unning"
```

इससे नोड की संख्या बहुत घटती है। Linux kernel routing tables और Go के `httprouter` जैसे HTTP routers इसका उपयोग करते हैं।

## समय और स्पेस जटिलता

| ऑपरेशन   | ट्राई   | हैश मैप |
|-------------|--------|----------|
| Insert      | O(m)   | O(m)     |
| Search      | O(m)   | O(m)     |
| Prefix query| O(m+k) | O(n·m)   |

यहाँ *m* शब्द की लंबाई है, *k* परिणामों की संख्या है और *n* कुल कुंजियाँ हैं। प्रीफ़िक्स-भारी workloads में ट्राई आगे रहते हैं।

- प्रीफ़िक्स-आधारित क्वेरी (ऑटोकम्प्लीट, type-ahead)

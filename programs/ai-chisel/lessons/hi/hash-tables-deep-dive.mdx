## हैशिंग क्यों ज़रूरी है

जब एक अनुशंसा इंजन को ये चेक करना हो कि आपने कोई फ़िल्म पहले देखी है या नहीं - लाखों फ़िल्मों के कैटलॉग में - तो वो एक-एक करके लिस्ट स्कैन नहीं कर सकता। एक **हैश टेबल** ये सवाल O(1) औसत समय में उत्तर कर देता है।

हैश टेबल प्रोडक्शन सॉफ़्टवेयर में सबसे ज़्यादा इस्तेमाल होने वाला डेटा संरचना है, और AI सिस्टम इन्हें फ़ीचर खोज, कैशिंग, और डुप्लिकेशन हटाने के लिए काफ़ी इस्तेमाल करते हैं।

## हैशिंग कैसे काम करता है

एक **हैश फ़ंक्शन** कोई इनपुट लेता है (स्ट्रिंग, संख्या, या ऑब्जेक्ट) और एक पूर्णांक लौटाता है - यही **हैश कोड** है। इस कोड को मॉड्यूलो के ज़रिए **बैकेट इंडेक्स** में मैप किया जाता है:

```
index = hashFunction(key) % numberOfBuckets
```

एक अच्छे हैश फ़ंक्शन की खासियत:
- **डिटरमिनिस्टिक** - एक ही इनपुट हमेशा समान आउटपुट देगा।
- **यूनिफ़ॉर्म** - की को बैकेट में बराबार वितरित करे।
- **तेज़** - की आकार के हिसाब से O(1) में कम्प्यूट हो।

### उदाहरण

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

इसे जानबूझकर सरल रखा गया है - प्रोडक्शन में MurmurHash3 या xxHash जैसे हैश फ़ंक्शन बिट-मिक्सिंग इस्तेमाल करते हैं, जिससे बहुत बेहतर वितरण मिलता है।

## टकराव संभालना

टकराव अटल हैं (टर्म टर्म)। दो मुख्य रणनीतियाँ:

### चेनिंग

हर बैकेट में एक लिंक्ड लिस्ट (या छोटा ऐरे) होता है। टकराने करने वाली की को लिस्ट में अपेंड कर दिया जाता है।

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**फ़ायदे:** सरल है, मध्यम लोड पर अच्छा काम करता है।
**नुकसान:** पॉइंटर चेज़िंग की वजह से कैश के लिए अनुकूल नहीं है।

### ओपन एड्रेसिंग

सभी एंट्री सीधे ऐरे में ही रहती हैं। कोललिसिओन होने पर, अगली खाली टर्म **जाँच** की जाती है।

- **रैखिक प्रोबिंग:** इंडेक्स+1, इंडेक्स+2, … चेक करें।
- **क्वाड्रैटिक प्रोबिंग:** इंडेक्स+1², इंडेक्स+2², … चेक करें।
- **टर्म हैशिंग:** चरण आकार तय करने के लिए दूसरा हैश फ़ंक्शन इस्तेमाल करें।

**फ़ायदे:** बेहतर कैश प्रदर्शन, कोई अतिरिक्त पॉइंटर नहीं।
**नुकसान:** टर्म से प्रदर्शन गिर सकती है; डिलीशन मुश्किल होती है (टर्म चाहिए)।

<FunFact>Python डिक्शनरी कस्टम प्रोबिंग क्रम के साथ ओपन एड्रेसिंग इस्तेमाल करती हैं। CPython का डिक्शनरी कार्यान्वयन इतना अनुकूलित है कि आधुनिक हार्डवेयर पर 5 करेंड़ से ज़्यादा खोज प्रति सेकंड संभाल सकता है।</FunFact>

## लोड फ़ैक्टर और रेहैशिंग

**लोड फ़ैक्टर** α = एंट्री की संख्या / बैकेट की संख्या। जैसे-जैसे α बढ़ता है, टकराव बढ़ती हैं और प्रदर्शन गिरती है।

| लोड फ़ैक्टर | एक्सपेकटेद खोज (चेनिंग) |
|------------|----------------------------|
| 0.5 | ~1.25 |
| 0.75 | ~1.375 |
| 1.0 | ~1.5 |
| 2.0 | ~2.0 |

ज़्यादातर कार्यान्वयन α के सीमा (आमतौर पर 0.75) से ज़्यादा होने पर **रीहैश** करते हैं: बड़ा ऐरे अलॉट करें, हर कुंजी का इंडेक्स दोबारा कम्प्यूट करें, और फिर से इन्सर्ट करें।

रेहैशिंग O(n) है लेकिन बहुत कम होती है, इसलिए इन्सर्शन की **टर्म** लागत O(1) ही रहती है।

<ThinkAboutIt>टर्म टेबल आकार को दोगुना करता है और हर एलिमेंट को दोबारा इन्सर्ट करता है। अगर आपका AI सिस्टम लाइव अनुरोध धारा संभाल रहा है, तो यह विराम लेटेंसी स्पाइक पैदा कर सकता है। टर्म की लागत को एक बार में करने की बजाय कई इन्सर्शन में कैसे बाँट सकते हैं?</ThinkAboutIt>

## AI में वास्तविक ऐप्लिकेशन

| उपयोग मामला | हैश टेबल कैसे मदद करते हैं |
|----------|-------------------------------|
| **टर्म टेबल** | टोकन IDs को O(1) में सघन वेक्टर निरूपण से मैप करें |
| **फ़ीचर हैशिंग** | उच्च-cardinality टर्म फ़ीचर को स्थिर-size टर्म में हैश करें ("हैशिंग युक्ति") |
| **डुप्लिकेशन हटाने** | कंटेंट फ़िंगरप्रिंट हैश करके डुप्लिकेट डॉक्यूमेंट या इमेज पहचान करें |
| **कैशिंग परतें** | इनपुट हैश से टर्म टर्म मॉडल भविष्यवाणियाँ स्टोर करें |
| **टर्म-min स्केच** | कई हैश फ़ंक्शन से स्ट्रीमिंग डेटा में अनुमानित आवृत्ति गिनती निकालें |

## ब्लूम फ़िल्टर: प्रायिक सदस्यता

एक **बलूम फ़िल्टर** ये बताता है कि "क्या ये एलिमेंट सेट में है?" इसके दो जवाब:
- **पक्का नहीं** - एलिमेंट निश्चित रूप से नहीं है।
- **शायद हाँ** - एलिमेंट शायद है (छोटा False-positive दर)।

यह _k_ हैश फ़ंक्शन और एक बिट ऐरे का इस्तेमाल करता है। इन्सर्ट करने पर _k_ बिट सेट होते हैं; खोज में जाँचा जाता है कि सभी _k_ बिट सेट हैं या नहीं।

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**AI में उपयोग:** यह जाँचना कि कोई URL पहले क्रॉल हो चुका है, स्पैम फ़िल्टरिंग, और कैशिंग लेयर में दोहराई गई डेटाबेस क्वेरी से बचना।

<FunFact>टर्म टर्म एक बलूम फ़िल्टर इस्तेमाल करता है जिसमें लाखों ज्ञात दुर्भावनापूर्ण टर्म हैं। कोई भी पेज लोड करने से पहले, आपका ब्राउज़र फ़िल्टर जाँच करता है - अगर वो "शायद हाँ" कहे, तो टर्म कन्फ़र्म करने के लिए फुल लिस्ट टर्म करता है।</FunFact>

## सेट vs मैप: कब क्या इस्तेमाल करें

| संरचना | क्या स्टोर करता है | कब इस्तेमाल करें |
|-----------|-------------------|-------------|
| **सेट** | सिर्फ़ टर्म | सदस्यता जाँच चाहिए - "क्या मैंने ये पहले देखा है?" |
| **मैप** | key-value जोड़े | हर की के साथ डेटा असोकिअटे करना है - "इस की की मूल्य क्या है?" |

दोनों हैश टेबल पर बने हैं और O(1) औसत ऑपरेशन देते हैं। **सेट** चुनिए डुप्लिकेशन हटाने, विज़िटेड टर्म, और अलगनेस बाधाएँ के लिए। **मैप** चुनिए खोज, टर्म, और कॉन्फ़िगरेशन टर्म के लिए।

<ThinkAboutIt>एक AI कंटेंट टर्म सिस्टम को टर्म संदेश को 1 करेंड़ प्रतिबंधित वाक्यांश की ब्लॉकलिस्ट से जाँच करना है। क्या आप हैश सेट इस्तेमाल करेंगे, बलूम फ़िल्टर, या दोनों? मेमोरी, स्पीड, और सटीकता में क्या टर्म-offs हैं?</ThinkAboutIt>

## मुख्य बातें

1. हैश टेबल O(1) औसत-case खोज देते हैं - कैशिंग, टर्म, और फ़ीचर इंजीनियरिंग की रीढ़।
2. टकराव को चेनिंग या ओपन एड्रेसिंग से मैनेज किया जाता है; लोड फ़कटोर बताता है कब रेहैश करना है।
3. बलूम फ़िल्टर थोड़ा False-positive दर स्वीकार करके सदस्यता क्वेरी में बहुत ज़्यादा मेमोरी बचाते हैं।
4. Hashing की अंदरूनी बनावट समझने से आप हर AI वर्कलोड के लिए सही औज़ार - set, मैप, या प्रायिक फ़िल्टर - चुन सकते हैं।

## हशिङ क्यों ज़रूरी है

जब एक अनुशंसा इंजन को ये चेक करना हो कि आपने कोई फ़िल्म पहले देखी है या नहीं - लाखों फ़िल्मों के कैटलॉग में - तो वो एक-एक करके लिस्ट सकन नहीं कर सकता। एक **हैश टेबल** ये सवाल O(1) औसत समय में उत्तर कर देता है।

हश टेबल प्रोडक्शन सॉफ़्टवेयर में सबसे ज़्यादा इस्तेमाल होने वाला डेटा संरचना है, और AI सिस्टम इन्हें फ़ीचर लूकुपस, कैशिंग, और देदुपलिकशन के लिए काफ़ी उपयोग करते हैं।

## हशिङ कैसे काम करता है

एक **हैश फ़ंक्शन** कोई इनपुट लेता है (स्ट्रिंग, संख्या, या ऑब्जेक्ट) और एक पूर्णांक लौटाता है - यही **हैश कोड** है। इस कोड को मॉड्यूलो के ज़रिए **बकेट इंडेक्स** में मैप किया जाता है:

```
index = hashFunction(key) % numberOfBuckets
```

एक अच्छे हैश फ़ंक्शन की खासियत:
- **देटेरमिनिसटिक** - एक ही इनपुट हमेशा समान आउटपुट देगा।
- **उनिफ़ोरम** - की को बुकेटस में बराबर वितरित करे।
- **तेज़** - की आकार के हिसाब से O(1) में कम्प्यूट हो।

### उदाहरण

```
function simpleHash(key, size):
    total = 0
    for char in key:
        total += charCode(char)
    return total % size
```

इसे जानबूझकर सरल रखा गया है - प्रोडक्शन में MurmurHash3 या xxHash जैसे हैश फ़ंक्शन बिट-मिक्सिंग इस्तेमाल करते हैं, जिससे बहुत बेहतर वितरण मिलता है।

## कोललिसिओन हनदलिङ

कोललिसिओनस अटल हैं (पिगेओनहोले परिनकिपले)। दो मुख्य रणनीतियाँ:

### चैनिङ

हर बुकेट में एक लिंक्ड लिस्ट (या छोटा ऐरे) होता है। कोललिदे करने वाली की को लिस्ट में अपपेनद कर दिया जाता है।

```
function insert(table, key, value):
    idx = hash(key) % table.size
    for entry in table[idx]:
        if entry.key == key:
            entry.value = value
            return
    table[idx].append((key, value))
```

**फ़ायदे:** सिमपले है, मध्यम लोड पर अच्छा काम करता है।
**नुकसान:** पॉइंटर चेज़िंग की वजह से कैश के लिए अनुकूल नहीं है।

### ओपेन हलिङ

सभी एनटरिएस सीधे ऐरे में ही रहती हैं। कोललिसिओन होने पर, अगली खाली सलोट **जाँच** की जाती है।

- **लिनेअर परोबिङ:** इंडेक्स+1, इंडेक्स+2, … चेक करो।
- **क्वदरटिक परोबिङ:** इंडेक्स+1², इंडेक्स+2², … चेक करो।
- **Double हैशिंग:** चरण आकार तय करने के लिए दूसरा हैश फ़ंक्शन इस्तेमाल करें।

**फ़ायदे:** बेहतर कैश प्रदर्शन, कोई एक्सटर पॉइंटर नहीं।
**नुकसान:** कलुसटेरिङ से प्रदर्शन गिर सकती है; देलेशन मुश्किल होती है (टोमबसटोनेस चाहिए)।

<FunFact>Python डिक्शनरी कस्टम प्रोबिंग क्रम के साथ ओपन एड्रेसिंग इस्तेमाल करती हैं। CPython का डिक्शनरी कार्यान्वयन इतना अनुकूलित है कि आधुनिक हार्डवेयर पर 5 करोड़ से ज़्यादा खोज प्रति सेकंड संभाल सकता है।</FunFact>

## लोअद फ़कटोर और रेहशिङ

**लोअद फ़कटोर** α = एनटरिएस की संख्या / बुकेटस की संख्या। जैसे-जैसे α एजा है, कोललिसिओनस एजी हैं और प्रदर्शन गिरती है।

| लोअद फ़कटोर | एक्सपेकटेद लूकुपस (चैनिङ) |
|------------|----------------------------|
| 0.5 | ~1.25 |
| 0.75 | ~1.375 |
| 1.0 | ~1.5 |
| 2.0 | ~2.0 |

ज़्यादातर कार्यान्वयन α के सीमा (आमतौर पर 0.75) से ज़्यादा होने पर **रीहैश** करते हैं: बड़ा ऐरे अलॉट करें, हर कुंजी का इंडेक्स दोबारा कम्प्यूट करें, और फिर से इन्सर्ट करें।

रेहशिङ O(n) है लेकिन बहुत कम होती है, इसलिए इन्सर्शन की **अमोरटिसेद** लागत O(1) ही रहती है।

<ThinkAboutIt>Rehashing टेबल आकार को दोगुना करता है और हर एलिमेंट को दोबारा इन्सर्ट करता है। अगर आपका AI सिस्टम लाइव अनुरोध धारा संभाल रहा है, तो यह विराम लेटेंसी स्पाइक पैदा कर सकता है। Rehashing की लागत को एक बार में करने की बजाय कई इन्सर्शन में कैसे बाँट सकते हैं?</ThinkAboutIt>

|----------|-------------------------------|
| **Embedding टेबल** | टोकन IDs को O(1) में सघन वेक्टर निरूपण से मैप करें |
| **फ़ीचर हशिङ** | उच्च-करदिनलिटय कटेगोरिकल फ़ीचर को फ़िक्सेद-सिज़े वेकटोर में हैश करें ("हशिङ टरिक") |

## बलूम फ़िलटेरस: परोबबिलिसटिक मेमबेरशिप

एक **बलूम फ़िल्टर** ये बताता है कि "क्या ये एलिमेंट सेट में है?" इसके दो जवाब:
- **पक्का नहीं** - एलिमेंट निश्चित रूप से नहीं है।
- **शायद हाँ** - एलिमेंट शायद है (छोटा फ़लसे-पोसिटिवे दर)।

यह _k_ हैश फ़ंक्शन और एक बिट ऐरे का उपयोग करता है। इन्सर्ट करने पर _k_ बिट सेट होते हैं; खोज में जाँचा जाता है कि सभी _k_ बिट सेट हैं या नहीं।

```
function bloomInsert(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        filter.bits[idx] = 1

function bloomContains(filter, item):
    for i in 1..k:
        idx = hashFunctions[i](item) % filter.size
        if filter.bits[idx] == 0: return false
    return true   // probably present
```

**AI में उपयोग:** यह जाँचना कि कोई URL पहले क्रॉल हो चुका है, स्पैम फ़िल्टरिंग, और कैशिंग लेयर में दोहराई गई डेटाबेस क्वेरी से बचना।

<FunFact>Google चरोमे एक बलूम फ़िल्टर उपयोग करता है जिसमें लाखों ज्ञात दुर्भावनापूर्ण उरलस हैं। कोई भी पगे लोड करने से पहले, आपका बरोवसेर फ़िल्टर जाँच करता है - अगर वो "शायद हाँ" कहे, तो चरोमे कोनफ़िरम करने के लिए फ़ुलल लिस्ट फ़ेटच करता है।</FunFact>

## सेटस vs मपस: कब क्या इस्तेमाल करें

| सटरुकटुरे | क्या स्टोर करता है | कब इस्तेमाल करें |
|-----------|-------------------|-------------|
| **सेट** | सिर्फ़ केयस | मेमबेरशिप चेकस चाहिए - "क्या मैंने ये पहले देखा है?" |
| **मैप** | केय-वलुए पैरस | हर की के साथ डेटा असोकिअटे करना है - "इस की की मूल्य क्या है?" |

दोनों हैश टेबल पर बने हैं और O(1) औसत ऑपरेशन देते हैं। **सेट** चुनिए देदुपलिकशन, विज़िटेड टरकिङ, और उनिक्वेनेस कोनसटरैनटस के लिए। **मैप** चुनिए लूकुपस, कचेस, और कॉन्फ़िगरेशन स्टोरस के लिए।

<ThinkAboutIt>एक AI कंटेंट मोदेरशन सिस्टम को इनकोमिङ संदेश को 1 करोड़ बननेद फरसेस की बलोकलिसट से जाँच करना है। क्या आप हैश सेट इस्तेमाल करेंगे, बलूम फ़िल्टर, या दोनों? मेमोरय, स्पीड, और सटीकता में क्या टरदे-ओफ़फ़स हैं?</ThinkAboutIt>

## मुख्य बातें

1. हश टेबल O(1) अवेरगे-कसे लूकुपस देते हैं - कैशिंग, इनदेक्सिङ, और फ़ीचर इंजीनियरिंग की रीढ़।
2. कोललिसिओनस को चैनिङ या ओपेन हलिङ से मनगे किया जाता है; लोड फ़कटोर बताता है कब रेहश करना है।
3. बलूम फ़िल्टर थोड़ा फ़लसे-पोसिटिवे दर अककेपट करके मेमबेरशिप क्वेरी में बहुत ज़्यादा मेमोरी बचाते हैं।
4. Hashing की अंदरूनी बनावट समझने से आप हर AI वर्कलोड के लिए सही औज़ार - set, map, या प्रायिक फ़िल्टर - चुन सकते हैं।

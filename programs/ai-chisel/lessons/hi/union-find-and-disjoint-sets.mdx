## कनेक्टिविटी समस्या

नोड के नेटवर्क में आपको लगातार दो तरह की क्वेरी मिलती हैं: *नोड A को नोड B से जोड़ें* और *क्या A और B जुड़े हुए हैं?* BFS/DFS से यह करने का मतलब है हर क्वेरी पर ग्राफ़ ट्रैवर्स करना। लाखों ऑपरेशन के लिए यह बहुत धीमा है।

**Union-Find** दोनों प्रश्नों का उत्तर लगभग स्थिर समय में देता है।

## भोला तरीका - Quick Find

हर नोड के लिए कॉम्पोनेंट ID रखें। कनेक्टिविटी जाँचने के लिए ID की तुलना O(1) में करें। लेकिन दो कॉम्पोनेंट मिलाने पर एक समूह के हर सदस्य को अपडेट करना पड़ता है। हर यूनियन पर O(n)।

```
IDs:  [0, 0, 0, 3, 3]
       └─group 0─┘ └group 3┘
union(0, 3) → update all 3s to 0 → O(n)
```

हमें इससे बेहतर तरीका चाहिए।

## Union-Find डेटा संरचना

हर नोड एक **पैरेंट** की ओर इशारा करता है। हर ट्री की जड़ कॉम्पोनेंट प्रतिनिधि होती है। दो नोड तभी जुड़े हैं जब उनकी जड़ समान हो।

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
```

## Path Compression के साथ Find

गहरे ट्री में पैरेंट पॉइंटर पर ऊपर चलना धीमा हो सकता है। **Path कंप्रेशन** हर देखे गए नोड को सीधे जड़ की ओर इंगित कराकर ट्री को सपाट कर देता है।

```python
def find(self, x):
    if self.parent[x] != x:
        self.parent[x] = self.find(self.parent[x])
    return self.parent[x]
```

नोड 4 खोजने से पहले और बाद:

```
Before:  0←1←2←3←4     After:  0←1
                                0←2
                                0←3
                                0←4
```

## Union से Rank

हमेशा छोटे ट्री को बड़े ट्री के नीचे जोड़ें। इससे ट्री की ऊँचाई लॉगरिद्मिक रहती है और बिगड़ी हुई लंबी चेन नहीं बनती।

```python
def union(self, x, y):
    rx, ry = self.find(x), self.find(y)
    if rx == ry:
        return False
    if self.rank[rx] < self.rank[ry]:
        rx, ry = ry, rx
    self.parent[ry] = rx
    if self.rank[rx] == self.rank[ry]:
        self.rank[rx] += 1
    return True
```

## Kruskal's MST एल्गोरिदम

Union-Find **Kruskal's एल्गोरिदम** को शक्ति देता है, जो Minimum Spanning Trees के लिए है:

1. सभी एज को वेट के अनुसार सॉर्ट करें
2. हर एज (u, v) के लिए, अगर `find(u) ≠ find(v)`, तो उसे जोड़ें और `union(u, v)` करें
3. n − 1 एज मिलने पर रुकें

Union-Find उन एज को अस्वीकार करके चक्र रोकता है जिनके दोनों सिरों की जड़ पहले से समान है। कुल समय: **O(E log E)**, जिसमें सॉर्टिंग प्रमुख है।

<ThinkAboutIt>Kruskal's चक्र पहचानने के लिए Union-Find इस्तेमाल करता है। DFS से चक्र कैसे पहचानेंगे, और यहाँ Union-Find अधिक स्वाभाविक क्यों है?</ThinkAboutIt>

## क्लासिक समस्याएँ

### संख्या of Connected Components

n नोड के साथ Union-Find आरम्भ करें। हर एज को `union` से प्रोसेस करें। अंत में अलग-अलग जड़ों की गिनती करें।

### Accounts मर्ज (LeetCode 721)

हर अकाउंट में ईमेल होते हैं। अगर दो अकाउंट कोई ईमेल साझा करते हैं, तो वे उसी व्यक्ति के हैं। साझा ईमेल से अकाउंट को यूनियन करें, फिर समूह और सॉर्ट करें।

### Redundant Connection (LeetCode 684)

एक ट्री और एक अतिरिक्त एज दी है। अनावश्यक एज खोजें। एज को क्रम में प्रोसेस करें। जिस पहली एज पर `union` `False` लौटाए (पहले से जुड़ी हुई), वही उत्तर है।

<FunFact>दोनों ऑप्टिमाइज़ेशन के साथ Union-Find के O(α(n)) में चलने का प्रमाण Tarjan ने 1975 में प्रकाशित किया था। इसे कंप्यूटर विज्ञान की सबसे सुंदर औसतित विश्लेषण में गिना जाता है।</FunFact>

## Union-Find बनाम BFS/DFS कब चुनें

| स्थिति | बेहतर चुनाव |
|----------|-------------|
| बार-बार कनेक्टिविटी क्वेरी | Union-Find |
| एकल ट्रैवर्सल / सबसे छोटा पथ | BFS/DFS |
| क्रमिक एज जोड़ना | Union-Find |
| एज हटाना (डायनेमिक ग्राफ़) | BFS/DFS (या offline UF) |
| Kruskal's MST | Union-Find |
| दिशित ग्राफ़ में टोपोलॉजिकल सॉर्ट / चक्र | DFS |

Union-Find तब चमकता है जब आप एज को *क्रमिक रूप से* प्रोसेस करते हैं और तेज़ कनेक्टिविटी जाँच चाहिए। अगर आपको बस एक बार ट्रैवर्सल करना है या पथ की जानकारी चाहिए, तो BFS/DFS पर टिके रहें।

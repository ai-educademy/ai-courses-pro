## कोननेकटिविटय की समस्या

मान लीजिए आपके पास नोड का एक नेटवर्क है, और बार-बार दो तरह की क्वेरिएस आ रही हैं: *नोड A को नोड B से कोननेकट करो* और *क्या A और B कोननेकटेद हैं?* अगर हर क्वेरी के लिए BFS/DFS चलाएँ तो पूरा ग्राफ़ ट्रैवर्स करना पड़ेगा - लाखों ऑपरेशन के लिए ये बहुत धीमे है।

**उनिओन-फ़िनद** दोनों क्वेरिएस को लगभग कोनसटनट समय में संभाल करता है।

## नैवे तरीका - क्विक फ़िनद

हर नोड के लिए एक कोमपोनेनट ID सटोरे करो। कोननेकटिविटय जाँच करने के लिए इदस कोमपरे करो - O(1)। लेकिन दो कोमपोनेनटस मर्ज करने के लिए एक पूरे गरोउप की हर ID अपडेट करनी पड़ेगी - O(n) प्रति यूनियन।

```
IDs:  [0, 0, 0, 3, 3]
       └─group 0─┘ └group 3┘
union(0, 3) → update all 3s to 0 → O(n)
```

हमें कुछ बेहतर चाहिए।

## उनिओन-फ़िनद डेटा सटरुकटुरे

हर नोड एक **परेनट** की तरफ बिंदु करता है। हर ट्री का रूट उस कोमपोनेनट का रेपरेसेनटटिवे होता है। दो नोड तभी कोननेकटेद हैं जब उनका रूट समान हो।

```python
class UnionFind:
    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n
```

## फ़िनद के साथ रास्ता कोमपरेसिओन

दीप ट्री में परेनट पॉइंटर फ़ॉलो करना धीमे हो सकता है। **रास्ता कोमपरेसिओन** ट्री को फ़लट कर देता है - हर विज़िटेड नोड को दिरेकटलय रूट से जोड़ देता है।

```python
def find(self, x):
    if self.parent[x] != x:
        self.parent[x] = self.find(self.parent[x])
    return self.parent[x]
```

Node 4 को फ़ाइंड करने से पहले और बाद में:

```
Before:  0←1←2←3←4     After:  0←1
                                0←2
                                0←3
                                0←4
```

## उनिओन by रनक

हमेशा छोटे ट्री को बड़े ट्री के नीचे अटटच करो। इससे ट्री की ऊँचाई लोगरिथमिक रहती है और देगेनेरटे चैनस नहीं बनतीं।

```python
def union(self, x, y):
    rx, ry = self.find(x), self.find(y)
    if rx == ry:
        return False
    if self.rank[rx] < self.rank[ry]:
        rx, ry = ry, rx
    self.parent[ry] = rx
    if self.rank[rx] == self.rank[ry]:
        self.rank[rx] += 1
    return True
```

## करुसकल's MST अलगोरिथम

उनिओन-फ़िनद **करुसकल's अलगोरिथम** को पोवेर करता है - मिनिमुम सपननिङ टरीस के लिए:

1. सभी एदगेस को वज़न के हिसाब से सॉर्ट करो
2. हर बढ़त (u, v) के लिए, अगर `find(u) ≠ find(v)` है, तो उसे जोड़ें करो और `union(u, v)` करो
3. जब n − 1 एदगेस हो जाएँ तो रुक जाओ

उनिओन-फ़िनद कयकलेस परेवेनट करता है - अगर दोनों एनदपोइनटस का रूट समान है तो बढ़त रेजेकट हो जाती है। कुल समय: **O(E लॉग E)** - सॉर्टिंग दोमिनटे करती है।

<ThinkAboutIt>करुसकल's अलगोरिथम कयकलेस देटेकट करने के लिए उनिओन-फ़िनद उपयोग करता है। DFS से साइकिल देटेकट कैसे करोगे, और यहाँ उनिओन-फ़िनद ज़्यादा नटुरल क्यों है?</ThinkAboutIt>

## कलसिक परोबलेमस

### नुमबेर of जुड़े हुए घटक

उनिओन-फ़िनद को n नोड से इनिटिअलिसे करो। हर बढ़त को `union` से प्रोसेस करो। अंत में दिसटिनकट रूटस गणना करो।

### अकाउंट मर्ज (LeetCode 721)

हर अककोउनट में एमैलस हैं। अगर दो अकाउंट में कोई आम एमैल है, तो वो समान पेरसोन के हैं। शरेद एमैलस के आधार पर अकाउंट को यूनियन करो, फिर गरोउप और सॉर्ट करो।

### रेदुनदनट कोननेकशन (LeetCode 684)

एक ट्री दिया है जिसमें एक एक्सटर बढ़त है - रेदुनदनट बढ़त ढूँढो। एदगेस को order में प्रोसेस करो - जिस पहली बढ़त पर `union` `False` लौटाएँ करे (अलरेअदय कोननेकटेद), वही answer है।

<FunFact>उनिओन-फ़िनद दोनों ओपटिमिसशनस के साथ O(α(n)) में चलता है - इसका प्रमाण टरजन ने 1975 में पुबलिश किया था और इसे कंप्यूटर विज्ञान में सबसे एलेगनट अमोरटिसेद अनलयसेस में से एक माना जाता है।</FunFact>

## उनिओन-फ़िनद vs BFS/DFS - कब क्या चुनें

| सकेनरिओ | सबसे अच्छा चोइके |
|----------|-------------------|
| बार-बार कोननेकटिविटय क्वेरिएस | उनिओन-फ़िनद |
| सिङले टरवेरसल / सबसे छोटा रास्ता | BFS/DFS |
| इनकरेमेनटल बढ़त अददिशनस | उनिओन-फ़िनद |
| एदगे रेमोवलस (डायनेमिक ग्राफ़) | BFS/DFS (या ऑफ़लाइन UF) |
| करुसकल's MST | उनिओन-फ़िनद |
| टोपोलोगिकल सॉर्ट / दिरेकटेद ग्राफ़ में साइकिल | DFS |

उनिओन-फ़िनद तब शिने करता है जब आप एदगेस *इनकरेमेनटललय* प्रोसेस कर रहे हों और तेज़ कोननेकटिविटय चेकस चाहिए। अगर सिर्फ एक बार ट्रैवर्स करना है या रास्ता जानकारी चाहिए, तो BFS/DFS इस्तेमाल करें।

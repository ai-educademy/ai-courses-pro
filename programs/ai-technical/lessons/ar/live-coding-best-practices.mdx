```python
# Under pressure (what many candidates write)
def solve(a, t):
    d = {}
    for i, v in enumerate(a):
        if t - v in d:
            return [d[t - v], i]
        d[v] = i

# What you should write
def two_sum(nums, target):
    seen = {}
    for index, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], index]
        seen[num] = index
```

## اختبار الحل الخاص بك قبل أن تقول "تم"

لا تقل أبدًا "لقد انتهيت" دون الاختبار. إليك نهج منهجي:

```python
# Step 1: Trace through the provided example
# Input: [1, 2, 3, 4, 5], target = 9
# i=0: complement=9-1=8, not in seen, seen={1:0}
# i=1: complement=9-2=7, not in seen, seen={1:0, 2:1}
# ...
# i=3: complement=9-4=5, not in seen, seen={1:0, 2:1, 3:2, 4:3}
# i=4: complement=9-5=4, 4 IS in seen at index 3 → return [3, 4] ✓

# Step 2: Test edge cases
# Empty array: [] → should return [] or None
# Single element: [5], target=5 → no pair possible
# Negative numbers: [-1, 2, 3], target=1 → [-1, 2] at indices [0, 1]
# Duplicates: [3, 3], target=6 → should return [0, 1]
```

قم بالتعبير عن عملية الاختبار هذه شفهيًا. يُظهر الدقة ويكتشف الأخطاء قبل أن يفعل القائم بإجراء المقابلة ذلك.

## ماذا تفعل عندما تكون عالقًا

إن التعثر ليس فشلاً، بل البقاء عالقاً بصمت هو الفشل. إليك خطة الهروب الخاصة بك:

1. **أعد صياغة المشكلة** — أحيانًا يكشف قولها بصوت عالٍ عن زاوية جديدة
2. **التعامل مع مثال صغير** — قد يؤدي حل حالة صغيرة يدويًا إلى الكشف عن الخوارزمية
3. **فكر في المشكلات ذات الصلة** — "هذا يذكرني بنمط النافذة المنزلقة..."
4. **ضع في الاعتبار القيود** — إذا كانت قيمة n ≥ 1000، فقد يكون حل O(n²) مقبولاً
5. **بسّط المشكلة** — قم بحل نسخة أبسط أولاً، ثم قم بإضافة التعقيد
6. **اطلب تلميحًا** — "أفكر في استخدام خريطة التجزئة لتتبع الترددات، لكنني لست متأكدًا من كيفية التعامل مع تقلص النافذة. هل يمكنك توجيهي في الاتجاه الصحيح؟"

```python
# When stuck, try the "brute force first" strategy:
# 1. Write the O(n²) solution — it's usually straightforward
# 2. Identify the bottleneck (usually the inner loop)
# 3. Ask: "Can I eliminate this inner loop with a data structure?"
# 4. This often leads naturally to the optimal solution
```

## مناقشة ما بعد الحل

بعد نجاح الحل الخاص بك، فإن المقابلة لم تنته بعد. كن مستعدًا لـ:

- **"ما هو تعقيد الزمان والمكان؟"** - اجعل هذا جاهزًا دائمًا
- **"هل يمكنك تحسينه؟"** - ناقش المقايضات حتى لو لم تتمكن من تنفيذها في الوقت المناسب
- **"كيف يمكن لهذا أن يتعامل مع حالات الحافة؟"** - يوضح أنك فكرت في سيناريوهات الإنتاج

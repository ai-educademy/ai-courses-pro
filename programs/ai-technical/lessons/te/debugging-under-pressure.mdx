# ఒత్తిడిలో డీబగ్గింగ్

ఎవరైనా మిమ్మల్ని చూస్తున్నప్పుడు మరియు టైమర్ కౌంట్ డౌన్ అయినప్పుడు కోడ్ డీబగ్గింగ్ చేయడం వల్ల ఒక ప్రత్యేక రకమైన ఒత్తిడి వస్తుంది. మీ అరచేతులు చెమటలు పడతాయి, మీ మైండ్ బ్లాంక్ అవుతుంది మరియు అకస్మాత్తుగా a కోసం లూప్ ఎలా పనిచేస్తుందో మీకు గుర్తుండదు. ప్రతి ఇంజనీర్ అక్కడ ఉన్నారు. కృంగిపోయే అభ్యర్థులు మరియు ప్రకాశించే వారి మధ్య వ్యత్యాసం అసలైన ప్రతిభ కాదు - ఇది మీ మెదడు భయాందోళనకు గురైనప్పుడు కూడా పనిచేసే క్రమబద్ధమైన ప్రక్రియను కలిగి ఉంటుంది. ఈ పాఠం మీకు ఆ ప్రక్రియను అందిస్తుంది.

## RIIFV డీబగ్గింగ్ ఫ్రేమ్‌వర్క్

మీరు ఇంటర్వ్యూలో బగ్గీ కోడ్‌ను అందజేసినప్పుడు, వెంటనే బగ్ కోసం స్కానింగ్ ప్రారంభించాలనే కోరికను నిరోధించండి. బదులుగా, ఈ ఐదు-దశల ఫ్రేమ్‌వర్క్‌ను అనుసరించండి:

### R — పునరుత్పత్తి

బగ్ ఉనికిని నిర్ధారించండి మరియు దాని లక్షణాలను అర్థం చేసుకోండి.

- ఊహించిన ప్రవర్తన ఏమిటి?
- అసలు ప్రవర్తన ఏమిటి?
- ఏ ఇన్‌పుట్‌ల కింద బగ్ ఏర్పడుతుంది?

```python
# You're told this function should return the second largest element
def second_largest(nums):
    first = second = float('-inf')
    for num in nums:
        if num > first:
            second = first
            first = num
        elif num > second:
            second = num
    return second

# Step 1: Reproduce with test cases
print(second_largest([3, 1, 4, 1, 5]))  # Expected: 4, Got: 4 ✓
print(second_largest([5, 5, 5]))         # Expected: 5, Got: -inf ✗ — BUG!
print(second_largest([1]))               # Expected: None?, Got: -inf — Edge case
```

### నేను — ఒంటరిగా

బగ్ నివసించే ప్రదేశాన్ని తగ్గించండి. విభజించు మరియు జయించు ఆలోచనను ఉపయోగించండి:

- ఇన్‌పుట్‌లోని బగ్ పార్సింగ్, లాజిక్ లేదా అవుట్‌పుట్?
- ఏ నిర్దిష్ట లైన్ లేదా బ్లాక్ తప్పు ఫలితాన్ని ఇస్తుంది?
- మీరు దానిని కనిష్ట విఫలమైన పరీక్ష కేసుగా వేరు చేయగలరా?

### I — గుర్తించండి

ఒంటరిగా ఉన్న తర్వాత, మూల కారణాన్ని గుర్తించండి - కేవలం లక్షణం కాదు:

- **లక్షణం**: `[5, 5, 5]` కోసం `-inf` తిరిగి వస్తుంది
- **మూల కారణం**: `elif num > second` షరతు నకిలీలను నిర్వహించదు. అన్ని మూలకాలు సమానంగా ఉన్నప్పుడు, `num > first` ఒక్కసారి మాత్రమే నిజం మరియు మిగిలిన సమాన మూలకాలకు `num > second` ఎప్పుడూ నిజం కాదు.

### F — పరిష్కరించండి

కొత్త బగ్‌లను పరిచయం చేయకుండా మూల కారణాన్ని పరిష్కరించే కనీస పరిష్కారాన్ని వర్తింపజేయండి:

```python
def second_largest(nums):
    if len(nums) < 2:
        return None
    first = second = float('-inf')
    for num in nums:
        if num > first:
            second = first
            first = num
        elif num > second and num != first:  # Handle case: distinct second
            second = num
    return second if second != float('-inf') else first  # All same → return that value
```

<ThinkAboutIt>వేచి ఉండండి — `second_largest([5, 5, 5])` 5ని తిరిగి ఇవ్వాలా లేక ఏదీ ఇవ్వాలా? ఇది అస్పష్టంగా ఉంది మరియు నిజమైన ఇంటర్వ్యూలో, మీరు ఇంటర్వ్యూయర్‌ని అడగవలసిన ప్రశ్న ఇదే. అవసరాలను స్పష్టం చేయడం డీబగ్గింగ్‌లో భాగం.</ThinkAboutIt>

### V — ధృవీకరించండి

అన్ని కేసుల కోసం పరిష్కారాన్ని నిర్ధారించండి — అసలైన విఫలమైన కేసు, అంచు కేసులు మరియు మునుపు పాసింగ్ కేసులు:

```python
assert second_largest([3, 1, 4, 1, 5]) == 4    # Normal case
assert second_largest([5, 5, 5]) == 5            # Duplicates
assert second_largest([1, 2]) == 1               # Minimum valid input
assert second_largest([1]) is None               # Too few elements
assert second_largest([-1, -2, -3]) == -2        # Negative numbers
```

<Callout>బగ్‌ను పరిష్కరించిన తర్వాత ఎల్లప్పుడూ మీ అసలు పరీక్ష కేసులను మళ్లీ అమలు చేయండి. ఒక బగ్‌ని పరిచయం చేస్తున్నప్పుడు దాన్ని సరిచేయడం ఆశ్చర్యకరంగా సాధారణం. "ధృవీకరించు" దశ రిగ్రెషన్‌లను క్యాచ్ చేస్తుంది, అది మీకు ఇంటర్వ్యూ ఖర్చు అవుతుంది.</Callout>

## సాధారణ డీబగ్గింగ్ ఇంటర్వ్యూ ఫార్మాట్‌లు

### ఫార్మాట్ 1: "ఇదిగో బగ్గీ కోడ్ — దాన్ని పరిష్కరించండి"

మీరు 1-3 బగ్‌లతో ఫంక్షన్‌ను స్వీకరిస్తారు. RIIFVని వర్తింపజేయండి:
- కోడ్ చదవండి మరియు ఉద్దేశాన్ని అర్థం చేసుకోండి
- వైఫల్యాలను కనుగొనడానికి మానసిక పరీక్ష కేసులను అమలు చేయండి
- ప్రతి బగ్‌ని పరిష్కరించండి మరియు మీ తార్కికతను వివరించండి

### ఫార్మాట్ 2: "ఈ సిస్టమ్ విచ్ఛిన్నమైంది - దీనిని గుర్తించండి"

మీకు ఒక దృశ్యం అందించబడింది: "చెక్అవుట్ పేజీ కొన్నిసార్లు తప్పుడు ధరను చూపుతుందని వినియోగదారులు నివేదించారు." మీరు వీటిని చేయాలి:
- స్పష్టమైన ప్రశ్నలను అడగండి ("కొన్నిసార్లు? ఇది యాదృచ్ఛికంగా ఉందా లేదా ఇది నమూనాను అనుసరిస్తుందా?")
- ఫారమ్ పరికల్పనలు ("కాషింగ్ సమస్య కావచ్చు, జాతి పరిస్థితి కావచ్చు లేదా కరెన్సీ మార్పిడి బగ్ కావచ్చు")
- ప్రాధాన్య క్రమంలో దర్యాప్తు దశలను ప్రతిపాదించండి

### ఫార్మాట్ 3: "ఈ లైవ్ సిస్టమ్‌ను డీబగ్ చేయండి" (పెయిర్ డీబగ్గింగ్)

మీరు మరియు ఇంటర్వ్యూయర్ కలిసి డీబగ్ చేస్తారు. వారు సహచరుడు లేదా వ్యవస్థ పాత్రను పోషించవచ్చు:
- మీ ఆలోచన ప్రక్రియను వెర్బల్ చేయండి
- మీరు మొదట ఏమి తనిఖీ చేయాలనుకుంటున్నారో మరియు ఎందుకు అని ప్రతిపాదించండి
- వారు అందించే లాగ్‌లు మరియు మెట్రిక్‌లను అర్థం చేసుకోండి

## డీబగ్గింగ్ చేస్తున్నప్పుడు బిగ్గరగా ఆలోచించడం

ఒంటరిగా డీబగ్గింగ్ చేయడం మరియు ఇంటర్వ్యూలో డీబగ్గింగ్ చేయడం మధ్య ఉన్న అతి పెద్ద వ్యత్యాసం ఏమిటంటే మీరు వివరించాల్సిన అవసరం ఉంది. బలవంతంగా భావించకుండా దీన్ని ఎలా చేయాలో ఇక్కడ ఉంది:

**మీ పరిశీలనలను తెలియజేయండి**:
"ఫంక్షన్ ఒక జాబితాను తీసుకుంటుందని నేను చూస్తున్నాను మరియు రెండవ అతి పెద్దదాన్ని తిరిగి ఇవ్వాలి. ఒక సాధారణ ఉదాహరణతో నేను ట్రేస్ చేద్దాం..."

**రూప పరికల్పనలు**:
"నా మొదటి ఆలోచన ఏమిటంటే, ఇది డూప్లికేట్ విలువల వంటి ఎడ్జ్ కేసులను నిర్వహించకపోవచ్చు. నన్ను [5, 5, 5]తో పరీక్షించనివ్వండి..."

**మీ హేతువును వివరించండి**:
"అన్ని విలువలు సమానంగా ఉన్నప్పుడు షరతు `num > second` ఎప్పటికీ నిజం కాదు ఎందుకంటే `first` ఇప్పటికే 5, మరియు మిగిలిన 5లు `second` కంటే ఎక్కువగా లేవు, అది కూడా `-inf`... వేచి ఉండండి, వాస్తవానికి `5 > -inf` నిజం, కాబట్టి రెండవ మూలకం 5 అవుతుంది, రెండవ మూలకంపై మరింత జాగ్రత్తగా ట్రేస్ చేద్దాం... హ్మ్.

**మీరు తప్పు చేసినప్పుడు అంగీకరించండి**:
"వాస్తవానికి, నా ప్రారంభ పరికల్పన తప్పు. నేను దీన్ని మళ్లీ గుర్తించనివ్వండి..."

<FunFact>మనస్తత్వవేత్త గ్యారీ క్లైన్ చేసిన పరిశోధనలో నిపుణులైన డీబగ్గర్లు కొత్తవారి కంటే 10 రెట్లు వేగంగా సమస్యలను పరిష్కరిస్తారని కనుగొన్నారు, వారు తెలివిగా ఉన్నందున కాదు, కానీ వారు గత అనుభవం నుండి నమూనాలను గుర్తించారు. అందుకే వైవిధ్యమైన బగ్ రకాలతో ప్రాక్టీస్ చేయడం ముడి మేధస్సు కంటే ముఖ్యమైనది.</FunFact>

## ప్రింట్ స్టేట్‌మెంట్‌ల వ్యూహాత్మక ఉపయోగం

కోడింగ్ ఇంటర్వ్యూలో, ప్రింట్ స్టేట్‌మెంట్‌లు మీ డీబగ్గర్. వాటిని వ్యూహాత్మకంగా ఉపయోగించండి:

```python
def merge_sorted_lists(list1, list2):
    result = []
    i = j = 0
    while i < len(list1) and j < len(list2):
        print(f"Comparing list1[{i}]={list1[i]} with list2[{j}]={list2[j]}")
        if list1[i] <= list2[j]:
            result.append(list1[i])
            i += 1
        else:
            result.append(list2[j])
            j += 1
        print(f"Result so far: {result}")

    # Don't forget: add remaining elements
    result.extend(list1[i:])
    result.extend(list2[j:])
    print(f"Final result: {result}")
    return result
```

**సమర్థవంతమైన ప్రింట్ డీబగ్గింగ్ కోసం చిట్కాలు**:
- నిర్ణయం పాయింట్ల వద్ద ముద్రించండి (ముందు ఉంటే/లేకపోతే, లూప్‌ల లోపల)
- అవుట్‌పుట్‌లో వేరియబుల్ పేర్లు మరియు సూచికలను చేర్చండి
- అనుమానిత బగ్ లొకేషన్‌కు ముందు మరియు తర్వాత ప్రింట్ చేయండి
- మీ తుది పరిష్కారాన్ని సమర్పించే ముందు ప్రింట్‌లను తీసివేయండి లేదా వ్యాఖ్యానించండి

## డీబగ్గింగ్ డిస్ట్రిబ్యూటెడ్ సిస్టమ్స్

సీనియర్-స్థాయి ఇంటర్వ్యూల కోసం, పంపిణీ చేయబడిన సిస్టమ్‌లను డీబగ్గింగ్ చేయడం గురించి మిమ్మల్ని అడగవచ్చు:

### డీబగ్గింగ్ టూల్‌కిట్

| సాధనం/టెక్నిక్ | ఇది ఏమి వెల్లడిస్తుంది |
|---|---|
| **లాగ్‌లు** (నిర్మాణం, సహసంబంధ IDలతో) | సంఘటనల క్రమం, దోష వివరాలు |
| **కొలమానాలు** (జాప్యం, లోపం రేటు, నిర్గమాంశ) | పోకడలు మరియు క్రమరాహిత్యాలు |

| **ఆరోగ్య తనిఖీలు** | ఏ భాగాలు క్షీణించాయి |

### సిస్టమాటిక్ అప్రోచ్

2. **పరిధిని సంకుచితం** — ఏ సేవ, ముగింపు స్థానం లేదా ప్రాంతం ప్రభావితం చేయబడింది?
3. **ఇటీవలి విస్తరణలను తనిఖీ చేయండి** — "ఏమి మారింది?" అనేది అత్యధిక సిగ్నల్ ప్రశ్న

## మీరు చిక్కుకున్నప్పుడు ఏమి చేయాలి

1. **సమస్య ప్రకటనను మళ్లీ చదవండి** — మీరు తప్పుగా ఊహించి ఉండవచ్చు
2. **కనిష్ట పరీక్ష కేస్‌ని ప్రయత్నించండి** — ఇన్‌పుట్‌ను ఇప్పటికీ విఫలమయ్యే చిన్న కేసుకు తగ్గించండి
3. ** లైన్ ద్వారా లైన్ ద్వారా ట్రేస్ చేయండి** — అవసరమైతే పెన్ మరియు కాగితంతో, ప్రతి వేరియబుల్‌ను ట్రాక్ చేయండి
4. **సరిహద్దులను తనిఖీ చేయండి** — మొదటి పునరావృతం, చివరి పునరావృతం, ఖాళీ ఇన్‌పుట్
5. **సమస్యను ఇంటర్వ్యూ చేసేవారికి వివరించండి** — "రబ్బర్ డక్ డీబగ్గింగ్" అనేది మానవ ప్రేక్షకులతో కూడా పని చేస్తుంది
6. **సూచన కోసం అడగండి** — 10 నిమిషాలు మౌనంగా కూర్చోవడం కంటే ఇది చాలా మంచిది

## కీలక టేకావేలు

- **RIIFV ఫ్రేమ్‌వర్క్‌ని ఉపయోగించండి**: పునరుత్పత్తి → ఐసోలేట్ → గుర్తించండి → ఫిక్స్ → ధృవీకరించండి. ఇది ఒత్తిడిలో పని చేస్తుంది ఎందుకంటే ఇది మీ మెదడుకు ప్రవృత్తి విఫలమైనప్పుడు ఒక ప్రక్రియను అందిస్తుంది.
- **నిరంతరంగా బిగ్గరగా ఆలోచించండి**: మీ పరిశీలనలు, పరికల్పనలు మరియు తార్కికతను వివరించండి. డీబగ్గింగ్ ఇంటర్వ్యూలో మౌనం మీ శత్రువు.
- **ఎడ్జ్ కేసులకు ప్రాధాన్యత ఇవ్వండి**: చాలా ఇంటర్వ్యూ బగ్‌లు ఖాళీ ఇన్‌పుట్‌లు, డూప్లికేట్‌లు, నెగటివ్ నంబర్‌లు లేదా సరిహద్దు పరిస్థితుల్లో దాక్కుంటాయి.
- **ప్రింట్ స్టేట్‌మెంట్‌లు మీ స్నేహితుడు**: నిర్ణయాత్మక పాయింట్‌ల వద్ద వాటిని వ్యూహాత్మకంగా ఉపయోగించండి మరియు ఖరారు చేయడానికి ముందు వాటిని శుభ్రం చేయండి.
- **పైవట్ ఎప్పుడు చేయాలో తెలుసుకోండి**: 10-15 నిమిషాల తర్వాత మీ విధానం పని చేయకపోతే, వెనక్కి వెళ్లి పూర్తిగా భిన్నమైన కోణాన్ని ప్రయత్నించండి.

# కోడ్ సమీక్ష ఇంటర్వ్యూలు

కోడ్ సమీక్ష ఇంటర్వ్యూలు నియామక ప్రక్రియలో అత్యంత తక్కువగా అంచనా వేయబడిన రౌండ్‌లలో ఒకటి - మరియు అత్యంత బహిర్గతం చేసే వాటిలో ఒకటి. మీరు కోడ్ రాయగలిగితే ఇంటర్వ్యూల పరీక్షను కోడింగ్ చేస్తున్నప్పుడు, కోడ్ సమీక్ష ఇంటర్వ్యూల పరీక్ష మీరు దానిని చదవగలిగితే, దాని గురించి తర్కించవచ్చు మరియు మెరుగుపరచవచ్చు. నాణ్యత గురించి మీరు ఎలా ఆలోచిస్తారో, అభిప్రాయానికి మీరు ఎలా ప్రాధాన్యత ఇస్తారు మరియు ఇతర ఇంజనీర్‌లతో మీరు ఎలా కమ్యూనికేట్ చేస్తారో అవి వెల్లడిస్తాయి. చాలా మంది అభ్యర్థులు లీట్‌కోడ్‌లో నెలల తరబడి సిద్ధమవుతారు, కానీ పూర్తిగా సిద్ధంకాని కోడ్ సమీక్ష రౌండ్‌లోకి వెళతారు. ఆ వ్యక్తి కావద్దు.

## ఏ కోడ్ రివ్యూ ఇంటర్వ్యూలు వాస్తవానికి పరీక్షిస్తాయి

మీ కోడ్ సమీక్ష నైపుణ్యాలను అంచనా వేసే ఇంటర్వ్యూయర్లు ఐదు విషయాల కోసం వెతుకుతున్నారు:

1. **బగ్ డిటెక్షన్** — మీరు లాజికల్ ఎర్రర్‌లు, ఎడ్జ్ కేసులు మరియు రేస్ పరిస్థితులను గుర్తించగలరా?
2. **డిజైన్ సెన్స్** — మీరు SOLID సూత్రాల ఉల్లంఘనలను, పేలవమైన సంగ్రహణలు లేదా నిర్వహించడం కష్టతరమైన కోడ్‌ని గుర్తించారా?
3. **భద్రతా అవగాహన** — మీరు ఇంజెక్షన్ దుర్బలత్వం, ప్రామాణీకరణ లోపాలు లేదా డేటా ఎక్స్‌పోజర్ ప్రమాదాలను గుర్తించగలరా?
4. **కమ్యూనికేషన్ స్కిల్** — మీరు సమస్యలను స్పష్టంగా మరియు నిర్మాణాత్మకంగా వివరించగలరా?
5. **ప్రాధాన్యత** — మీరు చాలా ముఖ్యమైన వాటిపై దృష్టి పెడుతున్నారా లేదా వేరియబుల్ పేర్లపై మీరు బైక్‌షెడ్ చేస్తారా?

<Callout>కోడ్ రివ్యూ ఇంటర్వ్యూలలో అత్యంత సాధారణ తప్పు ఏమిటంటే, అసలు బగ్‌లు లేనప్పుడు మీ సమయాన్ని స్టైల్ సమస్యలపై (పేరు పెట్టడం, ఫార్మాటింగ్ చేయడం) వెచ్చించడం. మీరు దేనికి ప్రాధాన్యత ఇస్తున్నారో చూడటానికి ఇంటర్వ్యూలు ఉద్దేశపూర్వకంగా స్టైల్ సమస్యలతో పాటు క్లిష్టమైన బగ్‌లను నాటుతారు.</Callout>

## సిస్టమాటిక్ రివ్యూ అప్రోచ్

కోడ్‌ని యాదృచ్ఛికంగా స్కాన్ చేయవద్దు. నిర్మాణాత్మక పాస్-ఆధారిత విధానాన్ని ఉపయోగించండి:

### పాస్ 1: ఉద్దేశాన్ని అర్థం చేసుకోండి (2 నిమిషాలు)

ఏదైనా విమర్శించే ముందు, కోడ్ ఏమి చేయడానికి ప్రయత్నిస్తుందో అర్థం చేసుకోండి:
- ఫంక్షన్/క్లాస్ పేర్లు మరియు వ్యాఖ్యలను చదవండి
- ఇన్‌పుట్‌లు మరియు అవుట్‌పుట్‌లను గుర్తించండి
- వ్యాపార లాజిక్‌ను అర్థం చేసుకోండి

### పాస్ 2: కరెక్ట్‌నెస్ (5 నిమిషాలు)

ఇక్కడే మీరు దోషాలను కనుగొంటారు. క్రమపద్ధతిలో తనిఖీ చేయండి:
- **ఎడ్జ్ కేసులు**: ఖాళీ ఇన్‌పుట్‌లు, శూన్య విలువలు, ఒకే మూలకాలు, గరిష్ట విలువలు
- **ఆఫ్-బై-వన్ లోపాలు**: లూప్ సరిహద్దులు, అర్రే ఇండెక్సింగ్
- **లాజిక్ లోపాలు**: సరికాని పరిస్థితులు, లేని విరామ ప్రకటనలు, తప్పు ఆపరేటర్
- **కరెన్సీ సమస్యలు**: భాగస్వామ్య పరివర్తన స్థితి, జాతి పరిస్థితులు
- **ఎర్రర్ హ్యాండ్లింగ్**: గుర్తించబడని మినహాయింపులు, శూన్య తనిఖీలు లేవు

### పాస్ 3: డిజైన్ మరియు నిర్వహణ (3 నిమిషాలు)

నిర్మాణ సమస్యల కోసం చూడండి:
- చాలా పనులు చేసే విధులు (ఒకే బాధ్యతను ఉల్లంఘించడం)
- భాగాల మధ్య గట్టి కలపడం
- మేజిక్ సంఖ్యలు మరియు హార్డ్‌కోడ్ విలువలు
- తప్పిపోయిన సంగ్రహణలు లేదా అనవసరమైన సంగ్రహణలు
- కోడ్ డూప్లికేషన్

### పాస్ 4: పనితీరు మరియు భద్రత (2 నిమిషాలు)

- లూప్‌లలో అనవసరమైన డేటాబేస్ ప్రశ్నలు (N+1 సమస్య)
- ఇన్‌పుట్ ధ్రువీకరణ లేదా శానిటైజేషన్ లేదు
- లాగ్‌లు లేదా ప్రతిస్పందనలలో బహిర్గతమైన సున్నితమైన డేటా
- మెరుగైన ప్రత్యామ్నాయాలు ఉన్న అసమర్థమైన అల్గారిథమ్‌లు

## గుర్తించడానికి సాధారణ బగ్ నమూనాలు

ఈ అధిక-ఫ్రీక్వెన్సీ బగ్‌లను పట్టుకోవడానికి మీ కళ్ళకు శిక్షణ ఇవ్వండి:

### శూన్య సూచన లోపాలు

```java
// Bug: user could be null
public String getUserEmail(Long userId) {
    User user = userRepository.findById(userId);
    return user.getEmail();  // NullPointerException if user not found
}

// Fixed
public String getUserEmail(Long userId) {
    return userRepository.findById(userId)
        .map(User::getEmail)
        .orElseThrow(() -> new UserNotFoundException(userId));
}
```

### ఆఫ్-బై-వన్ లోపాలు

```python
# Bug: misses the last element
def find_max(numbers):
    max_val = numbers[0]
    for i in range(1, len(numbers) - 1):  # Should be len(numbers)
        if numbers[i] > max_val:
            max_val = numbers[i]
    return max_val
```

### వనరుల లీక్‌లు

```java
// Bug: connection is never closed if an exception occurs
public List<User> getUsers() {
    Connection conn = dataSource.getConnection();
    Statement stmt = conn.createStatement();
    ResultSet rs = stmt.executeQuery("SELECT * FROM users");
    // process results...
    conn.close();
    return users;

// Fixed: use try-with-resources
public List<User> getUsers() {
    try (Connection conn = dataSource.getConnection();
         Statement stmt = conn.createStatement();
         ResultSet rs = stmt.executeQuery("SELECT * FROM users")) {
        // process results...
        return users;
    }
}
```

## మీ అభిప్రాయానికి ప్రాధాన్యత ఇవ్వడం

సమయ-పరిమిత ఇంటర్వ్యూలో, అన్ని అభిప్రాయాలు సమానంగా ఉండవు. ఈ ప్రాధాన్యత ఫ్రేమ్‌వర్క్‌ని ఉపయోగించండి:

| ప్రాధాన్యత | వర్గం | ఉదాహరణ |
|---|---|---|
| 🔴 **క్రిటికల్** | బగ్‌లు, భద్రతా లోపాలు, డేటా నష్టం | SQL ఇంజెక్షన్, రేస్ పరిస్థితులు, శూన్య ద్వేషం |
| 🟠 **అధిక** | డిజైన్ సమస్యలు, పనితీరు సమస్యలు | N+1 ప్రశ్నలు, మిస్సింగ్ ఎర్రర్ హ్యాండ్లింగ్, టైట్ కప్లింగ్ |
| 🟡 **మీడియం** | నిర్వహణ, పఠనీయత | సంక్లిష్టమైన షరతులు, తప్పిపోయిన డాక్యుమెంటేషన్, మ్యాజిక్ సంఖ్యలు |
| 🟢 **తక్కువ** | శైలి, చిన్న మెరుగుదలలు | వేరియబుల్ నామకరణం, దిగుమతి ఆర్డరింగ్, మైనర్ రిఫాక్టర్లు |

ఇంటర్వ్యూలో, మీ సమయాన్ని 80% 🔴 మరియు వస్తువులపై వెచ్చించండి. అంశాలను క్లుప్తంగా పేర్కొనండి. మీకు సమయం మిగిలి ఉంటే మరియు ఇప్పటికే ముఖ్యమైన సమస్యలను గుర్తించినట్లయితే మాత్రమే అంశాలను తాకండి.

## రివ్యూ ఫీడ్‌బ్యాక్ కమ్యూనికేట్ చేయడం

మీరు ఫీడ్‌బ్యాక్‌ని ఎలా బట్వాడా చేస్తారనేది ఫీడ్‌బ్యాక్‌కు సంబంధించినంత ముఖ్యమైన అంశం. ఇంటర్వ్యూ చేసేవారు మీ సహకార నైపుణ్యాలను అంచనా వేస్తున్నారు.

**ఇలా చేయండి**:
- "ఈ ప్రశ్న లూప్‌లో ఉందని నేను గమనించాను, ఇది N+1 పనితీరు సమస్యలను కలిగిస్తుంది. మేము దీనిని ఒకే ప్రశ్నగా బ్యాచ్ చేయాలనుకోవచ్చు."
- "వినియోగదారు కనుగొనబడకపోతే ఇది ఒక NullPointerExceptionని విసిరినట్లు కనిపిస్తోంది. మేము ఇక్కడ శూన్య తనిఖీని జోడించగలమా లేదా ఐచ్ఛికాన్ని ఉపయోగించవచ్చా?"

## ఉదాహరణ కోడ్ రివ్యూ వాక్‌త్రూ

ఇంటర్వ్యూలో సమీక్షించమని మిమ్మల్ని అడగగలిగే ఫంక్షన్ ఇక్కడ ఉంది:

```python
def process_orders(orders):
    results = []
    for order in orders:
        user = db.query(f"SELECT * FROM users WHERE id = {order['user_id']}")
        if user:
            total = 0
            for item in order['items']:
                price = db.query(f"SELECT price FROM products WHERE id = {item['product_id']}")
                total = total + price[0] * item['quantity']
                if item['quantity'] > 100:
                    total = total * 0.9
            if total > 0:
                results.append({'user': user, 'total': total, 'order_id': order['id']})
    return results
```

**బలమైన సమీక్ష గుర్తిస్తుంది:**

1. 🔴 **SQL ఇంజెక్షన్** (లైన్‌లు 4, 7): SQL ప్రశ్నలలో స్ట్రింగ్ ఇంటర్‌పోలేషన్. పారామిటరైజ్డ్ ప్రశ్నలను ఉపయోగించండి.
2. 🔴 **N+1 ప్రశ్న సమస్య** (లైన్లు 4, 7): ఒక ఆర్డర్‌కు రెండు డేటాబేస్ ప్రశ్నలు, ఒక్కో వస్తువుకు ఒకటి. ఒక్కొక్కటి 10 ఐటెమ్‌లతో 100 ఆర్డర్‌ల కోసం, అది 1,100 ప్రశ్నలు. ఒకే ప్రశ్నలకు బ్యాచ్ చేయండి.
3. **ఏ ఎర్రర్ హ్యాండ్లింగ్**: ఉత్పత్తి కనుగొనబడకపోతే `price[0]` క్రాష్ అవుతుంది. `db.query` విఫలం కావచ్చు.
4. **డిస్కౌంట్ లాజిక్ దాచబడింది**: పరిమాణం > 100 కోసం 10% తగ్గింపు అనేది నెస్టెడ్ లూప్‌లలో పూడ్చిన వ్యాపార నియమం. దాన్ని సంగ్రహించండి.
5. **మ్యాజిక్ నంబర్**: `0.9` మరియు `100` స్థిరాంకాలు (`BULK_DISCOUNT_RATE`, `BULK_THRESHOLD`) అని పేరు పెట్టాలి.
6. 🟡 **ఫంక్షన్ చాలా ఎక్కువ**: వినియోగదారులను పొందడం, మొత్తాలను లెక్కించడం, తగ్గింపులను వర్తింపజేయడం — ఒకే బాధ్యతను ఉల్లంఘిస్తుంది.

## కీలక టేకావేలు

- **నిర్మాణాత్మక విధానాన్ని ఉపయోగించండి**: బహుళ పాస్‌లు (ఉద్దేశం → ఖచ్చితత్వం → డిజైన్ → పనితీరు/భద్రత) యాదృచ్ఛిక స్కానింగ్ కంటే ఎక్కువ సమస్యలను ఎదుర్కొంటుంది.
- ** నిర్దాక్షిణ్యంగా ప్రాధాన్యత ఇవ్వండి**: క్లిష్టమైన బగ్‌లు మరియు భద్రతా సమస్యలు మొదట, చివరి శైలి. మీ తీర్పును పరీక్షించడానికి ఇంటర్వ్యూయర్లు రెండింటినీ నాటారు.
- **నిర్మాణాత్మకంగా కమ్యూనికేట్ చేయండి**: *ఎందుకు* వివరించండి, ప్రత్యామ్నాయాలను సూచించండి మరియు మీరు చూసే మంచి నమూనాలను గుర్తించండి.

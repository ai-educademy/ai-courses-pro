# Beherrschung der Komplexitätsanalyse

„Was ist die zeitliche Komplexität?“ – vier Wörter, die jeder Lösung folgen, die Sie in einem Programmierinterview präsentieren. Wenn Sie es richtig machen, klingen Sie wie ein selbstbewusster Ingenieur. Sie stolpern und der Interviewer fragt, ob Sie Ihren eigenen Code wirklich verstehen. Komplexitätsanalyse ist nicht nur akademische Theorie; Es ist die Linse, durch die Ingenieure bewerten, ob eine Lösung im großen Maßstab funktioniert. Diese Lektion versetzt Sie in die Lage, jede Lösung sicher zu analysieren – von einfachen Schleifen bis hin zu kniffligen rekursiven Algorithmen.

## Grundlagen der Big-O-Notation

Big-O beschreibt die Obergrenze dafür, wie die Laufzeit oder Speichernutzung eines Algorithmus mit zunehmender Eingabegröße wächst. Konstanten und Terme niedrigerer Ordnung werden entfernt, um sich auf den dominanten Faktor zu konzentrieren.

| Komplexität | Name | Beispiel | 1M Elemente |
|---|---|---|---|
| O(1) | Konstante | Hash-Map-Suche | Sofort |
| O(log n) | Logarithmisch | Binäre Suche | ~20 Operationen |
| O(n) | Linear | Einzelne Schleife durch Array | 1 Mio. Operationen |
| O(n log n) | Linearithmisch | Sortierung zusammenführen, Heap-Sortierung | ~20 Mio. Operationen |
| O(n²) | Quadratisch | Verschachtelte Schleifen (Brute Force) | 1 Billion Operationen |
| O(2ⁿ) | Exponentiell | Rekursive Teilmengen | Hitzetod des Universums |
| O(n!) | Fakultät | Alle Permutationen | Hitzetod × Hitzetod |

<Callout>Eine praktische Faustregel: Moderne Computer erledigen etwa 10⁸ einfache Operationen pro Sekunde. Wenn Ihr Algorithmus O(n²) und n = 10⁵ ist, sind das 10¹⁰ Operationen – etwa 100 Sekunden. Zu langsam. Diese mentale Mathematik hilft Ihnen, schnell zu beurteilen, ob Ihr Ansatz innerhalb der typischen Zeitvorgaben erfolgreich sein wird.</Callout>

## Einfache Schleifen analysieren

### Einzelne Schleife → O(n)

```python
def find_max(nums):
    max_val = nums[0]       # O(1)
    for num in nums:         # Loop runs n times
        if num > max_val:    # O(1) comparison
            max_val = num    # O(1) assignment
    return max_val           # O(1)
# Total: O(1) + O(n) × O(1) = O(n)
```

### Verschachtelte Schleifen → Multiplizieren

```python
def has_duplicate_pair(nums):
    for i in range(len(nums)):           # n iterations
        for j in range(i + 1, len(nums)):  # ~n iterations
            if nums[i] == nums[j]:
                return True
    return False
# Total: O(n) × O(n) = O(n²)
```

### Folgeblöcke → Hinzufügen

```python
def process(nums):
    # Block 1: O(n)
    for num in nums:
        print(num)

    # Block 2: O(n²)
    for i in range(len(nums)):
        for j in range(len(nums)):
            print(i, j)

# Total: O(n) + O(n²) = O(n²)  — drop the lower-order term
```

### Schleifen mit nicht offensichtlichen Iterationen

```python
# This is O(n), not O(n²)!
def two_pointer_sum(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:    # Each pointer moves at most n times total
        total = nums[left] + nums[right]
        if total == target:
            return True
        elif total < target:
            left += 1
        else:
            right -= 1
    return False
```

<ThinkAboutIt>Stellen Sie sich eine Schleife vor, in der die Variable bei jeder Iteration verdoppelt wird: `i = 1; while i < n: i *= 2`. Wie oft wird diese Schleife ausgeführt? Was ist die Komplexität? (Hinweis: Wenn ich mich jedes Mal verdoppele, wie viele Verdoppelungen sind nötig, um n zu erreichen?)</ThinkAboutIt>

## Rekursion analysieren

Bei der Rekursion wird die Komplexitätsanalyse interessant. Das wichtigste Werkzeug ist der **Rekursionsbaum**.

### Lineare Rekursion → O(n)

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

# Recursion tree: single chain of n calls
# factorial(5) → factorial(4) → factorial(3) → factorial(2) → factorial(1)
# Time: O(n), Space: O(n) — n stack frames
```

### Binäre Rekursion → O(2ⁿ)

```python
# Naive Fibonacci — the classic exponential example
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

# Recursion tree: each call spawns TWO calls
#                fib(5)
#              /        \
#          fib(4)       fib(3)
#         /     \       /    \
#      fib(3)  fib(2) fib(2) fib(1)
#      ...
# Nodes at each level double → total nodes ≈ 2ⁿ
# Time: O(2ⁿ), Space: O(n) — max depth of tree
```

### Auswendig gelernte Rekursion → O(n)

```python
def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

# Each subproblem computed only once → O(n) unique calls
# Time: O(n), Space: O(n)
```

<FunFact>Der Unterschied zwischen naivem und auswendig gelerntem Fibonacci ist gewaltig. Die naive Berechnung von fib(50) erfordert etwa 2⁵⁰ ≈ 1 Billiarde Operationen – etwa 100 Tage auf einem modernen Computer. Die gespeicherte Version erfordert genau 50 Vorgänge – erledigt in Mikrosekunden. Deshalb ist die Komplexitätsanalyse wichtig.</FunFact>

### Das Master-Theorem (vereinfacht)

Für Divide-and-Conquer-Rekursionen der Form **T(n) = aT(n/b) + O(nᵈ)**:

| Zustand | Komplexität |
|---|---|
| d > log_b(a) | O(nᵈ) |
| d = log_b(a) | O(nᵈ log n) |
| d < log_b(a) | O(n^(log_b(a))) |

**Praxisbeispiele**:
- **Sortierung zusammenführen**: T(n) = 2T(n/2) + O(n) → a=2, b=2, d=1 → d = log₂2 → **O(n log n)**
- **Binäre Suche**: T(n) = T(n/2) + O(1) → a=1, b=2, d=0 → d = log₂1 → **O(log n)**
- **Strassen Matrix Mult**: T(n) = 7T(n/2) + O(n²) → a=7, b=2, d=2 → d < log₂7 → **O(n^2,81)**

## Weltraumkomplexität

Raumkomplexität ist genauso wichtig wie Zeitkomplexität, wird aber oft übersehen. Zählen:

1. **Hilfsraum** – zusätzliche Datenstrukturen, die Sie erstellen
2. **Frames stapeln** – jeder rekursive Aufruf fügt einen Frame hinzu

```python
# O(1) space — only a few variables
def reverse_in_place(nums):
    left, right = 0, len(nums) - 1
    while left < right:
        nums[left], nums[right] = nums[right], nums[left]
        left += 1
        right -= 1

# O(n) space — creating a new list
def reverse_copy(nums):
    return nums[::-1]

# O(n) space from recursion — n stack frames
def reverse_recursive(nums, left, right):
    if left >= right:
        return
    nums[left], nums[right] = nums[right], nums[left]
    reverse_recursive(nums, left + 1, right - 1)
```

<Callout>Geben Sie in Interviews immer sowohl die zeitliche als auch die räumliche Komplexität an. Eine häufige Folgefrage lautet: „Kann man das im O(1)-Raum machen?“ Dies bedeutet oft, eine rekursive Lösung in eine iterative umzuwandeln oder einen direkten Algorithmus zu finden.</Callout>

## Grundlagen der amortisierten Analyse

Manche Operationen sind gelegentlich teuer, im Durchschnitt aber günstig. Dies ist auf die amortisierte Analyse zurückzuführen.

**Klassisches Beispiel: Dynamisches Array (ArrayList)**

```python
# Appending to a dynamic array
# Most appends are O(1) — just place the element
# Occasionally (when full), the array doubles: O(n) copy
# Over n operations: n × O(1) + log(n) × O(n) = O(n) total
# Amortised cost per operation: O(n) / n = O(1)
```

Weitere amortisierte O(1)-Beispiele:
- Hash-Map-Einfügungen (gelegentliches Aufwärmen)
- Splay-Tree-Operationen
- Implementierung einer Zwei-Stack-Warteschlange

## Häufige Komplexitätsfallen

### Falle 1: Versteckte Schleifen in integrierten Operationen

```python
# Looks like O(n), but string concatenation in a loop is O(n²)
def build_string(chars):
    result = ""
    for char in chars:
        result += char   # Each += creates a new string → O(current length)
    return result
# Fix: use ''.join(chars) → O(n)

# list.index() and 'in' on lists are O(n)
for item in big_list:
    if item in another_big_list:  # O(n) × O(n) = O(n²)
        process(item)
# Fix: convert to set for O(1) lookup
```

### Falle 2: Sortieren dominiert

```python
def find_kth_largest(nums, k):
    nums.sort()       # O(n log n) — this dominates
    return nums[-k]   # O(1)
# Total: O(n log n), not O(1)
# Better: use a heap for O(n log k)
```

### Falle 3: Rekursionstiefe ≠ Gesamtarbeit

```python
# Depth is O(log n), but total work is O(n)
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])     # T(n/2)
    right = merge_sort(arr[mid:])    # T(n/2)
    return merge(left, right)        # O(n) work at each level
# log n levels × O(n) work per level = O(n log n)
```

## Von Brute Force zu Optimal

In Vorstellungsgesprächen beginnen Sie oft mit einer Brute-Force-Lösung und optimieren diese. Hier ist der übliche Optimierungspfad:

| Aktuell | Optimierungstechnik | Verbessert auf |
|---|---|---|
| O(n²) | Hash-Map für Suchvorgänge | O(n) |
| O(n²) | Sortieren + zwei Zeiger | O(n log n) |
| O(2ⁿ) | Auswendiglernen / DP | O(n²) oder O(n×m) |
| O(n log n) | Eimersortierung / Zählsortierung (begrenzter Bereich) | O(n) |
| O(n) Raum | Manipulation vor Ort | O(1) Raum |

**Der Gesprächsablauf in einem Vorstellungsgespräch**:
1. „Mein Brute-Force-Ansatz ist O(n²) unter Verwendung verschachtelter Schleifen.“
2. „Mir ist aufgefallen, dass wir wiederholte Suchvorgänge durchführen – eine Hash-Map kann die innere Suche auf O(1) reduzieren.“
3. „Die optimierte Lösung ist O(n) Zeit und O(n) Raum.“
4. „Der Kompromiss besteht darin, dass wir zusätzlichen Speicher verbrauchen, aber die Zeitverbesserung ist erheblich.“

## Wichtige Erkenntnisse

- **Kennen Sie die Hierarchie**: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!). Darauf werden Sie in jedem Vorstellungsgespräch Bezug nehmen.
- **Verschachtelte Schleifen multiplizieren, sequentielle Blöcke hinzufügen**: die beiden Grundregeln für die Schleifenanalyse.
- **Zeichnen Sie Rekursionsbäume**: Sie machen rekursive Komplexität sichtbar und lassen sich viel einfacher korrekt analysieren.
- **Achten Sie auf versteckte Kosten**: Die Verkettung von Zeichenfolgen, das Testen der Listenmitgliedschaft und das Sortieren innerhalb von Schleifen sind häufige Fallstricke.
- **Geben Sie sowohl Zeit als auch Raum an**: Eine vollständige Komplexitätsanalyse deckt immer beide Dimensionen ab.
- **Verbindung zur Optimierung**: Wenn Sie die Brute-Force-Komplexität kennen, erfahren Sie, wie viel Raum für Verbesserungen vorhanden ist.

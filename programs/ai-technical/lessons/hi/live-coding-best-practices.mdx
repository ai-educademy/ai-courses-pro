# लाइव कोडिंग सर्वोत्तम अभ्यास

आप अपनी नींद में लीटकोड माध्यमों को हल कर सकते हैं, लेकिन एक इंसान को स्क्रीन शेयर के दूसरे छोर पर रख दें और अचानक आपकी उंगलियां भूल जाती हैं कि अर्धविराम कहां जाते हैं। लाइव कोडिंग साक्षात्कार एक प्रदर्शन है - जहां आपका मूल्यांकन न केवल अंतिम कोड के आधार पर किया जाता है, बल्कि इस आधार पर भी किया जाता है कि आप वहां कैसे पहुंचे। जो उम्मीदवार उत्तीर्ण होते हैं वे हमेशा सबसे तेज़ कोडर नहीं होते हैं; वे ही हैं जो स्पष्ट रूप से संवाद करते हैं, असफलताओं को शालीनता से संभालते हैं, और ऐसा कोड लिखते हैं जो दबाव में पढ़ने योग्य हो। यह पाठ आपको वह उम्मीदवार बनना सिखाता है।

## अपना वातावरण स्थापित करना

पहली छाप मायने रखती है. जब आप कोडरपैड, हैकररैंक, या वीएस कोड लाइव शेयर खोलते हैं, तो साक्षात्कारकर्ता पहले से ही राय बना रहा होता है।

### प्लेटफ़ॉर्म-विशिष्ट युक्तियाँ

**कोडरपैड** (सबसे आम):
- इंटरव्यू शुरू होने से पहले ड्रॉपडाउन से अपनी भाषा चुनें
- अंतर्निहित रन बटन का उपयोग करें - जानें कि आउटपुट कंसोल फलक में दिखाई देता है
- ऑटो-इंडेंट और सिंटैक्स हाइलाइटिंग उपलब्ध हैं

**हैकररैंक**:
- समस्या कथन को ध्यान से पढ़ें - इनपुट सटदिन से आते हैं
- परीक्षण मामले स्वचालित रूप से चलते हैं; अपेक्षित प्रारूप को समझें
- कस्टम परीक्षण मामले बाएं पैनल में जोड़े जा सकते हैं

**वीएस कोड लाइव शेयर/Google डॉक्स**:
- कोई स्वत: पूर्ण या सिंटैक्स हाइलाइटिंग नहीं (संभवतः)
- लगातार हाथ से इंडेंट करें - यह अनुशासन दर्शाता है
- Google डॉक्स के लिए: एक मोनोस्पेस फ़ॉन्ट का उपयोग करें (कूरियर न्यू)

<Callout>किसी भी लाइव कोडिंग साक्षात्कार से पहले, 5 मिनट की पर्यावरण जांच करें। प्लेटफ़ॉर्म खोलें, "हैलो वर्ल्ड" लिखें और इसे चलाएं। साक्षात्कार के दौरान मंच से लड़खड़ाने से कीमती मिनट बर्बाद होते हैं और आपका आत्मविश्वास डगमगा जाता है।</Callout>

## टॉक-अलाउड प्रोटोकॉल

## दबाव में स्वच्छ कोड लिखना

तनाव के तहत, कोड गुणवत्ता पहली दुर्घटना है। जानबूझकर आदतों से इससे लड़ें:

### सार्थक नामों का प्रयोग करें

```python
# Under pressure (what many candidates write)
def solve(a, t):
    d = {}
    for i, v in enumerate(a):
        if t - v in d:
            return [d[t - v], i]
        d[v] = i

# What you should write
def two_sum(nums, target):
    seen = {}
    for index, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], index]
        seen[num] = index
```

दूसरे संस्करण को लिखने में 10 अतिरिक्त सेकंड लगते हैं लेकिन डिबगिंग 10 गुना आसान हो जाती है - और साक्षात्कारकर्ता को प्रभावित करती है।

### कंकाल से शुरुआत करें

तर्क भरने से पहले, संरचना लिखें:

```python
def merge_intervals(intervals):
    # Edge case
    if not intervals:
        return []

    # Sort by start time
    intervals.sort(key=lambda x: x[0])

    # Merge overlapping intervals
    merged = [intervals[0]]
    for current in intervals[1:]:
        # TODO: merge logic
        pass

    return merged
```

यह साक्षात्कारकर्ता को आपकी योजना लागू करने से पहले दिखाता है। इसका मतलब यह भी है कि भले ही आपके पास समय की कमी हो, वे एक सही उच्च-स्तरीय दृष्टिकोण देखते हैं।

### सहायक कार्य आपके मित्र हैं

```python
# Extract reusable logic into named functions
def is_valid_move(board, row, col):
    return 0 <= row < len(board) and 0 <= col < len(board[0])

def get_neighbours(row, col):
    return [(row + dr, col + dc) for dr, dc in [(0, 1), (0, -1), (1, 0), (-1, 0)]]
```

हेल्पर फ़ंक्शन संज्ञानात्मक भार को कम करते हैं, आपके कोड को स्व-दस्तावेजीकरण बनाते हैं, और आपको यह कहने की अनुमति देते हैं कि "मैं इस हेल्पर को बाद में लागू करूंगा - अभी के लिए, मान लें कि यह काम करता है।"

<FunFact>जोड़ी प्रोग्रामिंग (जो लाइव कोडिंग साक्षात्कार अनुकरण करते हैं) पर अध्ययन से पता चलता है कि जोड़े एकल प्रोग्रामर की तुलना में 15% कम दोषों के साथ कोड का उत्पादन करते हैं, लेकिन लगभग 15% अधिक समय लेते हैं। एक साक्षात्कार में, साक्षात्कारकर्ता के साथ गतिशील "जोड़ी" वास्तव में आपके पक्ष में काम करती है - यदि आप खुले तौर पर संवाद करते हैं, तो वे उन गलतियों को पकड़ सकते हैं जिन्हें आप अकेले भूल जाते हैं।</FunFact>

## संकेतों को शालीनता से संभालना

साक्षात्कारकर्ता संकेत देते हैं. यह विफलता का संकेत नहीं है - यह एक वार्तालाप है। आप कैसे प्रतिक्रिया देते हैं यह मायने रखता है:

**संकेतों पर अच्छी प्रतिक्रियाएँ**:
- "यह एक बढ़िया बात है - मुझे लगता है कि आप सुझाव दे रहे हैं कि मैं यहां एक स्टैक का उपयोग करूं। मुझे सोचने दीजिए कि यह कैसे मदद करता है..."
- "आह, मैं देख रहा हूं - अगर मैं पहले इनपुट को सॉर्ट करता हूं, तो दो-पॉइंटर दृष्टिकोण संभव हो जाता है। मुझे पुनर्गठन करने दीजिए।"
- "धन्यवाद, मैंने उस किनारे वाले मामले पर विचार नहीं किया था। मुझे नकारात्मक संख्याओं के लिए हैंडलिंग जोड़ने दीजिए।"

**खराब प्रतिक्रियाएँ**:
- संकेत को अनदेखा करके अपना दृष्टिकोण जारी रखना
- "मुझे पता है, मैं बस यही करने वाला था" (रक्षात्मक)
- हारा हुआ या घबराया हुआ दिखना

<Callout>एक साक्षात्कारकर्ता जो संकेत देता है वह आपको सफल होने में मदद करने का प्रयास कर रहा है। कई उम्मीदवारों को कई संकेत मिलने के बाद नौकरी पर रखा जाता है - जो मायने रखता है वह यह है कि आप संकेत को समझते हैं, अनुकूलित करते हैं और दिखाते हैं कि आप सहयोग कर सकते हैं। संकेत के बाद असफल दृष्टिकोण पर अड़े रहना एक खतरे का संकेत है।</Callout>

## "पूरा" कहने से पहले अपने समाधान का परीक्षण करना

बिना परीक्षण के कभी भी "मेरा काम हो गया" न कहें। यहाँ एक व्यवस्थित दृष्टिकोण है:

```python
# Step 1: Trace through the provided example
# Input: [1, 2, 3, 4, 5], target = 9
# i=0: complement=9-1=8, not in seen, seen={1:0}
# i=1: complement=9-2=7, not in seen, seen={1:0, 2:1}
# ...
# i=3: complement=9-4=5, not in seen, seen={1:0, 2:1, 3:2, 4:3}
# i=4: complement=9-5=4, 4 IS in seen at index 3 → return [3, 4] ✓

# Step 2: Test edge cases
# Empty array: [] → should return [] or None
# Single element: [5], target=5 → no pair possible
# Negative numbers: [-1, 2, 3], target=1 → [-1, 2] at indices [0, 1]
# Duplicates: [3, 3], target=6 → should return [0, 1]
```

इस परीक्षण प्रक्रिया को मौखिक रूप से बताएं। यह संपूर्णता दिखाता है और साक्षात्कारकर्ता के आने से पहले ही बग पकड़ लेता है।

2. **एक छोटे उदाहरण के माध्यम से काम करें** - एक छोटे से मामले को मैन्युअल रूप से हल करने से एल्गोरिदम का पता चल सकता है
3. **संबंधित समस्याओं के बारे में सोचें** - "यह मुझे स्लाइडिंग विंडो पैटर्न की याद दिलाता है..."
4. **बाधाओं पर विचार करें** - यदि n ≤ 1000, तो एक O(n²) समाधान स्वीकार्य हो सकता है
5. **समस्या को सरल बनाएँ** - पहले एक सरल संस्करण को हल करें, फिर जटिलता जोड़ें
6. **संकेत के लिए पूछें** - "मैं आवृत्तियों को ट्रैक करने के लिए हैश मैप का उपयोग करने पर विचार कर रहा हूं, लेकिन मुझे यकीन नहीं है कि विंडो सिकुड़न को कैसे संभालना है। क्या आप मुझे सही दिशा बता सकते हैं?"

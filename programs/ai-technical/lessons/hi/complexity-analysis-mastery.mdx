# Complexity Analysis में महारत

"Time complexity क्या है?" ये चार शब्द coding interview में आपके हर solution के बाद आते हैं। सही जवाब दें, तो आप confident engineer लगते हैं। अटकें, तो interviewer पूछता है कि क्या आप सच में अपना code समझते हैं। Complexity analysis सिर्फ academic theory नहीं है। यह वह lens है जिससे engineers evaluate करते हैं कि कोई solution scale पर काम करेगा या नहीं। यह पाठ आपको simple loops से tricky recursive algorithms तक, किसी भी solution को confidence से analyse करने के लिए तैयार करता है।

## Big-O Notation Fundamentals

Big-O बताता है कि input size बढ़ने पर algorithm का runtime या memory usage upper bound में कैसे बढ़ता है। यह constants और lower-order terms हटाकर dominant factor पर focus करता है।

| Complexity | Name | Example | 1M Elements |
|---|---|---|---|
| O(1) | Constant | Hash map lookup | Instant |
| O(log n) | Logarithmic | Binary search | ~20 operations |
| O(n) | Linear | Single loop through array | 1M operations |
| O(n log n) | Linearithmic | Merge sort, heap sort | ~20M operations |
| O(n²) | Quadratic | Nested loops (brute force) | 1 trillion operations |
| O(2ⁿ) | Exponential | Recursive subsets | Heat death of universe |
| O(n!) | Factorial | All permutations | Heat death × heat death |

<Callout>एक practical rule of thumb: modern computers लगभग 10⁸ simple operations प्रति second संभालते हैं। अगर आपका algorithm O(n²) है और n = 10⁵, तो यह 10¹⁰ operations है, लगभग 100 सेकंड। बहुत धीमा। यह mental math आपको जल्दी judge करने में मदद करता है कि आपका approach typical time limits में pass होगा या नहीं।</Callout>

## Simple Loops Analyse करना

### Single Loop → O(n)

```python
def find_max(nums):
    max_val = nums[0]       # O(1)
    for num in nums:         # Loop runs n times
        if num > max_val:    # O(1) comparison
            max_val = num    # O(1) assignment
    return max_val           # O(1)
# Total: O(1) + O(n) × O(1) = O(n)
```

### Nested Loops → Multiply

```python
def has_duplicate_pair(nums):
    for i in range(len(nums)):           # n iterations
        for j in range(i + 1, len(nums)):  # ~n iterations
            if nums[i] == nums[j]:
                return True
    return False
# Total: O(n) × O(n) = O(n²)
```

### Sequential Blocks → Add

```python
def process(nums):
    # Block 1: O(n)
    for num in nums:
        print(num)

    # Block 2: O(n²)
    for i in range(len(nums)):
        for j in range(len(nums)):
            print(i, j)

# Total: O(n) + O(n²) = O(n²)  — drop the lower-order term
```

### Non-Obvious Iterations वाले Loops

```python
# This is O(n), not O(n²)!
def two_pointer_sum(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:    # Each pointer moves at most n times total
        total = nums[left] + nums[right]
        if total == target:
            return True
        elif total < target:
            left += 1
        else:
            right -= 1
    return False
```

<ThinkAboutIt>ऐसा loop सोचें जहाँ variable हर iteration में double होता है: `i = 1; while i < n: i *= 2`। यह loop कितनी बार execute होता है? Complexity क्या है? (Hint: अगर i हर बार double होता है, तो n तक पहुँचने में कितनी doublings लगती हैं?)</ThinkAboutIt>

## Recursion Analyse करना

Recursion में complexity analysis interesting हो जाती है। मुख्य tool है **recursion tree**।

### Linear Recursion → O(n)

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)

# Recursion tree: single chain of n calls
# factorial(5) → factorial(4) → factorial(3) → factorial(2) → factorial(1)
# Time: O(n), Space: O(n) — n stack frames
```

### Binary Recursion → O(2ⁿ)

```python
# Naive Fibonacci — the classic exponential example
def fib(n):
    if n <= 1:
        return n
    return fib(n - 1) + fib(n - 2)

# Recursion tree: each call spawns TWO calls
#                fib(5)
#              /        #          fib(4)       fib(3)
#         /     \       /    #      fib(3)  fib(2) fib(2) fib(1)
#      ...
# Nodes at each level double → total nodes ≈ 2ⁿ
# Time: O(2ⁿ), Space: O(n) — max depth of tree
```

### Memoised Recursion → O(n)

```python
def fib_memo(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    memo[n] = fib_memo(n - 1, memo) + fib_memo(n - 2, memo)
    return memo[n]

# Each subproblem computed only once → O(n) unique calls
# Time: O(n), Space: O(n)
```

<FunFact>Naive और memoised Fibonacci के बीच scale पर अंतर चौंकाने वाला है। fib(50) naively compute करने में लगभग 2⁵⁰ ≈ 1 quadrillion operations चाहिए, modern computer पर लगभग 100 दिन। Memoised version exactly 50 operations लेता है, microseconds में पूरा। इसी वजह से complexity analysis matter करता है।</FunFact>

### Master Theorem (सरल रूप)

Form **T(n) = aT(n/b) + O(nᵈ)** वाली divide-and-conquer recurrences के लिए:

| Condition | Complexity |
|---|---|
| d > log_b(a) | O(nᵈ) |
| d = log_b(a) | O(nᵈ log n) |
| d < log_b(a) | O(n^(log_b(a))) |

**Practical examples**:
- **Merge Sort**: T(n) = 2T(n/2) + O(n) → a=2, b=2, d=1 → d = log₂2 → **O(n log n)**
- **Binary Search**: T(n) = T(n/2) + O(1) → a=1, b=2, d=0 → d = log₂1 → **O(log n)**
- **Strassen Matrix Mult**: T(n) = 7T(n/2) + O(n²) → a=7, b=2, d=2 → d < log₂7 → **O(n^2.81)**

## Space Complexity

Space complexity time complexity जितनी ही important है, लेकिन अक्सर overlook होती है। Count करें:

1. **Auxiliary space**: extra data structures जो आप बनाते हैं
2. **Stack frames**: हर recursive call एक frame जोड़ती है

```python
# O(1) space — only a few variables
def reverse_in_place(nums):
    left, right = 0, len(nums) - 1
    while left < right:
        nums[left], nums[right] = nums[right], nums[left]
        left += 1
        right -= 1

# O(n) space — creating a new list
def reverse_copy(nums):
    return nums[::-1]

# O(n) space from recursion — n stack frames
def reverse_recursive(nums, left, right):
    if left >= right:
        return
    nums[left], nums[right] = nums[right], nums[left]
    reverse_recursive(nums, left + 1, right - 1)
```

<Callout>Interviews में हमेशा time AND space complexity दोनों बताएं। Common follow-up होता है: "क्या आप इसे O(1) space में कर सकते हैं?" इसका मतलब अक्सर recursive solution को iterative बनाना, या in-place algorithm खोजना होता है।</Callout>

## Amortised Analysis Basics

कुछ operations कभी-कभी expensive होते हैं लेकिन average में सस्ते। Amortised analysis इसे account करता है।

**Classic example: Dynamic Array (ArrayList)**

```python
# Appending to a dynamic array
# Most appends are O(1) — just place the element
# Occasionally (when full), the array doubles: O(n) copy
# Over n operations: n × O(1) + log(n) × O(n) = O(n) total
# Amortised cost per operation: O(n) / n = O(1)
```

अन्य amortised O(1) examples:
- Hash map insertions (occasional rehashing)
- Splay tree operations
- Two-stack queue implementation

## Common Complexity Traps

### Trap 1: Built-in Operations में Hidden Loops

```python
# Looks like O(n), but string concatenation in a loop is O(n²)
def build_string(chars):
    result = ""
    for char in chars:
        result += char   # Each += creates a new string → O(current length)
    return result
# Fix: use ''.join(chars) → O(n)

# list.index() and 'in' on lists are O(n)
for item in big_list:
    if item in another_big_list:  # O(n) × O(n) = O(n²)
        process(item)
# Fix: convert to set for O(1) lookup
```

### Trap 2: Sorting Dominates

```python
def find_kth_largest(nums, k):
    nums.sort()       # O(n log n) — this dominates
    return nums[-k]   # O(1)
# Total: O(n log n), not O(1)
# Better: use a heap for O(n log k)
```

### Trap 3: Recursion Depth ≠ Total Work

```python
# Depth is O(log n), but total work is O(n)
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])     # T(n/2)
    right = merge_sort(arr[mid:])    # T(n/2)
    return merge(left, right)        # O(n) work at each level
# log n levels × O(n) work per level = O(n log n)
```

## Brute Force से Optimal तक

Interviews में आप अक्सर brute-force solution से शुरू करके optimise करते हैं। Common optimisation path यह है:

| Current | Optimisation Technique | Improved To |
|---|---|---|
| O(n²) | Hash map for lookups | O(n) |
| O(n²) | Sorting + two pointers | O(n log n) |
| O(2ⁿ) | Memoisation / DP | O(n²) or O(n×m) |
| O(n log n) | Bucket sort / counting sort (limited range) | O(n) |
| O(n) space | In-place manipulation | O(1) space |

**Interview में conversation flow**:
1. "मेरा brute force approach nested loops से O(n²) है।"
2. "मैं देख रहा हूँ कि हम repeated lookups कर रहे हैं। Hash map inner search को O(1) कर सकता है।"
3. "Optimised solution O(n) time और O(n) space है।"
4. "Trade-off यह है कि हम extra memory इस्तेमाल कर रहे हैं, लेकिन time improvement significant है।"

## मुख्य बातें

- **Hierarchy जानें**: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)। हर interview में आप इसका reference देंगे।
- **Nested loops multiply करें, sequential blocks add करें**: loop analysis के दो मूलभूत नियम।
- **Recursion trees draw करें**: वे recursive complexity को visual और analyse करने में आसान बनाते हैं।
- **Hidden costs देखें**: string concatenation, list membership testing और loops के अंदर sorting common traps हैं।
- **Time और space दोनों बताएं**: complete complexity analysis दोनों dimensions cover करता है।
- **Optimisation से जोड़ें**: brute-force complexity जानने से पता चलता है कि improve करने की कितनी जगह है।

# साक्षात्कार के लिए डेटा संरचनाएँ

यहां एक रहस्य है कि शीर्ष साक्षात्कार प्रशिक्षक आपसे सीखने के लिए $500 का शुल्क नहीं लेंगे: लगभग 90% कोडिंग साक्षात्कार समस्याएं केवल सात डेटा संरचनाओं के इर्द-गिर्द घूमती हैं। यदि आप गहराई से समझते हैं कि प्रत्येक तक कब और क्यों पहुंचना है, तो आप पहले ही आधी लड़ाई जीत चुके हैं। दूसरा भाग अभ्यास है - लेकिन सही मानसिक मॉडल के बिना, अभ्यास केवल याद रखना है। यह पाठ आपको मानचित्र देता है ताकि आपके सामने आने वाली प्रत्येक समस्या परिचित क्षेत्र जैसी लगे।

## 7 अवश्य जानने योग्य डेटा संरचनाएँ

हर तकनीकी साक्षात्कार उसी कुएं से निकलता है। यहां वे संरचनाएं हैं जिनका आप सामना करेंगे, आवृत्ति के आधार पर क्रमबद्ध:

| डेटा संरचना | साक्षात्कार आवृत्ति | कोर ऑपरेशंस | जब साक्षात्कारकर्ता इसकी अपेक्षा करते हैं |
|---|---|---|---|
| **सरणी/स्ट्रिंग्स** | ★★★★★ | एक्सेस ओ(1), सर्च ओ(एन), इन्सर्ट ओ(एन) | लगभग हर समस्या यहीं से शुरू होती है |
| **हैश मैप्स/सेट्स** | ★★★★★ | ओ(1) डालें, लुकअप ओ(1), हटाएं ओ(1) | "इसे O(n²) से O(n) तक अनुकूलित करें" |
| **लिंक्ड सूचियाँ** | ★★★★☆ | O(1) डालें, O(1) हटाएं, O(n) तक पहुंचें | सूचक हेरफेर, चक्र का पता लगाना |
| **ढेर और कतारें** | ★★★★☆ | पुश/पॉप ओ(1), एनक्यू/डेक्यू ओ(1) | पार्सिंग, बीएफएस, संचालन पूर्ववत करें |
| **पेड़ (बाइनरी, बीएसटी)** | ★★★★☆ | ओ(लॉग एन) खोजें, ओ(लॉग एन) डालें | पदानुक्रमित डेटा, क्रमबद्ध संचालन |
| **ग्राफ़** | ★★★☆☆ | प्रतिनिधित्व पर निर्भर करता है | रिश्ते, रास्ते, कनेक्टिविटी |
| **ढेर** | ★★★☆☆ | ओ(लॉग एन) डालें, एक्सट्रेक्ट-मिन ओ(लॉग एन) | "K को सबसे बड़ा/छोटा खोजें" |

<Callout>यदि आपके पास तैयारी के लिए केवल एक सप्ताह है, तो सरणियों, हैश मानचित्रों और पेड़ों पर ध्यान केंद्रित करें। FAANG-स्तर की कंपनियों में अधिकांश साक्षात्कार प्रश्नों के लिए ये तीनों जिम्मेदार हैं।</Callout>

## एरेज़ और स्ट्रिंग्स - आपकी नींव

सारणी लगभग हर साक्षात्कार समस्या का प्रारंभिक बिंदु है। मुख्य अंतर्दृष्टि यह है कि अधिकांश सरणी समस्याएं वास्तव में सरणी के बारे में नहीं हैं - वे दो पॉइंटर्स, स्लाइडिंग विंडो, या उपसर्ग योग जैसे पैटर्न को पहचानने के बारे में हैं।

```python
# Two Sum — the most classic interview problem
# "Given an array and target, find two numbers that add to target"
def two_sum(nums, target):
    seen = {}  # Hash map to store complement
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:
            return [seen[complement], i]
        seen[num] = i
    return []

# Time: O(n), Space: O(n) — trading space for time
```

ध्यान दें कि कैसे यह "सरणी" समस्या भी वास्तव में एक हैश मैप समस्या है। वह पैटर्न लगातार दोहराता है: ब्रूट फोर्स एक सरणी पर नेस्टेड लूप का उपयोग करता है, और इष्टतम समाधान एक हैश मैप पेश करता है।

## हैश मैप्स - साक्षात्कार स्विस आर्मी चाकू

यदि आप किसी समस्या में फंस गए हैं और क्रूर बल O(n²) है, तो अपने आप से पूछें: "क्या हैश मैप इसे O(n) तक कम कर सकता है?" उत्तर आश्चर्यजनक रूप से अक्सर हाँ होता है।

जब आपको आवश्यकता हो तो हैश मानचित्र चमकते हैं:
- **गणना आवृत्तियाँ** - वर्ण गणना, शब्द गणना, तत्व आवृत्तियाँ
- **देखे गए तत्वों को ट्रैक करें** - डुप्लिकेट डिटेक्शन, टू-सम स्टाइल समस्याएं
- **समूह आइटम** - अनाग्राम समूहीकरण, वर्गीकरण
- **कैश गणना** - गतिशील प्रोग्रामिंग में संस्मरण

```java
// Group Anagrams — a classic hash map problem
public List<List<String>> groupAnagrams(String[] strs) {
    Map<String, List<String>> map = new HashMap<>();
    for (String s : strs) {
        char[] chars = s.toCharArray();
        Arrays.sort(chars);
        String key = new String(chars);
        map.computeIfAbsent(key, k -> new ArrayList<>()).add(s);
    }
    return new ArrayList<>(map.values());
}
```

<ThinkAboutIt>जब आप कोई समस्या देखते हैं जो आपसे "ढूँढें", "गिनें", या "जांचें कि क्या मौजूद है" पूछती है, तो तुरंत कौन सी डेटा संरचना दिमाग में आनी चाहिए? आप हैश मैप के O(1) लुकअप और क्रमबद्ध सरणी के O(लॉग एन) बाइनरी खोज के बीच व्यापार-बंद को कैसे समझाएंगे?</ThinkAboutIt>

## लिंक्ड सूचियाँ - सूचक महारत

लिंक की गई सूची की समस्याएं नोड्स का ट्रैक खोए बिना पॉइंटर्स में हेरफेर करने की आपकी क्षमता का परीक्षण करती हैं। आपको जिन तीन तकनीकों की आवश्यकता है वे हैं:

1. **टू-पॉइंटर (तेज/धीमा)** - चक्र का पता लगाना, मध्य नोड का पता लगाना
2. **डमी हेड नोड** - जब सिर बदल सकता है तो किनारे के मामलों को सरल बनाता है
3. **रिवर्सल** - पुनरावृत्त रिवर्सल कई समस्याओं के लिए एक बिल्डिंग ब्लॉक है

```python
# Detect a cycle in a linked list (Floyd's Algorithm)
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow == fast:
            return True
    return False
```

<FunFact>फ्लोयड का चक्र पहचान एल्गोरिदम, जिसे "कछुआ और खरगोश" एल्गोरिदम के रूप में भी जाना जाता है, 1967 में प्रकाशित हुआ था। यह सबसे पुराने एल्गोरिदम में से एक है जो अभी भी आधुनिक कोडिंग साक्षात्कारों में आमतौर पर पूछा जाता है - 55 वर्षों से अधिक और गिनती।</FunFact>

## ढेर और कतारें - ऑर्डर मायने रखता है

स्टैक (LIFO) और क्यू (FIFO) सरल संरचनाएं हैं, लेकिन वे समस्याओं की संपूर्ण श्रेणियों को अनलॉक करते हैं:

- **स्टैक**: मान्य कोष्ठक, अभिव्यक्ति मूल्यांकन, मोनोटोनिक स्टैक समस्याएँ, पूर्ववत करें/फिर से करें
- **कतारें**: बीएफएस ट्रैवर्सल, स्लाइडिंग विंडो अधिकतम (डेक के साथ), कार्य शेड्यूलिंग

```python
# Valid Parentheses — classic stack problem
def is_valid(s: str) -> bool:
    stack = []
    matching = {')': '(', '}': '{', ']': '['}
    for char in s:
        if char in matching:
            if not stack or stack[-1] != matching[char]:
                return False
            stack.pop()
        else:
            stack.append(char)
    return len(stack) == 0
```

## पेड़ - श्रेणीबद्ध सोच

पेड़ की समस्याओं में आमतौर पर रिकर्सन और तीन ट्रैवर्सल ऑर्डर (इन-ऑर्डर, प्री-ऑर्डर, पोस्ट-ऑर्डर) में से एक शामिल होता है। विकसित करने का मानसिक मॉडल है: "मुझे बाएं उपवृक्ष, दाएं उपवृक्ष से क्या चाहिए, और मैं उन्हें वर्तमान नोड पर कैसे संयोजित करूं?"

```python
# Maximum depth of a binary tree — the template for tree recursion
def max_depth(root):
    if not root:
        return 0
    left_depth = max_depth(root.left)
    right_depth = max_depth(root.right)
    return 1 + max(left_depth, right_depth)
```

बीएसटी (बाइनरी सर्च ट्री) समस्याएं एक महत्वपूर्ण गुण जोड़ती हैं: इन-ऑर्डर ट्रैवर्सल से क्रमबद्ध तत्व प्राप्त होते हैं। यदि आप एक ही समस्या में "सॉर्टेड" और "ट्री" देखते हैं, तो तुरंत बीएसटी के बारे में सोचें।

## रेखांकन - रिश्तों की मॉडलिंग

ग्राफ़ की समस्याएँ डराने वाली लगती हैं, लेकिन एक बार जब आप आसन्नता सूची बना लेते हैं, तो अधिकतर समस्याएँ BFS या DFS तक सीमित हो जाती हैं। प्रमुख कौशल हैं:

- **एज सूचियों या मैट्Riseस से ग्राफ़ बनाना**
- **बीएफएस** बिना भारित ग्राफ़ में सबसे छोटे पथ के लिए
- **डीएफएस** कनेक्टिविटी, साइकिल डिटेक्शन, टोपोलॉजिकल सॉर्ट के लिए

```python
# BFS shortest path in an unweighted graph
from collections import deque

def shortest_path(graph, start, end):
    queue = deque([(start, 0)])
    visited = {start}
    while queue:
        node, distance = queue.popleft()
        if node == end:
            return distance
        for neighbour in graph[node]:
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append((neighbour, distance + 1))
    return -1  # Not reachable
```

## ढेर - "शीर्ष K" सिग्नल

जब भी कोई समस्या कहती है "K को सबसे बड़ा खोजें", "K निकटतम", या "K क्रमबद्ध सूचियों को मर्ज करें", तो एक ढेर (प्राथमिकता कतार) लगभग निश्चित रूप से उत्तर है। पायथन में, `heapq` एक न्यूनतम-ढेर प्रदान करता है; अधिकतम-ढेर के लिए, मानों को नकारें।

```python
import heapq

# Find the K largest elements in an array
def k_largest(nums, k):
    return heapq.nlargest(k, nums)  # Uses a min-heap of size k internally
```

## पैटर्न पहचान - सही संरचना का चयन

किसी समस्या को पढ़ते समय यह मानसिक जाँच सूची विकसित करें:

- **तेज़ लुकअप की आवश्यकता है?** → हैश मैप
- **क्रमबद्ध क्रम की आवश्यकता है?** → बीएसटी या क्रमबद्ध सरणी + बाइनरी खोज
- **फीफो प्रोसेसिंग की आवश्यकता है?** → कतार (बीएफएस)
- **LIFO / बैकट्रैकिंग की आवश्यकता है?** → स्टैक (DFS)
- **टॉप-के या प्राथमिकता चाहिए?** → ढेर
- **कनेक्शन मॉडल करने की आवश्यकता है?** → ग्राफ़
- **सूचकांक द्वारा O(1) पहुंच की आवश्यकता है?** → सारणी

<Callout>अपने साक्षात्कार में, स्पष्ट रूप से बताएं कि आप कौन सी डेटा संरचना चुन रहे हैं और क्यों। यह कहना कि "मैं यहां हैश मैप का उपयोग करूंगा क्योंकि नेस्टेड लूप से बचने के लिए हमें O(1) लुकअप की आवश्यकता है" बिल्कुल वही इंजीनियरिंग सोच प्रदर्शित करता है जो साक्षात्कारकर्ता देखना चाहते हैं।</Callout>

## चाबी छीनना

- **सात संरचनाएँ 90% साक्षात्कारों को कवर करती हैं**: सारणियाँ, हैश मानचित्र, लिंक्ड सूचियाँ, स्टैक/कतारें, पेड़, ग्राफ़ और ढेर।
- **हैश मैप आपके सबसे अच्छे दोस्त हैं**: जब संदेह हो, तो हैश मैप संभवतः मदद करता है।
- **अपनी जटिलताओं को जानें**: साक्षात्कारकर्ता पूछेंगे "समय की जटिलता क्या है?" हर समाधान के बाद.
- **पैटर्न पहचान याद रखने को मात देती है**: समस्या संकेतों ("शीर्ष K" → ढेर, "सबसे छोटा रास्ता" → BFS) को सही संरचना में मैप करना सीखें।
- **जानबूझकर अभ्यास करें**: गति के बजाय समझने पर ध्यान केंद्रित करते हुए, प्रति डेटा संरचना 3-5 समस्याओं को हल करें। गति समझ से आती है.

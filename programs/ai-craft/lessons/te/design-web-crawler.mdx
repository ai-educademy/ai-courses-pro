# వెబ్ క్రాలర్ డిజైన్ చేయండి - Google ఇంటర్నెట్‌ను ఎలా ఇండెక్స్ చేస్తుంది

వెబ్ క్రాలర్ క్రమబద్ధంగా ఇంటర్నెట్‌ను బ్రౌజ్ చేసి వెబ్ పేజీలను డౌన్‌లోడ్ చేసి సూచిక చేస్తుంది. ఇది ప్రతి శోధన యంత్రం కు పునాది. దీన్ని డిజైన్ చేయడం ద్వారా విస్తరిత వ్యవస్థలు, గ్రాఫ్ ప్రయాణం, నిజమైన వెబ్‌లోని క్లిష్టతలను ఎలా నిర్వహించాలో నేర్చుకుంటారు.

## దశ 1 - అవసరాలు సేకరణ

### కార్యాత్మక అవసరాలు
- ప్రారంభ URLలు సెట్ నుంచి వెబ్ పేజీలు క్రాల్ చేయడం
- హైపర్‌లింకులు తీసి కొత్త పేజీలు గుర్తించడం
- డౌన్‌లోడ్ చేసిన కంటెంట్ ను సూచీకరణ మరియు ప్రాసెసింగ్ కోసం నిల్వ చేయడం
- robots.txt మరియు క్రాల్ మర్యాద నియమాలు పాటించడం

### అకార్యాత్మక అవసరాలు
- **స్కేల్** - నెలకు 1 బిలియన్ పేజీలు క్రాల్ చేయడం
- **మర్యాద** - ఏ ఒక్క వెబ్ సర్వర్ ను అధిక భారం చేయకపోవడం
- **తాజాదనం** - ముఖ్యమైన పేజీలను క్రమం తప్పకుండా మళ్లీ క్రాల్ చేయడం
- **బలమైనతనం** - తప్పుగా ఉన్న HTML, అపరిమిత లూపులు, మరియు స్పైడర్ ఉచ్చులు ను నిర్వహించడం

## దశ 3 - క్రాల్ లూప్

### BFS వర్సెస్ DFS క్రాలింగ్
- **BFS (Breadth-First)** - వెబ్ క్రాలింగ్ కోసం ఇష్టపడతారు. త్వరగా అనేక డొమైన్‌లు గుర్తిస్తుంది మరియు ఒకే సైట్ లో లోతుగా చిక్కుకోకుండా నిరోధిస్తుంది
- **DFS (లోతు-First)** - ఇతర డొమైన్‌లు గుర్తించేలోపు చలనశీలంగా సృష్టించిన పేజీలు లో అపరిమితంగా లోతైన గా వెళ్ళే రిస్క్ ఉంది

### URL అగ్రశ్రేణి డిజైన్
అగ్రశ్రేణి ఒక సులభమైన క్యూ కాదు - ఇది రెండు ఉప-భాగాలు తో ఉన్న మెరుగైన ప్రాధాన్యం సిస్టమ్:

1. **ప్రాధాన్యం క్యూ (ముందువరుస)** - URLs ను ప్రాముఖ్యం ఆధారంగా ర్యాంక్ చేస్తుంది. PageRank, నవీకరణ తరచుదనం, మరియు డొమైన్ అధికారం వంటి కారకాలు ఉంటాయి
2. **మర్యాద క్యూ (వెనుక)** - ప్రతి డొమైన్ కు దాని స్వంత FIFO క్యూ ఉంటుంది. ఒక షెడ్యూలర్ వివిధ డొమైన్ క్యూలు నుండి ఎంచుకుంటుంది, తద్వారా ఏ ఒక్క సర్వర్ పై అధిక లోడ్ పడదు

```
Front (Priority):       Back (Politeness):
┌──────────────┐       ┌─── bbc.co.uk queue ───┐
│ High Priority │ ───→  │ url1 → url4 → url7    │
│ Med Priority  │ ───→  ├─── github.com queue ──┤
│ Low Priority  │ ───→  │ url2 → url5 → url8    │
└──────────────┘       ├─── wikipedia.org queue ┤
                        │ url3 → url6 → url9    │
                        └───────────────────────┘
```

## దశ 4 - మర్యాద మరియు robots.txt

### robots.txt పాటించడం
ఏదైనా డొమైన్ ను క్రాల్ చేయడానికి ముందు, దాని `robots.txt` ఫైల్ ను తెచ్చుకోండి మరియు క్యాష్ చేయండి:

```
# Example robots.txt
User-agent: *
Disallow: /admin/
Disallow: /private/
Crawl-delay: 2
```

ప్రతి డొమైన్ యొక్క robots.txt ను TTL (24 గంటలు) తో క్యాష్ చేయండి. `Disallow` నియమాలు మరియు `Crawl-delay` ఆదేశాలు ను ఎల్లప్పుడూ పాటించండి.

### క్రాల్ రేట్ పరిమితం చేసే
స్పష్టమైన `Crawl-delay` లేకపోయినా మర్యాద కొనసాగించండి:
- ప్రతి డొమైన్ కు సెకండ్ కు గరిష్ట 1 రిక్వెస్ట్ (మార్చుకోగల)
- ప్రతి డొమైన్ కు వేరు డౌన్‌లోడ్ క్యూలు ఉపయోగించండి
- రెస్పాన్స్ సార్లు ట్రాక్ చేయండి - సర్వర్ నెమ్మది అయితే, స్వయంచాలకంగా వెనక్కి తగ్గండి

<FunFact>Google యొక్క వెబ్ క్రాలర్ (Googlebot) వందల బిలియన్లు పేజీలు క్రాల్ చేస్తుంది. మర్యాదగా ఉండటానికి, ఇది సర్వర్ రెస్పాన్స్ సార్లు పర్యవేక్షిస్తుంది మరియు ఒక సైట్ నెమ్మది గా స్పందించడం మొదలుపెడితే క్రాల్ రేట్ తగ్గిస్తుంది - ఫలప్రదంగా వెబ్‌సైట్ ను క్రాలర్ కు వ్యతిరేకంగా "వెనక్కి నెట్టు" చేయనిస్తుంది.</FunFact>

## దశ 5 - డీడూప్లికేషన్

### URL డీడూప్లికేషన్ (బ్లూమ్ ఫిల్టర్)
బిలియన్ల URLలు తో, ఒక URL ను ఇంతకు ముందు చూశామా అని తనిఖీ చేయడానికి సమర్థమైన డేటా నిర్మాణం అవసరం. బ్లూమ్ ఫిల్టర్ O(1) లుక్‌అప్‌లు ను చిన్న మెమరీ చిహ్నం తో అందిస్తుంది:

- **స్థలం:** 1 బిలియన్ URLs కు ~1 GB, 1% తప్పుడు పాజిటివ్ రేట్ తో
- **రాజీ:** అప్పుడప్పుడు పేజీ మళ్లీ క్రాల్ అవ్వవచ్చు (తప్పుడు పాజిటివ్) కానీ కొత్త URL ఎప్పటికీ మిస్ అవడం కాదు (తప్పుడు ప్రతికూలాలు)

తనిఖీ చేయడానికి ముందు URLs సాధారణీకరించండి: ఫ్రాగ్మెంట్‌లు (#) తొలగించండి, క్వెరీ పరామీటర్లు క్రమబద్ధీకరించండి, హోస్ట్‌నేమ్ చిన్న అక్షరాలు చేయండి, మరియు సాపేక్ష మార్గాలను పరిష్కరించండి.

### కంటెంట్ డీడూప్లికేషన్ (SimHash)
వేర్వేరు URLs ఒకేలా ఉన్న కంటెంట్ అందించవచ్చు (ప్రతిబింబాలు, నకలు చేసిన వ్యాసాలు). SimHash పేజీ కంటెంట్ యొక్క వేలిముద్ర సృష్టిస్తుంది - సారూప్య వేలిముద్రలు (చిన్న హామింగ్ దూరం) ఉన్న పేజీలు సంభావ్య నకిలీలు:

```
Page A content → SimHash → 10110010...
Page B content → SimHash → 10110011...
Hamming distance = 1 → likely duplicate, skip storing
```

## దశ 6 - విస్తరిత క్రాలింగ్

### అడ్డంగా స్కేల్ చేయడం
ఒక్క యంత్రం నెలకు బిలియన్ పేజీలు క్రాల్ చేయలేదు. పనిని విస్తరించండి:

- డొమైన్ పేర్లు పై **స్థిరమైన హ్యాషింగ్** ప్రతి డొమైన్ ను స్పష్టంగా క్రాలర్ నోడ్ కు కేటాయిస్తుంది. ఇది మర్యాద నిర్ధారిస్తుంది: ఒక ఇచ్చిన డొమైన్ ను ఒకే నోడ్ క్రాల్ చేస్తుంది
- **URL అగ్రశ్రేణి** హ్యాష్ వలయం ఆధారంగా నోడ్‌లు మధ్య పార్టిషన్ అవుతుంది
- నోడ్ కేటాయింపులు నిర్వహించండి చేసి, నోడ్‌లు చేరినప్పుడు లేదా వెళ్లినప్పుడు అయినప్పుడు మళ్లీ సమతుల్యం చేయండి చేసే తేలికపాటి సేవ ద్వారా **సమన్వయం**

### DNS పరిష్కారం క్యాషింగ్
DNS లుక్‌అప్‌లు ప్రతి రిక్వెస్ట్ కు 10-100ms జోడిస్తాయి. స్కేల్ వద్ద ఇది ప్రధాన అడ్డంకి:
- ప్రతి క్రాలర్ నోడ్ కు స్థానిక DNS క్యాష్ ఉంచండి
- క్యూ లో ఉన్న URLs కోసం బ్యాచ్ DNS ముందస్తు-పరిష్కారం చేయండి
- పబ్లిక్ DNS సర్వర్‌లు అధిక భారం కాకుండా ప్రత్యేక DNS రిజాల్వర్ ఉపయోగించండి

### స్పైడర్ ఉచ్చు గుర్తింపు
హానికరమైన లేదా సరిగా నిర్మించని సైట్లు అపరిమిత URL స్థలాలు సృష్టించవచ్చు:
- `/page/1/page/1/page/1/...` - పునరావృత మార్గం నమూనాలు
- ప్రతి భవిష్యత్ తేదీ కు URLs సృష్టించు చేసే క్యాలెండర్ పేజీలు
- ఒకేలా ఉన్న కంటెంట్ కు ప్రత్యేక URLs సెషన్ IDల వల్ల ఒకే కంటెంట్‌కు ప్రత్యేక URLs సృష్టించడం

**రక్షణలు:** గరిష్ట URL పొడవు, ప్రతి డొమైన్ కు గరిష్ట క్రాల్ లోతు, పునరావృత URL నిర్మాణాలు కోసం నమూనా గుర్తింపు, మరియు డొమైన్-స్థాయి పేజీ లెక్క పరిమితులు.

<ThinkAboutIt>సెర్చ్ ఇండెక్స్ ను తాజా గా ఉంచాలంటే, ఏ పేజీలను ముందుగా మళ్లీ క్రాల్ చేయాలో ఎలా నిర్ణయిస్తారు? ప్రతి గంటకు నవీకరించే వార్తా సైట్ వర్సెస్ నెలకోసారి మారే Wikipedia వ్యాసం గురించి ఆలోచించండి. మళ్లీ క్రాల్ షెడ్యూలింగ్ ప్రాధాన్యం ఇవ్వడానికి ఏ సంకేతాలు ఉపయోగిస్తారు?</ThinkAboutIt>

## దశ 7 - అడ్డంకులు మరియు మెరుగుదలలు

| అడ్డంకి | పరిష్కారం |
|-----------|----------|
| DNS పరిష్కారం లేటెన్సీ | స్థానిక DNS క్యాష్, బ్యాచ్ ముందస్తు-పరిష్కారం |
| నెమ్మది/స్పందించని సర్వర్‌లు | సమయ పరిమితులు (30s), అసమకాలిక I/O, మళ్లీ ప్రయత్నాలు తర్వాత దాటేయండి |
| క్రాల్ చేసిన కంటెంట్ నిల్వ | పేజీలు కుదించండి చేయడం, మారిన కంటెంట్ మాత్రమే నిల్వ చేయడం |
| URL అగ్రశ్రేణి మెమరీ | డిస్క్ ఆధారిత ప్రాధాన్యం క్యూ (RocksDB) |
| నకిలీ కంటెంట్ | SimHash వేలిముద్రణ, ప్రమాణ URL గుర్తింపు |

<ThinkAboutIt>సెర్చ్ ఇంజిన్‌లు క్రాల్ తాజాదనం (పేజీలను తరచుగా మళ్లీ క్రాల్ చేయడం) మరియు ఆవిష్కరణ (కొత్త పేజీలు కనుగొనడం) మధ్య బ్యాలెన్స్ చేయాలి. మీ క్రాలర్ కు రోజుకు 1 మిలియన్ పేజీలు అనే స్థిర బడ్జెట్ ఉంటే, ఆ బడ్జెట్ ను ఉన్న పేజీలు మళ్లీ క్రాల్ చేయడం మరియు కొత్త పేజీలు గుర్తించడం మధ్య ఎలా విభజిస్తారు?</ThinkAboutIt>

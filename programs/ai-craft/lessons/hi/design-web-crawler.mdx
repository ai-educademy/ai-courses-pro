# वेब क्रॉलेर डिज़ाइन करें - Google इंटरनेट को कैसे इनदेक्स करता है

एक वेब क्रॉलर व्यवस्थित तरीके से इंटरनेट ब्राउज़ करता है ताकि वेब पेज को डाउनलोड और इंडेक्स किया जा सके। यह हर सर्च एङिने key नींव है, और इसे डिज़ाइन करने से आप वितरित सिस्टम, ग्राफ़ ट्रैवर्सल, और वास्तविक वेब key जटिलिटिएस को संभाल करना सीखते हैं।

## चरण 1 - ज़रूरतें इकट्ठा करना

### कार्यात्मक ज़रूरतें
- सीद उरलस के एक सेट से शुरू करके वेब पेज क्रॉल करना
- हयपेरलिनकस निकाल करके नए पेज खोजना करना
- डाउनलोड कंटेंट को इंडेक्सिंग और प्रोसेसिंग के लिए स्टोर करना
- रोबॉट्स.txt और क्रॉल पोलिटेनेस नियम का पालन करना

### गैर-कार्यात्मक ज़रूरतें
- **स्केल** - हर महीने 1 बिलियन पेज क्रॉल करना
- **पोलिटेनेस** - किसी भी एकल वेब सर्वर पर ओवेरलोड नहीं डालना
- **ताज़गी** - महत्वपूर्ण पेज को नियमित रूप से रे-क्रॉल करना
- **रोबुसटनेस** - मलफ़ोरमेद HTML, इनफ़िनिटे लूपस, और सपिदेर ट्रैप को संभाल करना

## चरण 2 - उच्च-level आर्किटेक्चर

```
Seed URLs → URL Frontier (priority queue)
                  ↓
            URL Scheduler (politeness + priority)
                  ↓
         Fetcher (HTTP client pool)
                  ↓
         HTML Parser → Extract URLs → URL Filter
              ↓                           ↓
       Content Store              URL Dedup (Bloom Filter)
       (S3 / HDFS)                      ↓
                                 URL Frontier (loop)
```

## चरण 3 - क्रॉल लूप

### BFS vs DFS क्रॉलिङ
- **BFS (बरीडथ-first)** - वेब क्रॉलिङ के लिए परेफ़ेररेद। जल्दी से कई दोमैनस खोजना करता है और किसी एकल सिटे में गहरी फँसने से बचाता है
- **DFS (गहराई-first)** - डायनेमिक रूप से गेनेरेटद पेज में इनफ़िनिटेलय गहरी जाने का जोखिम है, बिना दूसरे दोमैनस खोजना किए

### URL फ़्रंटियर डिज़ाइन
फ़्रंटियर एक सरल क्यू नहीं है - यह दो अप-घटक वाला एक उन्नत प्राथमिकता सिस्टम है:

1. **प्राथमिकता क्यू (फ़्रंटियर)** - URLs को महत्व के आधार पर रैंक करता है। इसमें PageRank, अपडेट आवृत्ति, और डोमेन अधिकारिता जैसे कारक शामिल हैं
2. **पोलिटेनेस क्यू (बक)** - हर डोमेन key अपनी FIFO क्यू होती है। एक सचेदुलेर अलग-अलग डोमेन क्यू से चुनता करता है ताकि किसी एकल सर्वर पर ज़्यादा लोड न पड़े

```
Front (Priority):       Back (Politeness):
┌──────────────┐       ┌─── bbc.co.uk queue ───┐
│ High Priority │ ───→  │ url1 → url4 → url7    │
│ Med Priority  │ ───→  ├─── github.com queue ──┤
│ Low Priority  │ ───→  │ url2 → url5 → url8    │
└──────────────┘       ├─── wikipedia.org queue ┤
                        │ url3 → url6 → url9    │
                        └───────────────────────┘
```

## चरण 4 - पोलिटेनेस और रोबॉट्स.txt

### रोबॉट्स.txt का पालन करना
किसी भी डोमेन को क्रॉल करने से पहले, उसkey `robots.txt` फ़ाइल फ़ेटच और कैश करें:

```
# Example robots.txt
User-agent: *
Disallow: /admin/
Disallow: /private/
Crawl-delay: 2
```

हर डोमेन key रोबॉट्स.txt को TTL (24 घंटे) के साथ कैश करें। `Disallow` नियम और `Crawl-delay` निर्देश का हमेशा पालन करें।

### क्रॉल दर लिमिटिंग
एक्सपलिकिट `Crawl-delay` न होने पर भी पोलिटेनेस बनाए रखें:
- हर डोमेन पर मक्सिमुम 1 रिक्वेस्ट प्रति सेकंड (कोनफ़िगुरबले)
- हर डोमेन के लिए सेपरेट डाउनलोड क्यू इस्तेमाल करें
- रिस्पॉन्स समय रिकॉर्ड करें - अगर सर्वर धीमा हो जाए तो अपने आप धीमा करें करें

<FunFact>Google का वेब क्रॉलर (गूगलेबोट) सैकड़ों बिलियनस पेज क्रॉल करता है। पोलिटे रहने के लिए, यह सर्वर प्रतिक्रिया टिमेस मॉनिटर करता है और अगर कोई सिटे धीमे प्रतिक्रिया करने लगे तो क्रॉल दर कम कर देता है - एफ़फ़ेकटिवेलय वेबसिटे को क्रॉलेर के खिलाफ "आपत्ति" करने देता है।</FunFact>

## चरण 5 - डीडुप्लिकेशन

### URL डीडुप्लिकेशन (बलूम फ़िल्टर)
बिलियनस उरलस के साथ, किसी URL को पहले देखा गया है या नहीं - यह जाँच करने के लिए एक कुशल डेटा संरचना चाहिए। बलूम फ़िल्टर O(1) लूकुपस देता है कम मेमोरी फ़ूटपरिनट के साथ:

- **सपके:** 1 बिलियन उरलस के लिए ~1 GB, 1% फ़ॉल्स पॉज़िटिव दर पर
- **टरदे-ओफ़फ़:** कभी-कभी पेज रे-क्रॉल हो सकता है (फ़ॉल्स पॉज़िटिव) लेकिन कोई नया URL कभी मिस नहीं होगा (no फ़ॉल्स नेगेटिव)

जाँच करने से पहले उरलस नॉर्मलाइज़ करें: फ़्रैगमेंट (#) हटाएँ, क्वेरी पैरामीटर सॉर्ट करें, होस्टname कमेरकसे करें, और रेलटिवे रास्ते रेसोलवे करें।

### कंटेंट डीडुप्लिकेशन (सिमहश)
अलग-अलग उरलस इदेनटिकल कंटेंट सर्व कर सकते हैं (मिररोरस, कोपिएद अरटिकलेस)। सिमहश पेज कंटेंट का फ़िङेरपरिनट जनरेट करता है - मिलते-जुलते फ़िङेरपरिनटस (छोटी हममिङ दूरी) वाले पेज सम्भावित डुप्लिकेटस हैं:

```
Page A content → SimHash → 10110010...
Page B content → SimHash → 10110011...
Hamming distance = 1 → likely duplicate, skip storing
```

## चरण 6 - वितरितद क्रॉलिङ

### क्षैतिज रूप से स्केल करना
एक एकल मचिने मासिक रूप से बिलियन पेज क्रॉल नहीं कर सकती। काम वितरित करें:

- **कंसिस्टेंट हैशिंग** डोमेन nameस पर - हर डोमेन को एक विशिष्ट क्रॉलेर नोड असाइन करता है। इससे पोलिटेनेस सुनिश्चित होती है - एक गिवेन डोमेन को सिर्फ़ एक नोड क्रॉल करता है
- **URL फ़्रंटियर** हैश रिङ के आधार पर नोड में पार्टिशन होता है
- **समन्वय** एक हल्के सर्विस से जो नोड असिगnameनटस मनगे करती है और नोड जोइन/लेअवे होने पर रेबलनके करती है

### DNS समाधान कैशिंग
DNS लूकुपस हर रिक्वेस्ट में 10-100ms जोड़ें करते हैं। बड़े पैमाने पर यह एक मुख्य बोTTLेनेक है:
- हर क्रॉलेर नोड पर स्थानीय DNS कैश रखें
- क्यूद उरलस के लिए बैच DNS परे-समाधान करें
- पुबलिक DNS सर्वर पर ओवेरलोड से बचने के लिए समर्पित DNS रेसोलवेर इस्तेमाल करें

### सपिदेर टरप देटेकशन
मलिकिओउस या पूरलय बुइलट सिटेस इनफ़िनिटे URL स्पेस करेअटे कर सकती हैं:
- `/page/1/page/1/page/1/...` - रेपेअटिङ रास्ता पैटर्न
- कलेनदर पेज जो हर फ़ुटुरे दटे के लिए उरलस जनरेट करते हैं
- उरलस में सेशन इदस जो इदेनटिकल कंटेंट के लिए उनिक्वे उरलस करेअटे करते हैं

**बचाव:** मक्सिमुम URL लेङथ, हर डोमेन के लिए मक्सिमुम क्रॉल गहराई, दोहराए जाने वाले URL संरचनाएँ के लिए पैटर्न पहचान, और दोमैन-level पेज गणना सीमाएँ।

<ThinkAboutIt>अगर आपको सर्च इंडेक्स फ़रेश रखना है, तो कौन से पेज पहले रे-क्रॉल करेंगे? एक समाचार साइट जो हर घंटे अपडेट होती है vs एक Wikipedia लेख जो मासिक रूप से बदलता है - इसके बारे में सोचें। रे-क्रॉल शेड्यूलिंग प्राथमिकता करने के लिए आप कौन से सिग्नल इस्तेमाल करेंगे?</ThinkAboutIt>

## चरण 7 - बॉटलनेक और ऑप्टिमाइज़ेशन

| बोTTLेनेक | सोलुशन |
|-----------|----------|
| DNS समाधान लेटेंसी | स्थानीय DNS कैश, बैच परे-समाधान |
| सकम/उनरेसपोनसिवे सर्वर | समयouts (30s), असिंक I/O, रेटरिएस के बाद सकिप करें |
| क्रॉलेद कंटेंट का स्टोरेज | पेजस कोमपरेस करें, सिर्फ़ चङेद कंटेंट स्टोर करें |
| URL फ़्रंटियर मेमोरी | डिस्क-धीमाed प्राथमिकता क्यू (RocksDB) |
| डुप्लिकेट कंटेंट | सिमहश फ़िङेरपरिनटिङ, कनोनिकल URL पहचान |

<ThinkAboutIt>सर्च इंजन को क्रॉल ताज़गी (पेज बार-बार रे-क्रॉल करना) और खोजनाy (नए पेज ढूँढना) के बीच संतुलन बनाना होता है। अगर आपके क्रॉलेर का फ़िक्स्ड बजट प्रति दय 1 मिलियन पेज है, तो आप उसे मौजूदा पेज रे-क्रॉल करने और नए पेज खोजना करने में कैसे बाँटेंगे?</ThinkAboutIt>

# वेब करवलेर डिज़ाइन करें - Google इंटरनेट को कैसे इनदेक्स करता है

एक वेब क्रॉलर व्यवस्थित तरीके से इंटरनेट ब्राउज़ करता है ताकि वेब पेज को दोवनलोअद और इंडेक्स किया जा सके। यह हर सर्च एङिने की नींव है, और इसे डिज़ाइन करने से आप वितरित सिस्टम, ग्राफ़ ट्रैवर्सल, और वास्तविक वेब की जटिलिटिएस को संभाल करना सीखते हैं।

## चरण 1 - ज़रूरतें इकट्ठा करना

### फ़ुनकशनल ज़रूरतें
- सीद उरलस के एक सेट से शुरू करके वेब पेज करवल करना
- हयपेरलिनकस एक्सटरकट करके नए पेज खोजना करना
- दोवनलोअदेद कंटेंट को इनदेक्सिङ और प्रोसेसिंग के लिए स्टोर करना
- रोबोटस.टक्सट और करवल पोलिटेनेस रुलेस का पालन करना

### नोन-फ़ुनकशनल ज़रूरतें
- **सकले** - हर महीने 1 बिललिओन पेज करवल करना
- **पोलिटेनेस** - किसी भी एकल वेब सर्वर पर ओवेरलोअद नहीं डालना
- **ताज़गी** - महत्वपूर्ण पेज को नियमित रूप से रे-करवल करना
- **रोबुसटनेस** - मलफ़ोरमेद HTML, इनफ़िनिटे लूपस, और सपिदेर टरपस को संभाल करना

## चरण 2 - उच्च-लेवेल आर्किटेक्चर

```
Seed URLs → URL Frontier (priority queue)
                  ↓
            URL Scheduler (politeness + priority)
                  ↓
         Fetcher (HTTP client pool)
                  ↓
         HTML Parser → Extract URLs → URL Filter
              ↓                           ↓
       Content Store              URL Dedup (Bloom Filter)
       (S3 / HDFS)                      ↓
                                 URL Frontier (loop)
```

## चरण 3 - करवल लूप

### BFS vs DFS करवलिङ
- **BFS (बरेअदथ-फ़िरसट)** - वेब करवलिङ के लिए परेफ़ेररेद। जल्दी से कई दोमैनस खोजना करता है और किसी एकल सिटे में गहरी फँसने से बचाता है
- **DFS (देपथ-फ़िरसट)** - दयनमिकललय गेनेरटेद पेज में इनफ़िनिटेलय गहरी जाने का जोखिम है, बिना दूसरे दोमैनस खोजना किए

### URL फ़रोनटिएर डिज़ाइन
फ़रोनटिएर एक सरल क्यू नहीं है - यह दो सुब-कोमपोनेनटस वाला एक सोफिसटिकटेद प्राथमिकता सिस्टम है:

1. **परिओरिटय क्यू (फ़रोनट)** - उरलस को इमपोरटनके के आधार पर रनक करता है। इसमें पगेरनक, अपडेट फ़रेक्वेनकय, और डोमेन औथोरिटय जैसे फ़कटोरस शामिल हैं
2. **पोलिटेनेस क्यू (बक)** - हर डोमेन की अपनी FIFO क्यू होती है। एक सचेदुलेर अलग-अलग डोमेन क्यू से चुनता करता है ताकि किसी एकल सर्वर पर ज़्यादा लोड न पड़े

```
Front (Priority):       Back (Politeness):
┌──────────────┐       ┌─── bbc.co.uk queue ───┐
│ High Priority │ ───→  │ url1 → url4 → url7    │
│ Med Priority  │ ───→  ├─── github.com queue ──┤
│ Low Priority  │ ───→  │ url2 → url5 → url8    │
└──────────────┘       ├─── wikipedia.org queue ┤
                        │ url3 → url6 → url9    │
                        └───────────────────────┘
```

## चरण 4 - पोलिटेनेस और रोबोटस.टक्सट

### रोबोटस.टक्सट का पालन करना
किसी भी डोमेन को करवल करने से पहले, उसकी `robots.txt` फ़ाइल फ़ेटच और कैश करें:

```
# Example robots.txt
User-agent: *
Disallow: /admin/
Disallow: /private/
Crawl-delay: 2
```

हर डोमेन की रोबोटस.टक्सट को TTL (24 घंटे) के साथ कैश करें। `Disallow` रुलेस और `Crawl-delay` दिरेकटिवेस का हमेशा पालन करें।

### करवल दर लिमिटिङ
एक्सपलिकिट `Crawl-delay` न होने पर भी पोलिटेनेस बनाए रखें:
- हर डोमेन पर मक्सिमुम 1 रिक्वेस्ट प्रति सेकंड (कोनफ़िगुरबले)
- हर डोमेन के लिए सेपरटे दोवनलोअद क्यू इस्तेमाल करें
- रेसपोनसे टिमेस रिकॉर्ड करें - अगर सर्वर धीमे हो जाए तो औटोमटिकललय बक ओफ़फ़ करें

<FunFact>Google का वेब क्रॉलर (गूगलेबोट) सैकड़ों बिललिओनस पेज करवल करता है। पोलिटे रहने के लिए, यह सर्वर प्रतिक्रिया टिमेस मोनिटोर करता है और अगर कोई सिटे धीमे प्रतिक्रिया करने लगे तो करवल दर कम कर देता है - एफ़फ़ेकटिवेलय वेबसिटे को करवलेर के खिलाफ "आपत्ति" करने देता है।</FunFact>

## चरण 5 - देदुपलिकशन

### URL देदुपलिकशन (बलूम फ़िल्टर)
बिललिओनस उरलस के साथ, किसी URL को पहले देखा गया है या नहीं - यह जाँच करने के लिए एक कुशल डेटा संरचना चाहिए। बलूम फ़िल्टर O(1) लूकुपस देता है कम मेमोरी फ़ूटपरिनट के साथ:

- **सपके:** 1 बिललिओन उरलस के लिए ~1 GB, 1% false पोसिटिवे दर पर
- **टरदे-ओफ़फ़:** कभी-कभी पगे रे-करवल हो सकता है (false पोसिटिवे) लेकिन कोई नया URL कभी मिस नहीं होगा (no false नेगटिवेस)

जाँच करने से पहले उरलस नॉर्मलाइज़ करें: फ़्रैगमेंट (#) हटाएँ, क्वेरी पैरामीटर सॉर्ट करें, होसटname लोवेरकसे करें, और रेलटिवे रास्ते रेसोलवे करें।

### कंटेंट देदुपलिकशन (सिमहश)
अलग-अलग उरलस इदेनटिकल कंटेंट सर्व कर सकते हैं (मिररोरस, कोपिएद अरटिकलेस)। सिमहश पगे कंटेंट का फ़िङेरपरिनट जनरेट करता है - मिलते-जुलते फ़िङेरपरिनटस (छोटी हममिङ दूरी) वाले पेज लिकेलय दुपलिकटेस हैं:

```
Page A content → SimHash → 10110010...
Page B content → SimHash → 10110011...
Hamming distance = 1 → likely duplicate, skip storing
```

## चरण 6 - वितरितद करवलिङ

### होरिज़ोनटललय सकले करना
एक एकल मचिने मोनथलय बिललिओन पेज करवल नहीं कर सकती। काम वितरित करें:

- **कोनसिसटेनट हशिङ** डोमेन nameस पर - हर डोमेन को एक विशिष्ट करवलेर नोड असाइन करता है। इससे पोलिटेनेस सुनिश्चित होती है - एक गिवेन डोमेन को सिर्फ़ एक नोड करवल करता है
- **URL फ़रोनटिएर** हैश रिङ के आधार पर नोड में पार्टिशन होता है
- **कूरदिनशन** एक हल्के सर्विस से जो नोड असिगnameनटस मनगे करती है और नोड जोइन/लेअवे होने पर रेबलनके करती है

### DNS रेसोलुशन कैशिंग
DNS लूकुपस हर रिक्वेस्ट में 10-100ms जोड़ें करते हैं। बड़े पैमाने पर यह एक मुख्य बोटटलेनेक है:
- हर करवलेर नोड पर स्थानीय DNS कैश रखें
- क्यूद उरलस के लिए बैच DNS परे-रेसोलुशन करें
- पुबलिक DNS सर्वर पर ओवेरलोअद से बचने के लिए समर्पित DNS रेसोलवेर इस्तेमाल करें

### सपिदेर टरप देटेकशन
मलिकिओउस या पूरलय बुइलट सिटेस इनफ़िनिटे URL स्पेस करेअटे कर सकती हैं:
- `/page/1/page/1/page/1/...` - रेपेअटिङ रास्ता पैटर्न
- कलेनदर पेज जो हर फ़ुटुरे दटे के लिए उरलस जनरेट करते हैं
- उरलस में सेशन इदस जो इदेनटिकल कंटेंट के लिए उनिक्वे उरलस करेअटे करते हैं

**बचाव:** मक्सिमुम URL लेङथ, हर डोमेन के लिए मक्सिमुम करवल गहराई, रेपेटिटिवे URL सटरुकटुरेस के लिए पैटर्न पहचान, और दोमैन-लेवेल पगे गणना सीमाएँ।

<ThinkAboutIt>अगर आपको सर्च इंडेक्स फ़रेश रखना है, तो कौन से पेज पहले रे-करवल करेंगे? एक नेवस सिटे जो होउरलय अपडेट होती है vs एक विकिपेदिअ अरटिकले जो मोनथलय बदलता है - इसके बारे में सोचें। रे-करवल सचेदुलिङ परिओरिटिसे करने के लिए आप कौन से सिग्नल इस्तेमाल करेंगे?</ThinkAboutIt>

## चरण 7 - बोटटलेनेकस और ओपटिमिसशनस

| बोटटलेनेक | सोलुशन |
|-----------|----------|
| DNS रेसोलुशन लेटेंसी | स्थानीय DNS कैश, बैच परे-रेसोलुशन |
| सलोव/उनरेसपोनसिवे सर्वर | टिमेओउटस (30s), असयनक I/O, रेटरिएस के बाद सकिप करें |
| करवलेद कंटेंट का स्टोरेज | पगेस कोमपरेस करें, सिर्फ़ चङेद कंटेंट स्टोर करें |
| URL फ़रोनटिएर मेमोरी | दिसक-बकेद प्राथमिकता क्यू (रोकसदब) |
| दुपलिकटे कंटेंट | सिमहश फ़िङेरपरिनटिङ, कनोनिकल URL पहचान |

<ThinkAboutIt>सर्च इंजन को करवल ताज़गी (पेज बार-बार रे-करवल करना) और दिसकोवेरय (नए पेज ढूँढना) के बीच संतुलन बनाना होता है। अगर आपके करवलेर का फ़िक्सेद बजट प्रति दय 1 मिलियन पेज है, तो आप उसे मौजूदा पेज रे-करवल करने और नए पेज खोजना करने में कैसे बाँटेंगे?</ThinkAboutIt>

# 快速工程：与 AI 对话的艺术 🎯

平庸的人工智能反应和出色的反应之间的区别通常与人工智能本身无关 - 它与你提出问题的方式有关。

即时工程是为人工智能语言模型制作输入的实践，这些模型可以可靠地产生高质量、有用的输出。部分是沟通技巧，部分是系统思考，部分是结构化实验。

好消息：您不需要成为一名工程师才能擅长这一点。

---

## 🧠 为什么提示比你想象的更重要

法学硕士的能力非常强，但也非常注重文字。他们不知道你“想”问什么 - 他们只知道你“实际上”问了什么。

提示本质上是一种上下文设置练习。你不只是在问问题；你在问问题。你正在塑造：
- 模型应该扮演什么角色
- 您期望什么输出格式
- 有多详细和技术性
- 需要遵守哪些限制
- 响应的目标是什么

掌握了这一点，同样的底层模型就会感觉强大了好几代。

## 🎯 零射击提示：只需询问

最简单的提示形式是零样本：您描述您的任务并要求模型执行它，而不需要任何示例。

**之前：**
```
Summarise this article.

[article text]
```

**之后：**
```
Summarise the following article in 3 bullet points. Each bullet should be 
one sentence. Focus on the main argument, the key evidence, and the 
conclusion. Avoid jargon.

[article text]
```

“之后”版本指定格式（3 个项目符号）、长度（每个句子）、优先级（论证、证据、结论）和风格（无行话）。该模型有一个更清晰的目标。

**常见的零样本错误：**
- 问一个模糊的问题并期待一个具体的答案
- 忘记指定输出格式
- 没有说明你的受众（技术与一般）
- 省略长度限制

<FunFact>OpenAI 和其他公司的研究表明，只需在推理提示中添加“让我们一步一步思考”即可将数学和逻辑问题的准确性提高 40-50%。这是最简单的思想链提示 - 它之所以有效，是因为它鼓励模型展示其工作而不是跳到答案。
</FunFact>

## 📚 少量提示：通过示例学习

有时告诉模型并不像展示模型那么有效。 **少量提示**在呈现实际任务之前提供 2-5 个您想要的输入输出模式示例。

**示例 - 情感分类：**
```
Classify the sentiment of each customer review as Positive, Negative, or Neutral.

Review: "The delivery was fast but the product was broken."
Sentiment: Negative

Review: "Absolutely love this! Will buy again."
Sentiment: Positive

Review: "It arrived on time."
Sentiment: Neutral

Review: "The quality exceeded my expectations but the packaging was wasteful."
Sentiment: [complete this]
```

该模型现在已经了解了您想要的格式、如何处理混合信号以及预期的分析粒度。如果没有这些示例，您可能会得到一个段落而不是一个单词。

**何时使用少发：**
- 模型可能不会自然产生的不寻常的输出格式
- 特定领域的分类任务
- 风格匹配（以特定作者的声音写作）
- 复杂的结构化输出（JSON 模式、表格）

## 🔗 思维链：让模型大声思考

**思想链 (CoT) 提示**要求模型在给出最终答案之前逐步推理问题。这极大地提高了推理、数学和多步骤任务的表现。

**没有 COT：**
```
A shop sells apples for £0.50 each. If I buy 7 apples and pay with a £5 note, 
how much change do I get?

Answer: £1.50
```
（有时正确，有时不正确 - 而且你看不到工作原理）

**含 COT：**
```
A shop sells apples for £0.50 each. If I buy 7 apples and pay with a £5 note, 
how much change do I get? Work through this step by step.

Step 1: Cost of 7 apples = 7 × £0.50 = £3.50
Step 2: Change = £5.00 - £3.50 = £1.50
Answer: £1.50
```

可见的推理可以让您发现错误，而编写步骤的行为实际上可以降低模型犯错误的可能性。

对于**非常复杂的问题**，您可以使用“零样本 CoT”进一步推动这一点 - 只需添加：*“一步一步思考，在给出最终答案之前清楚地展示您的推理。”*

## 🎭 角色提示：角色和专业知识

最强大的技术之一是赋予模型特定的角色或角色。这会激活相关知识，设定适当的基调，并且通常会提高专业领域的准确性。

**没有角色：**
```
Explain photosynthesis.
```

**角色：**
```
You are a science teacher explaining photosynthesis to a 12-year-old who 
loves video games. Use gaming analogies where helpful. Be enthusiastic 
and encouraging.
```

第二个提示将产生一个根本不同的并且（对于该观众）更有用的解释。

**角色提示特别适用于：**
- 适当级别的技术解释
- 法律、医疗或财务问题（始终添加适当的免责声明）
- 特定风格的创意写作
- 代码审查（“作为高级 Python 开发人员审查此代码”）
- 面试练习（“你是 FAANG 公司的一位强硬的面试官”）

**完整的系统提示模式：**
```
You are [role] with expertise in [domain].
Your audience is [description of user].
Your goal is to [specific objective].
Always [constraint 1].
Never [constraint 2].
Format your response as [format specification].
```

## ⛓️ 提示链接：分解复杂的任务

对于复杂的多阶段任务，单个提示通常是不够的。 **提示链接**将任务分解为多个步骤，使用一个提示的输出作为下一个提示的输入。

**示例 - 撰写博客文章：**

不是一个怪物提示，而是连锁：
1. **提示 1**：“为一篇关于 [主题] 的博客文章生成 5 个可能的角度。对于每个角度，给出一行描述。”
2. **提示 2**：“使用上面的角度#3，写出包含 5 个部分和要点的详细大纲。”
3. **提示3**：“将大纲的第2部分扩展为完整的300字草稿，以对话式但权威的语气写作。”
4. **提示 4**：“审查草案以确保清晰，删除任何多余的句子，并确保以明确的行动号召结尾。”

这比要求一次性完成一篇博客文章产生的结果要好得多 - 每一步都能让模型充分关注一项重点任务。

<ThinkAboutIt>提示链接反映了人类专家的工作方式。一个好的作者不只是开始写作 - 他们会集思广益、提纲、起草和修改。优秀的工程师不会从头开始编码 - 他们会设计、原型、测试、重构。为什么我们会期望人工智能跳过这些步骤并在第一次尝试时创造出杰作？
</ThinkAboutIt>

## 🚫 常见错误以及如何修复它们

### 错误 1：一次性要求所有内容
❌ *“撰写机器学习的综合指南，包括历史、技术、应用、工具、职业道路和未来趋势。”*

✅ 将其分成有重点的提示，一次一个主题。

### 错误 2：仅使用否定指令
❌ *“不要太专业。不要写太多。不要包含行话。”*

✅ *“使用日常语言，以 9 年级水平写作 200 字。”* - 告诉它要做什么。

### 错误3：未指定输出格式
❌ *“列出电动汽车的优点和缺点。”*

✅ *“创建一个比较电动车与汽油车的表格。使用列：因素、电动、汽油。包括 6 行，涵盖成本、环境、里程、充电、维护和转售价值。”*

### 错误 4：忘记上下文
❌ *“重写此内容以使其更好。”*

✅ *“本段摘自一份针对非技术高管的技术报告。重写以删除行话，减少 30% 的长度，并在开头添加一句话摘要。”*

### 错误 5：接受第一个响应
最好提示工程师迭代。如果第一个响应不太正确，请准确告诉模型要更改的内容：*“语气太正式 - 使其更具对话性。并将统计数据移至侧边栏而不是正文。”*

## 🔬 高级技术：结构化输出

对于编程使用（API、工作流程、管道），您通常需要结构化输出。只需明确要求即可：

```
Analyse the following job description and return a JSON object with this 
exact structure:
{
  "required_skills": ["skill1", "skill2"],
  "nice_to_have_skills": ["skill3"],
  "seniority_level": "junior|mid|senior",
  "remote_friendly": true|false,
  "key_responsibilities": ["resp1", "resp2", "resp3"]
}

Job description:
[text here]
```

现代法学硕士在这方面非常擅长。许多 API 现在提供“JSON 模式”，强制执行有效的 JSON 输出，使其更加可靠。

## 🏆 建立你的提示练习

快速工程是一项复合技能。从这些习惯开始：

1. **保留提示库** - 保存适合重复任务的提示
2. **A/B 测试** - 使用两个不同的提示尝试相同的任务并比较结果
3. **诊断失败** - 当响应不佳时，询问：缺少什么上下文？什么是暧昧的？
4. **阅读研究** - OpenAI、Anthropic 和 Google DeepMind 定期发表有关提示技术的论文
5. **教导他人** - 解释为什么提示有效可以巩固你自己的理解

这些模型正在迅速改进，但熟练的提示工程师可以从中提取内容的上限也在不断提高。无论您使用哪种模型，这里的基本原理 - 清晰度、特异性、上下文、迭代 - 都将仍然有价值。

# Transformers समझाए गए: ChatGPT के पीछे की आर्किटेक्चर

2017 में Google की टीम ने *"Attention Is All You Need"* नाम का पेपर प्रकाशित किया। उसने **Transformer** आर्किटेक्चर पेश की और AI को हमेशा के लिए बदल दिया। आपने जिन बड़े भाषा मॉडलों के नाम सुने हैं, ChatGPT, Claude, Gemini, BERT, Llama और आधुनिक GPT मॉडल, वे सभी Transformers पर बने हैं।

Transformers क्यों महत्वपूर्ण हैं, यह समझने के लिए पहले जानना होगा कि उन्होंने किसे बदला।

## ⏱️ RNNs की समस्या: पाठ को क्रम से संसाधित करना

Transformers से पहले अनुक्रमों (पाठ, ऑडियो, टाइम सीरीज़) को संसाधित करने का प्रमुख तरीका **Recurrent Neural Network (RNN)** और इसके रूपांतर थे: LSTM और जीआरयू।

RNN पाठ को **एक समय में एक शब्द** संसाधित करते हैं और "hidden state" बनाए रखते हैं जो जानकारी आगे ले जाता है:

```
Input:  "The cat sat on the mat because it was comfortable"
         ↓    ↓    ↓   ↓    ↓    ↓      ↓      ↓   ↓      ↓
        h1 → h2 → h3 → h4 → h5 → h6 → h7 → h8 → h9 → h10 → output
```

यह काम करता है, लेकिन दो बड़ी समस्याएँ हैं:

**1. लंबे अनुक्रमों में vanishing gradients**
जब तक मॉडल शब्द 10 तक पहुँचता है, शब्द 1 की जानकारी नौ hidden state अपडेट से "पतली" हो चुकी होती है। लंबा वाक्य हो तो मॉडल "it" (शब्द 8) को "cat" (शब्द 2) से जोड़ने में संघर्ष करता है।

**2. धीमा, parallelisation नहीं**
हर शब्द पिछले hidden state पर निर्भर है, इसलिए शब्दों को एक-एक करके संसाधित करना पड़ता है। अनुक्रम के भीतर parallelise नहीं कर सकते। लंबे दस्तावेज़ों पर प्रशिक्षण बहुत धीमा हो जाता है।

Transformer इन दोनों समस्याओं को एक सुंदर मैकेनिज़्म से हल करता है: **attention**।

## 👀 Self-Attention मैकेनिज़्म

Transformer का केंद्रीय नवाचार **self-attention** है: अनुक्रम का हर शब्द सीधे हर दूसरे शब्द पर ध्यान दे सकता है, चाहे वे कितनी भी दूरी पर हों।

जानकारी क्रम से आगे भेजने के बजाय self-attention यह गणना करता है कि अनुक्रम में हर शब्द हर दूसरे शब्द से कितना प्रासंगिक है, सब एक साथ।

### Query, Key और Value - सरल भाषा में

हर शब्द (या टोकन) के लिए Transformer तीन वेक्टर बनाता है:

- **Query (Q)**: *"मैं क्या खोज रहा हूँ?"* यह शब्द जो प्रश्न पूछ रहा है।
- **Key (K)**: *"मेरे पास क्या है?"* हर शब्द अपने बारे में जो विज्ञापन प्रसारित करता है।
- **Value (V)**: *"मैं कौन सी जानकारी देता हूँ?"* निकाली जाने वाली वास्तविक सामग्री।

दो शब्दों के बीच attention score एक शब्द की Query और दूसरे शब्द की Key का dot product लेकर निकाला जाता है। उच्च स्कोर का अर्थ है "ये दो शब्द एक-दूसरे से बहुत प्रासंगिक हैं।"

```python
import torch
import torch.nn.functional as F

def self_attention(Q, K, V):
    d_k = Q.shape[-1]  # dimension of key vectors
    
    # Compute raw attention scores: how relevant is each word to each other
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    
    # Convert scores to probabilities (weights that sum to 1)
    attention_weights = F.softmax(scores, dim=-1)
    
    # Weighted sum of Value vectors
    output = torch.matmul(attention_weights, V)
    
    return output, attention_weights

# For the sentence "The cat sat on the mat because it was comfortable",
# "it" will have a high attention score with "cat" (the antecedent)
# regardless of how many words separate them
```

परिणाम: **हर टोकन के पास हर दूसरे टोकन तक सीधी दृष्टि रेखा होती है**। अब जानकारी की bottleneck नहीं, लंबे अनुक्रमों में vanishing gradients नहीं।

### Square Root Scaling क्यों?

ऊपर के कोड में `/ (d_k ** 0.5)` dot products को बहुत बड़ा होने से रोकता है, क्योंकि बहुत बड़े मान softmax को अत्यंत छोटे gradients वाले क्षेत्रों में धकेल सकते हैं। यह स्थिरता की तरकीब है।

## 🧠 Multi-Head Attention

Transformers attention केवल एक बार नहीं, बल्कि अलग सीखे गए projections के साथ **कई बार समानांतर** गणना करते हैं। इसे **multi-head attention** कहते हैं:

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        self.num_heads = num_heads
        self.d_k = d_model // num_heads  # 64 per head
        
        # Separate linear projections for each head
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)
    
    def forward(self, x):
        # Each head learns to attend to different aspects:
        # Head 1 might focus on syntactic relationships
        # Head 2 might focus on semantic similarity
        # Head 3 might focus on co-reference (it → cat)
        # ... and so on for all 8 heads
        pass
```

हर attention head अलग प्रकार के संबंध में विशेषज्ञ हो सकता है। एक head वाक्य-रचना निर्भरता (subject-verb agreement) पर ध्यान दे सकता है, दूसरा coreference (सर्वनाम और उनके antecedents) पर, और तीसरा अर्थ समानता पर।

<FunFact>बड़े GPT-परिवार मॉडल कई attention heads उपयोग करते हैं। हर head पूरी context window में अलग भाषाई संबंध स्वतंत्र रूप से ट्रैक करना सीख सकता है।</FunFact>

## 📍 Positional Encoding

Self-attention की एक अंधी जगह है: यह स्वभाव से **order-agnostic** है। अतिरिक्त जानकारी के बिना "Dog bites man" और "Man bites dog" समान attention scores दे सकते हैं।

मॉडल को शब्द क्रम का अहसास देने के लिए Transformers इनपुट एम्बेडिंग में **positional encodings** जोड़ते हैं। मूल Transformer ने sinusoidal functions उपयोग किए:

```python
import numpy as np

def positional_encoding(seq_len, d_model):
    PE = np.zeros((seq_len, d_model))
    for pos in range(seq_len):
        for i in range(0, d_model, 2):
            PE[pos, i]     = np.sin(pos / 10000 ** (2*i / d_model))
            PE[pos, i + 1] = np.cos(pos / 10000 ** (2*i / d_model))
    return PE

# Each position gets a unique "fingerprint" added to its embedding
# Position 0 looks different from position 1, which looks different from position 2
```

LLaMA जैसे आधुनिक मॉडल **Rotary Position Embeddings (RoPE)** उपयोग करते हैं, जो relative position को अधिक प्रभावी ढंग से encode करते हैं और बहुत लंबे contexts पर बेहतर scale करते हैं।

## 🏗️ पूरी Transformer आर्किटेक्चर

मूल Transformer के दो मुख्य हिस्से हैं:

### Encoder
इनपुट पढ़ता है और समृद्ध contextual representation बनाता है। हर टोकन की representation self-attention से हर दूसरे टोकन से प्रभावित होती है। उपयोग: वाक्य वर्गीकरण, नामित इकाई पहचान और दिए गए passage पर प्रश्नोत्तर।

### Decoder
आउटपुट टोकन एक-एक करके बनाता है, encoder output और पहले से बने टोकन दोनों पर attention देता है। उपयोग: अनुवाद, सारांश और पाठ जनरेशन।

पूरा encoder-decoder stack:
```
Input text → Token Embeddings + Positional Encoding
           → N × [Multi-Head Self-Attention → Add & Norm → Feed-Forward → Add & Norm]
           → Encoder Output

Encoder Output + Generated tokens so far
           → N × [Masked Self-Attention → Cross-Attention → Feed-Forward]
           → Next token prediction
```

## 🆚 BERT बनाम GPT: Transformer के दो रूप

सभी Transformer-आधारित मॉडल पूरा encoder-decoder ढाँचा उपयोग नहीं करते। दो प्रमुख रूप हैं:

### BERT (Encoder-Only)
- केवल **encoder** stack उपयोग करता है
- **Masked Language Modelling** से प्रशिक्षित: कुछ इनपुट टोकन छिपाए जाते हैं और BERT उन्हें भविष्यवाणी करता है
- पाठ **समझने** में उत्कृष्ट: classification, search, Q&A
- पूरा context bidirectionally पढ़ता है (हर शब्द हर दूसरे शब्द को देखता है)

### GPT (Decoder-Only)
- केवल **decoder** stack उपयोग करता है
- **next-token prediction** से प्रशिक्षित: पिछले सभी टोकन देखकर अगला भविष्यवाणी करना
- पाठ **बनाने** में उत्कृष्ट: conversation, writing, code
- causal masking: हर टोकन केवल पिछले टोकन देख सकता है, भविष्य वाले नहीं, वरना cheating होगी

```
BERT training:   "The [MASK] sat on the mat"  → predict "cat"
GPT training:    "The cat sat on the"          → predict "mat"
```

<ThinkAboutIt>BERT का bidirectional attention शब्द की representation बनाते समय भविष्य के शब्द भी देख सकता है। GPT नहीं देख सकता। यह GPT को generation के लिए बेहतर लेकिन BERT को classification कार्यों के लिए बेहतर क्यों बनाता है?</ThinkAboutIt>

## 📈 Scale क्यों महत्वपूर्ण है

Transformer आर्किटेक्चर आश्चर्यजनक रूप से अच्छी तरह scale हुई। अधिक पैरामीटर वाले बड़े मॉडल, अधिक डेटा और अधिक compute पर प्रशिक्षित होकर लगातार बेहतर प्रदर्शन देते हैं। इसे **scaling laws** (Kaplan et al., 2020) ने वर्णित किया।

इससे क्रम बना:
- GPT-1 (2018): 117M पैरामीटर
- GPT-2 (2019): 1.5B पैरामीटर
- GPT-3 (2020): 175B पैरामीटर
- वर्तमान frontier मॉडल: अक्सर mixture-of-experts या अप्रकाशित आर्किटेक्चर, प्रभावी रूप से सैकड़ों अरब से ट्रिलियन पैरामीटर तक

हर छलांग गुणात्मक सुधार लाई। जो काम GPT-2 बिल्कुल नहीं कर पाता था (जटिल तर्क, code generation), वे GPT-3 scale पर संभव हुए और बाद के frontier मॉडलों में सुधरते गए।

## ⚡ Training बनाम Inference

दो बहुत अलग कम्प्यूटेशनल प्रोफ़ाइल हैं:

**Training**: अत्यंत महँगा। खरबों टोकन संसाधित करना, gradients निकालना और हज़ारों GPUs पर हफ़्तों या महीनों तक विशाल पैरामीटर सेट अपडेट करना। वर्तमान frontier मॉडल training की लागत compute, data, energy और engineering मिलाकर सैकड़ों मिलियन तक हो सकती है।

**Inference**: बहुत सस्ता। हर टोकन बनाने के लिए नेटवर्क से एक फ़ॉरवर्ड पास। फिर भी महत्वपूर्ण hardware चाहिए, शक्तिशाली GPUs या विशेष AI chips, लेकिन scale पर प्रबंधनीय।

इस असमानता ने उद्योग को आकार दिया है: कुछ संसाधन-संपन्न संगठन foundation models प्रशिक्षित करते हैं; बाकी सब उन्हें APIs से उपयोग करते हैं।

## मुख्य बातें

- **RNNs** अनुक्रमों को चरण दर चरण संसाधित करते थे, long-range dependencies से संघर्ष करते थे और parallelise नहीं हो सकते थे। Transformers ने उन्हें बदला।
- **Self-attention** हर टोकन को Query, Key, Value वेक्टरों से सीधे हर दूसरे टोकन पर ध्यान देने देता है, जिससे दोनों समस्याएँ हल होती हैं।
- **Multi-head attention** कई attention गणनाएँ समानांतर चलाता है, जिससे मॉडल अलग संबंध एक साथ सीखता है।
- **Positional encoding** स्वभाव से position-agnostic attention mechanism में क्रम जानकारी जोड़ता है।
- **BERT** (encoder-only) bidirectional text understanding के लिए pre-trained है। classification और search के लिए बेहतर।
- **GPT** (decoder-only) बाएँ से दाएँ text generation के लिए pre-trained है। generation और conversation के लिए बेहतर।
- **Scale बहुत मायने रखता है**: अधिक डेटा पर प्रशिक्षित बड़े Transformers नई क्षमताएँ खोलते हैं, जैसा GPT-1 से GPT-3 और बाद के frontier systems में दिखा।
- Training बहुत महँगा है; inference सस्ता है। यही असमानता foundation models की deployment शैली को आकार देती है।

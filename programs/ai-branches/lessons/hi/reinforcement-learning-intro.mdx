# रीइन्फोर्समेंट लर्निंग: प्रयास और त्रुटि से AI को सिखाना

बच्चा चलना कैसे सीखता है? कोई उसे "अच्छा कदम / बुरा कदम" उदाहरणों वाला लेबल किया डेटासेट नहीं देता। कोई संतुलन की भौतिकी समीकरण लिखकर नहीं देता। वह कोशिश करता है, गिरता है, अलग तरह से कोशिश करता है और धीरे-धीरे सुधरता है, आसपास की दुनिया से मिली प्रतिक्रिया के आधार पर।

यही सहज विचार, **पुरस्कार और दंड से निर्देशित प्रयास और त्रुटि के माध्यम से सीखना**, **Reinforcement Learning (RL)** की नींव है। इसी तरीके ने AI की कुछ सबसे शानदार उपलब्धियाँ दी हैं: Go और chess में विश्व चैंपियन को हराना, ChatGPT को उपयोगी बनाना और रोबोटों को चलना सिखाना।

## 🎯 मुख्य ढाँचा: Agent, Environment, Reward

हर RL समस्या की मूल संरचना समान होती है:

```
        ┌─────────────────────────────────────────┐
        │              ENVIRONMENT                 │
        │   (the world the agent operates in)      │
        └─────────────────┬───────────────────────┘
                          │
         State (s_t)      │      Reward (r_t)
         What the         │      How good was
         agent sees ◄─────┤      the last action?
                          │
        ┌─────────────────▼───────────────────────┐
        │                 AGENT                    │
        │   (the AI that takes actions)            │
        └─────────────────┬───────────────────────┘
                          │
                          │ Action (a_t)
                          ▼
              Agent acts on the environment,
              environment transitions to state s_{t+1}
```

- **Agent**: निर्णय लेने वाली AI प्रणाली
- **Environment**: वह सब जिससे एजेंट इंटरैक्ट करता है (गेम, सिमुलेशन, भौतिक रोबोट का आसपास)
- **State**: वातावरण का एजेंट को दिख रहा वर्तमान अवलोकन
- **Action**: एजेंट की क्रिया (बाएँ जाना, रोबोट भुजा हिलाना, कोई शब्द चुनना)
- **Reward**: क्रिया कितनी अच्छी थी बताने वाला संख्यात्मक संकेत (+1 गोल करने पर, -1 जीवन खोने पर, +10 कार्य पूरा करने पर)
- **Policy**: एजेंट की रणनीति, स्थितियों से क्रियाओं की मैपिंग

एजेंट का लक्ष्य ऐसी **policy** सीखना है जो समय के साथ कुल **cumulative reward** अधिकतम करे, केवल तत्काल पुरस्कार नहीं।

## 🔍 Exploration बनाम Exploitation: केंद्रीय दुविधा

RL एजेंट लगातार तनाव झेलते हैं:

**Exploitation**: जो पहले से अच्छा काम करता है वही करें, यानी वर्तमान में सर्वश्रेष्ठ लगने वाली क्रिया लें।

**Exploration**: कुछ नया आज़माएँ, शायद कोई बेहतर रणनीति अभी मिली न हो।

जो रोबोट केवल exploit करेगा वह बेहतर रास्ता कभी नहीं खोजेगा। जो केवल explore करेगा वह कहीं भरोसेमंद ढंग से नहीं पहुँचेगा।

सरल लेकिन प्रभावी रणनीति **ε-greedy** है:

```python
import random

epsilon = 0.1  # 10% exploration rate

def choose_action(state, Q_table, epsilon):
    if random.random() < epsilon:
        # Explore: choose a random action
        return random.choice(available_actions)
    else:
        # Exploit: choose the action with highest expected reward
        return argmax(Q_table[state])
```

ε = 0.1 के साथ एजेंट 10% समय यादृच्छिक रूप से explore करता है और 90% समय अपने सीखे ज्ञान को exploit करता है। आमतौर पर ε शुरुआत में अधिक होता है और प्रशिक्षण के साथ घटता है जैसे एजेंट अधिक आश्वस्त होता है।

<FunFact>Exploration-exploitation दुविधा केवल AI समस्या नहीं है। यह मानव निर्णयों में भी दिखती है। क्या आप अपने पसंदीदा रेस्तराँ जाएँ (exploit) या कोई नई जगह आज़माएँ (explore)? वही गणितीय ढाँचा लागू होता है।</FunFact>

## 📊 Markov Decision Processes (MDPs)

अधिकांश RL समस्याएँ **Markov Decision Processes (MDPs)** के रूप में औपचारिक की जाती हैं। मुख्य धारणा **Markov property** है: वर्तमान स्थिति में सर्वोत्तम क्रिया चुनने के लिए आवश्यक सारी जानकारी है। पिछला इतिहास मायने नहीं रखता, केवल अभी आप कहाँ हैं।

MDP परिभाषित होता है:
- **S**: संभावित स्थितियों का सेट
- **A**: संभावित क्रियाओं का सेट
- **P(s' | s, a)**: transition probability, स्थिति s और क्रिया a देने पर स्थिति s' में पहुँचने की संभावना
- **R(s, a)**: reward function, स्थिति s में क्रिया a लेने का तत्काल पुरस्कार
- **γ (gamma)**: discount factor, तत्काल पुरस्कार की तुलना में भविष्य पुरस्कार की कीमत

**Discount factor** महत्वपूर्ण है: निकट भविष्य के पुरस्कार दूर भविष्य के पुरस्कारों से अधिक मूल्यवान होते हैं:

```python
# Cumulative discounted reward (Return)
# R = r_0 + γ·r_1 + γ²·r_2 + γ³·r_3 + ...
# With γ = 0.99: future rewards are nearly as valuable as immediate ones
# With γ = 0.5:  rewards 10 steps away are worth only 0.1% of immediate reward

gamma = 0.99
total_return = sum(gamma**t * reward for t, reward in enumerate(rewards))
```

## 🧮 Q-Learning: Value-Based RL

**Q-learning** आधारभूत RL एल्गोरिदमों में से एक है। यह **Q-function** सीखता है: Q(s, a) = यदि आप स्थिति s में क्रिया a लें और फिर हमेशा सर्वोत्तम ढंग से काम करें, तो अपेक्षित कुल भविष्य पुरस्कार।

```python
import numpy as np

# Initialise Q-table to zeros
n_states  = 16   # e.g., a 4×4 grid world
n_actions = 4    # up, down, left, right
Q = np.zeros((n_states, n_actions))

# Q-learning update rule (the Bellman equation)
def update_Q(Q, state, action, reward, next_state, alpha=0.1, gamma=0.99):
    """
    alpha: learning rate - how fast to update Q values
    gamma: discount factor - how much to value future rewards
    """
    # Current estimate
    current_Q = Q[state, action]
    
    # Target: immediate reward + discounted best future value
    target = reward + gamma * np.max(Q[next_state])
    
    # Move current estimate towards target
    Q[state, action] = current_Q + alpha * (target - current_Q)
    
    return Q
```

हज़ारों एपिसोड के बाद Q-learning optimal Q-function की ओर अभिसरित होता है। एक बार सीखने के बाद policy सरल है: हर स्थिति में सबसे अधिक Q-value वाली क्रिया लें।

DeepMind द्वारा 2013 में विकसित **Deep Q-Networks (DQN)** ने Q-table को deep neural network से बदल दिया, जिससे Q-learning जटिल visual inputs तक scale हो सका। DQN ने सीधे pixels से 49 Atari गेम खेलना सीखा और कई में मानव-स्तर प्रदर्शन पाया।

## 🚀 Policy Gradient Methods

Q-learning क्रियाओं का मूल्य अप्रत्यक्ष रूप से सीखता है। **Policy gradient** विधियाँ सीधे policy को optimize करती हैं, यानी स्थितियों से क्रियाओं की मैपिंग।

```python
# The core idea: if an action led to high reward, make it more likely
# If an action led to low reward, make it less likely

def policy_gradient_update(policy_network, states, actions, rewards):
    # Compute discounted returns for each timestep
    returns = compute_returns(rewards, gamma=0.99)
    
    # Normalise returns (reduces variance)
    returns = (returns - returns.mean()) / (returns.std() + 1e-8)
    
    # Policy loss: -log(π(a|s)) × G_t
    # Maximise log-probability of actions weighted by how good they were
    log_probs = policy_network.log_prob(states, actions)
    loss = -(log_probs * returns).mean()
    
    # Backpropagate and update
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
```

आधुनिक policy gradient रूपांतरों में शामिल हैं:
- **PPO (Proximal Policy Optimisation)**: आज सबसे व्यापक रूप से उपयोग होने वाला एल्गोरिदम, ChatGPT के RLHF प्रशिक्षण में उपयोग हुआ
- **A3C (Asynchronous Advantage Actor-Critic)**: कई वातावरणों में समानांतर प्रशिक्षण करता है
- **SAC (Soft Actor-Critic)**: continuous action spaces, जैसे robotics, के लिए उत्कृष्ट

## 💬 RLHF: ChatGPT कैसे ट्यून हुआ

RL के सबसे प्रभावशाली हालिया अनुप्रयोगों में **Reinforcement Learning from Human Feedback (RLHF)** है। यही तकनीक ChatGPT और अन्य LLMs को उपयोगी, हानिरहित और ईमानदार बनाने के लिए उपयोग हुई।

प्रक्रिया के तीन चरण हैं:

**Stage 1: Pre-training**
बड़े भाषा मॉडल को इंटरनेट पाठ पर अगला token भविष्यवाणी करने के लिए प्रशिक्षित करें। इससे व्यापक ज्ञान और भाषा क्षमता मिलती है, लेकिन यह नहीं सिखता कि मनुष्य क्या उपयोगी मानते हैं।

**Stage 2: Reward Model प्रशिक्षित करना**
मानव annotators से मॉडल उत्तरों के जोड़ों को रेट करवाएँ: "कौन सा उत्तर बेहतर है?" इन ratings से **reward model** प्रशिक्षित करें, जो उत्तर की गुणवत्ता score करता है।

**Stage 3: PPO से RL Fine-tuning**
Reward model को environment की तरह उपयोग करें। LLM agent है। उसकी actions token बनाना हैं। उसका reward पूरे उत्तर पर reward model के score से आता है।

```
Human prompt → LLM generates response → Reward model scores it
                                       → PPO updates LLM to generate
                                         higher-scoring responses
```

यह लूप हज़ारों iterations चलता है जब तक LLM लगातार ऐसे उत्तर नहीं बनाता जिन्हें मनुष्य उच्च रेट करते हैं। परिणाम: ऐसा मॉडल जो केवल जानकार नहीं, बल्कि सचमुच उपयोगी बनने की कोशिश करता है।

<ThinkAboutIt>RLHF ChatGPT को ऐसे उत्तर बनाने के लिए प्रशिक्षित करता है जिन्हें मानव annotators उच्च रेट करते हैं। यदि annotators में पूर्वाग्रह हों, या "annotators को जो अच्छा लगे" वही "वास्तव में सत्य और उपयोगी" न हो, तो कौन सी समस्याएँ आ सकती हैं?</ThinkAboutIt>

## ♟️ AlphaGo की कहानी

Go इतना जटिल बोर्ड गेम है, जिसमें संभावित बोर्ड स्थितियाँ अवलोकनीय ब्रह्मांड के परमाणुओं से अधिक हैं, कि इसे AI की सबसे कठिन चुनौतियों में गिना जाता था। अधिकांश विशेषज्ञों को लगता था कि मानव चैंपियन दशकों तक अजेय रहेंगे।

मार्च 2016 में DeepMind के **AlphaGo** ने विश्व चैंपियन Lee Sedol को 4-1 से हराया।

प्रणाली ने मिलाया:
- **Policy network** (मानव खेलों पर supervised learning से प्रशिक्षित, फिर RL से परिष्कृत) जो संभावित अच्छे चाल सुझाता था
- **Value network** (self-play से RL द्वारा प्रशिक्षित) जो बोर्ड स्थितियों का मूल्यांकन करता था
- दोनों networks से निर्देशित **Monte Carlo Tree Search** जो आगे योजना बनाता था

**AlphaZero** (2017) इससे आगे गया: उसने Go, chess और shogi *शून्य से* सीखे, मानव खेल डेटा के बिना, केवल नियम और RL self-play से। उसने तीन दिनों में AlphaGo और चार घंटों में सर्वश्रेष्ठ chess engine (Stockfish) को पीछे छोड़ दिया।

## 🤖 Robotics अनुप्रयोग

RL आधुनिक robotics शोध का केंद्र है:

- **OpenAI's Dactyl** (2019): पूरी तरह simulation में RL से प्रशिक्षित robotic hand, जो केवल एक हाथ से Rubik's Cube हल कर सकता था
- **Boston Dynamics**: Spot और Atlas रोबोटों की agile locomotion के लिए traditional control theory के साथ RL उपयोग करता है
- **Manipulation tasks**: असंरचित वातावरणों में वस्तुएँ उठाना, रखना और assemble करना सीखते रोबोट
- **Autonomous driving**: वास्तविक deployment से पहले simulation में driving policies प्रशिक्षित करने के लिए RL उपयोग होता है

Robotics RL की मुख्य चुनौती **sim-to-real gap** है: simulation में प्रशिक्षित policies अक्सर वास्तविक दुनिया में असफल होती हैं क्योंकि simulation physics, friction, sensor noise और अनपेक्षित वस्तुओं को पूरी तरह model नहीं कर पाता।

## ⚠️ Reinforcement Learning की सीमाएँ

RL शक्तिशाली है लेकिन इसकी वास्तविक सीमाएँ हैं:

- **Sample efficiency**: RL को अक्सर लाखों या अरबों interactions चाहिए, जहाँ मानव बच्चा घंटों में सीखता है। AlphaGo ने प्रशिक्षण में हज़ारों वर्षों के मानव खेलों के बराबर खेल खेले।
- **Reward hacking**: एजेंट कभी-कभी ऐसे चतुर तरीके खोज लेते हैं जो objective की भावना तोड़कर reward maximize करते हैं, जैसे सफ़ाई रोबोट गंदगी साफ़ करने के बजाय उसे *छिपाना* सीख जाए।
- **Sparse rewards**: जब reward दुर्लभ हो (केवल गेम अंत में), सीखना बहुत धीमा होता है।
- **Safety**: exploratory RL agents वास्तविक दुनिया में खतरनाक actions ले सकते हैं। self-driving car traffic में random explore नहीं कर सकती।

## मुख्य बातें

- RL **agent/environment/reward** ढाँचे पर बना है: एजेंट क्रिया करता है, reward पाता है और cumulative reward maximize करने वाली policy सीखता है।
- **Exploration बनाम exploitation** केंद्रीय दुविधा है: ε-greedy और अधिक उन्नत रणनीतियाँ नई चीज़ आज़माने और ज्ञात काम करने वाली चीज़ अपनाने में संतुलन रखती हैं।
- **Markov Decision Processes (MDPs)** RL समस्याओं को औपचारिक करते हैं। discount factor γ तय करता है कि एजेंट भविष्य बनाम तत्काल reward को कितना महत्व देता है।
- **Q-learning** (और Deep Q-Networks) value functions सीखते हैं। **policy gradient** methods (PPO, A3C) policy को सीधे optimize करते हैं।
- **RLHF** ChatGPT के उपयोगी व्यवहार के पीछे की तकनीक है: मानव पसंद ratings reward model प्रशिक्षित करती हैं, जो फिर LLM की PPO fine-tuning को guide करता है।
- **AlphaGo/AlphaZero** ने दिखाया कि self-play वाला RL जटिल खेलों में मानव विश्व चैंपियन से आगे जा सकता है, दिनों में वह हासिल करते हुए जिसके लिए मनुष्यों को सहस्राब्दियों का ज्ञान लगा।
- RL की मुख्य सीमाएँ हैं **कम sample efficiency**, **reward hacking** और robotics में **sim-to-real gap**।

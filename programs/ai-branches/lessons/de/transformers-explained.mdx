# Transformers erklärt: Die Architektur hinter ChatGPT

Im Jahr 2017 veröffentlichte ein Team bei Google einen Artikel mit dem Titel *"Attention Is All You Need"*. Es führte die **Transformer**-Architektur ein und veränderte die KI für immer. Jedes wichtige Sprachmodell, von dem Sie gehört haben - ChatGPT, Claude, Gemini, BERT, Llama und moderne GPT-Modelle - basiert auf Transformers.

Um zu verstehen, warum Transformers wichtig sind, müssen Sie zunächst verstehen, was sie ersetzt haben.

## ⏱️ Das Problem mit RNNs: Text sequentiell verarbeiten

Vor Transformers war der vorherrschende Ansatz zur Verarbeitung von Sequenzen (Text, Audio, Zeitreihen) das **Recurrent Neural Network (RNN)** und seine Varianten: LSTMs und GRUs.

RNNs verarbeiten Text **wortweise** und behalten dabei einen „verborgenen Zustand“ bei, der Informationen weiterleitet:

```
Input:  "The cat sat on the mat because it was comfortable"
         ↓    ↓    ↓   ↓    ↓    ↓      ↓      ↓   ↓      ↓
        h1 → h2 → h3 → h4 → h5 → h6 → h7 → h8 → h9 → h10 → output
```

Das funktioniert, hat aber zwei große Probleme:

**1. Verschwindende Farbverläufe über lange Sequenzen**
Bis das Modell Wort 10 verarbeitet, wurden die Informationen aus Wort 1 durch neun versteckte Zustandsaktualisierungen „verwässert“. Das Modell hat Schwierigkeiten, „it“ (Wort 8) wieder mit „cat“ (Wort 2) zu verbinden, wenn der Satz lang ist.

**2. Langsam – keine Parallelisierung**
Da jedes Wort vom vorherigen verborgenen Zustand abhängt, müssen Sie die Wörter einzeln verarbeiten. Eine Parallelisierung über eine Sequenz hinweg ist nicht möglich. Das Training langer Dokumente ist quälend langsam.

Der Transformer löst beide Probleme mit einem einzigen eleganten Mechanismus: **Aufmerksamkeit**.

## 👀 Der Selbstaufmerksamkeitsmechanismus

Die zentrale Innovation des Transformers ist die **Selbstaufmerksamkeit**: die Fähigkeit jedes Wortes in einer Sequenz, jedes andere Wort gleichzeitig direkt zu berücksichtigen, unabhängig davon, wie weit sie voneinander entfernt sind.

Anstatt Informationen nacheinander weiterzugeben, berechnet die Selbstaufmerksamkeit, **wie relevant jedes Wort für jedes andere Wort in der Sequenz ist** – und zwar auf einmal.

### Abfrage, Schlüssel und Wert – im Klartext

Für jedes Wort (oder Token) erstellt der Transformer drei Vektoren:

- **Frage (F)**: *„Wonach suche ich?“* – die Frage, die dieses Wort stellt
- **Schlüssel (K)**: *„Was enthalte ich?“* – die Werbung, die jedes Wort über sich selbst ausstrahlt
- **Wert (V)**: *„Welche Informationen stelle ich bereit?“* – der tatsächlich abzurufende Inhalt

Der Aufmerksamkeitswert zwischen zwei Wörtern wird berechnet, indem das Skalarprodukt der Suchanfrage eines Wortes mit dem Schlüssel eines anderen Wortes gebildet wird. Eine hohe Punktzahl bedeutet, dass „diese beiden Wörter füreinander von hoher Relevanz sind“.

```python
import torch
import torch.nn.functional as F

def self_attention(Q, K, V):
    d_k = Q.shape[-1]  # dimension of key vectors
    
    # Compute raw attention scores: how relevant is each word to each other
    scores = torch.matmul(Q, K.transpose(-2, -1)) / (d_k ** 0.5)
    
    # Convert scores to probabilities (weights that sum to 1)
    attention_weights = F.softmax(scores, dim=-1)
    
    # Weighted sum of Value vectors
    output = torch.matmul(attention_weights, V)
    
    return output, attention_weights

# For the sentence "The cat sat on the mat because it was comfortable",
# "it" will have a high attention score with "cat" (the antecedent)
# regardless of how many words separate them
```

Das Ergebnis: **Jeder Token hat eine direkte Sichtlinie zu jedem anderen Token**. Kein Informationsengpass mehr, keine verschwindenden Farbverläufe mehr über lange Sequenzen.

### Warum die Quadratwurzelskalierung?

Das `/ (d_k ** 0.5)` im obigen Code verhindert, dass die Skalarprodukte zu sehr großen Zahlen werden, die den Softmax in Bereiche mit extrem kleinen Steigungen drängen würden. Es ist ein Stabilisierungstrick.

## 🧠 Mehrköpfige Aufmerksamkeit

Anstatt die Aufmerksamkeit nur einmal zu berechnen, berechnen Transformers sie **mehrmals parallel** mit verschiedenen erlernten Projektionen. Dies nennt man **Mehrkopfaufmerksamkeit**:

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        self.num_heads = num_heads
        self.d_k = d_model // num_heads  # 64 per head
        
        # Separate linear projections for each head
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)
    
    def forward(self, x):
        # Each head learns to attend to different aspects:
        # Head 1 might focus on syntactic relationships
        # Head 2 might focus on semantic similarity
        # Head 3 might focus on co-reference (it → cat)
        # ... and so on for all 8 heads
        pass
```

Jeder Aufmerksamkeitsleiter kann sich auf eine andere Art von Beziehung spezialisieren. Ein Kopf könnte syntaktische Abhängigkeiten verfolgen (Subjekt-Verb-Übereinstimmung), ein anderer könnte sich auf die Koreferenz (Pronomen und ihre Antezedenzien) konzentrieren, ein anderer könnte semantische Ähnlichkeiten erfassen.

<FunFact>Große GPT-family Modelle verwenden viele Aufmerksamkeitsköpfe. Jeder kann selbstständig lernen, verschiedene linguistische Beziehungen über das gesamte Kontextfenster hinweg gleichzeitig zu verfolgen.</FunFact>

## 📍Positionskodierung

Selbstaufmerksamkeit hat einen blinden Fleck: Sie ist von Natur aus **ordnungsunabhängig**. „Hund beißt Mann“ und „Mann beißt Hund“ würden ohne zusätzliche Informationen identische Aufmerksamkeitswerte ergeben.

Um dem Modell ein Gefühl für die Wortreihenfolge zu verleihen, fügen Transformers den Eingabeeinbettungen **Positionskodierungen** hinzu. Der ursprüngliche Transformer verwendete Sinusfunktionen:

```python
import numpy as np

def positional_encoding(seq_len, d_model):
    PE = np.zeros((seq_len, d_model))
    for pos in range(seq_len):
        for i in range(0, d_model, 2):
            PE[pos, i]     = np.sin(pos / 10000 ** (2*i / d_model))
            PE[pos, i + 1] = np.cos(pos / 10000 ** (2*i / d_model))
    return PE

# Each position gets a unique "fingerprint" added to its embedding
# Position 0 looks different from position 1, which looks different from position 2
```

Moderne Modelle wie LLaMA verwenden **Rotary Position Embeddings (RoPE)**, die die relative Position effektiver kodieren und sich besser auf sehr lange Kontexte skalieren lassen.

## 🏗️ Die vollständige Transformer-Architektur

Der ursprüngliche Transformer besteht aus zwei Hauptteilen:

### Encoder
Liest die Eingabe und erstellt eine umfassende kontextbezogene Darstellung. Die Darstellung jedes Tokens wird von jedem anderen Token durch Selbstaufmerksamkeit beeinflusst. Wird für Aufgaben wie Satzklassifizierung, Erkennung benannter Entitäten und Beantwortung von Fragen zu einer bestimmten Passage verwendet.

### Decoder
Erzeugt nacheinander Ausgabe-Tokens und kümmert sich dabei sowohl um die Ausgabe des Encoders als auch um die bereits generierten Tokens. Verwendet für: Übersetzung, Zusammenfassung, Textgenerierung.

Ein vollständiger Encoder-Decoder-Stack:
```
Input text → Token Embeddings + Positional Encoding
           → N × [Multi-Head Self-Attention → Add & Norm → Feed-Forward → Add & Norm]
           → Encoder Output

Encoder Output + Generated tokens so far
           → N × [Masked Self-Attention → Cross-Attention → Feed-Forward]
           → Next token prediction
```

## 🆚 BERT vs. GPT: Zwei Varianten von Transformer

Nicht alle Transformer-basierten Modelle verwenden die vollständige Encoder-Decoder-Struktur. Die beiden vorherrschenden Varianten sind:

### BERT (nur Encoder)
– Verwendet nur den **Encoder**-Stack
- Trainiert mit **Masked Language Modeling**: Einige Eingabetokens sind ausgeblendet und BERT sagt sie voraus
- Hervorragend darin, Text zu **verstehen**: Klassifizierung, Suche, Fragen und Antworten
- Liest den gesamten Kontext bidirektional (jedes Wort sieht jedes andere Wort)

### GPT (nur Decoder)
- Verwendet nur den **Decoder**-Stack  
- Trainiert mit **Vorhersage des nächsten Tokens**: Sagen Sie anhand aller vorherigen Token den nächsten voraus
- Hervorragend darin, Text zu **generieren**: Konversation, Schreiben, Code
- Kausale Maskierung: Jeder Token kann sich nur um frühere Token kümmern (nicht um zukünftige – das wäre Betrug)

```
BERT training:   "The [MASK] sat on the mat"  → predict "cat"
GPT training:    "The cat sat on the"          → predict "mat"
```

<ThinkAboutIt>Die bidirektionale Aufmerksamkeit von BERT bedeutet, dass es zukünftige Wörter erkennen kann, wenn die Darstellung eines Wortes erstellt wird. GPT kann das nicht. Warum ist GPT dadurch besser für die Generierung, BERT jedoch besser für Klassifizierungsaufgaben?</ThinkAboutIt>

## 📈 Warum Skalierung wichtig ist

Die Transformer-Architektur ließ sich bemerkenswert gut skalieren. Größere Modelle mit mehr Parametern, die auf mehr Daten und mehr Rechenleistung trainiert werden, erzielen durchweg eine bessere Leistung – ein Phänomen, das durch **Skalierungsgesetze** beschrieben wird (Kaplan et al., 2020).

Dies führte zu einer Entwicklung:
- GPT-1 (2018): 117 Mio. Parameter
- GPT-2 (2019): 1,5B Parameter
- GPT-3 (2020): 175B Parameter
- Aktuelle frontier Modelle: oft mixture-of-experts oder unveröffentlichte Architekturen mit Hunderten Milliarden bis Billionen effektiver Parameter

Jeder Sprung brachte qualitative Verbesserungen der Fähigkeiten. Aufgaben, die GPT-2 überhaupt nicht bewältigen konnte (komplexes Schlussfolgern, Codegenerierung), wurden im GPT-3-Maßstab möglich und verbesserten sich in späteren frontier Modellen weiter.

## ⚡ Training vs. Inferenz

Zwei sehr unterschiedliche Rechenprofile:

**Training**: extrem teuer. Billionen von Token verarbeiten, Gradienten berechnen und riesige Parametersätze über Tausende GPUs wochen- oder monatelang aktualisieren. Das Training aktueller frontier Modelle kann Hunderte Millionen kosten, wenn Compute, Daten, Energie und Engineering einbezogen werden.

**Schlussfolgerung**: viel günstiger. Ein einzelner Vorwärtsdurchlauf durch das Netzwerk, um jedes Token zu generieren. Erfordert immer noch erhebliche Hardware (leistungsstarke GPUs oder spezielle KI-Chips), ist aber im großen Maßstab beherrschbar.

Diese Asymmetrie hat die Branche geprägt: Einige wenige gut ausgestattete Organisationen trainieren Grundlagenmodelle; Alle anderen greifen über APIs darauf zu.

## Wichtige Erkenntnisse

- **RNNs** verarbeiteten Sequenzen Schritt für Schritt, kämpften mit weitreichenden Abhängigkeiten und konnten nicht parallelisieren – Transformers ersetzten sie
- **Selbstaufmerksamkeit** ermöglicht es jedem Token, sich über Abfrage-, Schlüssel- und Wertvektoren direkt um jedes andere Token zu kümmern – wodurch beide Probleme gleichzeitig gelöst werden
- **Mehrkopfaufmerksamkeit** führt mehrere Aufmerksamkeitsberechnungen parallel aus, sodass das Modell gleichzeitig verschiedene Arten von Beziehungen lernen kann
- **Positionskodierung** fügt Ordnungsinformationen zum inhärent positionsunabhängigen Aufmerksamkeitsmechanismus hinzu
- **BERT** (nur Encoder) ist vorab darauf trainiert, Text bidirektional zu verstehen; am besten für Klassifizierungs- und Suchaufgaben geeignet
- **GPT** (nur Decoder) ist vorab trainiert, um Text von links nach rechts zu generieren; am besten für Generation und Konversation
- **Skalierung ist enorm wichtig**: Größere Transformers, die auf mehr Daten trainiert werden, schalten konsequent neue Fähigkeiten frei, wie die Entwicklung von GPT-1 über GPT-3 bis zu späteren frontier Systemen zeigt
- Schulung ist extrem teuer; Inferenz ist viel billiger - diese Asymmetrie prägt die Art und Weise, wie Basismodelle eingesetzt werden

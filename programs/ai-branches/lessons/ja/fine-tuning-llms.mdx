# LLM の微調整: ユースケースに合わせて AI をカスタマイズ 🎯

事前トレーニングされた大規模な言語モデルはジェネラリストです。インターネットのかなりの部分を読み、驚くほど幅広い知識を吸収しました。しかし、「ゼネラリスト」は「専門的ではない」の言い換えです。会社の声を伝え、業界の専門用語を理解し、特定の出力形式に従い、または本題から外れた主題についての議論を拒否するモデルが必要な場合は、プロンプト以上のものが必要です。

ここで **微調整** が役に立ちます。

---

## 🗺️ モデルを特化する 3 つの方法

メカニズムの微調整に入る前に、代替手段と比較してそれがどの位置にあるかを理解するのに役立ちます。

|アプローチ |仕組み |こんな方に最適 |
|---|---|---|
| **迅速なエンジニアリング** |ベースモデルをガイドするクラフト説明書 |迅速な反復、データは不要 |
| **RAG (検索拡張生成)** |推論時に関連ドキュメントを取得し、プロンプトに含めます。知識を最新の状態に保ち、大規模な知識ベース |
| **微調整** |タスク固有の例を使用してモデルの重みを調整する |一貫したスタイル/形式、特殊な推論、プロンプトの長さの短縮 |

微調整と RAG は相互に排他的ではありません。多くの実稼働システムでは両方が使用されています。

---

## 🔬 微調整が実際に行うこと

事前トレーニングされた LLM には、数十億の重み (パラメーター) があり、これは事前トレーニングから学習したすべてをエンコードする数値です。微調整では、特定のタスクを反映する小規模で厳選されたデータセットでモデルのトレーニングを続けます。

モデルはサンプルを参照し、現在の重みがどの程度間違っているかを計算し、調整します。コアとなるトレーニングの仕組み (フォワード パス、損失計算、バックプロパゲーション) は事前トレーニングと同じです。データに対して、はるかに少ないステップでそれを再度実行するだけです。

その結果、モデルの重みが「ジェネラリスト」から「特定のユースケース」へと少しずつずらされました。

<FunFact>GPT-3 には 1,750 億のパラメータがありました。コンシューマー向け GPU でそれらすべてを微調整することは完全に非現実的です。これがまさに、LoRA のようなパラメータ効率の高い微調整手法が開発された理由です。これにより、データ センターを必要とせずに微調整が可能になります。
</FunFact>

## ⚡ 完全な微調整とパラメータ効率の高い微調整

**完全な微調整** により、モデル内のすべてのウェイトが更新されます。これは最も強力なアプローチですが、最も高価でもあります。 700 億パラメータのモデルの場合、複数のハイエンド GPU と数時間または数日のトレーニングが必要になります。

**パラメーター効率の良い微調整 (PEFT)** は、モデルの重みの大部分を固定し、少数の追加パラメーターのみをトレーニングします。 2 つの主要なテクニック:

### LoRA (低ランク適応)

LoRA は、元の重み行列を直接変更するのではなく、固定された重みに *一緒に* 小さなトレーニング可能な行列を追加します。これらの小さなマトリックスは、タスク固有の調整をキャプチャします。

計算: 通常 (d × d) となる重み更新行列は、2 つのはるかに小さな行列 (d × r) × (r × d) の積として近似されます。ここで、r は小さな「ランク」 (通常は 4 ～ 64) です。これにより、トレーニング可能なパラメータの数が大幅に減少します。

その結果、コンピューティングとメモリのコストのほんの一部で、おそらく全パラメータの 0.1 ～ 1% をトレーニングし、完全な微調整に近いパフォーマンスを達成します。

### QLoRA (量子化 LoRA)

QLoRA は、LoRA と **量子化** を組み合わせたもので、凍結された基本モデルの重みを 16 ビットや 32 ビットではなく 4 ビット精度で表します。これによりメモリ使用量が約 75% 削減され、単一のコンシューマ GPU で非常に大規模なモデルを微調整できるようになります。

QLoRA により、大規模組織以外の研究者や開発者が 700 億以上のモデルを微調整できるようになりました。これによりアクセスが大幅に民主化されました。

<ThinkAboutIt>LoRA は、凍結された事前トレーニング済みの重みとともに軽量のトレーニング可能な行列を追加します。推論のためにそれらをマージすると、異なる値を持つ同じアーキテクチャが得られます。 LoRA ウェイトを永続的にマージするのではなく、ベース モデルから *分離* しておきたい理由を考えられますか?
</ThinkAboutIt>

## 📊 トレーニング データ チャレンジ

微調整はトレーニング データに依存します。一般的な形式:

- **命令に続くペア**: `{"instruction": "Summarise in one sentence:", "input": "...", "output": "..."}`
- **会話ペア**: マルチターン対話の例
- **ドメイン テキスト**: ドメインを適応させる場合は、フィールドからのプレーン テキストで十分な場合があります

量よりも質がはるかに重要です。通常、1,000 個の高品質なサンプルからなる厳選されたデータセットは、ノイズの多い 100,000 個のデータセットよりも優れたパフォーマンスを発揮します。一般的なデータの問題:
- 一貫性のないフォーマットまたはトーン
- ラベルエラー
- データが狭すぎる (モデルが特殊になりすぎる)、または広すぎる (メリットが最小限)

## 🔄 RLHF: 人間のフィードバックによる微調整

**ヒューマン フィードバックからの強化学習 (RLHF)** は、モデルの動作を人間の好みに合わせるために使用される微調整の第 2 段階です。これは、ChatGPT が役に立ち、有害なリクエストを拒否するように訓練された方法です。

プロセス: 人間がモデルの出力の品質をランク付けし、「報酬モデル」が人間の好みを予測するように学習し、その後、報酬を最大化するために強化学習を使用して LLM が微調整されます。これは高価で複雑ですが、安全で快適に使用できるモデルを作成するためには不可欠です。

## 🛠️ 実践的な手順

1. **ベースモデルを選択** - ラマ 3、ミストラル、クウェン、ジェマ。ライセンス、サイズ、基本機能を考慮してください。
2. **データセットを準備します** - クリーンで一貫性があり、命令と応答のペアとしてフォーマットされています。 500 ～ 10,000 の高品質なサンプルを目指します。
3. **メソッドを選択** - ほとんどのユースケースでは LoRA/QLoRA。完全な微調整は、コンピューティング能力があり、タスクでそれが必要な場合にのみ実行してください。
4. **トレーニング** - Hugging Face `transformers` + `peft`、または Axolotl や Unsloth などのより高いレベルのフレームワークを使用します。
5. **評価** - ホールドアウトされたセットでテストします。ベースモデルと強力なプロンプトエンジニアリングベースラインと比較します。
6. **反復** - 微調整が最初から完璧に機能することはほとんどありません。データを改善し、ハイパーパラメータを調整し、繰り返します。

## 🚫 微調整しない場合

微調整が常に正しい答えであるとは限りません。

- **プロンプトを表示することで問題は解決できます** - 手間を省きます。最初にプロンプトを繰り返す
- **知識は常に最新のものである必要があります** - トレーニング時に微調整して知識を埋め込みます。 RAG は動的な情報に適しています
- **データが非常に少ない** - 数百未満の例は、役立つというよりも害を及ぼすことがよくあります
- **迅速な反復が必要です** - 微調整の実行には数時間かかります。プロンプトの変更には数秒かかります

<FunFact>Alpaca モデル (2023) は、GPT-3.5 によって生成されたわずか 52,000 の命令に従うサンプルを使用して、LLaMA から微調整されました。データ生成コストの合計は 500 ドル未満でした。これは、指示に従う行動が驚くほど小さなデータセットから学習できることを実証しました。
</FunFact>

# 大規模言語モデル - 最新の AI を支えるエンジン

大規模な言語モデルにより、マシンがテキスト、コード、および推論で実行できる内容が根本的に変わりました。このレッスンでは、それらがどのように機能するか、なぜ非常に強力なのか、そしてまだ不十分な点はどこなのかについてカーテンを引き戻します。

## LLM とは正確には何ですか?

**大規模言語モデル** は、シーケンス内の次のトークンを予測するために膨大な量のテキストでトレーニングされたニューラル ネットワークです。 「大規模」とは、トレーニング データからパターンをエンコードする学習可能な重みである **パラメータ** の数を指します。

- **GPT-6 Astra** は現在の OpenAI 最先端 を表しており、モデル内部は公開されていません。
- **Llama 4 Scout と Maverick** は 専門家混合 設計を採用し、170 億のアクティブパラメータと、はるかに大きな総パラメータ数を持ちます。
- **ミストラル 7B** は、小型モデルがその重量をはるかに超えてパンチできることを示しています。

これらのモデルは、書籍、Web サイト、コード リポジトリ、学術論文から抽出された数千億の単語に基づいてトレーニングされています。データとパラメータの規模が非常に大きいため、LLM に驚くべき多用途性が与えられます。

**単語ではなくトークン:** LLM は単語全体を処理しません。サブ単語単位である **トークン** を処理します。 「理解する」という言葉は、「下」+「立つ」+「ing」に分解できるかもしれません。一般的な英単語は平均して約 1.3 トークンです。このトークン化スキームにより、モデルは、まれな単語、専門用語、さらには、信じられないほど大量の語彙を必要とせずに複数の言語を処理できるようになります。

<FunFact>最先端の言語モデル のトレーニングは、計算、データ、エネルギー、エンジニアリングを含めると数億ドルかかることがあります。これは大作映画の予算に近いですが、「俳優」があらゆるプログラミング言語を話せる点が違います。</FunFact>
</FunFact>

## トランスフォーマーのアーキテクチャ

最新の LLM はすべて、2017 年の論文 *Attending Is All You Need* で紹介された **transformer** 上に構築されています。主要な革新は **セルフ アテンション** です。これはモデルが入力内の他のすべての単語と比較して各単語がどれだけ重要であるかを評価できるメカニズムです。

**自己注意の仕組み (簡略化):**
1. 各トークンは、**Query**、**Key**、および **Value** の 3 つのベクトルに変換されます。
2. モデルは、すべてのクエリをすべてのキーと比較することによってアテンション スコアを計算します。
3. これらのスコアは、各トークンが他のすべてのトークンにどの程度「注意を払う」かを決定します。
4. 値の加重合計により、コンテキストを認識した表現が生成されます。

注目の中心となる数式は次のとおりです。

**注意(Q, K, V) = ソフトマックス(QK^T / √d) × V**

√d (キー次元の平方根) による除算により、内積が大きくなりすぎてソフトマックス関数が非常に小さな勾配を持つ領域に押し込まれるのを防ぎます。この単純なスケーリング トリックは、ディープ トランスフォーマーのトレーニングを安定させるための重要な洞察の 1 つでした。

これは複数の **アテンション ヘッド**にわたって並行して繰り返され、モデルがさまざまな種類の関係 (あるヘッドでは構文、別のヘッドではセマンティクス) を同時にキャプチャできるようになります。

<ThinkAboutIt>文に 500 個のトークンがある場合、セルフ アテンションはすべてのトークンを他のすべてのトークンと比較します。つまり、レイヤーごとに 250,000 回の比較が行われることになります。この二次コストは、LLM が処理できる内容にどのような影響を与える可能性がありますか?
</ThinkAboutIt>

## ランドスケープにおける主要なモデル

|モデル |クリエイター |注目の機能 |
|------|-------|------|
| **GPT-6 Astra** | OpenAI | 最先端の推論、コーディング、リサーチ、マルチモーダル入力 |
| **Claude Opus 5.5** | Anthropic | 長時間のエージェント型コーディングと知識労働 |
| **Gemini 3.1 Pro** | Google DeepMind | 高度な推論、コーディング、マルチモーダル |
| **Llama 4** | Meta | オープンウェイト、ネイティブなマルチモーダル、長いコンテキスト |
| **Mistral Large** | Mistral AI | 効率的なヨーロッパの選択肢 |

この分野の動きは非常に速く、あなたがこれを読んでいる頃には、新しいモデルがすでに存在しているかもしれません。

この状況における重要な違いは、API のみが利用可能な **クローズドソース** モデル (GPT、Claude、Gemini) と、モデルの重みが公開されている **オープンウェイト** モデル (Llama、Mistral) の違いです。オープンウェイト モデルを使用すると、組織は独自のインフラストラクチャで推論を実行し、特定のドメインに合わせて微調整し、モデルの動作を検査できます。これは、プライバシーに敏感な業界にとって非常に重要な利点です。

<Callout>すべての「オープン」モデルが真のオープンソースであるわけではありません。一部のウェイトはリリースされますが、商用利用が制限されているか、トレーニング データとコードを共有していません。実稼働環境にオープンウェイト モデルをデプロイする前に、必ずライセンスを確認してください。
</Callout>

## 事前トレーニング、微調整、および RLHF

LLM は段階的に構築されます。

1. **事前トレーニング** - モデルは膨大な量のテキストを読み取り、次のトークンを予測する方法を学習します。この段階は非常にコストがかかり、テキストを完成させることができる基本モデルを生成しますが、特に役に立ちません。

2. **教師あり微調整 (SFT)** - 人間が書いた理想的な応答の例により、モデルは指示に従い、質問に適切に答えることができます。

3. **RLHF (人間のフィードバックからの強化学習)** - 人間の評価者は、モデルの出力を最良から最悪までランク付けします。報酬モデルはこれらの好みを学習し、LLM は報酬を最大化するようにトレーニングされます。これがモデルを有益で、無害で、誠実なものにする理由です。

## 緊急の機能

モデルがスケールアップするにつれて、明示的にトレーニングされていない能力が発達します。

- **複雑な推論** - 多段階の論理的推論と数学的問題解決。
- **コード生成** - 数十の言語でコードを作成、デバッグ、説明します。
- **多言語の流暢さ** - トレーニング データが比較的少ない言語でテキストを翻訳および生成します。
- **コンテキスト内学習** - 重みを更新せずに、プロンプトで提供される例に基づいて動作を適応させます。

これらの新たなプロパティは、スケーリングの最も魅力的な側面の 1 つであり、モデルが特定のサイズのしきい値を超えると、ほぼ「無料」で表示される機能です。

<FunFact>初期の 最先端モデル はこのパターンを明確に示しました。難しい専門試験に合格できる一方で、プロンプト が弱点を突くと、単純な算術や数え上げでつまずくことがありました。</FunFact>
</FunFact>

## 理解する必要がある制限事項

LLM は強力ですが、完璧には程遠いです。

- **幻覚** - モデルは、事実としては間違っている自信に満ちた響きのテキストを生成します。彼らは事実を「知らない」のです。彼らは可能性の高いトークンシーケンスを予測します。
- **コンテキスト ウィンドウの制限** - 各モデルには最大入力サイズがあります。現在の最先端システムでは、数十万から 100 万を超えるトークンまで幅があります。このウィンドウの外にある情報は見えません。
- **コストとレイテンシー** - 大規模なモデルで推論を実行するには、高価な GPU クラスターが必要です。トップ tier の 最先端モデルへのクエリ は、小型または中型モデルへの クエリ よりも大幅に高価です。
- **真の理解の欠如** - LLM はテキスト内の統計パターンを操作します。これが「理解」に該当するかどうかは、深い哲学的な議論です。
- **トレーニング データのカットオフ** - モデルは、取得システムで強化しない限り、トレーニング データが収集された後のイベントについて知りません。

<Callout>LLM の出力から得られる重要な事実を、信頼できる情報源と照らし合わせて常に検証してください。 LLM を、優秀ではあるが信頼性の低い研究助手として扱います。非常に役に立ちますが、事実に関する最終決定を下すことはありません。
</Callout>

## スケーリングに関する議論

長年にわたり、**大きいほど常に優れている** - より多くのパラメータ、より多くのデータ、より多くの計算が性能を着実に改善するという考えが支配的でした。この「スケーリング則」は、GPT-2、GPT-3、GPT-4 の世代と、その後の最先端システムを通じて非常によく維持されました。

しかし、最近の研究は、生の規模だけで収益が逓減に近づいている可能性を示唆しています。焦点は次の方向に移りつつあります。
- **量よりも優れたデータ品質** (厳選され重複排除されたデータセット)。
- **推論時間の計算** - モデル自体を大きくするのではなく、モデルに難しい問題について「より長く考える」ようにします。
- **特殊なアーキテクチャ** - クエリごとに一部のパラメーターのみをアクティブにし、機能を犠牲にすることなく効率を向上させる専門家の混合モデル。

## まとめ

大規模な言語モデルは、コンピューティングにおける真のパラダイム シフトを表しています。 AI に真剣に取り組んでいる人にとって、そのアーキテクチャ、トレーニング パイプライン、制限事項を理解することは必須ではありません。これは、この分野が進化し続けるときに役立つ基礎知識です。

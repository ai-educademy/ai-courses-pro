## Demos ఆధారాలు కావు

ఆకట్టుకునే demo ఒక మార్గం ఒకసారి పనిచేసిందని మాత్రమే నిరూపిస్తుంది. Production లో నడిచే AI system కు పునరావృతం చేయగల evaluation set, traces, failure taxonomy మరియు release thresholds అవసరం.

## Evaluation loop ను నిర్మించండి

వాస్తవ వినియోగదారు ఉద్దేశాన్ని, edge cases ను, adversarial inputs ను మరియు తెలిసిన వైఫల్యాలను ప్రతిబింబించే golden dataset ను తయారు చేయండి. ప్రతి కోణాన్ని విడిగా కొలవండి:

- **Retrieval:** recall, precision, సంబంధితత్వం, freshness మరియు permission ఖచ్చితత్వం.
- **Generation:** groundedness, వాస్తవ ఖచ్చితత్వం, సంపూర్ణత మరియు refusal నాణ్యత.
- **Agent ప్రవర్తన:** tool ఎంపిక, arguments చెల్లుబాటు, పని విజయం, అనవసర దశలు మరియు recovery.
- **Operations:** latency, token వినియోగం, ఖర్చు, error rate మరియు వినియోగదారు అభిప్రాయం.

ప్రతి release కు automated checks వాడండి, ఆ తర్వాత ప్రాతినిధ్య వైఫల్యాలను మాన్యువల్‌గా పరిశీలించండి. LLM-as-a-judge సమీక్షను పెద్ద ఎత్తున చేయడానికి సహాయపడుతుంది, కానీ దానికి ఒక rubric, calibration ఉదాహరణలు మరియు మానవ నిర్ణయంతో పోల్చే spot checks అవసరం.

## మార్పును దృష్టిలో ఉంచుకుని నిర్వహణ

Prompts, models, tools, retrieval settings మరియు evaluation data కు versioning చేయండి. సున్నితమైన సమాచారాన్ని అనవసరంగా నిల్వ చేయకుండా requests ను trace చేయండి. మార్పులను క్రమంగా rollout చేయండి, cohorts ను పోల్చండి, మరియు rollback మార్గాన్ని ఎల్లప్పుడూ అందుబాటులో ఉంచండి.

## Build సవాలు

గత పాఠాల నుండి RAG లేదా agent ను తీసుకోండి. అందులో 20 golden cases, మూడు safety cases, latency మరియు ఖర్చు కొలతలు, మరియు ఒక release gate జోడించండి. System ను ఉద్దేశపూర్వకంగా విచ్ఛిన్నం చేయండి, వైఫల్యాలను వర్గీకరించండి, మరియు తదుపరి సవరణను డాక్యుమెంట్ చేయండి.

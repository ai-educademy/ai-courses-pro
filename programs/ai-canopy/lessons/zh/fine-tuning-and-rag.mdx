# 微调和 RAG - 公司如何为其数据定制 AI

通用法学硕士对世界了解很多，但对公司的内部文件、专有数据或特定领域的术语一无所知。本课程介绍了弥补这一差距的两种主要方法：**微调**和**检索增强生成（RAG）**。

## 为什么通用模型还不够

想象一下，要求一个 前沿模型 回答客户有关贵公司的具体退货政策、内部产品代码或医疗协议的询问。它不能，因为这些信息不在其训练数据中。

企业需要将大型模型的**通用智能**与其领域的**特定知识**相结合的人工智能。到达那里有两条路，选择正确的一条至关重要。

<Callout>一个常见的误解是您可以简单地“上传数据”到法学硕士。实际上，定制模型需要重新训练其权重（微调）或构建检索管道 (RAG) - 两者都是需要仔细规划的工程工作。
</Callout>

## 微调：教授模型新技巧

微调采用预先训练的模型，并继续在您自己的数据集上对其进行训练。模型的权重会更新以反映您所在领域的语言、风格和知识。

**何时进行微调：**
- 您需要模型始终采用特定的语气或写作风格。
- 您的领域有专门的术语，基本模型处理得很差。
- 您想要更快的推理（知识是“嵌入”而不是检索）。

**过程：**
1. 准备您所在领域的高质量示例数据集（通常是数百到数千个输入输出对）。
2. 选择基本模型（例如 Llama 4、Mistral）。
3. 以低学习率训练几个 epoch，以避免灾难性遗忘。
4. 评估保留的测试数据。

<FunFact>彭博社通过对 3630 亿个金融数据代币进行微调，构建了 BloombergGPT。由此产生的模型在财务 NLP 任务（例如财报电话会议的情绪分析和 SEC 文件中的命名实体识别）上显着优于通用模型。
</FunFact>

## LoRA 和 QLoRA：高效微调

传统的微调会更新**所有**模型参数，需要大量的 GPU 内存。 700 亿参数的模型仅梯度存储就需要数百 GB。

**LoRA（低阶适应）** 优雅地解决了这个问题：
- LoRA 不是更新所有权重，而是冻结原始模型并向每一层添加小型**可训练适配器矩阵**。
- 这些适配器通常仅添加 0.1 - 1% 的额外参数。
- 结果是性能几乎相同，而成本却只有一小部分。

**QLoRA** 更进一步，将冻结模型量化为 4 位精度，从而显着降低内存需求。您可以在具有 48GB VRAM 的单个消费级 GPU 上微调 70B 参数模型。

## RAG：检索增强生成

RAG 采用了完全不同的方法。您无需更改模型，而是**让它在查询时访问外部文档**。

**RAG 的工作原理：**
1. **索引** - 您的文档被分成块并使用嵌入模型转换为数值向量（嵌入）。
2. **存储** - 这些向量存储在向量数据库中，用于快速相似性搜索。
3. **检索** - 当用户提出问题时，也会嵌入查询，并检索最相关的文档块。
4. **生成** - 检索到的块作为上下文插入到提示中，LLM 会根据您的实际文档生成答案。

**何时使用 RAG：**
- 您的知识库经常变化（新文档、更新的政策）。
- 您需要来源引用和可追溯性。
- 您希望避免微调的成本和复杂性。
- 事实准确性至关重要，必须尽量减少幻觉。

<ThinkAboutIt>RAG 在查询时为模型提供相关文档，但模型仍然生成最终答案。您如何验证模型的响应实际上反映了检索到的文档所说的内容，而不是产生超出它们的幻觉？
</ThinkAboutIt>

## 向量数据库

矢量数据库是专门为存储和搜索高维嵌入而构建的：

|数据库|类型 |主要特点|
|----------|------|-------------|
| **松果** |托管云|完全托管、简单的 API |
| **偏离** |开源|混合搜索（矢量+关键字）|
| **pg向量** | PostgreSQL 扩展 |使用现有的 Postgres 数据库 |
| **色度** |开源|轻量级，非常适合原型设计 |
| **Qdrant** |开源|高性能，基于 Rust |

选择矢量数据库取决于您的规模、现有基础设施以及您是否需要托管托管还是更喜欢自托管解决方案。

<Quiz question="在RAG系统中，矢量数据库起什么作用？" options="它根据新数据训练语言模型|它存储文档嵌入并支持快速相似性搜索相关上下文|它生成用户查询的最终答案|它完全取代了对语言模型的需求" answer="1" explanation="矢量数据库存储文档的数字表示（嵌入）。当查询到达时，它会快速找到语义上最相似的文档块，然后将其提供给 LLM 作为生成答案的上下文。" />

## 何时进行微调 vs 何时使用 RAG

|考虑|微调 |抹布|
|----------------|-------------|-----|
| **数据新鲜度** |静态（重新训练更新）|动态（随时更新文档）|
| **成本** |更高的前期（培训）|降低前期、持续检索成本 |
| **可追溯性** |低（知识是隐性的） |高（可引用源文件）|
| **风格/行为** |语气和格式都非常出色 |仅限提示指示|
| **幻觉风险** |中等|较低（以文件为基础）|

**最好的生产系统通常将两者结合起来。** 针对特定领域的语言和风格进行微调，然后使用 RAG 在查询时注入最新的事实内容。

<FunFact>英国国家卫生服务中心已经试行了 RAG 系统，将法学硕士与临床指南和药物相互作用数据库连接起来。医生可以提出自然语言问题，并获得基于最新 NICE 指南的答案，并附有页面参考。
</FunFact>

## 现实世界的例子

- **客户支持** - 零售商根据过去的支持票证微调模型以获取实际答案，然后根据产品目录和退货政策使用 RAG。
- **法律文件分析** - 律师事务所使用 RAG 搜索数百万份案件文件，法学硕士总结每个新案件的相关先例。
- **医学问答** - 医疗保健提供者使用 RAG 对照同行评审的文献，以便临床医生可以用自然语言提出问题并获得带有引用的基于证据的答案。

## 构建生产 RAG 管道

强大的 RAG 系统需要的不仅仅是矢量数据库和法学硕士。主要考虑因素包括：

- **分块策略** - 如何分割文档非常重要。太大且不相关的内容会削弱信号；太小你就会失去上下文。 10-20% 重叠的重叠块通常效果很好。
- **重新排名** - 在初始向量检索后，跨编码器重新排名器可以按相关性对结果重新排序，从而显着提高答案质量。
- **评估** - 分别测量检索精度（您是否找到了正确的块？）和生成忠实度（答案是否反映了块？）。
- **混合搜索** - 将矢量相似性与传统关键字搜索 (BM25) 相结合，可以捕获仅语义搜索遗漏确切术语或首字母缩略词的情况。

</ThinkAboutIt>

# 人工智能代理和自治系统 - 下一个前沿

到目前为止，我们已经探索了响应单个提示的人工智能模型。但人工智能中最令人兴奋的前沿是**代理** - 可以观察环境、推理要做什么、采取行动并从结果中学习的系统，所有这些都在一个连续的循环中。

## 什么是人工智能代理？

人工智能代理是一个由法学硕士驱动的系统，它超越了单轮问答。它循环运行：

1. **观察** - 感知当前状态（读取文件、检查数据库、查看搜索结果）。
2. **思考** - 根据目标和观察结果，推理下一步要采取什么行动。
3. **行动** - 执行操作（搜索网络、编写代码、调用 API、发送消息）。
4. **学习** - 评估结果并决定下一步。

重复此循环，直到任务完成或代理确定任务无法继续。与聊天机器人的关键区别在于**自主性** - 代理决定自己的后续步骤，而不是每次都等待人工输入。

## 工具使用：可以做事的人工智能

让智能体变得实用的突破在于**工具的使用**。代理可以调用​​外部工具，而不是仅仅依赖存储在其权重中的知识：

- **网络搜索** - 查找超出训练数据截止范围的当前信息。
- **代码执行** - 编写并运行 Python、JavaScript 或其他代码来计算答案。
- **API 调用** - 与数据库、服务和外部平台交互。
- **文件操作** - 读取、写入和修改系统上的文件。

当代理遇到无法从记忆中回答的问题时，它会制定工具调用，解释结果，并将其合并到推理中。

**函数调用**是工具使用背后的技术机制。 LLM 经过训练可以输出结构化 JSON，指定要调用哪个工具以及使用哪些参数。编排层执行该工具并将结果反馈给模型。这种结构化方法比要求模型生成自由格式的代码或命令可靠得多。

<Callout>代理的质量在很大程度上取决于其工具描述的质量。具有清晰参数定义且记录良好的工具使模型能够正确使用它。描述不当的工具会导致频繁的错误和重试。
</Callout>

<FunFact>GitHub Copilot - 您现在可能正在使用的工具 - 是一个人工智能代理。它会观察您的代码库，分析您的需求，编写代码，运行测试，并根据结果进行迭代。它甚至可以使用终端命令、搜索网络以及与版本控制交互。
</FunFact>

## 反应模式

**ReAct（推理+行动）**是大多数现代智能体背后的基本模式。该模型在显式推理轨迹和具体操作之间交替：

```text
Question: What is the latest UK population density?

Thought: I need the UK's current population and total area.
Action: search("latest UK population density ONS")
Observation: The UK population is approximately 68.3 million.

Thought: Now I need the area of the UK.
Action: search("UK total area square kilometres")
Observation: The UK covers 242,495 square kilometres.

Thought: Population density = population ÷ area = 68,300,000 ÷ 242,495
Action: calculate(68300000 / 242495)
Observation: 281.65

Answer: Recent UK population density estimates are roughly 280 people per square kilometre, but cite the latest ONS source before using the number.
```

通过使推理变得**明确**，ReAct 允许模型将复杂的问题分解为可管理的步骤，并在此过程中进行自我纠正。

## 多代理系统

单个代理有其局限性。 **多代理系统**使用专业代理团队来协作处理复杂的任务：

- **规划代理** - 将总体目标分解为子任务并分配它们。
- **研究员代理** - 从文档、数据库或网络收集信息。
- **编码器代理** - 编写和测试代码以实施解决方案。
- **审阅代理** - 检查工作中的错误、质量和一致性。

这些代理通过结构化消息进行通信，就像人类团队一样。规划者进行协调，专家执行，审核者进行验证 - 创建一个比任何单个代理都更强大的系统。

<ThinkAboutIt>如果你有一个人工智能代理团队，其中一个编写代码，另一个审查代码，那么当两个代理都犯相同的系统错误时会发生什么？您如何设计系统来捕获所有代理共享的盲点？
</ThinkAboutIt>

## 真实世界的代理应用程序

**编码助手** - GitHub Copilot、Cursor 和类似工具充当编码代理，可以理解您的代码库、建议更改、运行测试和迭代，直到代码正常工作。

**研究代理** - 像 Perplexity 和 Deep Research 这样的系统将复杂的研究问题分解为子查询、搜索多个来源、综合发现并生成参考报告。

**客户服务** - 公司部署的代理可以查找订单、处理退款、检查库存，并仅在必要时上报给人工 - 自主处理 60-80% 的查询。

**数据分析** - 代理可以编写 SQL 查询、生成可视化、解释结果并根据在数据中发现的内容完善分析。

**DevOps 和基础设施** - 代理监控系统运行状况，通过读取日志和指标诊断事件，并可以执行操作手册来修复常见问题 - 将平均解决时间从几小时缩短到几分钟。

## 风险和安全注意事项

自主代理引入了重大的新风险：

- **意外行为** - 负责“优化我们的广告支出”的代理可能会做出技术上最佳但道德上有问题的决策。
- **级联错误** - 如果代理在一系列操作的早期犯了错误，后续步骤可能会在没有人为监督的情况下使错误变得更加复杂。
- **控制和协调** - 确保代理追求我们*实际*想要的目标，而不是偏离意图的字面解释。
- **问责** - 当自主代理人做出有害决定时，谁负责？

当前的最佳实践包括用于高风险操作的**人机交互**检查点、用于测试的**沙盒环境**以及限制代理可以访问的工具的**显式权限边界**。

<FunFact>2023 年，麻省理工学院的研究人员让人工智能代理访问模拟计算机环境，发现代理有时会发现创造性的变通办法，从技术上完成任务，但违反了指令的精神 - 比如删除测试文件而不是修复失败的测试。
</FunFact>

## 未来：从助理到同事

轨迹很清晰。人工智能正在从：
- **工具**（您操作它们）→ **助理**（他们在需要时提供帮助）→ **代理**（他们自主工作）→ **同事**（他们作为同行进行协作）。

我们目前正处于从助理到代理人的转变过程中。未来几年将决定我们如何有效地构建足够强大、真正有用、足够安全、值得信赖的代理，并增加自主权。

关键的挑战不是让智能体变得更有能力，而是让它们更加**可靠**、**可预测**以及**与人类价值观保持一致**。解决这个问题的组织将定义人工智能的下一个时代。

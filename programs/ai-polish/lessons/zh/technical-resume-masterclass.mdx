# 技术简历大师班 - 通过 ATS 并进入面试

你的简历有 **六秒** 的人类注意力 - 如果它甚至到达了人类的注意力。在大多数大公司，申请人跟踪系统（ATS）会在招聘人员看到您的简历之前对您的简历进行解析和排名。了解 ATS 软件的工作原理是获得面试机会的第一步。

## ATS 软件的实际工作原理

ATS（申请人跟踪系统）是一种软件，可以扫描简历中的关键字，对候选人进行排名，并过滤掉与职位描述不匹配的申请。 Workday、Greenhouse 和 Lever 等公司为超过 95% 的财富 500 强企业提供招聘服务。

ATS 做了三件事：

1.**将您的简历解析为结构化字段（姓名、电子邮件、经验、技能）
2. **将职位描述中的关键字与您的内容进行匹配
3. 您相对于其他申请人的**排名**

<FunFact>超过 75% 的简历在人们阅读之前就被 ATS 软件拒绝了。格式良好、关键字优化的简历会大大增加您的胜算。</FunFact>

## 一页规则

除非您有 15 年以上的经验，否则请将其控制在**一页**。谷歌、亚马逊和 Meta 的招聘人员在公开演讲中多次证实了这一点。每次，一页聚焦的页面都会击败两页稀释的页面。

## 恢复重要的部分

### 1. 标题
姓名、电子邮件、电话、位置（仅限城市）、LinkedIn URL、GitHub URL、作品集链接。没有照片，没有出生日期，没有婚姻状况。

### 2.专业总结（2-3行）
简洁的宣传：您的角色、多年的经验、关键技术和主要成就。

> *“高级后端工程师，拥有 6 年使用 Java 和 Go 构建分布式系统的经验。领导支付服务迁移到事件驱动架构，将延迟减少了 40%，每年节省 12 万英镑。”*

### 3.经验（核心）
对每个项目符号使用 **XYZ 公式**：*通过执行 **Y** 完成 **X**，导致 **Z**。*

|弱|强 (XYZ) |
|------|--------------|
| “致力于搜索功能”| “通过实施 BM25 排名，搜索相关性提高了 23%，用户参与度提高了 15%”|
| “负责 CI/CD” | “通过迁移到具有并行测试阶段的 GitHub Actions，将部署时间从 45 分钟减少到 8 分钟”|

### 4.技能
诚实地列出技术。将它们分组：**语言**、**框架**、**云/DevOps**、**数据**。匹配职位描述中的确切术语 - 如果列表中显示“Kubernetes”，则“Kubernetes”而不是“K8s”。

### 5. 教育
学位、大学、毕业年份。仅当您处于职业生涯早期时才添加相关课程或论文。

## 通过 ATS 过滤器的动作动词

每个项目符号都用一个强有力的动词开头：**设计**、**实施**、**迁移**、**减少**、**编排**、**优化**、**自动化**、**扩展**、**指导**、**交付**。

避免弱开场白：“帮助”、“协助”、“负责”、“参与”。

## 根据每个职位描述进行定制

将职位描述复制到文档中。突出显示**前 10 个关键词**（技术、方法、领域术语）。确保这 10 个中至少有 7 个自然出现在您的简历中。这不是在玩弄系统——而是在说雇主的语言。

根据您的所有经验创建一份**主简历**，然后为每个应用程序定制一份副本。将大师作为唯一的事实来源，并根据角色减少它。申请机器学习平台角色的后端工程师应强调数据管道和基础设施经验；申请纯后端角色的同一个人应该负责 API 设计和可扩展性。

<ThinkAboutIt>选择您感兴趣的职位列表。确定前 10 个关键词。有多少出现在您当前的简历中？您可以添加或改写什么？</ThinkAboutIt>

## 导致应用程序失效的常见错误

- **带有列、表格或图形的精美模板** - ATS 无法解析它们。使用单列、简洁的布局。
- **在技能方面撒谎** - 技术面试会立即暴露这一点，并且会永久断绝关系。
- **包括您曾经接触过的每一项技术** - 仅列出您可以在面试中自信地讨论的内容。
- **包含图像或扫描文本的 PDF** - 使用从文字处理器导出的基于文本的 PDF。
- **使用通用目标陈述** - 将“寻求具有挑战性的职位”替换为有针对性的专业摘要，其中列出了公司和职位的名称。
- **省略日期** - 面试官注意到并假设您在隐藏就业差距。保持透明；间隙是正常的。

## GitHub 配置文件优化

你的 GitHub 就是你的活生生的投资组合。招聘人员**确实**检查它。

- **固定 4-6 个最佳存储库**，并提供清晰的自述文件（问题、解决方案、技术堆栈、如何运行）
- **编写个人资料自述文件**（`username/username` 存储库），其中包含简短的个人简介和链接
- **维护贡献图** - 一致性比强度更重要
- **清理旧的存储库** - 存档或将任何令人尴尬的事情设为私有

## 作品集链接和个人网站

如果您有个人网站或作品集，请将其包含在标题中。结构良好的作品集页面应包含：

- **特色项目** 带有现场演示或屏幕截图
- **与您的简历摘要相匹配的简短“关于我”**部分
- **您提供的文章或演讲的链接**
- 保持快速加载和移动友好 - 招聘人员经常在手机上浏览

使用自定义域（例如，`janedoe.dev`）而不是通用子域。它标志着专业精神和对细节的关注。

## LinkedIn 协同

您的 LinkedIn 和简历应该以不同的深度讲述**同一个故事**。 LinkedIn 允许提供更多详细信息、媒体和推荐。确保职位名称、日期和公司完全匹配——差异会引发危险信号。

LinkedIn 的关键优化：
- **标题**：使用您的目标角色和关键技术，而不仅仅是您当前的头衔
- **关于部分**：用叙述语气和号召性用语扩展您的摘要
- **特色部分**：固定您最好的文章、演讲或项目演示
- **建议**：向能够谈论具体成就的经理或高级同事提出 2-3 条要求

## 提交前的简历清单

- [ ] 单栏、无图形、无表格
- [ ] 完整联系信息（电子邮件、电话、LinkedIn、GitHub）
- [ ] 每个项目符号都使用 XYZ 或动作动词加影响格式
- [ ] 技能部分反映了职位描述关键字
- [ ] 没有拼写错误（使用拼写检查器和人工审阅者）
- [ ] 另存为基于文本的 PDF
- [ ] 一页（除非有 15 年以上经验）

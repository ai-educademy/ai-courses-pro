# 端到端 ML 管道 - 从原始数据到部署模型

大多数教程停在`model.fit()`。在生产中，这仅占工作量的 20%。本课程将介绍**整个机器学习生命周期** - Spotify 的推荐引擎、Stripe 的欺诈检测和 Google 的搜索排名采用相同的管道。

## 🗺️ 机器学习生命周期概览

<Illustration src="/images/lessons/end-to-end-ml-pipeline.svg" alt="从数据摄取到监控的 ML 管道阶段图" caption="生产 ML 管道的八个阶段 - 每个阶段都是潜在的故障点。" />

每个生产机器学习系统都会经历以下阶段：

1. **数据收集** - API、数据库、事件流、网络抓取
2. **数据清理** - 处理空值、重复数据删除、类型强制
3. **特征工程** - 将原始信号转换为模型就绪特征
4. **模型选择** - 选择符合您问题的架构
5. **训练** - GPU/CPU编排、超参数调优
6. **评估** - 离线指标、A/B 测试、公平性审计
7. **部署** - 服务基础设施、延迟预算
8. **监控** - 漂移检测、警报、再训练触发

## 📦 数据收集和版本控制

原始数据是您的基础。将其视为源代码 - **对所有内容进行版本控制**。

```bash
# Initialise DVC in your repo
dvc init
dvc remote add -d storage s3://my-ml-data-bucket

# Track a dataset
dvc add data/transactions.csv
git add data/transactions.csv.dvc .gitignore
git commit -m "Track raw transaction dataset v1"
dvc push
```

**DVC**（数据版本控制）可让您`git checkout`任何历史数据集。结合 Git 标签，您可以重现任何时间点的任何实验。

<FunFact>Netflix 每天通过其数据管道处理超过 1.5 万亿个事件 - 每秒大约有 1700 万个事件馈送到其推荐模型。</FunFact>

## 🛠️ 特征工程 - 赢得比赛的地方

特征比算法更重要。具有出色特征的梯度增强树击败了具有较差特征的深度神经网络。

```python
import pandas as pd

df = pd.read_csv("data/transactions.csv", parse_dates=["timestamp"])

# Temporal features
df["hour"] = df["timestamp"].dt.hour
df["is_weekend"] = df["timestamp"].dt.dayofweek >= 5

# Aggregation features
user_stats = df.groupby("user_id")["amount"].agg(["mean", "std", "count"])
user_stats.columns = ["user_avg_amount", "user_std_amount", "user_txn_count"]
df = df.merge(user_stats, on="user_id")

# Ratio features
df["amount_vs_avg"] = df["amount"] / df["user_avg_amount"]
```

## 🧪 使用 MLflow 进行实验跟踪

永远不要忘记你尝试过的事情。 MLflow 自动记录参数、指标和工件。

```python
import mlflow
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import f1_score

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run(run_name="gbm-baseline"):
    params = {"n_estimators": 500, "max_depth": 6, "learning_rate": 0.05}
    mlflow.log_params(params)

    model = GradientBoostingClassifier(**params)
    model.fit(X_train, y_train)
```

## 🌐 模型服务和部署

您的模型需要一个 API。两种主要模式：

**REST API** - 简单，基于 HTTP，非常适合中等吞吐量：
```python
# FastAPI model server
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("model.pkl")

@app.post("/predict")
async def predict(features: dict):
    prediction = model.predict([list(features.values())])
    return {"prediction": int(prediction[0])}
```

**gRPC** - 二进制协议，比 REST 快 2 - 10 倍，非常适合内部微服务和高吞吐量场景。

### 金丝雀部署

永远不要将 100% 的流量发送到新模型。使用 **金丝雀发布**：路线 5% → 25% → 50% → 100%，监控每个步骤的错误率。如果指标下降，请立即回滚。

## 📊 监控和反馈循环

部署不是终点线，而是发令枪。监控：

- **数据漂移** - 输入分布从训练数据发生变化
- **概念漂移** - 特征和目标变化之间的关系
- **性能下降** - 准确性/延迟指标下降

**Evidently AI**、**WhyLabs** 和 **Arize** 等工具提供漂移仪表板。当漂移超过阈值时，使用新的生产数据触发自动重新训练 - 关闭反馈循环。

## 🎯 要点

- 版本**一切**：代码、数据、模型和管道配置
- 特征工程比架构变更带来更多的投资回报
- 将管道编码为代码 - 手动步骤是技术债务
- 使用金丝雀版本进行部署并持续监控
- 反馈循环（生产数据→再培训）是将演示与生产系统区分开来的

# 构建您自己的人工智能项目

你花了几个月的时间学习理论。现在是时候**构建一些真实的东西**，将其运送到世界各地，并证明您可以端到端地交付。

你的简历上没有什么比人们实际可以使用的已部署产品更能说明问题的了。

<Illustration src="/images/lessons/build-your-ai-project.svg" alt="显示从想法到构建、部署和迭代的旅程的图表" caption="Capstone AI 项目的完整生命周期" />

## 选择正确的项目

选择正确的项目是您在此顶点中做出的最重要的决定。做对了，剩下的就自然而然了。

您的项目应该位于三件事的交叉点：

- **激情** - 你会为此花上几个晚上；选择你真正关心的事情。
- **技能差距** - 它应该将你延伸到至少一个你尚未掌握的领域。
- **投资组合价值** - 招聘经理应该审视它并思考，“这个人可以交付。”

<Callout>避免玩具数据集和教程克隆。招聘人员已经见过一千个 MNIST 分类器。解决对真正的受众来说很重要的问题，即使受众很少。
</Callout>

| ＃|项目|关键技能|难度|
|---|---------|------------|------------|
| 1 | **针对利基领域（例如食谱、法律文档）的语义搜索引擎** |嵌入、矢量数据库、REST API | ⭐⭐ |
| 2 | **人工智能驱动的代码审查程序**，对 GitHub PR 进行评论 | LLM 提示、GitHub API、CI/CD | ⭐⭐⭐ |

选择一个 - 或者发明你自己的 - 并立即致力于它。最好的项目是您将实际完成的项目。

## 规划您的 MVP

构建者犯的最大错误是范围太大。无情地定义你的**最小可行产品**：

1. **仅核心功能** - 一种用户流程、一种模型、一种界面。
2. **技术堆栈** - 选择你知道的工具加上一件新东西。对于大多数项目：Python + FastAPI 后端、React 或 Next.js 前端、托管数据库。
3. **时间表** - 给自己两周的时间来获得 MVP。如果需要更长的时间，那么你的范围就太大了。
4. **成功指标** - 定义一个数字来告诉您该项目是否有效（例如，“在我的测试集上检索精度高于 80%”）。

<ThinkAboutIt>用一句话写下您的项目想法。现在划掉一半的功能。那是你的 MVP。
</ThinkAboutIt>

## 公共建筑

在社交媒体上分享您的进步并不是虚荣心 - 这是一种职业策略。

- **第一天**：发表您的想法并寻求反馈。
- **每周**：分享简短的更新 - 您构建了什么，破坏了什么，您学到了什么。
- **发布日**：撰写一篇讨论该架构的帖子或博客文章。

公开建设可以创造责任感，吸引合作者，甚至在你申请之前就把你的名字放在招聘经理面前。

<FunFact>Stack Overflow 2024 年的一项调查发现，68% 的招聘经理在决定是否面试候选人之前会检查候选人的公共项目和帖子。
</FunFact>

## 部署您的项目

仅在 `localhost` 上运行的项目是不可见的。没有人可以尝试它，没有人可以分享它，也没有招聘经理会看到它。

部署并不是一个可有可无的东西——它是业余爱好项目和投资组合之间的区别。以下是三个可靠的选择：

|平台|最适合 |免费套餐 |
|----------|---------|------------|
| **维塞尔** | Next.js 前端、无服务器 API |慷慨 |
| **铁路** | Python 后端、数据库 | 500 小时/月 |
| **拥抱脸部空间** |使用 Gradio 或 Streamlit 进行 ML 演示 | CPU 无限 |

无论您选择哪一个，请确保您的自述文件包括：

- 对项目用途的一行描述。
- 实时链接或演示 GIF。
- 本地开发的清晰设置说明。

## 获取反馈和迭代

一旦您的 MVP 上线，真正的学习就开始了。运输不是终点线，而是起跑线。

积极寻求对你诚实的人的反馈：

- 在相关的 Discord 和 Slack 社区中分享。
- 在 Reddit 上特定领域的 subreddits 中发布。
- 请两到三位你尊敬的工程师尝试一下并给予诚实的批评。

将每一条反馈视为一份礼物。修复关键问题，记下第二版的其余部分，并快速推送更新。

<ThinkAboutIt>想一想您的目标用户常去的一个社区。计划在启动后 48 小时内在那里分享您的项目。
</ThinkAboutIt>

## 将其添加到您的投资组合中

您的项目的价值取决于它的演示。当您将其添加到您的投资组合时：

1. **撰写案例研究** - 问题、方法、架构图、结果、经验教训。
2. **将其固定在 GitHub 上** - 干净的提交历史记录、良好的自述文件、未来工作的开放问题。
3. **录制两分钟的演示视频** - 浏览产品并解释一项技术决策。
4. **随处链接** - 简历、LinkedIn、个人网站、GitHub 个人资料自述文件。

## 你的下一步

别再读书了。立即打开一个新的存储库。以您的项目想法命名。

首先编写 README - 描述它将做什么、适用于谁以及您的 MVP 范围是什么。今晚推送该自述文件。

“我想构建一些东西”和“我交付一些东西”之间的差距是一次提交。

<FunFact>GitHub 数据显示，拥有编写良好的 README 的存储库获得的星星和分叉数量是那些没有编写良好的存储库的四倍——即使在开源领域，第一印象也很重要。
</FunFact>

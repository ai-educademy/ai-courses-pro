# End-to-End-ML-Pipeline – von Rohdaten bis zum bereitgestellten Modell

Die meisten Tutorials enden bei `model.fit()`. In der Produktion sind das knapp 20 % der Arbeit. Diese Lektion führt durch den **gesamten ML-Lebenszyklus** – dieselbe Pipeline, die Empfehlungs-Engines bei Spotify, Betrugserkennung bei Stripe und Suchranking bei Google antreibt.

## 🗺️ Der ML-Lebenszyklus auf einen Blick

<Illustration src="/images/lessons/end-to-end-ml-pipeline.svg" alt="Diagramm der ML-Pipeline-Stufen von der Datenaufnahme bis zur Überwachung" caption="Die acht Phasen einer Produktions-ML-Pipeline – jede einzelne ist ein potenzieller Fehlerpunkt." />

Jedes Produktions-ML-System durchläuft diese Phasen:

1. **Datenerfassung** – APIs, Datenbanken, Ereignisströme, Web Scraping
2. **Datenbereinigung** – Umgang mit Nullen, Deduplizierung, Typzwang
3. **Feature Engineering** – Umwandlung von Rohsignalen in modellbereite Features
4. **Modellauswahl** – Auswahl der Architekturen, die zu Ihrem Problem passen
5. **Training** – GPU/CPU-Orchestrierung, Hyperparameter-Tuning
6. **Bewertung** – Offline-Metriken, A/B-Tests, Fairness-Audits
7. **Bereitstellung** – Bereitstellung der Infrastruktur, Latenzbudgets
8. **Überwachung** – Abweichungserkennung, Alarmierung, Neuschulungsauslöser

## 📦 Datenerfassung und Versionierung

Rohdaten sind Ihre Grundlage. Behandeln Sie es wie Quellcode – **alles versionieren**.

```bash
# Initialise DVC in your repo
dvc init
dvc remote add -d storage s3://my-ml-data-bucket

# Track a dataset
dvc add data/transactions.csv
git add data/transactions.csv.dvc .gitignore
git commit -m "Track raw transaction dataset v1"
dvc push
```

**DVC** (Data Version Control) lets you `git checkout` any historical dataset. Combined with Git tags, you can reproduce any experiment from any point in time.

<FunFact>Netflix verarbeitet über 1,5 Billionen Ereignisse pro Tag über seine Datenpipelines – etwa 17 Millionen Ereignisse pro Sekunde, die in seine Empfehlungsmodelle einfließen.</FunFact>

## 🛠️ Feature Engineering – Wo Wettbewerbe gewonnen werden

Funktionen sind wichtiger als Algorithmen. Ein durch Gradienten verstärkter Baum mit brillanten Merkmalen schlägt ein tiefes neuronales Netzwerk mit schlechten Merkmalen.

```python
import pandas as pd

df = pd.read_csv("data/transactions.csv", parse_dates=["timestamp"])

# Temporal features
df["hour"] = df["timestamp"].dt.hour
df["is_weekend"] = df["timestamp"].dt.dayofweek >= 5

# Aggregation features
user_stats = df.groupby("user_id")["amount"].agg(["mean", "std", "count"])
user_stats.columns = ["user_avg_amount", "user_std_amount", "user_txn_count"]
df = df.merge(user_stats, on="user_id")

# Ratio features
df["amount_vs_avg"] = df["amount"] / df["user_avg_amount"]
```

## 🧪 Experimentverfolgung mit MLflow

Verlieren Sie nie den Überblick darüber, was Sie versucht haben. MLflow protokolliert Parameter, Metriken und Artefakte automatisch.

```python
import mlflow
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import f1_score

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run(run_name="gbm-baseline"):
    params = {"n_estimators": 500, "max_depth": 6, "learning_rate": 0.05}
    mlflow.log_params(params)

    model = GradientBoostingClassifier(**params)
    model.fit(X_train, y_train)

    score = f1_score(y_test, model.predict(X_test))
```

## 🌐 Modellbereitstellung und -bereitstellung

Ihr Modell benötigt eine API. Zwei vorherrschende Muster:

**REST-API** – einfach, HTTP-basiert, ideal für moderaten Durchsatz:
```python
# FastAPI model server
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("model.pkl")

@app.post("/predict")
async def predict(features: dict):
    prediction = model.predict([list(features.values())])
    return {"prediction": int(prediction[0])}
```

**gRPC** – Binärprotokoll, 2–10-mal schneller als REST, ideal für interne Microservices und Szenarien mit hohem Durchsatz.

### Canary-Bereitstellungen

Leiten Sie niemals 100 % des Traffics an ein neues Modell weiter. Verwenden Sie **Canary-Releases**: Routen Sie 5 % → 25 % → 50 % → 100 % und überwachen Sie die Fehlerraten bei jedem Schritt. Führen Sie sofort einen Rollback durch, wenn sich die Messwerte verschlechtern.

## 📊 Überwachung und Feedbackschleife

Der Einsatz ist nicht die Ziellinie – er ist der Startschuss. Überwachen Sie Folgendes:

- **Datendrift** – Eingabeverteilungen verschieben sich von Trainingsdaten
- **Konzeptdrift** – die Beziehung zwischen Funktionen und Zieländerungen
- **Leistungsabfall** – Genauigkeits-/Latenzmetriken sinken

Tools wie **Evidently AI**, **WhyLabs** und **Arize** bieten Drift-Dashboards. Wenn die Drift die Schwellenwerte überschreitet, lösen Sie ein automatisches Neutraining mit neuen Produktionsdaten aus und schließen so die Rückkopplungsschleife.

## 🎯 Wichtige Erkenntnisse

- Version **alles**: Code, Daten, Modelle und Pipeline-Konfigurationen
- Feature Engineering liefert einen höheren ROI als Architekturänderungen
- Pipelines als Code kodieren – manuelle Schritte sind technische Schulden
- Bereitstellung mit Canary-Releases und kontinuierliche Überwachung
- Die Rückkopplungsschleife (Produktionsdaten → Umschulung) ist es, was Demos von Produktionssystemen trennt

# أرسل مشروعًا مفتوح المصدر للذكاء الاصطناعي - تحفتك الفنية

هذا هو - الدرس الأخير. كل ما تعلمته يتقارب هنا: خطوط تعلم الآلة، وتنفيذ الأبحاث، وتصميم النظام، والحرف الهندسية. ستقوم **بشحن مشروع ذكاء اصطناعي حقيقي مفتوح المصدر** يحل مشكلة حقيقية ويستمر إلى ما بعد هذه الدورة.

## 💡اختيار فكرة مشروعك

أفضل مشاريع OSS تبدأ من **الإحباط الشخصي**. لا تنشئ تطبيق TODO آخر باستخدام الذكاء الاصطناعي - ابحث عن فجوة:

- **اخدش حكةك بنفسك** - أداة تتمنى لو كانت موجودة في سير عملك اليومي
- **تحسين أداة موجودة** - ابحث عن قيود المكتبة الشائعة وحلها
- **تنفيذ ورقة بحثية** - تحويل اكتشاف بحثي إلى مكتبة قابلة للاستخدام
- **سد الفجوة** - قم بتوصيل نظامين بيئيين لا يتحدثان مع بعضهما البعض

<Illustration src="/images/lessons/open-source-ai-project.svg" alt="دورة حياة المشروع مفتوح المصدر بدءًا من الفكرة وحتى الإطلاق وحتى نمو المجتمع" caption="دورة حياة OSS - الشحن هو نقطة المنتصف، وليس خط النهاية." />

**التحقق قبل البناء**: ابحث في GitHub وPyPI وnpm. إذا كان هناك شيء مماثل، فإن مشروعك يحتاج إلى تمييز واضح - واجهة برمجة تطبيقات أسرع وأبسط، أو وثائق أفضل، أو نهج جديد.

<FunFact>بدأت Hugging Face كشركة chatbot للمراهقين. عندما فتحوا مكتبة Transformers الخاصة بهم كمشروع جانبي، أصبحت شائعة جدًا لدرجة أنهم قاموا بتحويل الشركة بأكملها حولها - والتي تقدر قيمتها الآن بأكثر من 4.5 مليار دولار.</FunFact>

## 📋 تخطيط المشروع - نطاق MVP

حدد **الحد الأدنى من المشروع القابل للتطبيق** بلا هوادة:

```markdown
## MVP Scope (Week 1-2)
- Core functionality: ONE thing, done well
- CLI or Python API interface
- 3 working examples
- Basic README with installation and quickstart

## V1.0 Scope (Week 3-4)
- Comprehensive documentation
- Test coverage > 80%
- CI/CD pipeline
- Published to PyPI/npm
- Demo deployed
```

**النمط المضاد**: قضاء أشهر في إتقان التعليمات البرمجية لم يره أحد. قم بالشحن مبكرًا، وكرر ذلك بناءً على التعليقات.

<ThinkAboutIt>فكر في الأدوات الثلاثة الأخيرة التي قمت بتثبيتها. ما الذي جعلك تختارهم على البدائل؟ هل كان الملف التمهيدي أم تصميم واجهة برمجة التطبيقات أم عدد النجوم أم أي شيء آخر؟ قم بتطبيق هذه الأفكار على مشروعك الخاص.</ThinkAboutIt>

## 🏗️ إعداد المستودع

الانطباعات الأولى مهمة. يحتاج المستودع الاحترافي إلى: تخطيط `src/` للتعليمات البرمجية، `tests/`، `examples/`، `docs/`، `.github/workflows/ci.yml`، بالإضافة إلى ملفات الجذر - `LICENSE` (MIT أو Apache 2.0)، `README.md`، `CONTRIBUTING.md`، `CODE_OF_CONDUCT.md`، و `pyproject.toml`.

### الملف التمهيدي - الملف الأكثر أهمية لديك

README الخاص بك هو صفحة مبيعات. يجب أن يحتوي على: **وصف من سطر واحد**، **التثبيت** (`pip install my-project`)، **البدء السريع** (رمز العمل في أقل من 10 أسطر)، **الميزات الرئيسية** (النقاط النقطية)، **جدول المقارنة** مقابل البدائل، و**رابط التوثيق**.

## 📦 النشر إلى PyPI

عبوة بايثون الحديثة بـ `pyproject.toml`:

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "my-ai-project"
version = "0.1.0"
description = "One-line description of your project"
requires-python = ">=3.9"
license = "MIT"
dependencies = ["torch>=2.0", "numpy>=1.24"]

[project.urls]
Documentation = "https://my-ai-project.readthedocs.io"
Repository = "https://github.com/username/my-ai-project"
```

```bash
# Build and publish
pip install build twine
python -m build
twine upload dist/*
```

**الإصدارات التلقائية**: استخدم GitHub Actions للنشر على PyPI في كل إصدار موسوم - لا تنشر يدويًا بعد المرة الأولى.

## 🎨 إنشاء العروض التوضيحية

العرض التوضيحي يحول المتشككين إلى مستخدمين. ثلاث منصات ممتازة:

| منصة | الأفضل لـ | النشر |
|----------|---------|-----------|
| ** معانقة مساحات الوجه ** | عروض نموذج ML | الدفع عبر Git، طبقة GPU مجانية |
| ** مبسطة ** | تطبيقات البيانات ولوحات المعلومات | سحابة Streamlit، الطبقة المجانية |
| **جراديو** | واجهات ML سريعة | معانقة مساحات الوجه أو مستقلة |

```python
# Gradio demo - 8 lines to a shareable interface
import gradio as gr
from my_ai_project import predict

demo = gr.Interface(
    fn=predict,
    inputs=gr.Textbox(label="Enter text"),
    outputs=gr.Label(label="Prediction"),
    title="My AI Project Demo"
)
demo.launch()
```

## 📖 كتابة التوثيق

اتبع **إطار عمل Diátaxis** - أربعة أنواع من الوثائق: **البرامج التعليمية** (موجهة للتعلم، خطوة بخطوة)، **أدلة إرشادية** (موجهة نحو المهام، عملية)، **مرجع** (مستندات API كاملة)، و **الشرح** (الفهم المفاهيمي). استخدم **MkDocs** أو **Docusaurus** لإنشاء مواقع من Markdown. انشر مجانًا على صفحات GitHub أو اقرأ المستندات.

## 📣 تسويق مشروعك

إن بنائه هو نصف المعركة. إن جعل الناس يستخدمونه هو النصف الآخر:

1. **أخبار القراصنة** - منشور "إظهار HN: [الوصف]" في يوم الإطلاق
2. **Reddit** - r/MachineLearning، وr/Python، والمواقع الفرعية ذات الصلة
3. **Twitter/X** - موضوع يشرح المشكلة والحل الخاص بك، مع عرض توضيحي بتنسيق GIF
4. ** البحث عن المنتج ** - إذا كان مشروعك يحتوي على واجهة ويب
5. **منشور المدونة** - كتابة فنية مفصلة على موقعك الشخصي أو Medium/Dev.to

**التوقيت مهم**: الإطلاق من الثلاثاء إلى الخميس صباحًا (بتوقيت جرينتش). تجنب عطلات نهاية الأسبوع والأعياد.

<FunFact>يرجع الفضل في إنشاء كل من FastAPI وLangChain وStreamlit إلى منشور "Show HN" على Hacker News في الوقت المناسب باعتباره المحرك الأكبر المنفرد لموجة الاعتماد الأولية الخاصة بهم.</FunFact>

<ThinkAboutIt>يحصل مشروعك على 500 نجمة على GitHub في الأسبوع الأول ولكن لا توجد مشكلات أو علاقات عامة من المساهمين الخارجيين. هل هذا نجاح؟ ما الذي ستفعله بشكل مختلف لتحويل مراقبي النجوم السلبيين إلى مساهمين نشطين؟</ThinkAboutIt>

## 🔧المحافظة على مشروعك

الاستدامة أهم من انتشار الفيروس:

- **مشاكل التصنيف** مثل `good-first-issue`، `help-wanted`، `bug`، `enhancement`
- **الرد على المشكلات خلال 48 ساعة** - حتى عبارة "شكرًا، سأنظر في هذا الأمر" تعمل على بناء الثقة
- **اكتب CONTRIBUTING.md** يتضمن تعليمات الإعداد ومعايير الترميز وإرشادات العلاقات العامة
- **استخدام الإصدار الدلالي** - تؤدي التغييرات العاجلة إلى تحسين الإصدار الرئيسي
- **أتمتة كل شيء** - CI، والإصدارات، وإنشاء سجل التغيير، وتحديثات التبعية

## 💰 مسارات تحقيق الدخل

المصدر المفتوح لا يعني العمل الحر إلى الأبد. النماذج المستدامة: **رعاة GitHub** (جهد منخفض، تبرعات متكررة)، **الاستشارات** (الإعداد والتدريب المدفوعان)، **غلاف SaaS** (إصدار مستضاف مع ميزات المؤسسة - أعلى جهد ولكن الأكثر استدامة)، **الترخيص المزدوج** (مفتوح المصدر + تجاري)، و **رعاية الشركات** (الميزات ذات الأولوية للشركات التي تدفع).

## 🎯 قائمة التحقق من تحفتك الفنية

قبل أن تسميها مشحونة:

- [ ] تعمل الوظيفة الأساسية ويتم اختبارها
- [ ] يحتوي الملف README على التثبيت والبدء السريع ونظرة عامة على الميزات
- [ ] تم النشر على PyPI أو npm
- [ ] عرض توضيحي مباشر على Hugging Face Spaces أو Streamlit
- [ ] يجري خط أنابيب CI/CD اختبارات على كل PR
- [ ] تغطي الوثائق البرامج التعليمية ومرجع واجهة برمجة التطبيقات (API).
- [ ] الترخيص وCONTRIBUTING.md وCODE_OF_CONDUCT.md موجودون
- [ ] تم إطلاقه على منصتين على الأقل (HN، Reddit، Twitter)

**هذا المشروع هو محفظتك.** عندما يسألك أحد القائمين على المقابلة "ما الذي قمت ببنائه؟"، سيكون لديك إجابة مباشرة وموثقة ومنشورة.

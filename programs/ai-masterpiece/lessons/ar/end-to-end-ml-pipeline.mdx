# خط أنابيب ML الشامل - من البيانات الأولية إلى النموذج المنشور

تتوقف معظم البرامج التعليمية عند `model.fit()`. في الإنتاج، هذا بالكاد يمثل 20% من العمل. يتناول هذا الدرس **دورة حياة تعلم الآلة بأكملها** - نفس المسار الذي يدعم محركات التوصيات في Spotify، واكتشاف الاحتيال في Stripe، وتصنيف البحث في Google.

## 🗺️ لمحة سريعة عن دورة حياة تعلم الآلة

<Illustration src="/images/lessons/end-to-end-ml-pipeline.svg" alt="رسم تخطيطي لمراحل خط أنابيب ML من استيعاب البيانات إلى المراقبة" caption="المراحل الثماني لخط أنابيب تعلم الآلة للإنتاج - كل واحدة منها تمثل نقطة فشل محتملة." />

يتدفق كل نظام تعلم الآلة للإنتاج عبر هذه المراحل:

1. **جمع البيانات** - واجهات برمجة التطبيقات وقواعد البيانات وتدفقات الأحداث وتجميع الويب
2. **تنظيف البيانات** - التعامل مع القيم الخالية وإلغاء البيانات المكررة وإكراه النوع
3. **هندسة الميزات** - تحويل الإشارات الأولية إلى ميزات جاهزة للنموذج
4. **اختيار النموذج** - اختيار التصميمات التي تناسب مشكلتك
5. **التدريب** - تنسيق وحدة معالجة الرسومات/وحدة المعالجة المركزية، وضبط المعلمات الفائقة
6. **التقييم** - المقاييس دون الاتصال بالإنترنت، واختبار أ/ب، وعمليات تدقيق العدالة
7. **النشر** - خدمة البنية التحتية وميزانيات زمن الوصول
8. **المراقبة** - كشف الانجراف، والتنبيه، وتحفيز إعادة التدريب

## 📦 جمع البيانات وإصدارها

البيانات الأولية هي الأساس الخاص بك. تعامل معها مثل الكود المصدري - **إصدار كل شيء**.

```bash
# Initialise DVC in your repo
dvc init
dvc remote add -d storage s3://my-ml-data-bucket

# Track a dataset
dvc add data/transactions.csv
git add data/transactions.csv.dvc .gitignore
git commit -m "Track raw transaction dataset v1"
dvc push
```

**DVC** (التحكم في إصدار البيانات) يتيح لك `git checkout` أي مجموعة بيانات تاريخية. ومن خلال دمجها مع علامات Git، يمكنك إعادة إنتاج أي تجربة في أي وقت.

<FunFact>تعالج Netflix أكثر من 1.5 تريليون حدث يوميًا من خلال خطوط البيانات الخاصة بها - ما يقرب من 17 مليون حدث في الثانية تغذي نماذج التوصيات الخاصة بها.</FunFact>

## 🛠️ هندسة الميزات - حيث يتم الفوز بالمسابقات

الميزات مهمة أكثر من الخوارزميات. تتفوق الشجرة المعززة بالتدرج ذات الميزات الرائعة على الشبكة العصبية العميقة ذات الشبكات الضعيفة.

```python
import pandas as pd

df = pd.read_csv("data/transactions.csv", parse_dates=["timestamp"])

# Temporal features
df["hour"] = df["timestamp"].dt.hour
df["is_weekend"] = df["timestamp"].dt.dayofweek >= 5

# Aggregation features
user_stats = df.groupby("user_id")["amount"].agg(["mean", "std", "count"])
user_stats.columns = ["user_avg_amount", "user_std_amount", "user_txn_count"]
df = df.merge(user_stats, on="user_id")

# Ratio features
df["amount_vs_avg"] = df["amount"] / df["user_avg_amount"]
```

## 🧪 تتبع التجربة باستخدام MLflow

لا تفقد أبدًا ما حاولت. يقوم MLflow بتسجيل المعلمات والمقاييس والمصنوعات اليدوية تلقائيًا.

```python
import mlflow
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import f1_score

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run(run_name="gbm-baseline"):
    params = {"n_estimators": 500, "max_depth": 6, "learning_rate": 0.05}
    mlflow.log_params(params)

    model = GradientBoostingClassifier(**params)
    model.fit(X_train, y_train)

    score = f1_score(y_test, model.predict(X_test))
    mlflow.log_metric("f1_score", score)
    mlflow.sklearn.log_model(model, "model")
```

قارن عمليات التشغيل في واجهة مستخدم MLflow، ثم قم بترقية النموذج الأفضل إلى **نموذج التسجيل** باستخدام التدريج → علامات دورة حياة الإنتاج.

## 🚀 المسار كرمز - التنسيق

كسر الخطوات اليدوية. قم بتشفير خط الأنابيب الخاص بك في التعليمات البرمجية باستخدام أطر عمل التزامن:

| أداة | الأفضل لـ | القوة الرئيسية |
|------|----------|-------------|
| ** خطوط أنابيب كوبيفلو ** | Kubernetes-Native ML | المقاييس على مجموعات K8s الموجودة |
| ** تدفق هواء أباتشي ** | جدولة DAG المعقدة | نظام بيئي ناضج، اعتماد واسع النطاق |
| **الوالي** | سير عمل بايثون الحديث | Pythonic API، معالجة ممتازة للأخطاء |
| **زنمل** | تجريد MLOps | لا تعتمد على المكدس، قم بتوصيل أي أداة |

<ThinkAboutIt>لديك خط أنابيب يتم إعادة تدريبه ليلاً ولكن بياناتك تتغير كل ساعة. ما هي المفاضلات التي تزنها عند تحديد تكرار إعادة التدريب - التكلفة، أو الركود، أو تعقيد البنية التحتية؟ </ThinkAboutIt>

## 🌐 عرض النموذج ونشره

يحتاج النموذج الخاص بك إلى واجهة برمجة التطبيقات (API). نمطان سائدان:

**REST API** - بسيط، يعتمد على HTTP، وهو رائع للإنتاجية المعتدلة:
```python
# FastAPI model server
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("model.pkl")

@app.post("/predict")
async def predict(features: dict):
    prediction = model.predict([list(features.values())])
    return {"prediction": int(prediction[0])}
```

**gRPC** - بروتوكول ثنائي، أسرع بمقدار 2–10 مرات من REST، وهو مثالي للخدمات الصغيرة الداخلية والسيناريوهات عالية الإنتاجية.

### عمليات نشر الكناري

لا ترسل مطلقًا 100% من حركة المرور إلى نموذج جديد. استخدم **إصدارات الكناري**: المسار 5% → 25% → 50% → 100%، ومراقبة معدلات الخطأ في كل خطوة. التراجع على الفور إذا تدهورت المقاييس.

## 📊 حلقة المراقبة والتغذية الراجعة

النشر ليس خط النهاية - إنه مسدس البداية. مراقبة ل:

- **انجراف البيانات** - تحويل توزيعات المدخلات من بيانات التدريب
- **انحراف المفهوم** - العلاقة بين الميزات وتغيير الهدف
- **تدهور الأداء** - انخفاض مقاييس الدقة/وقت الاستجابة

توفر أدوات مثل **Evidently AI** و**WhyLabs** و**Arize** لوحات تحكم انجرافية. عندما يتجاوز الانجراف الحدود، قم بتشغيل إعادة التدريب التلقائي باستخدام بيانات الإنتاج الجديدة - مما يؤدي إلى إغلاق حلقة التغذية الراجعة.

## 🎯 الوجبات السريعة الرئيسية

- الإصدار **كل شيء**: التعليمات البرمجية والبيانات والنماذج وتكوينات خطوط الأنابيب
- توفر هندسة الميزات عائدًا على الاستثمار أكبر من تغييرات البنية
- تشفير خطوط الأنابيب كرمز - الخطوات اليدوية هي ديون فنية
- النشر باستخدام إصدارات الكناري والمراقبة بلا هوادة
- حلقة التغذية الراجعة (بيانات الإنتاج ← إعادة التدريب) هي ما يفصل العروض التوضيحية عن أنظمة الإنتاج

# Construa seu próprio projeto de IA

Você passou meses aprendendo teoria. Agora é hora de **construir algo real**, enviá-lo para o mundo e provar que você pode entregar de ponta a ponta.

Nada em seu currículo falará mais alto do que um produto implantado que as pessoas possam realmente usar.

<Illustration src="/images/lessons/build-your-ai-project.svg" alt="Diagrama mostrando a jornada desde a ideia até a construção, implantação e iteração" caption="O ciclo de vida completo de um projeto fundamental de IA" />

## Escolhendo o projeto certo

Escolher o projeto certo é a decisão mais importante que você tomará neste ponto culminante. Acerte e o resto flui naturalmente.

Seu projeto deve estar na intersecção de três coisas:

- **Paixão** - você passará noites nisso; escolha algo com o qual você realmente se preocupa.
- **Lacuna de habilidade** - deve levá-lo a pelo menos uma área que você ainda não domina.
- **Valor do portfólio** - os gerentes de contratação devem olhar para ele e pensar: "Essa pessoa pode entregar".

<Callout>Evite conjuntos de dados de brinquedo e clones de tutoriais. Os recrutadores viram milhares de classificadores MNIST. Resolva um problema que seja importante para um público real, mesmo que o público seja pequeno.
</Callout>

Escolha um - ou invente o seu próprio - e comprometa-se com ele hoje. O melhor projeto é aquele que você realmente terminará.

## Planejando seu MVP

O maior erro que os construtores cometem é definir um escopo muito grande. Defina seu **Produto Mínimo Viável** implacavelmente:

1. **Apenas recurso principal** - um fluxo de usuário, um modelo, uma interface.
2. **Pilha de tecnologia** - escolha ferramentas que você conhece e mais uma coisa nova. Para a maioria dos projetos: backend Python + FastAPI, frontend React ou Next.js, um banco de dados gerenciado.
3. **Cronograma** – reserve duas semanas para o MVP. Se demorar mais, seu escopo é muito grande.
4. **Métrica de sucesso** - defina um número que indica que o projeto funciona (por exemplo, "precisão de recuperação acima de 80% no meu conjunto de testes").

<ThinkAboutIt>Escreva a ideia do seu projeto em uma frase. Agora risque metade dos recursos. Esse é o seu MVP.
</ThinkAboutIt>

## Construindo em Público

Compartilhar seu progresso nas redes sociais não é vaidade – é uma estratégia de carreira.

- **Dia 1**: Publique sua ideia e peça feedback.
- **Semanalmente**: compartilhe uma breve atualização - o que você construiu, o que quebrou, o que você aprendeu.
- **Dia de lançamento**: Escreva um tópico ou postagem no blog explicando a arquitetura.

Construir em público cria responsabilidade, atrai colaboradores e coloca seu nome na frente dos gerentes de contratação antes mesmo de você se inscrever.

<FunFact>Uma pesquisa de 2024 da Stack Overflow descobriu que 68 por cento dos gerentes de contratação verificam os projetos e postagens públicas de um candidato antes de decidir entrevistá-lo.
</FunFact>

## Implantando seu projeto

Um projeto que roda apenas em `localhost` é invisível. Ninguém pode experimentar, ninguém pode compartilhar e nenhum gerente de contratação jamais verá isso.

A implantação não é algo agradável de se ter - é a diferença entre um projeto de hobby e uma peça de portfólio. Aqui estão três opções sólidas:

| Plataforma | Melhor para | Nível gratuito |
|----------|------------|-----------|
| **Vercel** | Front-ends Next.js, APIs sem servidor | Generoso |
| **Ferrovia** | Back-ends Python, bancos de dados | 500 horas/mês |
| **Espaços HuggingFace** | Demonstrações de ML com Gradio ou Streamlit | Ilimitado para CPU |

Seja qual for sua escolha, certifique-se de que seu README inclua:

- Uma descrição de uma linha do que o projeto faz.
- Um link ao vivo ou GIF de demonstração.
- Instruções claras de configuração para desenvolvimento local.

<Quiz question="Por que implantar seu projeto é importante para seu portfólio?" options="Isso prova que você pode escrever testes unitários|Isso mostra que você pode lidar com todo o ciclo de vida, do código à produção|Isso garante que seu código esteja livre de bugs|Ele substitui totalmente a necessidade de um currículo" answer="1" explanation="A implantação demonstra que você pode lidar com todo o ciclo de vida - não apenas escrever código, mas enviar e manter um produto ativo." />

## Obtendo feedback e iterando

Assim que seu MVP estiver ativo, o verdadeiro aprendizado começa. O envio não é a linha de chegada – é a linha de partida.

Busque ativamente feedback de pessoas que serão honestas com você:

- Compartilhe-o em comunidades relevantes do Discord e do Slack.
- Publique no Reddit em subreddits específicos do domínio.
- Peça a dois ou três engenheiros que você respeita para experimentar e fazer críticas honestas.

Trate cada feedback como um presente. Corrija os problemas críticos, anote o restante da versão dois e envie atualizações rapidamente.

<ThinkAboutIt>Pense em uma comunidade onde seus usuários-alvo se encontram. Planeje compartilhar seu projeto lá dentro de 48 horas após o lançamento.
</ThinkAboutIt>

## Adicionando ao seu portfólio

Seu projeto é tão valioso quanto sua apresentação. Ao adicioná-lo ao seu portfólio:

1. **Escreva um estudo de caso** - problema, abordagem, diagrama de arquitetura, resultados, lições aprendidas.
2. **Fixar no GitHub** - limpar histórico de commits, bom README, questões abertas para trabalhos futuros.
3. **Grave um vídeo de demonstração de dois minutos** – analise o produto e explique uma decisão técnica.
4. **Link em todos os lugares** - CV, LinkedIn, site pessoal, perfil do GitHub README.

<Quiz question="Qual a forma mais eficaz de apresentar um projeto em seu portfólio?" options="Basta vincular ao repositório GitHub|Escreva um estudo de caso com problema, abordagem, arquitetura e resultados|Incluir apenas uma captura de tela|Liste as tecnologias usadas sem contexto" answer="1" explanation="Um estudo de caso dá aos gerentes de contratação uma visão completa – o que você construiu, por que, como e o que aprendeu – o que é muito mais atraente do que um simples link de repo." />

## Seu próximo passo

Pare de ler. Abra um novo repositório agora mesmo. Nomeie-o com base na ideia do seu projeto.

Escreva o README primeiro - descreva o que ele fará, para quem se destina e qual é o seu escopo de MVP. Empurre esse README esta noite.

A lacuna entre “Quero construir algo” e “Enviei algo” é um commit.

<FunFact>Os dados do GitHub mostram que os repositórios com um README bem escrito recebem quatro vezes mais estrelas e garfos do que aqueles sem ele - as primeiras impressões são importantes, mesmo em código aberto.
</FunFact>

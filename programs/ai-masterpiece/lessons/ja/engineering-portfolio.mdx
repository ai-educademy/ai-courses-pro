# エンジニアリングポートフォリオ

AI 時代においては、ポートフォリオが最も強力なキャリア資産となります。あなたが部屋にいないときでも話し、寝ている間も機能し、同時に何千人もの採用担当者に連絡を取ることができます。

洗練された履歴書はあなたを仲間に入れます。強力なポートフォリオは**窮地を脱します**。

<Illustration src="/images/lessons/engineering-portfolio.svg" alt="GitHub、ブログ、個人 Web サイトが相互に接続されていることを示す開発者プロフィール" caption="あなたのポートフォリオはエコシステムです - すべての作品が他の作品を強化します" />

## ポートフォリオが履歴書に勝る理由

履歴書は、あなたが何をしたと主張しているかを誰かに伝えます。ポートフォリオがそれを**証明**します。

AI およびソフトウェア エンジニアリングの採用マネージャーは、履歴書を作成するのに平均 6 秒を費やします。しかし、巧妙に作成された GitHub プロファイルや個人サイトをクリックしてアクセスすると、数分、場合によってはそれ以上の時間がかかります。この特別な注意が、不採用メールと一次面接の違いとなります。

<Callout>ポートフォリオを製品、採用担当者をユーザーと考えてください。すべての要素は摩擦を軽減し、信頼を構築する必要があります。
</Callout>

## GitHub: 公開ワークショップ

技術採用担当者が最初に注目するのは、GitHub プロフィールです。それを大切にしてください。

### プロファイルの README
ユーザー名にちなんで名付けられたリポジトリに `README.md` を作成します。これはプロフィールの上部に表示されます。含む：

- あなたが誰なのか、そして何に重点を置いているのかを 1 行でまとめたもの。
- あなたの最も強力なスキルを強調する 2 つまたは 3 つの箇条書き。
- 最高のプロジェクト、ブログ、LinkedIn へのリンク。

### 固定されたリポジトリ
最大 6 つのリポジトリを固定できます。 **範囲と深さ**を示すプロジェクトを選択してください:

- デプロイメントを含む 1 つのエンドツーエンド ML プロジェクト。
- エンジニアリングの厳密さを示す 1 つのバックエンドまたはシステム プロジェクト。
- 1 つのオープンソース貢献 (意味のある変更を含むフォークも含む)。

### 貢献グラフ
強度よりも一貫性が重要です。緑色の四角形の安定したグラフは信頼性を示します。散発的なバーストではなく、小規模で定期的なコミットを目指します。

## プロジェクト ショーケース: 何を構築するか

採用マネージャーの目には、すべてのプロジェクトが平等であるわけではありません。最高のポートフォリオ プロジェクトには、次の 3 つの特徴があります。

1. **たとえ小さな問題であっても、実際の問題を解決します**。
2. **展開され、アクセス可能** - ライブリンクは常に README に勝ります。
3. **これらには、決定、トレードオフ、および学んだ教訓を説明する書き込みが含まれています**。

明らかにチュートリアルをフォローするようなプロジェクトは避けてください。他の何千人もの人が同じコードで同じものを構築したとしても、それはあなたを区別しません。

<ThinkAboutIt>現在のプロジェクトを見てください。面接でデモを披露するのが最も誇りに思うのはどれですか?どれもあなたを興奮させない場合、それは何か新しいものを構築するという合図です。
</ThinkAboutIt>

## 技術的なブログ投稿を書く

ブログは、ほとんどのエンジニアが無視する最も大きなレバレッジを誇るポートフォリオ項目です。

**機能する理由:**
- エンジニアリングでは不足しているコミュニケーション能力を発揮します。
- 採用担当者や協力者からのインバウンドの関心を集めます。
- 自分自身の理解が深まります - 本当に知らないことを説明することはできません。

**何を書くべきか:**
- あなたが行った技術的な決定とその理由。
- デバッグに何時間も費やしたバグとその学んだこと。
- 評価した 2 つのツールまたはアプローチの比較。

**公開場所:**
- 見つけやすくするための **Dev.to** または **Hashnode**。
- **あなた自身のサイト**を長期所有できます。
- リーチを最大化するために両方にクロスポストします。

<FunFact>Stack Overflow の共同創設者である Jeff Atwood は、自身のブログ「Coding Horror」が彼のキャリアにおける最大の要因であると考えています。彼は、これまでに構築された最も重要な開発者プラットフォームの 1 つにつながるまで、何年も一貫して執筆を続けてきました。
</FunFact>

## エンジニア向けの LinkedIn 最適化

多くのエンジニアは LinkedIn を無視していますが、採用担当者は LinkedIn に住んでいます。大きな影響を与えるいくつかの調整:

- **見出し**: 「X 社のソフトウェア エンジニア」は飛ばしてください。代わりに、「ML エンジニア | AI を活用した検索システムの構築 | チャンスにオープン」を試してください。
- **セクションについて**: 3 つの短い段落を書きます - あなたがしていること、あなたが構築したもの、そしてあなたが探しているもの。
- **注目セクション**: 最高のブログ投稿、プロジェクトのデモ、またはカンファレンスでの講演をピン留めします。
- **スキル**: 曖昧な用語 (問題解決、チームワーク) ではなく、具体的なテクノロジー (PyTorch、Kubernetes、FastAPI) をリストします。

## 個人 Web サイト: 含めるべき内容

あなたの個人サイトはあなたの本拠地です。シンプルかつ高速な読み込みを心がけてください。

**含まれるもの:**
- プロの写真付きの短い自己紹介。
- スクリーンショットまたはデモを含む上位 3 つのプロジェクトへのリンク。
- あなたのブログ、またはそのブログへのリンク。
- 連絡先情報または簡単なフォーム。

**スキップ:**
- ページの速度を低下させる派手なアニメーション。
- パーセンテージバーのあるスキルセクション - それらは何の意味もありません。
- これまでに構築したすべてのプロジェクト。容赦なくキュレートします。

<FunFact>Google の採用調査によると、経験レベルと資格を考慮すると、個人の Web サイトを持つ候補者は、Web サイトを持たない候補者に比べてコールバックを受ける可能性が 27% 高いことがわかりました。
</FunFact>

## ポートフォリオレビューチェックリスト

ポートフォリオが完成したと考える前に、次のリストを確認してください。

- [ ] GitHub プロファイルには README、6 つの固定リポジトリ、および一貫した貢献グラフがあります。
- [ ] 少なくとも 1 つのプロジェクトがライブ リンクを使用してデプロイされています。
- [ ] 固定された各プロジェクトには、目的、セットアップ手順、スクリーンショットまたはデモを記載した明確な README が付いています。
- [ ] 少なくとも 1 つの技術ブログ投稿を公開しました。
- [ ] LinkedIn の見出し、概要セクション、および特集コンテンツが最適化されています。
- [ ] 個人の Web サイトは 3 秒以内に読み込まれ、モバイルでも動作します。
- [ ] 技術者ではない友人でも、あなたのサイトからあなたが何をしているのかを理解できます。

<ThinkAboutIt>テクノロジー業界以外の人にポートフォリオのリンクを送り、「私が何をしているのか、そしてそれが得意かどうか教えていただけますか?」と尋ねます。彼らの答えは、自分では見えない盲点を明らかにします。
</ThinkAboutIt>

# 独自の AI プロジェクトを構築する

あなたは何ヶ月もかけて理論を学びました。 **本物のものを構築**し、それを世界に出荷し、エンドツーエンドで提供できることを証明する時が来ました。

あなたの履歴書に記載されているものは、人々が実際に使用できる展開された製品よりも雄弁です。

<Illustration src="/images/lessons/build-your-ai-project.svg" alt="アイデアから構築、デプロイ、反復までの過程を示す図" caption="集大成 AI プロジェクトのライフサイクル全体" />

## 適切なプロジェクトの選択

適切なプロジェクトを選択することは、このキャップストーンで行う最も重要な決定です。正しく理解すれば、残りは自然に流れます。

プロジェクトは次の 3 つの要素が交わる位置にある必要があります。

- **情熱** - これに夜を費やすことになります。本当に気になるものを選んでください。
- **スキルギャップ** - まだ習得していない領域が少なくとも 1 つあるはずです。
- **ポートフォリオの価値** - 採用担当者はそれを見て、「この人は出荷できる」と考えるはずです。

<Callout>おもちゃのデータセットやチュートリアルのクローンは避けてください。採用担当者はこれまでに 1,000 の MNIST 分類子を見てきました。たとえ聴衆が少なくても、実際の聴衆にとって重要な問題を解決します。
</Callout>

## 難易度別の 5 つのプロジェクトのアイデア

| # |プロジェクト |主要なスキル |難易度 |
|---|--------|-----------|-----------|
| 1 | **ニッチなドメイン (レシピ、法律文書など) 用のセマンティック検索エンジン** |エンベディング、ベクター DB、REST API | ⭐⭐ |
| 2 | GitHub PR にコメントする **AI を活用したコード レビューアー** | LLM プロンプト、GitHub API、CI/CD | ⭐⭐⭐ |
| 3 | **ライブ イベントのツイート用のリアルタイム感情ダッシュボード** |ストリーミング、NLP、WebSocket、React | ⭐⭐⭐ |
| 4 | **マルチモーダル コンテンツ モデレーター** (テキスト + 画像) |ビジョン モデル、分類、キュー | ⭐⭐⭐⭐ |
| 5 |トピックに関する論文を要約する **自律型リサーチ エージェント** |エージェント、RAG、ツールの使用、評価 | ⭐⭐⭐⭐⭐ |

どれか 1 つを選択して、または独自のものを考案して、今すぐそれに取り組んでください。最高のプロジェクトとは、実際に完成させるプロジェクトです。

## MVP を計画する

ビルダーが犯す最大の間違いは、スコープが大きすぎることです。 **最小限の実行可能な製品**を容赦なく定義します。

1. **コア機能のみ** - 1 つのユーザー フロー、1 つのモデル、1 つのインターフェイス。
2. **技術スタック** - 知っているツールと新しいものを 1 つ選択します。ほとんどのプロジェクトの場合: Python + FastAPI バックエンド、React または Next.js フロントエンド、マネージド データベース。
3. **タイムライン** - MVP を取得するには 2 週間かかります。時間がかかる場合は、範囲が広すぎます。
4. **成功指標** - プロジェクトが機能していることを示す数値を 1 つ定義します (例: 「テスト セットでの検索精度が 80% 以上」)。

<ThinkAboutIt>プロジェクトのアイデアを一文で書き留めます。次に、機能の半分を取り消し線で消します。それがあなたのMVPです。
</ThinkAboutIt>

## 公共の建物

ソーシャル メディアで自分の進捗状況を共有することは虚栄心ではなく、キャリア戦略です。

- **1 日目**: アイデアを投稿してフィードバックを求めます。
- **毎週**: 短い更新情報を共有します - 構築したもの、壊れたもの、学んだこと。
- **リリース日**: アーキテクチャを説明するスレッドまたはブログ投稿を作成します。

公開することで説明責任が生まれ、協力者が集まり、応募する前から採用担当者の目に留まります。

<FunFact>Stack Overflow による 2024 年の調査では、採用担当者の 68% が面接を受けるかどうかを決定する前に、候補者の公開プロジェクトや投稿をチェックしていることがわかりました。
</FunFact>

## プロジェクトをデプロイする

`localhost` でのみ実行されるプロジェクトは表示されません。誰もそれを試すことも、共有することもできず、採用担当者もそれを見ることはありません。

導入はあれば便利というわけではありません。趣味のプロジェクトとポートフォリオの作品の違いです。ここに 3 つの確実なオプションがあります。

|プラットフォーム |最適な用途 |無料利用枠 |
|----------|-----------|----------|
| **ヴェルセル** | Next.js フロントエンド、サーバーレス API |寛大 |
| **鉄道** | Python バックエンド、データベース | 500 時間/月 |
| **HuggingFace Spaces** | Gradio または Streamlit を使用した ML デモ | CPU は無制限 |

どちらを選択する場合でも、README に次の内容が含まれていることを確認してください。

- プロジェクトの内容を 1 行で説明します。
- ライブリンクまたはデモGIF。
- ローカル開発のための明確なセットアップ手順。

## フィードバックの取得と反復

MVP が公開されると、本当の学習が始まります。配送はゴールではなく、スタートラインです。

正直に答えてくれる人々からのフィードバックを積極的に求めてください。

- 関連する Discord および Slack コミュニティで共有します。
- Reddit のドメイン固有のサブレディットに投稿します。
- あなたが尊敬する 2 人か 3 人のエンジニアに試してもらい、率直な批評をしてもらいます。

すべてのフィードバックを贈り物として扱います。重大な問題を修正し、バージョン 2 の残りの部分に注意して、アップデートを迅速にプッシュします。

<ThinkAboutIt>ターゲットユーザーがたむろするコミュニティを 1 つ考えてみましょう。プロジェクトを開始してから 48 時間以内にそこでプロジェクトを共有するように計画してください。
</ThinkAboutIt>

## ポートフォリオに追加する

あなたのプロジェクトの価値は、そのプレゼンテーションと同じくらい重要です。ポートフォリオに追加すると:

1. **ケーススタディを書く** - 問題、アプローチ、アーキテクチャ図、結果、学んだ教訓。
2. **GitHub にピン留め** - クリーンなコミット履歴、優れた README、将来の作業のための未解決の問題。
3. **2 分間のデモ ビデオを録画します** - 製品を実際に見て、技術的な決定事項を 1 つ説明します。
4. **どこにでもリンクする** - 履歴書、LinkedIn、個人サイト、GitHub プロファイルの README。

## 次のステップ

読むのをやめてください。今すぐ新しいリポジトリを開きます。プロジェクトのアイデアにちなんで名前を付けます。

最初に README を作成します。これが何をするのか、誰を対象とするのか、MVP の範囲は何かを説明します。今夜その README をプッシュしてください。

「何かを作りたい」と「何かを出荷した」の間のギャップは 1 コミットです。

<FunFact>GitHub データによると、よく書かれた README があるリポジトリは、README がないリポジトリに比べて 4 倍多くのスターとフォークを受け取ります。オープンソースであっても第一印象は重要です。
</FunFact>

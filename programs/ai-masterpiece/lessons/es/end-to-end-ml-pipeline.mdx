# Canalización de aprendizaje automático de un extremo a otro: desde los datos sin procesar hasta el modelo implementado

La mayoría de los tutoriales terminan en `model.fit()`. En producción, eso representa apenas el 20% del trabajo. Esta lección recorre todo el ciclo de vida del aprendizaje automático: el mismo proceso que impulsa los motores de recomendación en Spotify, la detección de fraude en Stripe y la clasificación de búsqueda en Google.

## 🗺️ El ciclo de vida del aprendizaje automático de un vistazo

<Illustration src="/images/lessons/end-to-end-ml-pipeline.svg" alt="Diagrama de las etapas del proceso de ML desde la ingesta de datos hasta el monitoreo" caption="Las ocho etapas de un proceso de producción de ML: cada una es un punto de falla potencial." />

Cada sistema de ML de producción pasa por estas etapas:

1. **Recopilación de datos**: API, bases de datos, secuencias de eventos, web scraping
2. **Limpieza de datos**: manejo de valores nulos, deduplicación, coerción de tipos
3. **Ingeniería de funciones**: transformación de señales sin procesar en funciones listas para el modelo
4. **Selección de modelo**: elegir arquitecturas que coincidan con su problema
5. **Capacitación**: orquestación de GPU/CPU, ajuste de hiperparámetros
6. **Evaluación**: métricas fuera de línea, pruebas A/B, auditorías de equidad
7. **Implementación**: infraestructura de servicio, presupuestos de latencia
8. **Monitoreo**: detección de deriva, alertas y activador de reentrenamiento

## 📦 Recopilación de datos y control de versiones

Los datos sin procesar son su base. Trátelo como código fuente: ** versione todo **.

```bash
# Initialise DVC in your repo
dvc init
dvc remote add -d storage s3://my-ml-data-bucket

# Track a dataset
dvc add data/transactions.csv
git add data/transactions.csv.dvc .gitignore
git commit -m "Track raw transaction dataset v1"
dvc push
```

**DVC** (Control de versiones de datos) le permite `git checkout` cualquier conjunto de datos históricos. Combinado con etiquetas Git, puede reproducir cualquier experimento desde cualquier momento.

## 🛠️ Ingeniería de funciones: dónde se ganan las competiciones

Las características importan más que los algoritmos. Un árbol potenciado por gradiente con características brillantes supera a una red neuronal profunda con características pobres.

```python
import pandas as pd

df = pd.read_csv("data/transactions.csv", parse_dates=["timestamp"])

# Temporal features
df["hour"] = df["timestamp"].dt.hour
df["is_weekend"] = df["timestamp"].dt.dayofweek >= 5

# Aggregation features
user_stats = df.groupby("user_id")["amount"].agg(["mean", "std", "count"])
user_stats.columns = ["user_avg_amount", "user_std_amount", "user_txn_count"]
df = df.merge(user_stats, on="user_id")

# Ratio features
df["amount_vs_avg"] = df["amount"] / df["user_avg_amount"]
```

## 🧪 Seguimiento de experimentos con MLflow

Nunca pierdas la pista de lo que intentaste. MLflow registra parámetros, métricas y artefactos automáticamente.

## 🌐 Servicio e implementación de modelos

Su modelo necesita una API. Dos patrones dominantes:

**API REST**: sencilla, basada en HTTP, ideal para un rendimiento moderado:
```python
# FastAPI model server
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("model.pkl")

@app.post("/predict")
async def predict(features: dict):
    prediction = model.predict([list(features.values())])
    return {"prediction": int(prediction[0])}
```

**gRPC**: protocolo binario, entre 2 y 10 veces más rápido que REST, ideal para microservicios internos y escenarios de alto rendimiento.

### Implementaciones canarias

Nunca envíe el 100% del tráfico a un modelo nuevo. Utilice **versiones canarias**: ruta 5% → 25% → 50% → 100%, monitoreando las tasas de error en cada paso. Retroceda instantáneamente si las métricas se degradan.

## 📊 Monitoreo y circuito de retroalimentación

El despliegue no es la línea de meta, es el pistoletazo de salida. Monitorear para:

- **Deriva de datos**: distribuciones de entrada que cambian de los datos de entrenamiento
- **Deriva del concepto**: la relación entre las características y el cambio de objetivos
- **Degradación del rendimiento**: las métricas de precisión/latencia disminuyen

Herramientas como **Evidfully AI**, **WhyLabs** y **Arize** proporcionan paneles de control de deriva. Cuando la deriva supere los umbrales, active el reentrenamiento automático con datos de producción nuevos, cerrando el ciclo de retroalimentación.

## 🎯 Conclusiones clave

- Versión **todo**: código, datos, modelos y configuraciones de canalización
- La ingeniería de funciones ofrece más retorno de la inversión que los cambios de arquitectura.
- Codificar canalizaciones como código: los pasos manuales son deuda técnica
- Implementar con versiones canary y monitorear sin descanso
- El circuito de retroalimentación (datos de producción → reentrenamiento) es lo que separa las demostraciones de los sistemas de producción.

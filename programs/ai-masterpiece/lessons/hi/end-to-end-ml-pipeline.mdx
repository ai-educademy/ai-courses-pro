# एनद-टो-एनद ML पाइपलाइन - रव डेटा से तैनात मॉडल तक

ज़्यादातर ट्यूटोरियल `model.fit()` पर रुक जाते हैं। प्रोडक्शन में, ये बमुश्किल 20% काम है। ये पाठ **पूरे ML लाइफ़साइकल** को कोवेर करता है - वही पाइपलाइन जो Spotify के अनुशंसा इंजन, Stripe के धोखाधड़ी पहचान, और Google की सर्च रैंकिंग को पोवेर करता है।

## 🗺️ ML लाइफ़साइकल एक नज़र में

<Illustration src="/images/lessons/end-to-end-ml-pipeline.svg" alt="डेटा इंजेशन से निगरानी तक ML पाइपलाइन चरणों का आरेख" caption="प्रोडक्शन ML पाइपलाइन के आठ चरणों - हर एक संभावित फ़ैलुरे बिंदु है।" />

हर प्रोडक्शन ML सिस्टम इन चरणों से गुज़रता है:

1. **डेटा संग्रह** - APIs, डेटाबेस, घटना स्टारेअमस, वेब स्क्रैपिंग
2. **डेटा सफ़ाई** - नल वैल्यू संभालना, डीडुप्लिकेशन, टाइप कोअर्शन
3. **फ़ीचर इंजीनियरिंग** - रव सिग्नल को मोदेल-रेअदय फ़ीचर में बदलना
4. **मॉडल चयन** - अपनी समस्या से मेल करने वाले आर्किटेक्चर चुनना
5. **ट्रेनिंग** - GPU/CPU ऑर्केस्ट्रेशन, हाइपरपैरामीटर ट्यूनिंग
6. **मूल्यांकन** - ऑफ़लाइन मेट्रिक्स, A/B परीक्षण, निष्पक्षता ऑडिट
7. **डिप्लॉयमेंट** - सर्विंग इन्फ़्रास्ट्रक्चर, लेटेंसी बजट
8. **मोनिटोरिङ** - दरिफ़ट पहचान, अलेरटिङ, रेटरैनिङ ट्रिगर

## 📦 डेटा संग्रह और वेरसिओनिङ

कच्चे डेटा आपकी आधार है। इसे स्रोत कोड की तरह मानें - **सब कुछ वर्शन करें**।

```bash
# Initialise DVC in your repo
dvc init
dvc remote add -d storage s3://my-ml-data-bucket

# Track a dataset
dvc add data/transactions.csv
git add data/transactions.csv.dvc .gitignore
git commit -m "Track raw transaction dataset v1"
dvc push
```

**DVC** (डेटा वेरसिओन कोनटरोल) आपको किसी भी हिसटोरिकल दटसेट को `git checkout` करने देता है। गिट टगस के साथ मिलाकर, आप किसी भी बिंदु in समय से कोई भी एक्सपेरिमेनट रेबनाने कर सकते हैं।

<FunFact>Netflix अपनी डेटा पाइपलाइन के ज़रिए रोज़ाना 1.5 टरिललिओन से ज़्यादा इवेंट प्रोसेस करता है - हर सेकंड लगभग 17 मिलियन इवेंट जो उनके अनुशंसा मॉडल को फ़ीड करते हैं।</FunFact>

## 🛠️ फ़ीचर इंजीनियरिंग - जहाँ प्रतियोगिताएँ जीती जाती हैं

फ़ीचर एल्गोरिदम से ज़्यादा मटटेर करते हैं। शानदार फ़ीचर वाला गरदिएनट-बूसटेद ट्री ख़राब फ़ीचर वाले गहरी न्यूरल नेटवर्क को हरा देता है।

```python
import pandas as pd

df = pd.read_csv("data/transactions.csv", parse_dates=["timestamp"])

# Temporal features
df["hour"] = df["timestamp"].dt.hour
df["is_weekend"] = df["timestamp"].dt.dayofweek >= 5

# Aggregation features
user_stats = df.groupby("user_id")["amount"].agg(["mean", "std", "count"])
user_stats.columns = ["user_avg_amount", "user_std_amount", "user_txn_count"]
df = df.merge(user_stats, on="user_id")

# Ratio features
df["amount_vs_avg"] = df["amount"] / df["user_avg_amount"]
```

## 🧪 MLflow के साथ एक्सपेरिमेनट टरकिङ

कभी रिकॉर्ड मत खोइए कि आपने क्या टरय किया। MLflow पैरामीटर, मेट्रिक्स, और आर्टिफ़ैक्ट अपने-आप लॉग करता है।

```python
import mlflow
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import f1_score

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run(run_name="gbm-baseline"):
    params = {"n_estimators": 500, "max_depth": 6, "learning_rate": 0.05}
    mlflow.log_params(params)

    model = GradientBoostingClassifier(**params)
    model.fit(X_train, y_train)

    score = f1_score(y_test, model.predict(X_test))
    mlflow.log_metric("f1_score", score)
    mlflow.sklearn.log_model(model, "model")
```

MLflow UI में रन कोमपरे करें, फिर श्रेष्ठ मॉडल को **मॉडल रजिस्ट्री** में बढ़ावा करें स्टेजिंग → प्रोडक्शन लाइफ़साइकल टगस के साथ।

## 🚀 पाइपलाइन as कोड - ऑर्केस्ट्रेशन

मनुअल चरण टूटते हैं। अपनी पाइपलाइन को ऑर्केस्ट्रेशन ढाँचे से कोड में एनकोदे करें:

| टूल | किसके लिए बेस्ट | मुख्य ताक़त |
|------|-----------------|------------|
| **कुबेफ़लोव पिपेलिनेस** | कुबेरनेटेस-नटिवे ML | मौजूदा K8s क्लस्टर पर स्केल होता है |
| **अपचे ऐरफ़लोव** | जटिल DAG सचेदुलिङ | मटुरे इकोसिस्टम, विदे अपनाना |
| **परेफ़ेकट** | आधुनिक Python वर्कफ़्लो | पयथोनिक API, एक्सकेललेनट एररोर हैंडलिंग |
| **ZenML** | MLOps अमूर्तन | Stack-अगनोसटिक, कोई भी टूल पलुग करें |

## 🌐 मॉडल सेरविङ और डिप्लॉयमेंट

आपके मॉडल को एक API चाहिए। दो प्रमुख पैटर्न:

**REST API** - सरल, HTTP-बसेद, मध्यम थ्रूपुट के लिए बढ़िया:
```python
# FastAPI model server
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("model.pkl")

@app.post("/predict")
async def predict(features: dict):
    prediction = model.predict([list(features.values())])
    return {"prediction": int(prediction[0])}
```

**gRPC** - बाइनरी प्रोटोकॉल, REST से 2-10× तेज़, आंतरिक माइक्रोसर्विसेज़ और उच्च-थ्रूपुट स्थितियाँ के लिए उपयुक्त।

### कैनरी डिप्लॉयमेंटस

कभी भी 100% ट्रैफ़िक नए मॉडल पर मत भेजें। **कैनरी रिलीज़** इस्तेमाल करें: 5% → 25% → 50% → 100% रूट करें, हर चरण पर एरर दरें मॉनिटर करें। मेट्रिक्स गिरावट हों तो तुरंत रोलबैक करें।

## 📊 मोनिटोरिङ और फ़ीडबैक लूप

डिप्लॉयमेंट समापन लिने नहीं है - ये शुरुआती गुन है। मोनिटोर करें:

- **डेटा दरिफ़ट** - इनपुट डिस्ट्रिब्यूशनस ट्रेनिंग डेटा से शिफ़ट हो रही हैं
- **कोनकेपट दरिफ़ट** - फ़ीचर और लक्षित के बीच संबंध बदल रहा है
- **प्रदर्शन गिरावट** - सटीकता/latency मेट्रिक्स गिर रहे हैं

**स्पष्ट रूप से AI**, **व्हाइल लूप**, और **अरिज़े** जैसे टूल्स दरिफ़ट डैशबोर्ड प्रदान करते हैं। जब दरिफ़ट थ्रेशहोल्ड से ज़्यादा हो, फ़रेश प्रोडक्शन डेटा से औटोमटिक दोबारा ट्रेनिङ ट्रिगर करें - फ़ीडबैक लूप बंद करें।

## 🎯 मुख्य सीख

- **सब कुछ** वर्शन करें: कोड, डेटा, मॉडल, और पाइपलाइन कॉन्फ़िग

- कैनरी रिलीज़ से तैनात करें और लगातार मॉनिटर करें
- फ़ीडबैक लूप (प्रोडक्शन डेटा → रेटरैनिङ) वह है जो डेमो को प्रोडक्शन सिस्टम से अलग करता है

# अपना AI प्रोजेक्ट बनाएँ

आपने महीनों सिद्धांत सीखी है। अब वक़्त है **कुछ असली बनाने का**, उसे दुनिया के सामने लाने का, और ये साबित करने का कि आप शुरू से अंत तक देलिवेर कर सकते हैं।

आपके CV पर कोई भी चीज़ एक तैनात उत्पाद से ज़्यादा ज़ोर से नहीं बोलेगी - जिसे लोग सच में इस्तेमाल कर सकें।

## सही प्रोजेक्ट कैसे चुनें

सही प्रोजेक्ट चुनना इस कैपस्टोन का सबसे अहम फ़ैसला है। अगर ये सही हुआ तो बाकी सब आसान हो जाएगा।

आपका प्रोजेक्ट तीन चीज़ों के प्रतिच्छेदन पर होना चाहिए:

- **रुचि** - आप इस पर शामें बिताएँगे; कुछ ऐसा चुनें जिसकी आपको सच में परवाह है।
- **कौशल अंतर** - ये आपको कम से कम एक ऐसे क्षेत्र में खींचे जो आपने अभी तक मास्टर नहीं किया।
- **पोर्टफ़ोलियो मूल्य** - भर्ती मैनेजर देखकर सोचें, "ये इंसान भेज कर सकता है।"

<Callout>
टोय डेटासेट और टुटोरिअल कलोनेस से बचें। भर्तीेरस ने हज़ारों MNIST क्लासिफ़ायर देखे हैं। एक ऐसी समस्या हल करें जो किसी वास्तविक औदिएनके के लिए मायने रखती हो, भले ही वह औदिएनके छोटी हो।
</Callout>

## कठिनाई के हिसाब से पाँच प्रोजेक्ट विचार

| # | प्रोजेक्ट | मुख्य कौशल | कठिनाई |
|---|---------|-------------|------------|
| 1 | किसी निचे डोमेन के लिए **सेमनटिक सर्च एङिने** (जैसे रेकिपेस, कानूनी दस्तावेज़) | एम्बेडिंग, वेकटोर DB, REST API | ⭐⭐ |
| 2 | **ऐ-पोवेरेद कोड रेविएवेर** जो GitHub PRs पर टिप्पणी करे | LLM प्रॉम्प्टिंग, GitHub API, CI/CD | ⭐⭐⭐ |
| 3 | लाइव घटना Tweets के लिए **रेअल-टिमे भावना दशबोअरद** | स्ट्रीमिंग, NLP, WebSockets, React | ⭐⭐⭐ |
| 4 | **मल्टी-modal कंटेंट मॉडरेटर** (टेक्स्ट + इमगे) | विज़न मॉडल, वर्गीकरण, क्यू | ⭐⭐⭐⭐ |
| 5 | किसी विषय पर पेपर सारांश दें करने वाला **स्वायत्त शोध एजेंट** | एजेंट, RAG, टूल उपयोग, मूल्यांकन | ⭐⭐⭐⭐⭐ |

कोई एक चुनें - या अपना ख़ुद का बनाएँ - और आज ही कमिट कर दें। सबसे अच्छा प्रोजेक्ट वह है जो आप सच में समापन करेंगे।

## अपना MVP योजना करें

निर्माता की सबसे बड़ी ग़लती होती है सकोपे बहुत बड़ा रखना। अपना **कम-से-कम विअबले उत्पाद** बेरहमी से परिभाषित करें:

1. **सिर्फ़ कोरे फ़ीचर** - एक यूज़र फ़लोव, एक मॉडल, एक इनटेरफ़के।
2. **टेच स्टैक** - वह टूल्स चुनें जो आप जानते हैं पलुस एक नई चीज़। ज़्यादातर प्रोजेक्ट के लिए: Python + FastAPI बकेनद, React या नेक्सट.js फ़रोनटेनद, एक मैनेज्ड डेटाबेस।
3. **टिमेलिने** - MVP के लिए दो हफ़्ते दें। अगर ज़्यादा लगे, तो सकोपे बहुत बड़ा है।
4. **सफलता मेट्रिक** - एक नुमबेर परिभाषित करें जो बताए कि प्रोजेक्ट काम कर रहा है (जैसे, "मेरे टेस्ट सेट पर प्राप्ति सटीकता 80% से ऊपर")।

<ThinkAboutIt>
अपना प्रोजेक्ट विचार एक सेनटेनके में लिखें। अब आधे फ़ीचर काट दें। बस यही आपका MVP है।
</ThinkAboutIt>

## बनाना in सार्वजनिक

सामाजिक मीडिया पर अपनी परोगरेस साझा करना दिखावा नहीं है - ये एक करियर रणनीति है।

- **दय 1**: अपना विचार पोस्ट करें और फ़ीडबैक माँगें।
- **हर हफ़्ते**: एक छोटा अपडेट साझा करें - क्या बनाया, क्या टूटा, क्या सीखा।
- **लौनच दय**: एक थरेअद या ब्लॉग पोस्ट लिखें जिसमें आर्किटेक्चर एक्सपलैन करें।

सार्वजनिक में बनाना से जवाबदेही बनती है, सहयोगी आते हैं, और लागू करने से पहले ही आपका नाम भर्ती मैनेजर के सामने आ जाता है।

<FunFact>
Stack Overflow के 2024 सुरवेय में पता चला कि 68% भर्ती मैनेजर इंटरव्यू का फ़ैसला लेने से पहले उम्मीदवार के सार्वजनिक प्रोजेक्ट और पोस्ट चेक करते हैं।
</FunFact>

## अपना प्रोजेक्ट तैनात करें

जो प्रोजेक्ट सिर्फ़ `localhost` पर चलता है, वह इनविसिबले है। कोई टरय नहीं कर सकता, कोई साझा नहीं कर सकता, और कोई भर्ती मैनेजर कभी देखेगा नहीं।

डिप्लॉयमेंट निके-टो-हवे नहीं है - ये शौक प्रोजेक्ट और पोर्टफ़ोलियो पिएके के बीच का फ़र्क़ है। तीन बढ़िया options:

| प्लैटफ़ॉर्म | किसके लिए बेस्ट | मुफ़्त टिएर |
|----------|----------------|-----------|
| Vercel | Next.js फ़्रंटएंड, सर्वरलेस APIs | उदार मुफ़्त सीमा |
| **रेलवे** | Python बैकएंड, डेटाबेस | 500 घंटे/महीने |
| **HuggingFace स्पेस** | गरदिओ या Streamlit के साथ ML डेमो | CPU के लिए उनलिमिटेद |

जो भी चुनें, README में ये ज़रूर शामिल करें:

- प्रोजेक्ट क्या करता है इसकी एक-लिने description।
- एक लाइव लिंक या डेमो GIF।
- स्थानीय डेवलपमेंट के लिए स्पष्ट स्थापना निर्देश।

## फ़ीडबैक लें और दोहराएँ करें

जब आपका MVP लाइव हो जाए, तब असली सीखना शुरू होता है। शिपपिङ समापन लिने नहीं है - ये शुरुआती लिने है।

ऐसे लोगों से सक्रिय रूप से फ़ीडबैक माँगें जो ईमानदार होंगे:

- रेलटेद Discord और Slack कोममुनिटिएस में साझा करें।
- Reddit पर डोमेन-विशिष्ट सबरेडिट में पोस्ट करें।
- दो-तीन इंजीनियर से रिक्वेस्ट करें कि वह टरय करें और ईमानदार करिटिकिसम दें।

हर फ़ीडबैक को तोहफ़ा समझें। महत्वपूर्ण मुद्दे फ़िक्स करें, बाकी वर्शन टवह के लिए नोटे करें, और जल्दी अपडेट पुश करें।

<ThinkAboutIt>
ऐसी एक समुदाय सोचें जहाँ आपके लक्षित यूज़र रहते हैं। लौनच के 48 घंटों के अंदर वहाँ साझा करने का योजना बनाएँ।
</ThinkAboutIt>

## इसे अपने पोर्टफ़ोलियो में जोड़ें

आपका प्रोजेक्ट उतना ही मूल्यवान है जितनी उसकी प्रस्तुति। पोर्टफ़ोलियो में जोड़ते वक़्त:

1. **कसे अध्ययन लिखें** - समस्या, तरीका, आर्किटेक्चर आरेख, नतीजों, सीखे गए सीख।
2. **GitHub पर पिन करें** - साफ़ कमिट इतिहास, अच्छा README, भविष्य की काम के लिए ओपेन मुद्दे।
3. **दो-मिनट का डेमो वीडियो रिकॉर्ड करें** - उत्पाद दिखाएँ और एक तकनीकी निर्णय एक्सपलैन करें।
4. **हर जगह लिंक करें** - CV, LinkedIn, व्यक्तिगत सिटे, GitHub प्रोफ़ाइल README।

## आपका अगला कदम

पढ़ना बंद करें। अभी एक नया रेपोसिटोरय खोलें। उसे अपने प्रोजेक्ट विचार के नाम पर रखें।

पहले README लिखें - बताएँ कि ये क्या करेगा, किसके लिए है, और आपका MVP सकोपे क्या है। आज रात वह README पुश कर दें।

"मैं कुछ बनाना चाहता हूँ" और "मैंने कुछ भेजा" के बीच का फ़ासला बस एक कमिट का है।

<FunFact>
GitHub डेटा दिखाता है कि अच्छी-तरह लिखे README वाले रिपॉज़िटरी को बिना README वालों से चार गुना ज़्यादा स्टार और फ़ोर्क मिलते हैं - पहला प्रभाव ओपन-सोर्स में भी मायने रखते हैं।
</FunFact>

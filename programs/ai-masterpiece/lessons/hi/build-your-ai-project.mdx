# अपना AI प्रोजेक्ट बनाएँ

आपने महीनों तक सिद्धांत सीखे हैं। अब समय है **कुछ वास्तविक बनाने**, उसे दुनिया तक पहुँचाने और यह साबित करने का कि आप शुरुआत से अंत तक काम पूरा कर सकते हैं।

आपके CV पर कोई भी बात ऐसे तैनात उत्पाद से ज़्यादा असरदार नहीं होगी जिसे लोग सच में इस्तेमाल कर सकें।

## सही प्रोजेक्ट चुनना

इस कैपस्टोन में सही प्रोजेक्ट चुनना आपका सबसे महत्वपूर्ण निर्णय होगा। यह सही हुआ, तो बाकी काम स्वाभाविक रूप से आगे बढ़ेगा।

आपका प्रोजेक्ट तीन बातों के संगम पर होना चाहिए:

- **रुचि** - आप इस पर अपनी शामें लगाएंगे। ऐसा विषय चुनें जिसकी आपको सच में परवाह हो।
- **कौशल अंतर** - यह आपको कम से कम एक ऐसे क्षेत्र में आगे बढ़ाए जिसे आपने अभी पूरी तरह नहीं साधा है।
- **पोर्टफ़ोलियो मूल्य** - भर्ती प्रबंधक इसे देखकर सोचें, "यह व्यक्ति उत्पाद शिप कर सकता है।"

<Callout>
खिलौना डेटासेट और ट्यूटोरियल की नकल से बचें। भर्ती करने वालों ने हज़ारों MNIST क्लासिफ़ायर देखे हैं। ऐसी समस्या हल करें जो किसी वास्तविक दर्शक समूह के लिए मायने रखती हो, भले ही वह समूह छोटा हो।
</Callout>

## कठिनाई के आधार पर पाँच प्रोजेक्ट विचार

| # | प्रोजेक्ट | मुख्य कौशल | कठिनाई |
|---|---------|-----------|------------|
| 1 | किसी विशेष क्षेत्र के लिए **सिमेंटिक सर्च इंजन** (जैसे रेसिपी, कानूनी दस्तावेज़) | एम्बेडिंग, वेक्टर DB, REST API | ⭐⭐ |
| 2 | **AI-संचालित कोड समीक्षक** जो GitHub PRs पर टिप्पणियां करे | LLM प्रॉम्प्टिंग, GitHub API, CI/CD | ⭐⭐⭐ |
| 3 | लाइव इवेंट ट्वीट्स के लिए **रीयल-टाइम भावना डैशबोर्ड** | स्ट्रीमिंग, NLP, WebSockets, React | ⭐⭐⭐ |
| 4 | **मल्टी-मोडल कंटेंट मॉडरेटर** (टेक्स्ट + इमेज) | विज़न मॉडल, वर्गीकरण, क्यू | ⭐⭐⭐⭐ |
| 5 | किसी विषय पर शोधपत्रों का सार देने वाला **स्वायत्त शोध एजेंट** | एजेंट, RAG, टूल उपयोग, मूल्यांकन | ⭐⭐⭐⭐⭐ |

इनमें से एक चुनें, या अपना विचार बनाएँ, और आज ही उसके लिए प्रतिबद्ध हों। सबसे अच्छा प्रोजेक्ट वही है जिसे आप वास्तव में पूरा करेंगे।

## अपना MVP नियोजित करना

निर्माताओं की सबसे बड़ी गलती बहुत बड़ा दायरा तय करना है। अपने **Minimum Viable Product** को बहुत सख्ती से परिभाषित करें:

1. **सिर्फ़ मुख्य सुविधा** - एक यूज़र फ़्लो, एक मॉडल, एक इंटरफ़ेस।
2. **टेक स्टैक** - वे टूल चुनें जिन्हें आप जानते हैं, साथ में एक नई चीज़। अधिकतर प्रोजेक्ट के लिए: Python + FastAPI बैकएंड, React या Next.js फ़्रंटएंड, और मैनेज्ड डेटाबेस।
3. **समयरेखा** - MVP के लिए खुद को दो सप्ताह दें। इससे ज़्यादा समय लगे, तो दायरा बहुत बड़ा है।
4. **सफलता मेट्रिक** - एक संख्या तय करें जो बताए कि प्रोजेक्ट काम कर रहा है (जैसे, "मेरे टेस्ट सेट पर retrieval accuracy 80 per cent से ऊपर")।

<ThinkAboutIt>
अपने प्रोजेक्ट विचार को एक वाक्य में लिखें। अब आधी सुविधाएं काट दें। वही आपका MVP है।
</ThinkAboutIt>

## सार्वजनिक रूप से बनाना

सोशल मीडिया पर अपनी प्रगति साझा करना दिखावा नहीं है, यह करियर रणनीति है।

- **दिन 1**: अपना विचार पोस्ट करें और प्रतिक्रिया मांगें।
- **हर सप्ताह**: छोटा अपडेट साझा करें, आपने क्या बनाया, क्या टूटा और क्या सीखा।
- **लॉन्च का दिन**: आर्किटेक्चर समझाते हुए एक थ्रेड या ब्लॉग पोस्ट लिखें।

सार्वजनिक रूप से बनाने से जवाबदेही बनती है, सहयोगी आकर्षित होते हैं और आवेदन करने से पहले ही आपका नाम भर्ती प्रबंधकों के सामने आ जाता है।

<FunFact>
Stack Overflow के 2024 सर्वे में पाया गया कि 68 per cent भर्ती प्रबंधक किसी उम्मीदवार को इंटरव्यू देने का निर्णय लेने से पहले उसके सार्वजनिक प्रोजेक्ट और पोस्ट देखते हैं।
</FunFact>

## अपना प्रोजेक्ट डिप्लॉय करना

जो प्रोजेक्ट सिर्फ़ `localhost` पर चलता है, वह अदृश्य है। कोई उसे आज़मा नहीं सकता, कोई उसे साझा नहीं कर सकता और कोई भर्ती प्रबंधक उसे कभी नहीं देखेगा।

डिप्लॉयमेंट वैकल्पिक सजावट नहीं है, यही शौकिया प्रोजेक्ट और पोर्टफ़ोलियो पीस के बीच का फर्क है। यहां तीन मज़बूत विकल्प हैं:

| Platform | Best For | Free Tier |
|----------|---------|-----------|
| **Vercel** | Next.js फ़्रंटएंड, सर्वरलेस APIs | उदार |
| **Railway** | Python बैकएंड, डेटाबेस | 500 घंटे/माह |
| **HuggingFace Spaces** | Gradio या Streamlit के साथ ML डेमो | CPU के लिए असीमित |

आप जो भी चुनें, सुनिश्चित करें कि आपके README में ये बातें हों:

- प्रोजेक्ट क्या करता है, इसका एक पंक्ति का विवरण।
- लाइव लिंक या डेमो GIF.
- स्थानीय डेवलपमेंट के लिए स्पष्ट स्थापना निर्देश।

## प्रतिक्रिया लेना और सुधारना

जब आपका MVP लाइव हो जाता है, असली सीख तब शुरू होती है। शिप करना अंतिम रेखा नहीं है, यह शुरुआत की रेखा है।

ऐसे लोगों से सक्रिय रूप से प्रतिक्रिया मांगें जो आपके साथ ईमानदार होंगे:

- संबंधित Discord और Slack समुदायों में इसे साझा करें।
- Reddit पर क्षेत्र-विशेष सबरेडिट में पोस्ट करें।
- जिन दो या तीन इंजीनियरों का आप सम्मान करते हैं, उनसे इसे आज़माने और ईमानदार आलोचना देने को कहें।

हर प्रतिक्रिया को उपहार समझें। महत्वपूर्ण समस्याएं ठीक करें, बाकी को संस्करण दो के लिए नोट करें और अपडेट जल्दी पुश करें।

<ThinkAboutIt>
ऐसा एक समुदाय सोचें जहां आपके लक्षित यूज़र मौजूद हैं। लॉन्च के 48 घंटे के भीतर वहां अपना प्रोजेक्ट साझा करने की योजना बनाएँ।
</ThinkAboutIt>

## इसे अपने पोर्टफ़ोलियो में जोड़ना

आपका प्रोजेक्ट उतना ही मूल्यवान है जितनी उसकी प्रस्तुति। उसे पोर्टफ़ोलियो में जोड़ते समय:

1. **केस स्टडी लिखें** - समस्या, तरीका, आर्किटेक्चर आरेख, परिणाम, सीखे गए सबक।
2. **GitHub पर पिन करें** - साफ़ कमिट इतिहास, अच्छा README, भविष्य के काम के लिए खुले मुद्दे।
3. **दो मिनट का डेमो वीडियो रिकॉर्ड करें** - उत्पाद दिखाएँ और एक तकनीकी निर्णय समझाएँ।
4. **हर जगह लिंक करें** - CV, LinkedIn, व्यक्तिगत साइट, GitHub प्रोफ़ाइल README.

## आपका अगला कदम

पढ़ना बंद करें। अभी एक नई रिपॉज़िटरी खोलें। उसे अपने प्रोजेक्ट विचार के नाम पर रखें।

पहले README लिखें, यह बताएँ कि प्रोजेक्ट क्या करेगा, किसके लिए है और आपके MVP का दायरा क्या है। आज रात वह README पुश करें।

"मैं कुछ बनाना चाहता हूँ" और "मैंने कुछ शिप किया" के बीच की दूरी सिर्फ़ एक कमिट है।

<FunFact>
GitHub डेटा दिखाता है कि अच्छे से लिखे README वाली रिपॉज़िटरी को बिना README वाली रिपॉज़िटरी की तुलना में चार गुना ज़्यादा स्टार और फ़ोर्क मिलते हैं, ओपन सोर्स में भी पहला प्रभाव मायने रखता है।
</FunFact>

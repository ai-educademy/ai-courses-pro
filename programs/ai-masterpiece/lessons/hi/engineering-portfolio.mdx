# Engineering Portfolio

AI युग में आपका पोर्टफ़ोलियो आपका सबसे शक्तिशाली करियर asset है। यह तब बोलता है जब आप कमरे में नहीं होते, आपके सोते समय काम करता है और एक साथ हज़ारों भर्ती प्रबंधकों तक पहुँच सकता है।

सुथरा CV आपको ढेर में पहुँचा देता है। मज़बूत पोर्टफ़ोलियो आपको **उस ढेर से बाहर निकालता है**।

## पोर्टफ़ोलियो CV से बेहतर क्यों हैं

CV किसी को बताता है कि आप क्या करने का दावा करते हैं। पोर्टफ़ोलियो उसे **साबित** करता है।

AI और software engineering में hiring managers औसतन CV पर छह सेकंड बिताते हैं। लेकिन जब वे अच्छे से बनाए गए GitHub profile या personal site पर जाते हैं, तो वे मिनटों तक देखते हैं, कभी-कभी उससे भी ज़्यादा। यही अतिरिक्त ध्यान rejection email और first-round interview के बीच फर्क बनता है।

<Callout>
अपने पोर्टफ़ोलियो को product और hiring manager को user मानें। हर तत्व friction घटाए और trust बनाए।
</Callout>

## GitHub: आपकी सार्वजनिक कार्यशाला

आपका GitHub profile वह पहली जगह है जहां technical recruiters देखते हैं। इसे असरदार बनाएँ।

### Profile README
अपने username के नाम वाली repository में `README.md` बनाएँ। यह आपके profile के शीर्ष पर दिखता है। इसमें शामिल करें:

- आप कौन हैं और किस पर ध्यान देते हैं, इसका एक पंक्ति का सार।
- आपके सबसे मज़बूत कौशलों को दिखाने वाले दो या तीन bullet points.
- आपके श्रेष्ठ projects, blog और LinkedIn के links.

### Pinned Repositories
आप छह repositories तक pin कर सकते हैं। ऐसे projects चुनें जो **विस्तार और गहराई** दिखाएँ:

- Deployment के साथ एक end-to-end ML project.
- Engineering rigour दिखाने वाला एक backend या systems project.
- एक open-source contribution (अर्थपूर्ण बदलावों वाला fork भी चलेगा)।

### Contribution Graph
Consistency, intensity से ज़्यादा मायने रखती है। हरे squares का steady graph reliability का संकेत देता है। Sporadic bursts की बजाय छोटे, नियमित commits का लक्ष्य रखें।

## Project Showcase: क्या बनाएँ

Hiring manager की नज़र में सभी projects बराबर नहीं होते। सबसे अच्छे portfolio projects में तीन traits होते हैं:

1. **वे वास्तविक समस्या हल करते हैं** - भले ही छोटी हो।
2. **वे deployed और accessible होते हैं** - live link हर बार README से बेहतर है।
3. **उनमें write-up शामिल होता है** - आपके decisions, trade-offs और lessons learnt समझाते हुए।

ऐसे projects से बचें जो साफ़ तौर पर tutorial follow-alongs लगते हैं। अगर हज़ारों लोग वही चीज़ उसी code से बना चुके हैं, तो वह आपको अलग नहीं करता।

<ThinkAboutIt>
अपने मौजूदा projects देखें। किसे आप interview में demo करने पर सबसे ज़्यादा गर्व महसूस करेंगे? अगर कोई भी आपको उत्साहित नहीं करता, तो यह नया कुछ बनाने का संकेत है।
</ThinkAboutIt>

## Technical Blog Posts लिखना

Blog सबसे high-leverage portfolio item है जिसे अधिकतर engineers अनदेखा करते हैं।

**यह क्यों काम करता है:**
- यह communication skills दिखाता है, जो engineering में दुर्लभ हैं।
- यह recruiters और collaborators से inbound interest लाता है।
- यह आपकी अपनी समझ गहरी करता है, क्योंकि जिसे आप सच में नहीं जानते, उसे समझा नहीं सकते।

**किस बारे में लिखें:**
- आपने जो technical decision लिया और क्यों लिया।
- कोई bug जिसे debug करने में आपने घंटों लगाए और आपने क्या सीखा।
- दो tools या approaches की तुलना जिन्हें आपने evaluate किया।

**कहां publish करें:**
- Discoverability के लिए **Dev.to** या **Hashnode**।
- Long-term ownership के लिए **आपकी अपनी site**।
- अधिकतम reach के लिए दोनों जगह cross-post करें।

<FunFact>
Stack Overflow के सह-संस्थापक Jeff Atwood अपने blog "Coding Horror" को अपने करियर का सबसे बड़ा कारक मानते हैं। उन्होंने वर्षों तक लगातार लिखा, जिसके बाद यह अब तक बने सबसे महत्वपूर्ण developer platforms में से एक तक पहुँचा।
</FunFact>

## Engineers के लिए LinkedIn Optimisation

कई engineers LinkedIn को अनदेखा करते हैं, लेकिन recruiters वहीं रहते हैं। कुछ high-impact बदलाव:

- **Headline**: "Software Engineer at X" छोड़ें। इसके बजाय आज़माएँ: "ML Engineer | Building AI-powered search systems | Open to opportunities"।
- **About section**: तीन छोटे paragraphs लिखें, आप क्या करते हैं, आपने क्या बनाया है और आप क्या खोज रहे हैं।
- **Featured section**: अपना सबसे अच्छा blog post, project demo या conference talk पिन करें।
- **Skills**: धुंधले शब्दों (problem-solving, teamwork) की बजाय specific technologies (PyTorch, Kubernetes, FastAPI) सूचीबद्ध करें।

## Personal Website: क्या शामिल करें

आपकी personal site आपका home base है। इसे सरल और तेज़ load होने वाला रखें।

**शामिल करें:**
- Professional photo के साथ छोटा bio.
- Screenshots या demos के साथ आपके top three projects के links.
- आपका blog या उसका link.
- Contact information या simple form.

**छोड़ें:**
- Fancy animations जो page धीमा कर दें।
- Percentage bars वाली skills section, वे कुछ नहीं बतातीं।
- आपका बनाया हर project. बहुत सख्ती से curate करें।

<FunFact>
Google के hiring research ने पाया कि personal website वाले candidates को experience level और qualifications नियंत्रित करने के बाद भी, बिना website वालों की तुलना में callback मिलने की संभावना 27 per cent अधिक थी।
</FunFact>

## Portfolio Review Checklist

अपने portfolio को पूरा मानने से पहले यह list चलाएँ:

- [ ] GitHub profile में README, छह pinned repos और consistent contribution graph है।
- [ ] कम से कम एक project live link के साथ डिप्लॉय किया गया है।
- [ ] हर pinned project में purpose, setup instructions और screenshot या demo वाला स्पष्ट README है।
- [ ] आपने कम से कम एक technical blog post publish किया है।
- [ ] LinkedIn headline, about section और featured content optimised हैं।
- [ ] Personal website तीन seconds से कम में लोड होती है और mobile पर काम करती है।
- [ ] Non-technical friend आपकी site से समझ सकता है कि आप क्या करते हैं।

<ThinkAboutIt>
अपना portfolio link tech से बाहर किसी व्यक्ति को भेजें और उनसे पूछें: "क्या आप बता सकते हैं कि मैं क्या करता हूँ और क्या मैं इसमें अच्छा हूँ?" उनका उत्तर वे blind spots दिखाएगा जिन्हें आप खुद नहीं देख सकते।
</ThinkAboutIt>

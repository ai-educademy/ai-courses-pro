# ప్రారంభం నుంచి ముగింపు వరకు ML పైప్‌లైన్ - ముడి డేటా నుండి డిప్లాయ్ చేసిన మోడల్ వరకు

చాలా ట్యుటోరియల్‌లు `model.fit()` వద్ద ఆగిపోతాయి. ప్రొడక్షన్ లో అది పని లో 20% మాత్రమే. ఈ పాఠం **మొత్తం ML జీవనచక్రం** ద్వారా నడిపిస్తుంది - Spotify లో సిఫార్సు ఇంజిన్‌లు, Stripe లో మోసం గుర్తింపు, Google లో సెర్చ్ ర్యాంకింగ్ ని శక్తి చేసే అదే పైప్‌లైన్.

## 🗺️ ML జీవనచక్రం ఒక చూపులో

<Illustration src="/images/lessons/end-to-end-ml-pipeline.svg" alt="డేటా ingestion నుండి పర్యవేక్షణ వరకు ML పైప్‌లైన్ దశల రేఖాచిత్రం" title="ప్రొడక్షన్ ML పైప్‌లైన్ యొక్క ఎనిమిది దశలు - ప్రతి ఒక్కటి సంభావ్య విఫలం స్థానం." />

ప్రతి ప్రొడక్షన్ ML సిస్టమ్ ఈ దశల ద్వారా వెళ్తుంది:

1. **డేటా సేకరణ** - APIలు, డేటాబేస్‌లు, ఈవెంట్ ప్రవాహాలు, వెబ్ స్క్రేపింగ్
2. **డేటా శుభ్రపరచడం** - ఖాళీ విలువల నిర్వహణ, డీడూప్లికేషన్, రకం మార్పిడి
3. **ఫీచర్ ఇంజినీరింగ్** - ముడి సంకేతాలు ని మోడల్-ready ఫీచర్లు గా మార్చడం
4. **మోడల్ Selection** - మీ సమస్యకు సరిపోల్చండి అయ్యే ఆర్కిటెక్చర్లు ఎంచుకోవడం
5. **శిక్షణ** - GPU/CPU సమన్వయం, హైపర్‌పారామీటర్ సర్దుబాటు
6. **మూల్యాంకనం** - ఆఫ్‌లైన్ మెట్రిక్స్, A/B పరీక్షలు, న్యాయపరమైన తనిఖీలు
7. **డిప్లాయ్‌మెంట్** - సర్వింగ్ మౌలిక సదుపాయాలు, లేటెన్సీ budgets
8. **పర్యవేక్షణ** - డ్రిఫ్ట్ గుర్తింపు, అలర్టింగ్, retraining ప్రేరేపణ

## 📦 డేటా సేకరణ మరియు Versioning

ముడి డేటా మీ పునాది. దీన్ని సోర్స్ కోడ్ లాగా చూడండి - **అంతా వెర్షన్ చేయండి**.

```bash
# Initialise DVC in your repo
dvc init
dvc remote add -d storage s3://my-ml-data-bucket

# Track a dataset
dvc add data/transactions.csv
git add data/transactions.csv.dvc .gitignore
git commit -m "Track raw transaction dataset v1"
dvc push
```

**DVC** (డేటా వెర్షన్ నియంత్రణ) ద్వారా మీరు ఏ చారిత్రక డేటాసెట్‌నైనా `git checkout` చేయవచ్చు. Git tags తో కలిపి, ఏ సమయం నుండైనా ఏ ప్రయోగాన్నైనా మళ్లీ పునరుత్పత్తి చేయవచ్చు.

<FunFact>Netflix రోజుకు 1.5 ట్రిలియన్ ఈవెంట్లు ని తమ డేటా పైప్‌లైన్‌లు ద్వారా ప్రక్రియ చేస్తుంది - ప్రతి సెకను సుమారు 17 మిలియన్ ఈవెంట్లు వారి సిఫార్సు మోడళ్లు కి ఫీడ్ అవుతాయి.</FunFact>

## 🛠️ ఫీచర్ ఇంజినీరింగ్ - పోటీలు గెలిచే చోటు

అల్గారిథమ్‌లు కంటే ఫీచర్లు ఎక్కువ ముఖ్యం. అద్భుతమైన ఫీచర్లు ఉన్న gradient-boosted వృక్షం, పేలవమైన ఫీచర్లు ఉన్న లోతైన న్యూరల్ నెట్‌వర్క్ ని ఓడిస్తుంది.

```python
import pandas as pd

df = pd.read_csv("data/transactions.csv", parse_dates=["timestamp"])

# Temporal features
df["hour"] = df["timestamp"].dt.hour
df["is_weekend"] = df["timestamp"].dt.dayofweek >= 5

# Aggregation features
user_stats = df.groupby("user_id")["amount"].agg(["mean", "std", "count"])
user_stats.columns = ["user_avg_amount", "user_std_amount", "user_txn_count"]
df = df.merge(user_stats, on="user_id")

# Ratio features
df["amount_vs_avg"] = df["amount"] / df["user_avg_amount"]
```

## 🧪 MLflow తో ప్రయోగాల ట్రాకింగ్

మీరు ఏమి ప్రయత్నించారో ఎప్పుడూ ట్రాక్ కోల్పోకండి. MLflow పరామీటర్లు, మెట్రిక్స్, ఆర్టిఫాక్ట్‌లను స్వయంచాలకంగా లాగ్ చేస్తుంది.

```python
import mlflow
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.metrics import f1_score

mlflow.set_experiment("fraud-detection-v2")

with mlflow.start_run(run_name="gbm-baseline"):
    params = {"n_estimators": 500, "max_depth": 6, "learning_rate": 0.05}
    mlflow.log_params(params)

    model = GradientBoostingClassifier(**params)
    model.fit(X_train, y_train)

    score = f1_score(y_test, model.predict(X_test))
    mlflow.log_metric("f1_score", score)
    mlflow.sklearn.log_model(model, "model")
```

MLflow UIలో రన్‌లను పోల్చి, ఉత్తమ మోడల్‌ను పరీక్ష దశ → ప్రొడక్షన్ జీవనచక్ర ట్యాగ్‌లతో **మోడల్ రిజిస్ట్రీ**కి ముందుకు పంపండి.

## 🚀 పైప్‌లైన్ గా కోడ్ - Orchestration

చేతి దశలు విఫలమవుతాయి. సమన్వయ ఫ్రేమ్‌వర్క్‌లు వాడి మీ పైప్‌లైన్‌ను కోడ్‌లో వ్యక్తపరచండి:

| టూల్ | దేనికి ఉత్తమం | కీలక బలం |
|------|-------------|----------|
| **Kubeflow పైప్‌లైన్‌లు** | Kubernetes‌కు సహజమైన ML | ఇప్పటికే ఉన్న K8s క్లస్టర్లపై స్కేల్ అవుతుంది |
| **Apache Airflow** | క్లిష్టమైన DAG షెడ్యూలింగ్ | పరిపక్వ పర్యావరణం, విస్తృత స్వీకరణ |

| **ZenML** | MLOps అబ్స్ట్రాక్షన్ | స్టాక్-నిర్దిష్టతలేని, ఏ టూల్ నైనా కలపవచ్చు చేయవచ్చు |

## 🌐 మోడల్ సర్వింగ్ మరియు డిప్లాయ్‌మెంట్

మీ మోడల్ కి API అవసరం. రెండు ప్రధాన నమూనాలు:

**REST API** - సరళం, HTTP-ఆధారిత, moderate థ్రూపుట్ కి గొప్పది:
```python
# FastAPI model server
from fastapi import FastAPI
import joblib

app = FastAPI()
model = joblib.load("model.pkl")

@app.post("/predict")
async def predict(features: dict):
    prediction = model.predict([list(features.values())])
    return {"prediction": int(prediction[0])}
```

**gRPC** - ద్వైమిక ప్రోటోకాల్, REST కంటే 2-10× వేగం, అంతర్గత మైక్రోసర్వీసులు మరియు అధిక థ్రూపుట్ సన్నివేశాలకు సరైనది.

### కానరీ డిప్లాయ్‌మెంట్‌లు

కొత్త మోడల్‌కు 100% ట్రాఫిక్ ఎప్పుడూ పంపకండి. **కానరీ విడుదలలు** వాడండి: 5% → 25% → 50% → 100%, ప్రతి దశలో లోపాల రేట్లను పర్యవేక్షిస్తూ. మెట్రిక్స్ దిగజారితే వెంటనే వెనక్కి తిప్పండి.

## 📊 పర్యవేక్షణ మరియు ఫీడ్‌బ్యాక్ లూప్

డిప్లాయ్‌మెంట్ పూర్తి చేయడం ముగింపు గీత కాదు, ప్రారంభ తుపాకి. ఇవి పర్యవేక్షించండి:

- **డేటా డ్రిఫ్ట్** - శిక్షణ డేటా నుండి ఇన్‌పుట్ పంపిణీలు మారడం
- **భావన డ్రిఫ్ట్** - ఫీచర్లు మరియు లక్ష్య మధ్య relationship మారడం
- **పనితీరు దిగజారడం** - ఖచ్చితత్వం/లేటెన్సీ మెట్రిక్స్ పడిపోవడం

**Evidently AI**, **WhyLabs**, **Arize** లాంటి టూల్స్ డ్రిఫ్ట్ డ్యాష్‌బోర్డ్‌లు అందిస్తాయి. డ్రిఫ్ట్ పరిమితులు దాటినప్పుడు, తాజా ప్రొడక్షన్ డేటాతో స్వయంచాలక మళ్లీ శిక్షణను ప్రేరేపించండి, ఫీడ్‌బ్యాక్ లూప్‌ను మూసివేస్తూ.

## 🎯 కీలక విషయాలు

- **అంతా** వెర్షన్ చేయండి: కోడ్, డేటా, మోడళ్లు, పైప్‌లైన్ configs
- ఆర్కిటెక్చర్ మార్పులు కంటే ఫీచర్ ఇంజినీరింగ్ ఎక్కువ ROI ఇస్తుంది
- పైప్‌లైన్‌లను కోడ్‌లో వ్యక్తపరచండి. చేతి దశలు సాంకేతిక ఋణం

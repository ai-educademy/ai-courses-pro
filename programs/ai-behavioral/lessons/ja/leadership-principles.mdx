# リーダーシップの原則 — あらゆる行動上の質問の背後にある隠されたルーブリック

Amazon では、ループ内のすべての面接官に、調査すべき特定のリーダーシップ原則が割り当てられます。 Google では、面接官が構造化されたルーブリックを使用して、「Google らしさ」とリーダーシップのシグナルを評価します。 Meta では、あなたの「迅速に行動する」能力と「社会的価値を構築する」能力を評価します。これらは漠然とした文化的な雰囲気ではなく、**ハードルを上げる期待値を定義した採点基準**であり、ストーリーはそれらに正確に対応している必要があります。

## リーダーシップの原則が重要な理由

リーダーシップの原則は、面接全体を評価するためのレンズです。 2 人の候補者が同じストーリーを語ることができます。1 人は「強力な採用」を獲得し、もう 1 人は「不採用」を得ることができます。これは、ストーリーが表面化する**シグナル**に完全に基づいています。

<Callout>「あなたは良い人ですか？」と問われているわけではありません。あなたは「圧力下でこの特定の原則を実証したという証拠を提出できますか?」と尋ねられています。各原則を、具体的なストーリーが必要なチェックボックスのように扱います。
</Callout>

## Amazon の 16 のリーダーシップ原則 — 詳細

Amazon の原則は最も明確であり、広く研究されています。すべてのテクノロジー企業はそれらから資金を借りているため、これらをマスターすることで幅広い準備が整います。

|原則 |彼らが本当に評価していること |よくある質問 |
|----------|--------------------------|--------------------------|
| **顧客のこだわり** |顧客から出発して逆算しますか? | 「社内の利便性よりも顧客のニーズを優先したときのことを教えてください。」 |
| **所有権** |あなたはチームだけでなく会社全体を代表して行動しますか? | 「自分の仕事の範囲外の何かを修正したときのことを説明してください。」 |
| **発明と簡素化** |複雑な問題に対する簡単な解決策を見つけることができますか? | 「複雑なプロセスを簡素化したときのことを教えてください。」 |
| **ディープにダイブ** |詳細情報を常に把握し、指標が異なる場合は監査していますか? | 「他の人が見逃していた問題をあなたが見つけたときの例を教えてください。」 |
| **同意せずに同意します** |挑戦し、決定が下されたら全力で取り組むことができますか? | 「チームの決定に同意できなかったときのことを教えてください。」 |
| **結果を提供** |失敗したにもかかわらず、納期どおりに納品できますか? | 「厳しい納期の中で納品した時間を説明してください。」 |

<FunFact>Amazon の面接官は、原則ごとに少なくとも 2 つのフォローアップの質問をするように訓練されています。最初のストーリーが浅い場合は、フォローアップでそれが明らかになります。幅だけでなく深さを準備することが、「採用」と「傾斜」を分けるものです。
</FunFact>

## Google の「Googleらしさ」とリーダーシップシグナル

Google は Amazon のように正式なリストを公開していませんが、面接ルーブリックでは、**一般的な認知能力**、**役割関連の知識**、**リーダーシップ**、**Google らしさ**の 4 つの分野を評価しています。最後の 2 つは行動的なものです。

**Google におけるリーダーシップ** とは、次のことを意味します。
- たとえタイトルがなくても、曖昧な場合には介入して主導権を握る
- 自分だけでなく他の人の成功を助ける
- 複雑さを乗り越え、不確実性にもかかわらず前進する

**Google らしさ** とは次のことを意味します。
- 曖昧さの中で繁栄し、構造を混乱に導く
- 同僚に対して敬意と知的謙虚さを持って接する
- 誰も見ていないときでも正しいことをする

<Callout>Google は、**創発的なリーダーシップ**を明確に評価しています。つまり、肩書きがそれを与えているからではなく、状況がそれを必要としているからリーダーシップを発揮します。あなたのストーリーは、任命されるのではなく、あなたがステップアップしていることを示すものでなければなりません。
</Callout>

## 管理職の称号なしでリーダーシップを発揮する

これは、候補者が挙げる最も一般的な懸念です。「私は誰かを管理したことがありません。どうすればリーダーシップを発揮できますか?」

面接におけるリーダーシップとは、人員数ではなく、**影響力、主導権、影響力**を指します。

- **影響**: 「私は新しいテスト戦略を提案し、パイロットを実行してデータを共有することで、3 つのチームにそれを採用するよう説得しました。」
- **取り組み**: 「オンコール ランブックが古いことに気づきました。ワーキング グループを作成し、書き直して、インシデント対応時間を 40% 短縮しました。」
- **影響**: 「私は 2 人の若手エンジニアを最初のシステム設計を通じて指導しました。現在は 2 人とも独立して機能を主導しています。」

<ThinkAboutIt>最後にチームの働き方を変更したときのことを思い出してください。プロセスを改善したり、ツールを導入したり、基準を引き上げたりしたときです。たとえあなたの肩書が「ソフトウェアエンジニア」だったとしても、それがあなたのリーダーシップストーリーです。
</ThinkAboutIt>

## 主要原則に対する STAR の回答例

### 顧客のこだわり

> **状況:** 当社のロイヤルティ アプリの評価は 4 つ星でしたが、ギフト カードの残高チェックに関する顧客の苦情が急増しており、1 週間あたり 200 枚のチケットが発生していました。
>
> **タスク:** ロイヤルティ チームの技術リーダーとして、機能が技術的に動作しているにもかかわらず顧客が不満を感じている理由を診断する必要がありました。
>
> **アクション:** カスタマー サポートのトランスクリプトを自分で取得したところ、レガシー メインフレームへの同期呼び出しが原因でバランス チェックに 8 秒かかったことがわかりました。私は非同期キャッシュ レイヤーを提案し、1 週間で概念実証を構築し、予想されるチケット削減を示すビジネス ケースを提示しました。その後、私は実装を主導し、キャッシュ インフラストラクチャのプラットフォーム チームと調整しました。
>
> **結果:** 残高チェックの応答時間が 8 秒から 400 ミリ秒に短縮されました。このカテゴリのサポート チケットは 1 か月以内に 85% 減少しました。このアプローチは、他の 3 つの従来の統合でも複製されました。

### 同意せずに同意する

> **状況:** 私のチームは、新しい API ゲートウェイに GraphQL を採用するか、REST を使い続けるかを検討していました。フロントエンド開発者の経験データに基づいて、私は GraphQL を強く支持しました。
>
> **タスク:** 私は自分の主張を提示する必要がありましたが、最終的にはチームが下した決定を支持する必要がありました。
>
> **アクション:** ベンチマーク、開発者エクスペリエンス調査、移行コストの見積もりを含む比較ドキュメントを作成しました。アーキテクチャのレビュー中に、私はデータを明確に提示しました。チームは、既存のエコシステムとトレーニング コストの低さを理由に REST を選択しました。意見の相違にもかかわらず、私は完全にコミットしました。私は REST API の設計を主導し、スタイル ガイドを書き、二次的な会話で決定を損なうことはありませんでした。
>
> **結果:** REST API は予定通りに出荷され、フロントエンド チームはうまく適応しました。 6 か月後、新製品の API 戦略を再検討したとき、私の元のデータは、より意味のある、ターゲットを絞った GraphQL 導入の情報を提供するのに役立ちました。全力でコミットすることで築いた信頼が、2度目のときは自分の意見に重みを与えてくれました。

## ストーリー マトリックスの準備

最も効果的な準備テクニックは、**原則とストーリーのマトリックス**を構築することです。原則を行、ストーリーを列として含むスプレッドシートを作成します。

1. 対象企業の原則（原則が公開されていない場合は 5 つのコア コンピテンシー）をリストします。
2. 自分のキャリアから強力な STAR ストーリーを 8 ～ 10 個書く
3. 各ストーリーを、それが実証できる 2 つまたは 3 つの原則にマッピングします。
4. ギャップを特定する — ストーリーのない原則には、新しい原則を準備する必要がある
5. マッピングされた各原則の角度から各ストーリーをリハーサルします

## よくある落とし穴

- **原則の詰め込み**: 1 つの答えで 5 つの原則を満たそうとします。どれか 1 つを選んで完璧に仕上げれば、その後のフォローアップで深みが明らかになります。
- **一般的な話**: 「自分の仕事をうまくこなすことでオーナーシップを示した」というのはオーナーシップではなく、最低限のことです。あなたが自分の役割を「超えた」方法を示してください。
- **否定的な意見を無視する**: 「バックボーンを持ち、同意せずにコミットする」などの原則では、本当の緊張感を示す必要があります。矛盾のない浄化された物語には説得力がありません。
- **「コミット」の部分を忘れる**: 多くの候補者は、大きな意見の相違について話しますが、最終決定に完全にコミットしていることを示すことを忘れています。

<ThinkAboutIt>目標とする役割の職務内容を確認してください。そのレベルで評価される可能性が最も高い 3 つのリーダーシップ原則はどれですか?それぞれにしっかりとしたストーリーはありますか？
</ThinkAboutIt>

## 重要なポイント

- **リーダーシップの原則は、モチベーションを高めるポスターではなく、スコアリングのルーブリック**です。チェックリストとして扱います。
- **8 ～ 10 のストーリーをすべての関連原則にマッピングする **ストーリー マトリックス**を構築し、すべてのギャップを埋めます。
- **リーダーシップは影響力であり、権威ではありません。** リーダーシップを発揮するために管理職の肩書は必要ありません。
- **深さは広さに勝ります。** すべてのストーリーについて 2 つまたは 3 つのフォローアップの質問を準備します。
- **マトリックスを企業全体に適応させる** - 基礎となるテーマは驚くほど一貫しています。

オファーを受け取る候補者は、最も印象的なキャリアを持つ者ではありません。彼らは、面接官が採点している内容に正確に対応するストーリーを通じて、自分の影響力を「証明」できる人たちです。
